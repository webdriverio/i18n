گزارشگر بصری (Visual Reporter) یک قابلیت جدید است که در `@wdio/visual-service` از نسخه [v5.2.0](https://github.com/webdriverio/visual-testing/releases/tag/%40wdio%2Fvisual-service%405.2.0) معرفی شده است. این گزارشگر به کاربران امکان می‌دهد گزارش‌های تفاوت JSON تولیدشده توسط سرویس تست بصری را به‌صورت بصری مشاهده کرده و آن‌ها را به قالبی خوانا برای انسان تبدیل کنند. این ابزار با فراهم کردن یک رابط گرافیکی برای بررسی خروجی، به تیم‌ها کمک می‌کند نتایج تست بصری را بهتر تحلیل و مدیریت کنند.

برای استفاده از این قابلیت، مطمئن شوید که پیکربندی لازم برای تولید فایل `output.json` را در اختیار دارید. این سند شما را در راه‌اندازی، اجرا و درک گزارشگر بصری راهنمایی می‌کند.

# پیش‌نیازها

پیش از استفاده از گزارشگر بصری، مطمئن شوید که سرویس تست بصری را برای تولید فایل‌های گزارش JSON پیکربندی کرده‌اید:

```ts
export const config = {
    // ...
    services: [
        [
            "visual",
            {
                createJsonReportFiles: true, // فایل output.json را تولید می‌کند
            },
        ],
    ],
};
```

برای دستورالعمل‌های دقیق‌تر راه‌اندازی، به [مستندات تست بصری](./) WebdriverIO یا [`createJsonReportFiles`](./service-options.md#createjsonreportfiles-new) مراجعه کنید.

# نصب

برای نصب گزارشگر بصری، آن را با استفاده از npm به‌عنوان یک وابستگی توسعه به پروژه خود اضافه کنید:

```bash
npm install @wdio/visual-reporter --save-dev
```

این کار اطمینان می‌دهد که فایل‌های لازم برای تولید گزارش از تست‌های بصری شما در دسترس هستند.

# استفاده

## ساخت گزارش بصری

پس از اجرای تست‌های بصری و تولید فایل `output.json`، می‌توانید گزارش بصری را با استفاده از CLI یا پرسش‌های تعاملی بسازید.

### استفاده از CLI

می‌توانید با اجرای دستور CLI زیر گزارش را تولید کنید:

```bash
npx wdio-visual-reporter --jsonOutput=<path-to-output.json> --reportFolder=<path-to-store-report> --logLevel=debug
```

#### گزینه‌های الزامی:

-   `--jsonOutput`: مسیر نسبی فایل `output.json` که توسط سرویس تست بصری تولید شده است. این مسیر نسبت به پوشه‌ای است که دستور را از آن اجرا می‌کنید.
-   `--reportFolder`: پوشه نسبی که گزارش تولیدشده در آن ذخیره می‌شود. این مسیر نیز نسبت به پوشه‌ای است که دستور را از آن اجرا می‌کنید.

#### گزینه‌های اختیاری:

-   `--logLevel`: برای دریافت لاگ‌های دقیق، آن را روی `debug` تنظیم کنید؛ این کار به‌ویژه برای عیب‌یابی مفید است.

#### مثال

```bash
npx wdio-visual-reporter --jsonOutput=/path/to/output.json --reportFolder=/path/to/report --logLevel=debug
```

این دستور گزارش را در پوشه مشخص‌شده تولید کرده و در کنسول بازخورد ارائه می‌دهد. برای مثال:

```bash
✔ Build output copied successfully to "/path/to/report".
⠋ Prepare report assets...
✔ Successfully generated the report assets.
```

#### مشاهده گزارش

:::warning
باز کردن مستقیم `path/to/report/index.html` در مرورگر **بدون ارائه آن از طریق یک سرور محلی** کار **نخواهد کرد**.
:::

برای مشاهده گزارش، باید از یک سرور ساده مانند [sirv-cli](https://www.npmjs.com/package/sirv-cli) استفاده کنید. می‌توانید سرور را با دستور زیر راه‌اندازی کنید:

```bash
npx sirv-cli /path/to/report --single
```

این کار لاگ‌هایی مشابه نمونه زیر تولید می‌کند. توجه داشته باشید که شماره پورت ممکن است متفاوت باشد:

```logs
  Your application is ready~! 🚀

  - Local:      http://localhost:8080
  - Network:    Add `--host` to expose

────────────────── LOGS ──────────────────
```

اکنون می‌توانید با باز کردن URL ارائه‌شده در مرورگر خود، گزارش را مشاهده کنید.

### استفاده از پرسش‌های تعاملی

به‌عنوان جایگزین، می‌توانید دستور زیر را اجرا کرده و برای تولید گزارش به پرسش‌ها پاسخ دهید:

```bash
npx @wdio/visual-reporter
```

پرسش‌ها شما را در ارائه مسیرها و گزینه‌های لازم راهنمایی می‌کنند. در پایان، پرسش تعاملی همچنین از شما می‌پرسد که آیا می‌خواهید سروری برای مشاهده گزارش راه‌اندازی کنید یا خیر. اگر راه‌اندازی سرور را انتخاب کنید، ابزار یک سرور ساده اجرا کرده و یک URL را در لاگ‌ها نمایش می‌دهد. می‌توانید این URL را در مرورگر خود باز کنید تا گزارش را مشاهده کنید.

# درک گزارش بصری

گزارشگر بصری نمایی سازمان‌یافته از نتایج تست‌های بصری شما ارائه می‌دهد. برای هر اجرای تست، شما قادر خواهید بود:

-   به‌راحتی بین موارد تست جابه‌جا شوید و نتایج تجمیع‌شده را ببینید.
-   فراداده‌هایی مانند نام تست‌ها، مرورگرهای استفاده‌شده و نتایج مقایسه را بررسی کنید.
-   تصاویر تفاوت را مشاهده کنید که نشان می‌دهند تفاوت‌های بصری در کجا شناسایی شده‌اند.

این نمایش بصری، تحلیل نتایج تست را ساده‌تر می‌کند و شناسایی و رفع پسرفت‌های بصری (visual regressions) را آسان‌تر می‌سازد.
