گزینه‌های مقایسه، گزینه‌هایی هستند که بر نحوهٔ اجرای مقایسه تأثیر می‌گذارند.

:::info NOTE
همهٔ گزینه‌های مقایسه را می‌توان هنگام نمونه‌سازی سرویس یا برای هر یک از متدهای `checkElement`،`checkScreen` و `checkFullPageScreen` به‌طور جداگانه استفاده کرد. اگر یک گزینهٔ متد، کلید یکسانی با گزینه‌ای داشته باشد که هنگام نمونه‌سازی سرویس تنظیم شده است، گزینهٔ مقایسهٔ متد، مقدار گزینهٔ مقایسهٔ سرویس را بازنویسی خواهد کرد.
:::

## حساسیت بصری

---

:::info تاریخچهٔ نسخه‌ها برای گزینه‌های `ignore*`
پیش‌تنظیم‌های `ignore*` یک بار، به‌صورت یک تغییر ناسازگار (breaking change)، رفتارشان تغییر کرد؛ زمانی که موتور مقایسه از ResembleJS به Pixelmatch تغییر یافت:

| نسخه | موتور | توضیحات |
| --- | --- | --- |
| v9 و پایین‌تر | ResembleJS | معنای اصلی `ignore*` (مبتنی بر RGB/روشنایی، با ترتیب پیش‌تنظیم‌های خاص resemble). |
| v10 و بالاتر | Pixelmatch | پیش‌تنظیم‌های `ignore*` به تنظیمات threshold/AA در pixelmatch نگاشت می‌شوند. مقادیر پیش‌فرض و رفتار فعلی در ادامه برای هر گزینه مستند شده‌اند؛ قابلیت‌ها/اصلاحات جدیدی که روی این پایه اضافه شده‌اند با یادداشت «Since» در گزینهٔ مربوطه مشخص شده‌اند. |

:::

**ترتیب «آخری برنده است»:** وقتی بیش از یک پرچم `ignore*` هم‌زمان فعال باشد، تنها یک پیش‌تنظیم واقعاً اعمال می‌شود، و این بر اساس ترتیب زیر است (مورد بعدی برنده است): `ignoreAlpha` ← `ignoreAntialiasing` ← `ignoreColors` ← `ignoreLess` ← `ignoreNothing`. یک هشدار ثبت می‌شود که نام پیش‌تنظیم برنده را اعلام می‌کند.

### `ignoreColors`

<Option type="boolean" default="false" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_
-   **Since:** `v10.1.0`: مقایسهٔ فقط روشنایی با استفاده از وزن‌های luma در resemble (`0.3/0.59/0.11`).

فقط روشنایی را مقایسه می‌کند و تفاوت‌های فام/رنگ را نادیده می‌گیرد. پیش‌تنظیم: آستانهٔ سخت‌گیرانه (حدود 16/255)، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه استفاده کنید وقتی** انتظار می‌رود خود رنگ تغییر کند (مثلاً رابط کاربری قابل تغییر تم، تصاویری که در هر محیط رنگ متفاوتی دارند) اما همچنان می‌خواهید تغییرات چیدمان یا روشنایی را تشخیص دهید.

</Option>
### `ignoreAlpha`

<Option type="boolean" default="false" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_
-   **Since:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

تصاویر را مقایسه کرده و تفاوت‌های کانال آلفا را نادیده می‌گیرد. پیش‌تنظیم: آستانهٔ سخت‌گیرانه (حدود 16/255)، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه استفاده کنید وقتی** رندر شفافیت/opacity ناپایدار است (مثلاً لایه‌های روی‌هم، عناصر نیمه‌شفاف) اما رنگ‌های واقعی پیکسل‌های زیرین اهمیت دارند.

</Option>
### `ignoreAntialiasing`

<Option type="boolean" default="true" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_
-   **Since:** `v10`: مقدار پیش‌فرض به `true` تغییر کرد (در v9 و پایین‌تر `false` بود).

پیکسل‌های anti-aliased را در حین مقایسه نادیده می‌گیرد (آستانهٔ آسان‌گیرانه حدود 32/255). این تنها پیش‌تنظیمی است که anti-aliasing را نادیده می‌گیرد و به‌طور پیش‌فرض فعال است تا نویز رندر زیرپیکسلی از همان ابتدا باعث شکست مقایسه‌ها نشود. برای مقایسهٔ سخت‌گیرانه که در آن پیکسل‌های anti-aliased باید به‌عنوان عدم تطابق محسوب شوند، آن را روی `false` تنظیم کنید.

**از این گزینه استفاده کنید تا** رایج‌ترین منبع ناپایداری تست‌های بصری را حل کنید: لبه‌های متن و اشکال که بین ماشین‌ها/مرورگرها با anti-aliasing کمی متفاوت رندر می‌شوند، در حالی که در واقع هیچ چیزی تغییر نکرده است.

</Option>
### `ignoreLess`

<Option type="boolean" default="false" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_
-   **Since:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

تصاویر را با استفاده از یک تلرانس RGB آسان‌گیرانه (حدود 16/255 برای هر کانال در فضای YIQ) مقایسه می‌کند. پیش‌تنظیم: آستانهٔ سخت‌گیرانه، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه استفاده کنید وقتی** می‌خواهید کمی فضای تنفس برای نویزهای جزئی رندر (آرتیفکت‌های فشرده‌سازی شبیه JPEG، گرد شدن جزئی رنگ) داشته باشید، بدون اینکه anti-aliasing نادیده گرفته شود.

</Option>
### `ignoreNothing`

<Option type="boolean" default="false" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_
-   **Since:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

از تلرانس صفر استفاده می‌کند: هر تفاوت پیکسلی، از جمله anti-aliasing، به‌عنوان عدم تطابق محسوب می‌شود.

**از این گزینه استفاده کنید وقتی** به اثبات پیکسل‌به‌پیکسل نیاز دارید که هیچ چیزی تغییر نکرده است، مثلاً برای اطمینان از اینکه یک اصلاح، هیچ رگرسیونی، هر چند کوچک، ایجاد نکرده است.

</Option>
### `scaleImagesToSameSize`

<Option type="boolean" default="false" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد_

دو تصویر را قبل از اجرای مقایسه به یک اندازه مقیاس‌بندی می‌کند. فعال‌سازی `ignoreAntialiasing` و `ignoreAlpha` به‌شدت توصیه می‌شود

</Option>
## کنترل مستقیم pixelmatch

---

:::info اضافه‌شده در v10.1.0
`compareOptions.pixelmatch` در v9 (ResembleJS) معادلی ندارد. این یک روش کاملاً جدید برای کنترل مستقیم موتور مقایسه است، به‌جای استفاده از یک پیش‌تنظیم `ignore*`.
:::

### `compareOptions.pixelmatch`

<Option type="object" default="undefined" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را برای همان متد مورد استفاده بازنویسی خواهد کرد_
-   **اضافه‌شده در:** `v10.1.0`

تنظیمات را مستقیماً به [pixelmatch](https://github.com/mapbox/pixelmatch) ارسال می‌کند، به‌جای استفاده از یک پیش‌تنظیم `ignore*`. **از این گزینه زمانی استفاده کنید که پنج پیش‌تنظیم `ignore*` بیش از حد کلی هستند:** به یک مقدار آستانهٔ مشخص نیاز دارید که پیش‌تنظیم‌ها ارائه نمی‌دهند، یا یک تصویر diff می‌خواهید که در گزارش‌ها/خروجی CI شما واقعاً خوانا باشد، به‌جای هایلایت پیش‌فرض سرخابی.

:::warning انحصار متقابل در یک شیء گزینه‌ها
قرار دادن هر کلید `ignore*` و `pixelmatch` در **یک** شیء گزینه‌ها، خطای `CompareOptionsConflictError` را پرتاب می‌کند، حتی اگر مقدار `ignore*` برابر `false` باشد (مثال نامعتبر زیر را ببینید). برای هر شیء یک حالت انتخاب کنید: پیش‌تنظیم‌های `ignore*` یا `pixelmatch`، هرگز هر دو.

این موضوع فقط درون یک شیء صدق می‌کند. پیکربندی سرویس و گزینه‌های فراخوانی یک متد، اشیای جداگانه‌ای هستند، بنابراین یک فراخوانی `check*` **مجاز است** از حالتی متفاوت با پیکربندی سرویس استفاده کند؛ برای مثال، سرویس از پیش‌تنظیم‌های `ignore*` استفاده می‌کند اما یک فراخوانی به‌جای آن `pixelmatch` ارسال می‌کند (یا برعکس). در این حالت خطایی رخ نمی‌دهد، فقط یک هشدار ثبت می‌شود که تغییر حالت مقایسه را اعلام می‌کند.
:::

| فیلد | نوع | پیش‌فرض | کاربرد |
| --- | --- | --- | --- |
| `threshold` | `number` | `0.1` | حساسیت از 0 (هر تفاوت پیکسلی باعث شکست می‌شود) تا 1 (تقریباً هیچ چیزی باعث شکست نمی‌شود). از این برای تنظیم دقیق یک مقدار حساسیت مشخص استفاده کنید، به‌جای انتخاب نزدیک‌ترین پیش‌تنظیم `ignore*`. |
| `includeAA` | `boolean` | `false` | `true` پیکسل‌های لبه‌ای anti-aliased را به‌عنوان عدم تطابق محسوب می‌کند؛ `false` آن‌ها را نادیده می‌گیرد. اگر تفاوت‌های رندر لبه‌های فونت/اشکال باعث شکست‌های ناپایدار می‌شوند، این را خاموش کنید. |
| `diffColor` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌های ناهمخوان در تصویر diff. اگر رنگ سرخابی با رابط کاربری شما ترکیب می‌شود (مثلاً تم صورتی/بنفش) و تشخیص عدم تطابق‌ها دشوار است، آن را تغییر دهید. |
| `aaColor` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌های anti-aliased، که به‌صورت بصری از عدم تطابق‌های واقعی جدا نگه داشته می‌شود تا بتوانید با یک نگاه «نویز رندر» را از «باگ واقعی» تشخیص دهید. |
| `diffColorAlt` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌هایی که اضافه یا حذف شده‌اند (نه فقط تغییر رنگ داده‌اند)، مفید برای تشخیص جابه‌جایی‌های چیدمان در برابر تغییرات رنگ. |
| `alpha` | `number` | `0.1` | میزان opacity لایهٔ diff روی اسکرین‌شات واقعی. آن را افزایش دهید تا diffها در گزارش‌ها برجسته‌تر شوند؛ کاهش دهید تا همچنان رابط کاربری زیرین را به‌وضوح ببینید. ارتباطی با پیش‌تنظیم `ignoreAlpha` ندارد. |
| `diffMask` | `boolean` | `false` | روی `true` تنظیم کنید تا فقط diff خام (با پس‌زمینهٔ شفاف) خروجی داده شود، به‌جای diff ترسیم‌شده روی اسکرین‌شات شما؛ مفید برای ساخت نمایشگر/گزارش diff سفارشی خودتان. |
| `checkerboard` | `boolean` | `true` | نحوهٔ رندر پیکسل‌های نیمه‌شفاف در diff را کنترل می‌کند. اگر الگوی شطرنجی به‌راحتی با محتوای واقعی اسکرین‌شات‌هایتان اشتباه گرفته می‌شود، آن را خاموش کنید. |

**پیکربندی سرویس:**

```js
// wdio.conf.js
export const config = {
    // ...
    services: [
        ['visual', {
            compareOptions: {
                pixelmatch: {
                    threshold: 0.063,
                    includeAA: true,
                },
            },
        }],
    ],
}
```

**بازنویسی در سطح متد وقتی سرویس از پیش‌تنظیم‌های `ignore*` استفاده می‌کند:**

```js
await browser.checkScreen('homepage', {
    pixelmatch: { threshold: 0.05 },
})
```

**بازنویسی در سطح متد وقتی سرویس از `pixelmatch` استفاده می‌کند:**

```js
await browser.checkScreen('homepage', {
    ignoreLess: true,
})
```

**نامعتبر: خطای `CompareOptionsConflictError` را پرتاب می‌کند**

```js
compareOptions: {
    ignoreLess: false,
    pixelmatch: { threshold: 0.063 },
}
```

برای معنای کامل گزینه‌ها، [مستندات pixelmatch](https://github.com/mapbox/pixelmatch) را ببینید.

</Option>
## پوشاندن نواحی در موبایل

---

### `blockOutStatusBar`

<Option type="boolean" default="true" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد. این گزینه **فقط برای موبایل** است_

نوار وضعیت و نوار آدرس را در حین مقایسه‌ها به‌طور خودکار می‌پوشاند. این کار از شکست‌ها به دلیل وضعیت زمان، وای‌فای یا باتری جلوگیری می‌کند.

</Option>
### `blockOutToolBar`

<Option type="boolean" default="true" required="no">

-   **نکته:** _می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` نیز استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد. این گزینه **فقط برای موبایل** است_

نوار ابزار را به‌طور خودکار می‌پوشاند.

</Option>
### `blockOutSideBar`

<Option type="boolean" default="true" required="no">

-   **نکته:** _فقط می‌تواند برای `checkScreen()` استفاده شود. این گزینه تنظیم پلاگین را بازنویسی خواهد کرد. این گزینه **فقط برای iPad** است_

نوار کناری را برای iPadها در حالت افقی (landscape) در حین مقایسه‌ها به‌طور خودکار می‌پوشاند. این کار از شکست‌ها به دلیل کامپوننت native تب/خصوصی/نشانک جلوگیری می‌کند.

</Option>
