گزینه‌های مقایسه، گزینه‌هایی هستند که بر نحوه اجرای مقایسه تأثیر می‌گذارند.

:::info نکته
تمام گزینه‌های مقایسه را می‌توان هنگام نمونه‌سازی سرویس یا برای هر `checkElement`، `checkScreen` و `checkFullPageScreen` به‌صورت جداگانه استفاده کرد. اگر یک گزینه متد کلیدی مشابه با گزینه‌ای داشته باشد که هنگام نمونه‌سازی سرویس تنظیم شده است، گزینه مقایسه متد مقدار گزینه مقایسه سرویس را بازنویسی خواهد کرد.
:::

## حساسیت بصری

---

:::info تاریخچه نسخه‌ها برای گزینه‌های `ignore*`
پیش‌تنظیم‌های `ignore*` یک بار، به‌عنوان یک تغییر ناسازگار (breaking change)، هنگامی که موتور مقایسه از ResembleJS به Pixelmatch تغییر کرد، رفتارشان تغییر کرد:

| نسخه | موتور | توضیحات |
| --- | --- | --- |
| v9 و پایین‌تر | ResembleJS | معنای اصلی `ignore*` (مبتنی بر RGB/روشنایی، با ترتیب پیش‌تنظیم‌های خودِ resemble). |
| v10 و بالاتر | Pixelmatch | پیش‌تنظیم‌های `ignore*` به تنظیمات threshold/AA در pixelmatch نگاشت می‌شوند. مقادیر پیش‌فرض و رفتار فعلی برای هر گزینه در ادامه مستند شده است؛ ویژگی‌ها/اصلاحات جدید بر پایه این نسخه با یادداشت «از نسخه» در گزینه مربوطه مشخص شده‌اند. |
| v11 و بالاتر | Pixelmatch 8 | رنگ‌ها در فضای رنگی OKLab با فاصله HyAB مقایسه می‌شوند (پیش‌تر: YIQ). مقیاس threshold و پیش‌تنظیم‌های `ignore*` تغییری نکرده‌اند، اما درصدهای عدم تطابق ممکن است اندکی با v10 متفاوت باشند. |

:::

**ترتیب «آخرین برنده است»:** هنگامی که بیش از یک پرچم `ignore*` به‌طور هم‌زمان فعال باشد، فقط یک پیش‌تنظیم واقعاً اعمال می‌شود، طبق این ترتیب (موارد بعدی برنده‌اند): `ignoreAlpha` ← `ignoreAntialiasing` ← `ignoreColors` ← `ignoreLess` ← `ignoreNothing`. یک هشدار ثبت می‌شود که نام پیش‌تنظیم برنده را اعلام می‌کند.

### `ignoreColors`

<Option type="boolean" default="false" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_
-   **از نسخه:** `v10.1.0`: مقایسه فقط بر اساس روشنایی با استفاده از وزن‌های luma در resemble (`0.3/0.59/0.11`).

فقط روشنایی را مقایسه می‌کند و تفاوت‌های فام/رنگ را نادیده می‌گیرد. پیش‌تنظیم: threshold سخت‌گیرانه (حدود ۱۶/۲۵۵)، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه زمانی استفاده کنید که** انتظار می‌رود خودِ رنگ تغییر کند (مثلاً UI قابل تغییر تم، تصاویری که در هر محیط رنگشان تغییر می‌کند) اما همچنان می‌خواهید تغییرات چیدمان یا روشنایی را تشخیص دهید.

</Option>
### `ignoreAlpha`

<Option type="boolean" default="false" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_
-   **از نسخه:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

تصاویر را مقایسه کرده و تفاوت‌های کانال آلفا را نادیده می‌گیرد. پیش‌تنظیم: threshold سخت‌گیرانه (حدود ۱۶/۲۵۵)، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه زمانی استفاده کنید که** رندر شفافیت/opacity ناپایدار است (مثلاً overlayها، عناصر نیمه‌شفاف) اما رنگ‌های واقعی پیکسل‌های زیرین اهمیت دارند.

</Option>
### `ignoreAntialiasing`

<Option type="boolean" default="true" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_
-   **از نسخه:** `v10`: مقدار پیش‌فرض به `true` تغییر کرد (در v9 و پایین‌تر `false` بود).

پیکسل‌های دارای anti-aliasing را در حین مقایسه نادیده می‌گیرد (threshold آسان‌گیرانه حدود ۳۲/۲۵۵). این تنها پیش‌تنظیمی است که anti-aliasing را نادیده می‌گیرد و به‌طور پیش‌فرض فعال است تا نویز رندر زیرپیکسلی از همان ابتدا باعث شکست مقایسه‌ها نشود. برای مقایسه سخت‌گیرانه که در آن پیکسل‌های anti-aliased باید به‌عنوان عدم تطابق شمرده شوند، آن را روی `false` تنظیم کنید.

**از این گزینه برای** حل رایج‌ترین منبع ناپایداری تست‌های بصری استفاده کنید: لبه‌های متن و اشکال که بین ماشین‌ها/مرورگرها با anti-aliasing کمی متفاوت رندر می‌شوند، حتی وقتی در واقع چیزی تغییر نکرده است.

</Option>
### `ignoreLess`

<Option type="boolean" default="false" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_
-   **از نسخه:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

تصاویر را با استفاده از تلرانس RGB آسان‌گیرانه (حدود ۱۶/۲۵۵ برای هر کانال در فضای YIQ) مقایسه می‌کند. پیش‌تنظیم: threshold سخت‌گیرانه، anti-aliasing نادیده گرفته نمی‌شود.

**از این گزینه زمانی استفاده کنید که** می‌خواهید کمی فضای تنفس برای نویزهای جزئی رندر (آرتیفکت‌های فشرده‌سازی شبیه JPEG، گرد شدن جزئی رنگ‌ها) داشته باشید، بدون اینکه anti-aliasing را نادیده بگیرید.

</Option>
### `ignoreNothing`

<Option type="boolean" default="false" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_
-   **از نسخه:** `v10.1.0`: قانون threshold/AA مخصوص به خود را مستقل از سایر پرچم‌های `ignore*` اعمال می‌کند.

از تلرانس صفر استفاده می‌کند: هر تفاوت پیکسلی، از جمله anti-aliasing، به‌عنوان عدم تطابق شمرده می‌شود.

**از این گزینه زمانی استفاده کنید که** به اثبات دقیق در حد پیکسل نیاز دارید که هیچ چیزی تغییر نکرده است، مثلاً برای تأیید اینکه یک اصلاح هیچ رگرسیونی، هرچقدر هم کوچک، ایجاد نکرده است.

</Option>
### `scaleImagesToSameSize`

<Option type="boolean" default="false" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد_

دو تصویر را پیش از اجرای مقایسه به یک اندازه مقیاس‌بندی می‌کند. فعال کردن `ignoreAntialiasing` و `ignoreAlpha` به‌شدت توصیه می‌شود

</Option>
## کنترل مستقیم pixelmatch

---

:::info اضافه‌شده در v10.1.0
`compareOptions.pixelmatch` هیچ معادلی در v9 (ResembleJS) ندارد. این یک روش کاملاً جدید برای کنترل مستقیم موتور مقایسه است، به‌جای استفاده از یک پیش‌تنظیم `ignore*`.
:::

### `compareOptions.pixelmatch`

<Option type="object" default="undefined" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را برای همان متد خاص مورد استفاده بازنویسی خواهد کرد_
-   **اضافه‌شده در:** `v10.1.0`

تنظیمات را به‌جای استفاده از یک پیش‌تنظیم `ignore*`، مستقیماً به [pixelmatch](https://github.com/mapbox/pixelmatch) ارسال می‌کند. **از این گزینه زمانی استفاده کنید که پنج پیش‌تنظیم `ignore*` بیش از حد کلی هستند:** به یک مقدار threshold مشخص نیاز دارید که پیش‌تنظیم‌ها ارائه نمی‌دهند، یا یک تصویر diff می‌خواهید که به‌جای هایلایت پیش‌فرض سرخابی، در گزارش‌ها/خروجی CI شما واقعاً خوانا باشد.

:::warning انحصار متقابل در یک شیء گزینه‌ها
قرار دادن هر کلید `ignore*` به همراه `pixelmatch` در **یک** شیء گزینه‌ها، خطای `CompareOptionsConflictError` پرتاب می‌کند، حتی اگر مقدار `ignore*` برابر `false` باشد (مثال نامعتبر زیر را ببینید). برای هر شیء یک حالت انتخاب کنید: پیش‌تنظیم‌های `ignore*` یا `pixelmatch`، هرگز هر دو.

این قانون فقط درون یک شیء اعمال می‌شود. پیکربندی سرویس و گزینه‌های فراخوانی یک متد، اشیاء جداگانه‌ای هستند، بنابراین یک فراخوانی `check*` **مجاز است** از حالتی متفاوت با پیکربندی سرویس استفاده کند؛ برای مثال سرویس از پیش‌تنظیم‌های `ignore*` استفاده می‌کند اما یک فراخوانی به‌جای آن `pixelmatch` ارسال می‌کند (یا برعکس). در این حالت خطایی رخ نمی‌دهد و فقط یک هشدار مبنی بر تغییر حالت مقایسه ثبت می‌شود.
:::

| فیلد | نوع | پیش‌فرض | کاربرد |
| --- | --- | --- | --- |
| `threshold` | `number` | `0.1` | حساسیت از ۰ (هر تفاوت پیکسلی شکست می‌خورد) تا ۱ (تقریباً هیچ چیز شکست نمی‌خورد). از این برای تنظیم یک مقدار حساسیت دقیق استفاده کنید، به‌جای انتخاب نزدیک‌ترین پیش‌تنظیم `ignore*`. |
| `includeAA` | `boolean` | `false` | مقدار `true` پیکسل‌های لبه anti-aliased را به‌عنوان عدم تطابق می‌شمارد؛ `false` آن‌ها را نادیده می‌گیرد. اگر تفاوت‌های رندر لبه فونت/اشکال باعث شکست‌های ناپایدار می‌شوند، این را خاموش کنید. |
| `diffColor` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌های ناهمخوان در تصویر diff. اگر رنگ سرخابی با UI شما ترکیب می‌شود (مثلاً یک تم صورتی/بنفش) و تشخیص عدم تطابق‌ها دشوار است، آن را تغییر دهید. |
| `aaColor` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌های anti-aliased، که از نظر بصری از عدم تطابق‌های واقعی جدا نگه داشته می‌شود تا بتوانید در یک نگاه «نویز رندر» را از «باگ واقعی» تشخیص دهید. |
| `diffColorAlt` | `[number, number, number]` | `[255, 0, 255]` (سرخابی) | رنگ RGB برای پیکسل‌هایی که اضافه یا حذف شده‌اند (نه فقط تغییر رنگ داده‌اند)، که برای تشخیص جابه‌جایی‌های چیدمان در مقابل تغییرات رنگ مفید است. |
| `alpha` | `number` | `0.1` | میزان opacity لایه diff روی اسکرین‌شات واقعی. آن را افزایش دهید تا diffها در گزارش‌ها برجسته‌تر شوند؛ کاهش دهید تا همچنان UI زیرین را به‌وضوح ببینید. ربطی به پیش‌تنظیم `ignoreAlpha` ندارد. |
| `diffMask` | `boolean` | `false` | روی `true` تنظیم کنید تا فقط diff خام (با پس‌زمینه شفاف) خروجی داده شود، به‌جای diff ترسیم‌شده روی اسکرین‌شات شما؛ برای ساخت نمایشگر/گزارش diff سفارشی خودتان مفید است. |
| `checkerboard` | `boolean` | `true` | نحوه رندر پیکسل‌های نیمه‌شفاف در diff را کنترل می‌کند. اگر الگوی شطرنجی به‌راحتی با محتوای واقعی اسکرین‌شات‌های شما اشتباه گرفته می‌شود، آن را خاموش کنید. |

**پیکربندی سرویس:**

```js
// wdio.conf.js
export const config = {
    // ...
    services: [
        ['visual', {
            compareOptions: {
                pixelmatch: {
                    threshold: 0.063,
                    includeAA: true,
                },
            },
        }],
    ],
}
```

**بازنویسی در متد وقتی سرویس از پیش‌تنظیم‌های `ignore*` استفاده می‌کند:**

```js
await browser.checkScreen('homepage', {
    pixelmatch: { threshold: 0.05 },
})
```

**بازنویسی در متد وقتی سرویس از `pixelmatch` استفاده می‌کند:**

```js
await browser.checkScreen('homepage', {
    ignoreLess: true,
})
```

**نامعتبر: خطای `CompareOptionsConflictError` پرتاب می‌کند**

```js
compareOptions: {
    ignoreLess: false,
    pixelmatch: { threshold: 0.063 },
}
```

برای معنای کامل گزینه‌ها، [مستندات pixelmatch](https://github.com/mapbox/pixelmatch) را ببینید.

</Option>

### `blockOutStatusBar`

<Option type="boolean" default="true" required="no">

-   **توضیح:** _همچنین می‌تواند برای `checkElement`، `checkScreen()` و `checkFullPageScreen()` استفاده شود. این گزینه تنظیمات پلاگین را بازنویسی خواهد کرد. این گزینه **فقط برای موبایل** است_

به‌طور خودکار نوار وضعیت و نوار آدرس را در حین مقایسه‌ها می‌پوشاند. این کار از شکست‌ها به دلیل وضعیت زمان، وای‌فای یا باتری جلوگیری می‌کند.

</Option>

### `blockOutSideBar`

<Option type="boolean" default="true" required="no">

</Option>
