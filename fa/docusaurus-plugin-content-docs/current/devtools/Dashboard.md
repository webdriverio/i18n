حالت Live رابط کاربری DevTools را در یک پنجره مرورگر خارجی باز می‌کند و اجرای تست شما را به‌صورت بلادرنگ پخش می‌کند. این حالت همتای تعاملی [Trace Mode](/docs/devtools/wdio/trace-mode) است که رابط کاربری را نادیده می‌گیرد و به‌جای آن یک خروجی آفلاین قابل‌حمل می‌نویسد. حالت Live به‌طور پیش‌فرض فعال است (`mode: 'live'`)، بنابراین تنها با اجرای تست‌های WebdriverIO، داشبورد راه‌اندازی می‌شود.

هنگامی که تست‌های خود را اجرا می‌کنید، رابط کاربری DevTools به‌طور خودکار در یک پنجره مرورگر خارجی باز می‌شود و تست‌ها بلافاصله با نمایش بصری بلادرنگ شروع به اجرا می‌کنند. پس از اتمام اجرای اولیه، از دکمه‌های پخش برای اجرای دوباره تست‌ها یا مجموعه‌های تست به‌صورت جداگانه، و از دکمه توقف برای پایان دادن به تست‌های در حال اجرا در هر زمان استفاده کنید.

## آنچه داشبورد نمایش می‌دهد

- **پیش‌نمایش زنده مرورگر** — مرورگر تحت تست را هنگام اجرای دستورات تماشا کنید.
- **پیشرفت تست** — مجموعه‌ها و تست‌ها هنگام اجرا به‌روزرسانی می‌شوند.
- **اجرای دستورات** — هر اقدام در همان لحظه‌ای که رخ می‌دهد پخش می‌شود.
- **زبانه‌های Workbench** — Actions و Metadata، به‌علاوه Source، Log، Console، Network و Errors (هر کدام با نشانی از تعداد)، و Compare پس از یک [Preserve & Rerun](/docs/devtools/wdio/preserve-and-rerun).

## ویژگی‌های حالت Live

- **[اجرای دوباره تعاملی تست و نمایش بصری](/docs/devtools/wdio/interactive-test-rerunning)** — پیش‌نمایش بلادرنگ مرورگر همراه با اجرای دوباره تست
- **[Preserve & Rerun (مقایسه)](/docs/devtools/wdio/preserve-and-rerun)** — از یک تست ناموفق تصویر لحظه‌ای بگیرید، آن را دوباره اجرا کنید و تفاوت دو اجرا را در کنار هم مقایسه کنید
- **[لاگ‌های Console](/docs/devtools/wdio/console-logs)** — ضبط و بررسی خروجی کنسول مرورگر
- **[لاگ‌های Network](/docs/devtools/wdio/network-logs)** — نظارت بر فراخوانی‌های API و فعالیت شبکه
- **[Metadata](/docs/devtools/wdio/metadata)** — قابلیت‌های نشست، محیط و زمان‌بندی برای هر نشست مرورگر
- **[TestLens](/docs/devtools/wdio/testlens)** — پیمایش به کد منبع با ناوبری هوشمند کد
- **[پشتیبانی از چند فریم‌ورک](/docs/devtools/wdio/multi-framework-support)** — با Mocha، Jasmine و Cucumber کار می‌کند
- **[Screencast نشست](/docs/devtools/wdio/screencast)** — ضبط خودکار ویدیو از نشست‌های مرورگر

## پیکربندی پنجره داشبورد

گزینه‌های `port`، `hostname` و `devtoolsCapabilities` سرور رابط کاربری DevTools و پنجره‌ای که در آن باز می‌شود را کنترل می‌کنند. برای جزئیات بیشتر به [مرجع پیکربندی](/docs/devtools/reference) مراجعه کنید.

## اجرای مستقل بک‌اند

آداپترها سرور داشبورد را درون همان فرایند راه‌اندازی می‌کنند، بنابراین معمولاً هرگز نیازی به دست زدن به آن ندارید. این سرور به‌صورت یک فایل اجرایی مستقل نیز ارائه می‌شود، که زمانی به کارتان می‌آید که داشبورد باید بیش از یک اجرای واحد پابرجا بماند - یا زمانی که تست‌ها به زبان JavaScript نیستند، مانند آداپتر Python (به صفحه [Selenium](/docs/devtools/selenium) مراجعه کنید).

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

هر دو شکل `--port 8080` و `--port=8080` پذیرفته می‌شوند. `--port` یک *ترجیح* است، نه یک تضمین: اگر آن پورت اشغال باشد، سرور به‌جای شکست خوردن، به یک پورت آزاد متصل می‌شود. سرور پورتی را که واقعاً به آن متصل شده چاپ می‌کند، و این همان خطی است که باید بخوانید، نه پورتی که درخواست کرده بودید:

```
devtools-backend listening at http://localhost:3000
```

آداپتر Python زمانی که `DEVTOOLS_PORT` تنظیم شده باشد، به‌جای راه‌اندازی یک سرور دوم، به سروری که از قبل در حال گوش دادن است متصل می‌شود. آداپترهای JavaScript بک‌اند خود را درون همان فرایند راه‌اندازی می‌کنند؛ برای انتخاب پورت از گزینه `port` آن‌ها استفاده کنید.

فایل اجرایی دوم، یعنی `show-trace`، یک آرشیو trace را در پخش‌کننده آفلاین باز می‌کند - به [Trace Player](/docs/devtools/trace-player) مراجعه کنید.
