حالت زنده (Live mode) رابط کاربری DevTools را در یک پنجره مرورگر خارجی باز می‌کند و اجرای تست شما را به‌صورت بلادرنگ پخش می‌کند. این حالت همتای تعاملی [حالت Trace](/docs/devtools/wdio/trace-mode) است که رابط کاربری را نادیده می‌گیرد و به‌جای آن یک خروجی آفلاین قابل‌حمل می‌نویسد. حالت زنده به‌طور پیش‌فرض فعال است (`mode: 'live'`)، بنابراین تنها با اجرای تست‌های WebdriverIO، داشبورد راه‌اندازی می‌شود.

هنگامی که تست‌های خود را اجرا می‌کنید، رابط کاربری DevTools به‌طور خودکار در یک پنجره مرورگر خارجی باز می‌شود و تست‌ها بلافاصله با نمایش بصری بلادرنگ شروع به اجرا می‌کنند. پس از اتمام اجرای اولیه، از دکمه‌های پخش برای اجرای مجدد تست‌ها یا مجموعه‌های تست به‌صورت جداگانه، و از دکمه توقف برای پایان دادن به تست‌های در حال اجرا در هر زمان استفاده کنید.

## آنچه داشبورد نمایش می‌دهد

- **پیش‌نمایش زنده مرورگر** — مرورگر تحت تست را هنگام اجرای دستورات تماشا کنید.
- **پیشرفت تست** — مجموعه‌ها و تست‌ها در حین اجرا به‌روزرسانی می‌شوند.
- **اجرای دستورات** — هر عمل در همان لحظه‌ای که رخ می‌دهد پخش می‌شود.
- **زبانه‌های Workbench** — بخش‌های Actions، Console، Network، Metadata و Source را برای تست انتخاب‌شده بررسی کنید.

## ویژگی‌های حالت زنده

- **[اجرای مجدد و نمایش بصری تعاملی تست‌ها](/docs/devtools/wdio/interactive-test-rerunning)** — پیش‌نمایش بلادرنگ مرورگر همراه با اجرای مجدد تست
- **[حفظ و اجرای مجدد (مقایسه)](/docs/devtools/wdio/preserve-and-rerun)** — از یک تست ناموفق اسنپ‌شات بگیرید، آن را دوباره اجرا کنید و تفاوت دو اجرا را در کنار هم مقایسه کنید
- **[لاگ‌های Console](/docs/devtools/wdio/console-logs)** — ثبت و بررسی خروجی کنسول مرورگر
- **[لاگ‌های Network](/docs/devtools/wdio/network-logs)** — نظارت بر فراخوانی‌های API و فعالیت شبکه
- **[Metadata](/docs/devtools/wdio/metadata)** — قابلیت‌های نشست (capabilities)، محیط و زمان‌بندی برای هر نشست مرورگر
- **[TestLens](/docs/devtools/wdio/testlens)** — پیمایش به کد منبع با ناوبری هوشمند کد
- **[پشتیبانی از چند فریم‌ورک](/docs/devtools/wdio/multi-framework-support)** — با Mocha، Jasmine و Cucumber کار می‌کند
- **[ضبط صفحه نشست](/docs/devtools/wdio/screencast)** — ضبط خودکار ویدیو از نشست‌های مرورگر

## پیکربندی پنجره داشبورد

گزینه‌های `port`، `hostname` و `devtoolsCapabilities` سرور رابط کاربری DevTools و پنجره‌ای را که در آن باز می‌شود کنترل می‌کنند. برای جزئیات بیشتر به [مرجع پیکربندی](/docs/devtools/reference) مراجعه کنید.

## اجرای مستقل بک‌اند

آداپتورها سرور داشبورد را درون همان فرایند راه‌اندازی می‌کنند، بنابراین معمولاً هرگز نیازی به دست زدن به آن ندارید. این سرور به‌صورت یک فایل اجرایی مستقل نیز ارائه می‌شود، که زمانی به آن نیاز دارید که داشبورد باید بیش از یک اجرا باقی بماند - یا زمانی که تست‌ها به زبان JavaScript نیستند، مانند آداپتور Python (به صفحه [Selenium](/docs/devtools/selenium) مراجعه کنید).

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

`--port` یک *ترجیح* است، نه یک تضمین: اگر آن پورت اشغال باشد، سرور به‌جای شکست خوردن، به یک پورت آزاد متصل می‌شود. سرور پورتی را که واقعاً به آن متصل شده چاپ می‌کند، و این همان خطی است که باید بخوانید، نه پورتی که درخواست کرده بودید:

```
devtools-backend listening at http://localhost:3000
```

با استفاده از `DEVTOOLS_PORT` (که همه آداپتورها از آن پشتیبانی می‌کنند)، یک اجرا را به سروری که از قبل در حال گوش دادن است هدایت کنید، تا اجرا به‌جای راه‌اندازی سرور دوم، به همان سرور متصل شود.

فایل اجرایی دوم، `show-trace`، یک آرشیو trace را در پخش‌کننده آفلاین باز می‌کند - به [پخش‌کننده Trace](/docs/devtools/trace-player) مراجعه کنید.
