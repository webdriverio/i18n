جلسات مرورگر را به‌صورت ویدیوهای `.webm` ضبط می‌کند. ویدیوها در رابط کاربری DevTools در کنار نمای snapshot و نمای تغییرات DOM نمایش داده می‌شوند.

در هر سه آداپتور در دسترس است - **WebdriverIO**، **[Selenium WebDriver](/docs/devtools/selenium)** و **[Nightwatch.js](/docs/devtools/nightwatch#screencast)**. حالت ضبط در هر فریم‌ورک متفاوت است (در صورت امکان CDP push و در غیر این صورت polling - بخش [پشتیبانی مرورگرها](#browser-support) را در ادامه ببینید).

## راه‌اندازی

رمزگذاری screencast به فایل اجرایی **ffmpeg** در `PATH` نیاز دارد. پوشش `fluent-ffmpeg` همراه با آداپتور نصب می‌شود، بنابراین نیازی به افزودن چیز دیگری نیست:

```sh
# Install ffmpeg - https://ffmpeg.org/download.html
brew install ffmpeg        # macOS
sudo apt install ffmpeg    # Ubuntu/Debian
```

بدون ffmpeg، ضبط‌کننده همچنان اجرا می‌شود، اما مرحله رمزگذاری یک هشدار ثبت می‌کند و هیچ فایلی نمی‌نویسد.

## پیکربندی

```ts
services: [
  [
    'devtools',
    {
      screencast: {
        enabled: true,
        captureFormat: 'jpeg',
        quality: 70,
        maxWidth: 1280,
        maxHeight: 720,
      }
    }
  ]
]
```

## گزینه‌ها

| گزینه | نوع | پیش‌فرض | توضیحات |
|---|---|---|---|
| `enabled` | `boolean` | `false` | فعال‌سازی ضبط جلسه |
| `captureFormat` | `'jpeg' \| 'png'` | `'jpeg'` | قالب تصویر فریم. **فقط Chrome/Chromium** - قالبی را که Chrome از طریق CDP ارسال می‌کند کنترل می‌کند. در حالت polling (Firefox، Safari) که اسکرین‌شات‌ها همیشه PNG هستند نادیده گرفته می‌شود. بر کانتینر ویدیوی خروجی که همیشه `.webm` است تأثیری ندارد |
| `quality` | `number` | `70` | کیفیت فشرده‌سازی JPEG بین 0 تا 100. فقط در حالت CDP در Chrome/Chromium با `captureFormat: 'jpeg'` اعمال می‌شود |
| `maxWidth` | `number` | `1280` | حداکثر عرض فریم بر حسب پیکسل. **فقط Chrome/Chromium** - Chrome فریم‌ها را پیش از ارسال از طریق CDP مقیاس‌بندی می‌کند. در حالت polling نادیده گرفته می‌شود |
| `maxHeight` | `number` | `720` | حداکثر ارتفاع فریم بر حسب پیکسل. **فقط Chrome/Chromium** - مشابه مورد بالا |
| `pollIntervalMs` | `number` | `200` | فاصله زمانی گرفتن اسکرین‌شات بر حسب میلی‌ثانیه برای مرورگرهای غیر Chrome (حالت polling). مقدار کمتر = ویدیوی روان‌تر اما رفت‌وبرگشت‌های بیشتر WebDriver در حین اجرای تست |
| `maxBufferFrames` | `number` | `2000` | سقف تعداد فریم‌های نگه‌داشته‌شده در حافظه. با عبور از آن، بافر در جا کم‌حجم می‌شود و فریم‌های اول و آخر حفظ می‌شوند |

## پشتیبانی مرورگرها

ضبط با انتخاب خودکار حالت در همه مرورگرهای اصلی کار می‌کند:

| مرورگر | حالت | نکات |
|---|---|---|
| Chrome / Chromium / Edge | **CDP push** | Chrome فریم‌ها را از طریق DevTools Protocol ارسال می‌کند. کارآمد - بدون تأثیر بر زمان‌بندی دستورات تست |
| Firefox / Safari / سایر | **BiDi polling** | به فراخوانی `browser.takeScreenshot()` در فواصل `pollIntervalMs` برمی‌گردد. هر جا که اسکرین‌شات WebDriver پشتیبانی شود کار می‌کند؛ سربار کوچکی متناسب با فاصله زمانی اضافه می‌کند |

برای تغییر حالت نیازی به تغییر پیکربندی نیست - سرویس قابلیت‌های مرورگر را به‌طور خودکار تشخیص می‌دهد و حالت فعال را ثبت می‌کند.

## رفتار

- ضبط با باز شدن جلسه مرورگر آغاز و با بسته شدن آن متوقف می‌شود.
- فریم‌های خالی ابتدایی (که پیش از اولین پیمایش URL گرفته شده‌اند) به‌طور خودکار حذف می‌شوند تا ویدیوها از اولین اقدام معنادار در صفحه آغاز شوند.
- اگر `browser.reloadSession()` در میانه اجرا فراخوانی شود، سرویس ضبط فعلی را نهایی کرده و ضبط تازه‌ای را برای جلسه جدید آغاز می‌کند. هر جلسه فایل `.webm` مخصوص به خود را تولید می‌کند.
- وقتی چندین ضبط وجود داشته باشد، رابط کاربری DevTools یک منوی کشویی **Recording N** برای جابه‌جایی بین آن‌ها نمایش می‌دهد.

### محل ذخیره فایل‌های خروجی

هر آداپتور در یک پوشه `test-results/` می‌نویسد؛ اما دایرکتوری پایه‌ای که این پوشه در آن قرار می‌گیرد متفاوت است، زیرا آداپتورها از یک resolver مشترک استفاده می‌کنند اما ورودی‌های متفاوتی به آن می‌دهند:

| آداپتور | محل خروجی |
|---|---|
| **WebdriverIO** | اگر `outputDir` به‌طور صریح در `wdio.conf.ts` تنظیم شده باشد `<outputDir>/test-results/`، در غیر این صورت `<rootDir>/test-results/` (`rootDir` دایرکتوری حاوی فایل پیکربندی است). از تنظیم `outputDir` صرفاً برای کنترل مسیر ویدیوها خودداری کنید - WDIO لاگ‌های worker را نیز به آنجا هدایت می‌کند. |
| **Selenium** | `test-results/` در دایرکتوری فایل تستی که همین الان اجرا شده است، و در صورت عدم امکان `process.cwd()`. |
| **Nightwatch** | `test-results/` در دایرکتوری فایل تست، و در صورت عدم امکان دایرکتوری حاوی `nightwatch.conf.*`، و سپس `process.cwd()`. |

در مسیر Selenium/Nightwatch، دایرکتوری‌های زیر `node_modules/` نادیده گرفته می‌شوند تا workspaceهای symlink‌شده ویدیوها را در پوشه وابستگی‌ها نریزند، و دایرکتوری‌ای که قابل نوشتن نباشد به گزینه بعدی واگذار می‌شود.

## فایل‌های خروجی

حالت live داده‌های گرفته‌شده را از طریق WebSocket به داشبورد استریم می‌کند و **هیچ فایل trace روی دیسک نمی‌نویسد** — برای یک خروجی قابل حمل، از [حالت trace](/docs/devtools/wdio/trace-mode) (`trace.zip`) استفاده کنید. تنها فایلی که حالت live می‌نویسد ویدیوی screencast است، و آن هم فقط زمانی که `screencast.enabled: true` باشد. نام فایل‌ها به آداپتور بستگی دارد (نام فریم‌ورک در پیشوند ظاهر می‌شود):

| آداپتور | ویدیوی screencast |
|---|---|
| WebdriverIO | `wdio-video-{sessionId}.webm` |
| Selenium | `selenium-video-{sessionId}.webm` |
| Nightwatch | `nightwatch-video-{sessionId}.webm` |
