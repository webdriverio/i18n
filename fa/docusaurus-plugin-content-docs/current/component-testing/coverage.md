browser runner در WebdriverIO از گزارش‌دهی پوشش کد با استفاده از [`istanbul`](https://istanbul.js.org/) پشتیبانی می‌کند. testrunner به‌طور خودکار کد شما را با استفاده از Vite ابزارگذاری (instrument) می‌کند و پوشش کد را برای شما ثبت می‌کند.

## نحوه عملکرد

`@wdio/browser-runner` از Vite برای ارائه (serve) برنامه شما استفاده می‌کند. هنگامی که پوشش کد را فعال می‌کنید، یک پلاگین به سرور Vite اضافه می‌شود که تلاش می‌کند کد منبع شما را در لحظه، هنگامی که توسط مرورگر درخواست می‌شود، ابزارگذاری کند.

:::warning مهم
**از test runner خارج نشوید!**

پوشش کد به فایل‌هایی متکی است که توسط سرور محلی Vite که WebdriverIO راه‌اندازی کرده است، ارائه و ابزارگذاری می‌شوند.
اگر از `browser.url('http://...')` یا `browser.url('file://...')` برای رفتن به صفحه‌ای دیگر استفاده کنید، محیط ابزارگذاری‌شده را ترک می‌کنید. کد شما اجرا خواهد شد، اما **هیچ پوششی جمع‌آوری نخواهد شد**.

**رویکرد صحیح (تست کامپوننت):**
کامپوننت خود را رندر کنید یا ماژول خود را مستقیماً در فایل تست import کنید.

```js
import { myFunction } from '../src/utils.js'

it('should cover my function', () => {
    myFunction() // این پوشش داده می‌شود
})
```

**رویکرد نادرست (سبک E2E):**
```js
it('will not have coverage', async () => {
    // ❌ خارج شدن از صفحه، ابزارگذاری را از کار می‌اندازد
    await browser.url('http://localhost:3000')
})
```
:::

## راه‌اندازی

برای فعال‌سازی گزارش‌دهی پوشش کد، آن را از طریق پیکربندی browser runner در WebdriverIO فعال کنید، به عنوان مثال:

```js title=wdio.conf.js
export const config = {
    // ...
    runner: ['browser', {
        preset: process.env.WDIO_PRESET,
        coverage: {
            enabled: true
        }
    }],
    // ...
}
```

تمام [گزینه‌های پوشش کد](/docs/runner#coverage-options) را بررسی کنید تا با نحوه پیکربندی صحیح آن آشنا شوید.

:::tip نکات پیکربندی
اگر فایل‌های غیراستاندارد (مانند اسکریپت‌های درون‌خطی در `.html`) را تست می‌کنید یا فایل‌های شما شناسایی نمی‌شوند، ممکن است لازم باشد گزینه‌های `include` و `extension` خود را به‌صراحت بررسی کنید:

```js
coverage: {
    enabled: true,
    // اگر تشخیص پیش‌فرض ناموفق بود، فایل‌های منبع خود را به‌صراحت مشخص کنید
    include: ['src/**/*.js', 'src/**/*.vue'],
    // اگر اسکریپت‌های درون‌خطی دارید، .html را اضافه کنید
    extension: ['.js', '.jsx', '.ts', '.tsx', '.vue', '.html']
}
```
:::

## نادیده گرفتن کد

ممکن است بخش‌هایی از کدبیس شما وجود داشته باشد که بخواهید عمداً آن‌ها را از ردیابی پوشش کد مستثنی کنید. برای این کار می‌توانید از راهنماهای تجزیه (parsing hints) زیر استفاده کنید:

- `/* istanbul ignore if */`: دستور if بعدی را نادیده می‌گیرد.
- `/* istanbul ignore else */`: بخش else یک دستور if را نادیده می‌گیرد.
- `/* istanbul ignore next */`: مورد بعدی در کد منبع را نادیده می‌گیرد (توابع، دستورات if، کلاس‌ها و هر چیز دیگری).
- `/* istanbul ignore file */`: کل یک فایل منبع را نادیده می‌گیرد (این باید در ابتدای فایل قرار گیرد).

:::info

توصیه می‌شود فایل‌های تست خود را از گزارش پوشش کد مستثنی کنید، زیرا ممکن است باعث بروز خطا شوند، به عنوان مثال هنگام فراخوانی دستور `execute`. اگر مایلید آن‌ها را در گزارش خود نگه دارید، اطمینان حاصل کنید که ابزارگذاری آن‌ها را از این طریق مستثنی می‌کنید:

```ts
await browser.execute(/* istanbul ignore next */() => {
    // ...
})
```

:::
