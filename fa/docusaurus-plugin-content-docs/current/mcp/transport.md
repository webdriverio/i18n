سرور MCP وب‌درایورآی‌او از دو حالت انتقال پشتیبانی می‌کند: **stdio** (پیش‌فرض) و **HTTP**.

## stdio (پیش‌فرض)

stdio انتقال استاندارد MCP است. کلاینت هوش مصنوعی سرور را به‌عنوان یک پردازه فرزند (child process) اجرا می‌کند و از طریق stdin/stdout با آن ارتباط برقرار می‌کند.

```json
{
  "mcpServers": {
    "webdriverio": {
      "command": "npx",
      "args": ["-y", "@wdio/mcp"]
    }
  }
}
```

از stdio برای راه‌اندازی‌های محلی با Claude Desktop، Claude Code، Cursor و کلاینت‌های مشابهی استفاده کنید که خودشان چرخه حیات سرور را مدیریت می‌کنند.

## HTTP (Streamable HTTP)

حالت HTTP سرور را به‌عنوان یک پردازه مستقل اجرا می‌کند که روی یک پورت گوش می‌دهد. کلاینت‌ها به‌جای اجرای آن به‌عنوان یک زیرپردازه (subprocess)، از طریق HTTP به آن متصل می‌شوند. در این موارد از آن استفاده کنید:

- کلاینت شما از MCP مبتنی بر زیرپردازه پشتیبانی نمی‌کند (مثلاً رابط کاربری وب llama.cpp)
- می‌خواهید یک نمونه سرور را بین چند کلاینت به اشتراک بگذارید
- در حالت امن Codex اجرا می‌کنید که در آن اجرای زیرپردازه محدود شده است
- می‌خواهید سرور در طول چندین نشست کلاینت در حال اجرا باقی بماند

### شروع در حالت HTTP

```bash
npx @wdio/mcp --http --port 3000
```

سرور یک نقطه پایانی (endpoint) واحد ارائه می‌دهد: `http://localhost:<port>/mcp`

### گزینه‌های کامل

```bash
npx @wdio/mcp --http \
  --port 3000 \
  --allowedHosts "localhost,127.0.0.1,::1" \
  --allowedOrigins "http://localhost:5173,https://myapp.example.com"
```

| پرچم               | پیش‌فرض                     | توضیحات                                                                     |
| ------------------ | --------------------------- | ------------------------------------------------------------------------------- |
| `--http`           | —                           | فعال‌سازی حالت انتقال HTTP                                                      |
| `--port`           | `3000`                      | پورتی که سرور روی آن گوش می‌دهد                                                               |
| `--allowedHosts`   | `localhost,127.0.0.1,::1`   | مقادیر مجاز هدر `Host` جداشده با کاما (محافظت در برابر DNS rebinding)         |
| `--allowedOrigins` | _(هیچ — مرورگرها مسدود می‌شوند)_ | مقادیر مجاز `Origin` جداشده با کاما برای CORS. از `*` برای مجاز کردن همه مبداها استفاده کنید. |

### امنیت

**`--allowedHosts`** — در برابر حملات DNS rebinding محافظت می‌کند. فقط درخواست‌هایی پذیرفته می‌شوند که هدر `Host` آن‌ها با این فهرست مطابقت داشته باشد. مقدار پیش‌فرض (`localhost,127.0.0.1,::1`) برای استفاده محلی امن است. اگر سرور را روی یک رابط عمومی در دسترس قرار می‌دهید، نام میزبان خود را اینجا اضافه کنید.

**`--allowedOrigins`** — کنترل می‌کند که کدام مبداهای مرورگر می‌توانند درخواست‌های بین‌مبدایی (CORS) ارسال کنند. به‌طور پیش‌فرض، هیچ مبدای مرورگری مجاز نیست. این کار دسترسی از وب‌سایت‌های دلخواه را مسدود می‌کند، در حالی که همچنان به کلاینت‌های غیرمرورگری (ابزارهای CLI، کلاینت‌های API) اجازه دسترسی می‌دهد. برای مجاز کردن همه مبداها آن را روی `*` تنظیم کنید، یا مبداهای مشخصی را فهرست کنید.

درخواست‌های کلاینت‌های غیرمرورگری (بدون هدر `Origin`) مشمول بررسی CORS نیستند؛ فقط `--allowedHosts` روی آن‌ها اعمال می‌شود.

## موارد استفاده

### رابط کاربری وب llama.cpp

رابط کاربری وب llama.cpp در مرورگر اجرا می‌شود و در هر درخواست یک هدر `Origin` ارسال می‌کند. سرور را با `--allowedOrigins` مطابق با مبدای رابط کاربری شروع کنید:

```bash
# llama.cpp web UI runs at http://localhost:8080
npx @wdio/mcp --http --port 3000 --allowedOrigins "http://localhost:8080"

# Or allow all local origins
npx @wdio/mcp --http --port 3000 --allowedOrigins "*"
```

در تنظیمات llama.cpp، یک سرور MCP اضافه کنید که به `http://localhost:3000/mcp` اشاره کند.

---

### حالت امن Codex

OpenAI Codex در یک محیط سندباکس‌شده بدون پشتیبانی از زیرپردازه اجرا می‌شود. از انتقال HTTP استفاده کنید تا Codex بتواند به سرور MCP در حال اجرا روی دستگاه میزبان شما دسترسی داشته باشد:

```bash
# Start on your host
npx @wdio/mcp --http --port 3000
```

در پیکربندی MCP مربوط به Codex، آدرس سرور را روی `http://localhost:3000/mcp` تنظیم کنید (یا اگر Codex در یک ماشین مجازی اجرا می‌شود، IP میزبان خود را وارد کنید).

### معماری مبتنی بر هر درخواست

هر درخواست HTTP یک نمونه جدید از سرور MCP ایجاد می‌کند. این یعنی:

- کلاینت‌ها می‌توانند پس از قطع شدن اتصال، بدون خطا دوباره متصل شوند.
- چندین کلاینت می‌توانند به‌طور همزمان متصل شوند (هر کدام یک نشست MCP مستقل دریافت می‌کند).
- وضعیت نشست (مرورگر/برنامه فعال) از طریق وضعیت سراسری به اشتراک گذاشته می‌شود، نه وضعیت انتقال.

هیچ mutex وجود ندارد؛ درخواست‌ها به‌صورت همزمان پردازش می‌شوند. حالت‌مندی پروتکل MCP (initialize ← فراخوانی ابزارها) به‌ازای هر درخواست مدیریت می‌شود.
