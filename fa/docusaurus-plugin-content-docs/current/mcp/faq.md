سؤالات متداول درباره WebdriverIO MCP.

## عمومی

### MCP چیست؟

MCP (Model Context Protocol) یک پروتکل باز است که به دستیارهای هوش مصنوعی مانند Claude امکان تعامل با ابزارها و سرویس‌های خارجی را می‌دهد. WebdriverIO MCP این پروتکل را پیاده‌سازی می‌کند تا قابلیت‌های خودکارسازی مرورگر و موبایل را در اختیار Claude Desktop و Claude Code قرار دهد.

### با WebdriverIO MCP چه چیزهایی را می‌توانم خودکارسازی کنم؟

شما می‌توانید موارد زیر را خودکارسازی کنید:
-   **مرورگرهای دسکتاپ** (Chrome، Firefox، Edge، Safari) - پیمایش، کلیک، تایپ، گرفتن اسکرین‌شات
-   **اپلیکیشن‌های iOS** - روی شبیه‌سازها یا دستگاه‌های واقعی
-   **اپلیکیشن‌های Android** - روی امولاتورها یا دستگاه‌های واقعی
-   **اپلیکیشن‌های هیبریدی** - جابه‌جایی بین کانتکست‌های native و وب
-   **دستگاه‌های ابری** - از طریق فضاهای ابری دستگاه BrowserStack، Sauce Labs، TestMu و TestingBot

### آیا لازم است کد بنویسم؟

خیر! این مزیت اصلی MCP است. می‌توانید کاری را که می‌خواهید انجام دهید به زبان طبیعی توصیف کنید و Claude از ابزارهای مناسب برای انجام آن استفاده خواهد کرد.

**نمونه پرامپت‌ها:**
-   "Open Chrome and navigate to webdriver.io"
-   "Click the Get Started button"
-   "Take a screenshot of the current page"
-   "Start my iOS app and log in as test user"

## نصب و راه‌اندازی

### چگونه WebdriverIO MCP را نصب کنم؟

نیازی به نصب جداگانه ندارید. سرور MCP هنگامی که آن را در محیط خود پیکربندی کنید، به‌طور خودکار از طریق npx اجرا می‌شود. این را به پیکربندی خود اضافه کنید:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

### فایل پیکربندی Claude Desktop کجاست؟

-   **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
-   **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

### آیا برای خودکارسازی مرورگر به Appium نیاز دارم؟

خیر. خودکارسازی مرورگر فقط نیاز دارد که مرورگر هدف نصب شده باشد. WebdriverIO مدیریت درایورها را به‌طور خودکار انجام می‌دهد.

### آیا برای خودکارسازی موبایل به Appium نیاز دارم؟

بله. خودکارسازی موبایل به موارد زیر نیاز دارد:
1. سرور Appium در حال اجرا (`npm install -g appium && appium`)
2. درایورهای پلتفرم نصب‌شده (`appium driver install xcuitest` برای iOS، `appium driver install uiautomator2` برای Android)
3. ابزارهای توسعه مناسب (Xcode برای iOS، Android SDK برای Android)

## خودکارسازی مرورگر

### کدام مرورگرها پشتیبانی می‌شوند؟

Chrome، Firefox، Edge و Safari همگی پشتیبانی می‌شوند. از پارامتر `browser` در `start_session` استفاده کنید:

```text
"Start a Firefox session"
"Start Chrome in headless mode"
```

### آیا می‌توانم مرورگر را در حالت headless اجرا کنم؟

بله. حالت headless پیش‌فرض است (`headless: true`). اگر می‌خواهید مرورگر را ببینید، از Claude بخواهید آن را در حالت headed اجرا کند:

"Start Chrome in headed mode (not headless)"

### آیا می‌توانم اندازه پنجره مرورگر را تنظیم کنم؟

بله. می‌توانید هنگام راه‌اندازی مرورگر ابعاد را مشخص کنید:

"Start Chrome with a window size of 1920x1080"

ابعاد پشتیبانی‌شده: عرض ۴۰۰ تا ۳۸۴۰ پیکسل، ارتفاع ۴۰۰ تا ۲۱۶۰ پیکسل. مقدار پیش‌فرض 1920×1080 است.

### آیا می‌توانم مرورگر را راه‌اندازی کرده و در یک مرحله به صفحه‌ای بروم؟

بله! از پارامتر `navigationUrl` استفاده کنید:

"Start Chrome and navigate to https://webdriver.io"

این روش کارآمدتر از راه‌اندازی مرورگر و سپس پیمایش جداگانه است.

### چگونه اسکرین‌شات بگیرم؟

کافی است درخواست کنید:

"Take a screenshot of the current page"

اسکرین‌شات‌ها به‌طور خودکار بهینه می‌شوند:
- مقیاس‌بندی تا حداکثر ابعاد 2000px
- فشرده‌سازی تا حداکثر حجم 1MB
- فرمت: PNG یا JPEG (به‌طور خودکار برای بهترین کیفیت انتخاب می‌شود)

### آیا می‌توانم با iframeها تعامل داشته باشم؟

بله. از ابزار `switch_frame` برای ورود به یک iframe با استفاده از سلکتور CSS یا XPath استفاده کنید. تمام فراخوانی‌های بعدی `click_element`، `set_value` و `get_elements` درون فریم انتخاب‌شده عمل می‌کنند. برای بازگشت به فریم سطح بالا، سلکتور را حذف کنید. iframeها باید از همان origin صفحه اصلی باشند.

### آیا می‌توانم JavaScript سفارشی اجرا کنم؟

بله! از ابزار `execute_script` استفاده کنید:

"Execute script to get the page title"
"Execute script: return document.querySelectorAll('button').length"

### آیا می‌توانم به یک نشست موجود Chrome متصل شوم؟

بله. ابتدا از `launch_chrome` استفاده کنید (Chrome را با قابلیت remote debugging باز می‌کند)، سپس `start_session` را با `attach: true` اجرا کنید.

"Launch Chrome with remote debugging, then attach to it"

### آیا می‌توانم با چند تب کار کنم؟

بله. از `get_tabs` برای فهرست کردن تب‌های باز و از `switch_tab` برای تمرکز روی یک تب خاص استفاده کنید:

"Get all open tabs"
"Switch to the tab at index 1"

## خودکارسازی موبایل

### چگونه یک نشست iOS یا Android را شروع کنم؟

از `start_session` با پلتفرم مناسب استفاده کنید:

"Start my iOS app located at /path/to/MyApp.app on the iPhone 15 simulator"

"Start my Android app at /path/to/app.apk on the Pixel 7 emulator"

یا برای اپلیکیشنی که از قبل نصب شده است:

"Start the app with noReset enabled on the iPhone 15 simulator"

### آیا می‌توانم روی دستگاه‌های واقعی تست کنم؟

بله! برای دستگاه‌های واقعی، به UDID دستگاه نیاز دارید:

-   **iOS:** دستگاه را متصل کنید، Finder را باز کنید، روی دستگاه کلیک کنید، سپس روی شماره سریال کلیک کنید تا UDID نمایش داده شود
-   **Android:** دستور `adb devices` را در ترمینال اجرا کنید

سپس درخواست کنید:

"Start my iOS app on the real device with UDID abc123..."

### چگونه دیالوگ‌های مجوز را مدیریت کنم؟

به‌طور پیش‌فرض، مجوزها به‌طور خودکار اعطا می‌شوند (`autoGrantPermissions: true`). اگر نیاز به تست جریان‌های مجوز دارید، می‌توانید این گزینه را غیرفعال کنید:

"Start my app without automatically granting permissions"

### چه حرکات لمسی (gesture) پشتیبانی می‌شوند؟

-   **ضربه (Tap):** ضربه روی عناصر یا مختصات (`tap_element`)
-   **کشیدن (Swipe):** کشیدن به بالا، پایین، چپ یا راست (`swipe`)
-   **کشیدن و رها کردن (Drag and Drop):** کشیدن از یک عنصر به عنصر دیگر یا به مختصات (`drag_and_drop`)

نکته: `long_press` از طریق `execute_script` با دستورات موبایل Appium در دسترس است.

### چگونه در اپلیکیشن‌های موبایل اسکرول کنم؟

از حرکات swipe استفاده کنید:

"Swipe up to scroll down"
"Swipe down to scroll up"

### آیا می‌توانم دستگاه را بچرخانم؟

بله:

"Rotate the device to landscape"
"Rotate the device to portrait"

### چگونه اپلیکیشن‌های هیبریدی را مدیریت کنم؟

برای اپلیکیشن‌هایی که webview دارند، می‌توانید کانتکست را تغییر دهید:

"Get available contexts"
"Switch to the webview context"
"Switch back to native context"

### آیا می‌توانم دستورات موبایل Appium را اجرا کنم؟

بله! از ابزار `execute_script` استفاده کنید:

```text
Execute script "mobile: pressKey" with args [{ keycode: 4 }]  // Press BACK on Android
Execute script "mobile: activateApp" with args [{ bundleId: "com.example.app" }]
Execute script "mobile: terminateApp" with args [{ bundleId: "com.example.app" }]
```

## انتخاب عناصر

### دستیار هوش مصنوعی چگونه می‌فهمد با کدام عنصر تعامل کند؟

از منبع `wdio://session/current/elements` یا ابزار `get_elements` برای شناسایی عناصر تعاملی در صفحه/نمایشگر استفاده می‌کند. هر عنصر همراه با سلکتورهای آماده استفاده ارائه می‌شود.

### اگر تعداد عناصر صفحه خیلی زیاد باشد چه؟

از صفحه‌بندی (pagination) برای مدیریت فهرست‌های بزرگ عناصر استفاده کنید:

"Get the first 20 elements"
"Get elements with offset 20 and limit 20"

پاسخ شامل `total`، `showing` و `hasMore` است تا به پیمایش میان عناصر کمک کند.

### اگر Claude روی عنصر اشتباهی کلیک کند چه؟

می‌توانید دقیق‌تر باشید:

-   متن دقیق را ارائه دهید: "Click the button that says 'Submit Order'"
-   سلکتور را ارائه دهید: "Click the element with selector #submit-btn"
-   شناسه دسترسی‌پذیری را ارائه دهید: "Click the element with accessibility ID loginButton"

### بهترین استراتژی سلکتور برای موبایل چیست؟

1. **Accessibility ID** (بهترین) - `~loginButton`
2. **Resource ID** (Android) - `id=login_button`
3. **Predicate String** (iOS) - `-ios predicate string:label == "Login"`
4. **XPath** (آخرین راه‌حل) - کندتر است اما همه‌جا کار می‌کند

### درخت دسترسی‌پذیری (accessibility tree) چیست و چه زمانی باید از آن استفاده کنم؟

درخت دسترسی‌پذیری اطلاعات معنایی درباره عناصر صفحه (نقش‌ها، نام‌ها، وضعیت‌ها) ارائه می‌دهد. در این موارد از `get_accessibility_tree` استفاده کنید:
- `get_elements` عناصر مورد انتظار را برنمی‌گرداند
- نیاز دارید عناصر را بر اساس نقش دسترسی‌پذیری (button، link، textbox و غیره) پیدا کنید
- به اطلاعات معنایی دقیق درباره عناصر نیاز دارید

"Get accessibility tree filtered to button and link roles"

## مدیریت نشست

### آیا می‌توانم چند نشست هم‌زمان داشته باشم؟

خیر. سرور MCP از مدل تک‌نشستی استفاده می‌کند. در هر لحظه فقط یک نشست مرورگر یا اپلیکیشن می‌تواند فعال باشد.

### وقتی یک نشست را می‌بندم چه اتفاقی می‌افتد؟

بستگی به نوع نشست و تنظیمات دارد:

-   **مرورگر:** مرورگر به‌طور کامل بسته می‌شود
-   **موبایل با `noReset: false`:** اپلیکیشن خاتمه می‌یابد
-   **موبایل با `noReset: true` یا بدون `appPath`:** اپلیکیشن باز می‌ماند (نشست به‌طور خودکار جدا می‌شود)

### آیا می‌توانم وضعیت اپلیکیشن را بین نشست‌ها حفظ کنم؟

بله! از گزینه `noReset` استفاده کنید:

"Start my app with noReset enabled"

این کار وضعیت ورود، تنظیمات و سایر داده‌های اپلیکیشن را حفظ می‌کند.

### تفاوت بین بستن (close) و جدا کردن (detach) چیست؟

-   **بستن (Close):** مرورگر/اپلیکیشن را به‌طور کامل خاتمه می‌دهد
-   **جدا کردن (Detach):** اتصال خودکارسازی را قطع می‌کند اما مرورگر/اپلیکیشن را در حال اجرا نگه می‌دارد

جدا کردن زمانی مفید است که بخواهید پس از خودکارسازی، وضعیت را به‌صورت دستی بررسی کنید.

### نشست من هنگام دیباگ مدام دچار timeout می‌شود

مقدار timeout دستورات را افزایش دهید:

"Start my app with newCommandTimeout of 300 seconds"

مقدار پیش‌فرض ۳۰۰ ثانیه است. برای نشست‌های دیباگ بسیار طولانی، ۶۰۰ ثانیه را امتحان کنید.

## عیب‌یابی

### خطای "Session not found"

این یعنی هیچ نشست فعالی وجود ندارد. ابتدا یک نشست مرورگر یا اپلیکیشن را شروع کنید:

"Start Chrome and navigate to google.com"

### خطای "Element not found"

ممکن است عنصر قابل مشاهده نباشد یا سلکتور متفاوتی داشته باشد. این موارد را امتحان کنید:

1. ابتدا از Claude بخواهید همه عناصر قابل مشاهده را دریافت کند
2. یک سلکتور دقیق‌تر ارائه دهید
3. منتظر بمانید تا صفحه/اپلیکیشن به‌طور کامل بارگذاری شود
4. از `inViewportOnly: false` برای یافتن عناصر خارج از صفحه استفاده کنید

### مرورگر اجرا نمی‌شود

1. مطمئن شوید مرورگر هدف نصب شده است
2. بررسی کنید که آیا فرایند دیگری از پورت دیباگ (9222) استفاده می‌کند
3. حالت headless را امتحان کنید

### اتصال به Appium ناموفق بود

این رایج‌ترین مشکل هنگام شروع خودکارسازی موبایل است.

1. **بررسی کنید Appium در حال اجرا باشد**: `curl http://localhost:4723/status`
2. در صورت نیاز Appium را اجرا کنید: `appium`
3. بررسی کنید که اتصال Appium شما با سرور مطابقت داشته باشد (از `appiumConfig` در `start_session` استفاده کنید)
4. مطمئن شوید درایورها نصب شده‌اند: `appium driver list --installed`

:::tip
سرور MCP نیاز دارد که Appium پیش از شروع نشست‌های موبایل در حال اجرا باشد. حتماً ابتدا Appium را اجرا کنید:
```sh
appium
```
نسخه‌های آینده ممکن است شامل مدیریت خودکار سرویس Appium باشند.
:::

### شبیه‌ساز iOS اجرا نمی‌شود

1. مطمئن شوید Xcode نصب شده است: `xcode-select --install`
2. شبیه‌سازهای موجود را فهرست کنید: `xcrun simctl list devices`
3. خطاهای مربوط به شبیه‌ساز را در Console.app بررسی کنید

### امولاتور Android اجرا نمی‌شود

1. `ANDROID_HOME` را تنظیم کنید: `export ANDROID_HOME=$HOME/Library/Android/sdk`
2. امولاتورها را بررسی کنید: `emulator -list-avds`
3. امولاتور را به‌صورت دستی اجرا کنید: `emulator -avd <avd-name>`
4. اتصال دستگاه را بررسی کنید: `adb devices`

### اسکرین‌شات‌ها کار نمی‌کنند

1. برای موبایل، مطمئن شوید نشست فعال است
2. برای مرورگر، صفحه دیگری را امتحان کنید (برخی صفحات گرفتن اسکرین‌شات را مسدود می‌کنند)
3. لاگ‌های Claude Desktop را برای یافتن خطاها بررسی کنید

اسکرین‌شات‌ها به‌طور خودکار تا حداکثر 1MB فشرده می‌شوند، بنابراین اسکرین‌شات‌های بزرگ کار خواهند کرد اما ممکن است کیفیت پایین‌تری داشته باشند.

## عملکرد

### چرا خودکارسازی موبایل کند است؟

خودکارسازی موبایل شامل موارد زیر است:
1. ارتباط شبکه‌ای با سرور Appium
2. ارتباط Appium با دستگاه/شبیه‌ساز
3. رندر و پاسخ دستگاه

نکاتی برای خودکارسازی سریع‌تر:
-   برای توسعه، به‌جای دستگاه‌های واقعی از امولاتورها/شبیه‌سازها استفاده کنید
-   به‌جای XPath از شناسه‌های دسترسی‌پذیری (accessibility ID) استفاده کنید
-   برای تشخیص عناصر، `inViewportOnly: true` را فعال کنید
-   برای کاهش مصرف توکن از صفحه‌بندی (`limit`) استفاده کنید

### چگونه می‌توانم تشخیص عناصر را سریع‌تر کنم؟

سرور MCP از قبل تشخیص عناصر را با استفاده از تجزیه XML سورس صفحه بهینه کرده است (۲ فراخوانی HTTP در مقابل بیش از ۶۰۰ فراخوانی در کوئری‌های سنتی عناصر). نکات بیشتر:

-   برای فیلتر کردن عناصر خارج از صفحه، `inViewportOnly: true` را تنظیم کنید
-   `includeContainers: false` را تنظیم کنید (پیش‌فرض)
-   برای صفحه‌بندی در صفحه‌نمایش‌های بزرگ از `limit` و `offset` استفاده کنید
-   به‌جای یافتن همه عناصر، از سلکتورهای مشخص استفاده کنید

### اسکرین‌شات‌ها کند هستند یا با شکست مواجه می‌شوند

اسکرین‌شات‌ها به‌طور خودکار بهینه می‌شوند:
- در صورت بزرگ‌تر بودن از 2000px، تغییر اندازه داده می‌شوند
- فشرده می‌شوند تا زیر 1MB بمانند
- در صورت بزرگ بودن بیش از حد PNG، به JPEG تبدیل می‌شوند

این بهینه‌سازی زمان پردازش را کاهش می‌دهد و تضمین می‌کند که Claude بتواند تصویر را پردازش کند.

## محدودیت‌ها

### محدودیت‌های فعلی چیست؟

-   **تک‌نشستی:** فقط یک مرورگر/اپلیکیشن در هر زمان
-   **پشتیبانی از iframe:** iframeهای هم‌origin از طریق `switch_frame` پشتیبانی می‌شوند؛ iframeهای cross-origin به دلیل محدودیت‌های امنیتی مرورگر در دسترس نیستند
-   **بارگذاری فایل:** به‌طور مستقیم از طریق ابزارها پشتیبانی نمی‌شود
-   **صدا/ویدیو:** امکان تعامل با پخش رسانه وجود ندارد
-   **افزونه‌های مرورگر:** پشتیبانی نمی‌شوند

### آیا می‌توانم از این برای تست production استفاده کنم؟

WebdriverIO MCP برای خودکارسازی تعاملی با کمک هوش مصنوعی طراحی شده است. برای تست‌های CI/CD در محیط production، استفاده از test runner سنتی WebdriverIO با کنترل کامل برنامه‌نویسی را در نظر بگیرید.

## امنیت

### آیا داده‌های من امن هستند؟

سرور MCP به‌صورت محلی روی دستگاه شما اجرا می‌شود. تمام خودکارسازی‌ها از طریق اتصالات محلی مرورگر/Appium انجام می‌شوند. هیچ داده‌ای فراتر از آنچه شما صراحتاً به آن پیمایش می‌کنید به سرورهای خارجی ارسال نمی‌شود.

هنگام استفاده از حالت انتقال HTTP (`--http`)، سرور به‌طور پیش‌فرض فقط اتصالات از `localhost` را می‌پذیرد؛ برای کنترل دسترسی از `--allowedHosts` و `--allowedOrigins` استفاده کنید. برای جزئیات بیشتر [Transport](./transport) را ببینید.

### آیا Claude می‌تواند به رمزهای عبور من دسترسی داشته باشد؟

Claude می‌تواند محتوای صفحه را ببیند و با عناصر تعامل داشته باشد، اما:
-   رمزهای عبور در فیلدهای `<input type="password">` پوشانده می‌شوند
-   باید از خودکارسازی اطلاعات ورود حساس خودداری کنید
-   برای خودکارسازی از حساب‌های تستی استفاده کنید
