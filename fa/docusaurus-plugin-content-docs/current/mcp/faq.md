سوالات متداول درباره WebdriverIO MCP.

## عمومی

### MCP چیست؟

MCP (Model Context Protocol) یک پروتکل باز است که به دستیارهای هوش مصنوعی مانند Claude امکان تعامل با ابزارها و سرویس‌های خارجی را می‌دهد. WebdriverIO MCP این پروتکل را پیاده‌سازی می‌کند تا قابلیت‌های خودکارسازی مرورگر و موبایل را در اختیار Claude Desktop و Claude Code قرار دهد.

### با WebdriverIO MCP چه چیزهایی را می‌توانم خودکارسازی کنم؟

شما می‌توانید موارد زیر را خودکارسازی کنید:
-   **مرورگرهای دسکتاپ** (Chrome، Firefox، Edge، Safari) - پیمایش، کلیک، تایپ، اسکرین‌شات
-   **اپلیکیشن‌های iOS** - روی شبیه‌سازها یا دستگاه‌های واقعی
-   **اپلیکیشن‌های Android** - روی امولاتورها یا دستگاه‌های واقعی
-   **اپلیکیشن‌های هیبریدی** - جابه‌جایی بین کانتکست‌های native و وب
-   **دستگاه‌های ابری** - از طریق سرویس‌های ابری دستگاه BrowserStack، Sauce Labs، TestMu و TestingBot

### آیا نیاز به نوشتن کد دارم؟

خیر! این مزیت اصلی MCP است. می‌توانید آنچه می‌خواهید انجام دهید را به زبان طبیعی توصیف کنید و Claude از ابزارهای مناسب برای انجام کار استفاده خواهد کرد.

**نمونه پرامپت‌ها:**
-   "Chrome را باز کن و به webdriver.io برو"
-   "روی دکمه Get Started کلیک کن"
-   "از صفحه فعلی اسکرین‌شات بگیر"
-   "اپلیکیشن iOS من را اجرا کن و با کاربر آزمایشی وارد شو"

## نصب و راه‌اندازی

### چگونه WebdriverIO MCP را نصب کنم؟

نیازی به نصب جداگانه ندارید. سرور MCP هنگامی که آن را در harness خود پیکربندی کنید، به‌طور خودکار از طریق npx اجرا می‌شود. این را به پیکربندی خود اضافه کنید:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

### فایل پیکربندی Claude Desktop کجاست؟

-   **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
-   **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

### آیا برای خودکارسازی مرورگر به Appium نیاز دارم؟

خیر. خودکارسازی مرورگر فقط نیاز دارد که مرورگر هدف نصب باشد. WebdriverIO مدیریت درایورها را به‌طور خودکار انجام می‌دهد.

### آیا برای خودکارسازی موبایل به Appium نیاز دارم؟

بله. خودکارسازی موبایل نیازمند موارد زیر است:
1. اجرای سرور Appium (`npm install -g appium && appium`)
2. نصب درایورهای پلتفرم (`appium driver install xcuitest` برای iOS، `appium driver install uiautomator2` برای Android)
3. ابزارهای توسعه مناسب (Xcode برای iOS، Android SDK برای Android)

## خودکارسازی مرورگر

### از کدام مرورگرها پشتیبانی می‌شود؟

از Chrome، Firefox، Edge و Safari پشتیبانی می‌شود. از پارامتر `browser` در `start_session` استفاده کنید:

```text
"Start a Firefox session"
"Start Chrome in headless mode"
```

### آیا می‌توانم مرورگر را در حالت headless اجرا کنم؟

بله. حالت headless پیش‌فرض است (`headless: true`). اگر می‌خواهید مرورگر را ببینید، از Claude بخواهید آن را در حالت headed اجرا کند:

"Chrome را در حالت headed (نه headless) اجرا کن"

### آیا می‌توانم اندازه پنجره مرورگر را تنظیم کنم؟

بله. می‌توانید هنگام اجرای مرورگر ابعاد را مشخص کنید:

"Chrome را با اندازه پنجره 1920x1080 اجرا کن"

ابعاد پشتیبانی‌شده: عرض ۴۰۰ تا ۳۸۴۰ پیکسل، ارتفاع ۴۰۰ تا ۲۱۶۰ پیکسل. پیش‌فرض 1920×1080 است.

### آیا می‌توانم مرورگر را اجرا کرده و در یک مرحله پیمایش کنم؟

بله! از پارامتر `navigationUrl` استفاده کنید:

"Chrome را اجرا کن و به https://webdriver.io برو"

این روش کارآمدتر از اجرای مرورگر و سپس پیمایش جداگانه است.

### چگونه اسکرین‌شات بگیرم؟

کافی است بخواهید:

"از صفحه فعلی اسکرین‌شات بگیر"

اسکرین‌شات‌ها به‌طور خودکار بهینه می‌شوند:
- مقیاس‌دهی به حداکثر ابعاد 2000px
- فشرده‌سازی به حداکثر حجم 1MB
- فرمت: PNG یا JPEG (به‌طور خودکار برای کیفیت بهینه انتخاب می‌شود)

### آیا می‌توانم با iframeها تعامل داشته باشم؟

بله. از ابزار `switch_frame` برای جابه‌جایی به یک iframe با سلکتور CSS یا XPath استفاده کنید. همه فراخوانی‌های بعدی `click_element`، `set_value` و `get_elements` درون فریم انتخاب‌شده عمل می‌کنند. برای بازگشت به فریم سطح بالا، سلکتور را حذف کنید. iframeها باید از همان origin صفحه اصلی باشند.

### آیا می‌توانم جاوااسکریپت سفارشی اجرا کنم؟

بله! از ابزار `execute_script` استفاده کنید:

"اسکریپتی برای دریافت عنوان صفحه اجرا کن"
"اجرای اسکریپت: return document.querySelectorAll('button').length"

### آیا می‌توانم به یک جلسه Chrome موجود متصل شوم؟

بله. ابتدا از `launch_chrome` استفاده کنید (Chrome را با remote debugging باز می‌کند)، سپس `start_session` را با `attach: true` اجرا کنید.

"Chrome را با remote debugging اجرا کن، سپس به آن متصل شو"

### آیا می‌توانم با چندین تب کار کنم؟

بله. از `get_tabs` برای فهرست کردن تب‌های باز و از `switch_tab` برای تمرکز روی یک تب خاص استفاده کنید:

"همه تب‌های باز را دریافت کن"
"به تب با اندیس 1 برو"

## خودکارسازی موبایل

### چگونه یک جلسه iOS یا Android را شروع کنم؟

از `start_session` با پلتفرم مناسب استفاده کنید:

"اپلیکیشن iOS من در مسیر /path/to/MyApp.app را روی شبیه‌ساز iPhone 15 اجرا کن"

"اپلیکیشن Android من در مسیر /path/to/app.apk را روی امولاتور Pixel 7 اجرا کن"

یا برای اپلیکیشنی که از قبل نصب شده است:

"اپلیکیشن را با فعال بودن noReset روی شبیه‌ساز iPhone 15 اجرا کن"

### آیا می‌توانم روی دستگاه‌های واقعی تست کنم؟

بله! برای دستگاه‌های واقعی به UDID دستگاه نیاز دارید:

-   **iOS:** دستگاه را متصل کنید، Finder را باز کنید، روی دستگاه کلیک کنید، روی شماره سریال کلیک کنید تا UDID نمایش داده شود
-   **Android:** دستور `adb devices` را در ترمینال اجرا کنید

سپس بخواهید:

"اپلیکیشن iOS من را روی دستگاه واقعی با UDID abc123... اجرا کن"

### چگونه دیالوگ‌های مجوز را مدیریت کنم؟

به‌طور پیش‌فرض، مجوزها به‌طور خودکار اعطا می‌شوند (`autoGrantPermissions: true`). اگر نیاز به تست فرایندهای مجوز دارید، می‌توانید این را غیرفعال کنید:

"اپلیکیشن من را بدون اعطای خودکار مجوزها اجرا کن"

### از کدام ژست‌ها پشتیبانی می‌شود؟

-   **ضربه (Tap):** ضربه روی المنت‌ها یا مختصات (`tap_element`)
-   **کشیدن (Swipe):** کشیدن به بالا، پایین، چپ یا راست (`swipe`)
-   **کشیدن و رها کردن (Drag and Drop):** کشیدن از یک المنت به المنت دیگر یا به مختصات (`drag_and_drop`)

توجه: `long_press` از طریق `execute_script` با دستورات موبایل Appium در دسترس است.

### چگونه در اپلیکیشن‌های موبایل اسکرول کنم؟

از ژست‌های swipe استفاده کنید:

"برای اسکرول به پایین، به بالا بکش"
"برای اسکرول به بالا، به پایین بکش"

### آیا می‌توانم دستگاه را بچرخانم؟

بله:

"دستگاه را به حالت افقی بچرخان"
"دستگاه را به حالت عمودی بچرخان"

### چگونه اپلیکیشن‌های هیبریدی را مدیریت کنم؟

برای اپلیکیشن‌هایی که webview دارند، می‌توانید کانتکست‌ها را جابه‌جا کنید:

"کانتکست‌های موجود را دریافت کن"
"به کانتکست webview برو"
"به کانتکست native برگرد"

### آیا می‌توانم دستورات موبایل Appium را اجرا کنم؟

بله! از ابزار `execute_script` استفاده کنید:

```text
Execute script "mobile: pressKey" with args [{ keycode: 4 }]  // فشردن دکمه BACK در Android
Execute script "mobile: activateApp" with args [{ bundleId: "com.example.app" }]
Execute script "mobile: terminateApp" with args [{ bundleId: "com.example.app" }]
```

## انتخاب المنت

### دستیار هوش مصنوعی چگونه می‌فهمد با کدام المنت تعامل کند؟

از منبع `wdio://session/current/elements` یا ابزار `get_elements` برای شناسایی المنت‌های تعاملی در صفحه استفاده می‌کند. هر المنت همراه با سلکتورهای آماده استفاده ارائه می‌شود.

### اگر تعداد المنت‌های صفحه خیلی زیاد باشد چه؟

از صفحه‌بندی برای مدیریت فهرست‌های بزرگ المنت استفاده کنید:

"۲۰ المنت اول را دریافت کن"
"المنت‌ها را با offset 20 و limit 20 دریافت کن"

پاسخ شامل `total`، `showing` و `hasMore` است تا به پیمایش در میان المنت‌ها کمک کند.

### اگر Claude روی المنت اشتباه کلیک کند چه؟

می‌توانید دقیق‌تر باشید:

-   ارائه متن دقیق: "روی دکمه‌ای که نوشته 'Submit Order' کلیک کن"
-   ارائه سلکتور: "روی المنت با سلکتور #submit-btn کلیک کن"
-   ارائه accessibility ID: "روی المنت با accessibility ID loginButton کلیک کن"

### بهترین استراتژی سلکتور برای موبایل چیست؟

1. **Accessibility ID** (بهترین) - `~loginButton`
2. **Resource ID** (Android) - `id=login_button`
3. **Predicate String** (iOS) - `-ios predicate string:label == "Login"`
4. **XPath** (آخرین راه‌حل) - کندتر اما همه‌جا کار می‌کند

### درخت دسترس‌پذیری (accessibility tree) چیست و چه زمانی باید از آن استفاده کنم؟

درخت دسترس‌پذیری اطلاعات معنایی درباره المنت‌های صفحه (نقش‌ها، نام‌ها، وضعیت‌ها) ارائه می‌دهد. از `get_accessibility_tree` در این مواقع استفاده کنید:
- `get_elements` المنت‌های مورد انتظار را برنمی‌گرداند
- نیاز دارید المنت‌ها را بر اساس نقش دسترس‌پذیری (button، link، textbox و غیره) پیدا کنید
- به اطلاعات معنایی دقیق درباره المنت‌ها نیاز دارید

"درخت دسترس‌پذیری را با فیلتر نقش‌های button و link دریافت کن"

## مدیریت جلسه

### آیا می‌توانم چند جلسه همزمان داشته باشم؟

خیر. سرور MCP از مدل تک‌جلسه‌ای استفاده می‌کند. در هر زمان فقط یک جلسه مرورگر یا اپلیکیشن می‌تواند فعال باشد.

### وقتی یک جلسه را می‌بندم چه اتفاقی می‌افتد؟

بستگی به نوع جلسه و تنظیمات دارد:

-   **مرورگر:** مرورگر به‌طور کامل بسته می‌شود
-   **موبایل با `noReset: false`:** اپلیکیشن خاتمه می‌یابد
-   **موبایل با `noReset: true` یا بدون `appPath`:** اپلیکیشن باز می‌ماند (جلسه به‌طور خودکار جدا می‌شود)

### آیا می‌توانم وضعیت اپلیکیشن را بین جلسات حفظ کنم؟

بله! از گزینه `noReset` استفاده کنید:

"اپلیکیشن من را با فعال بودن noReset اجرا کن"

این کار وضعیت ورود، تنظیمات و سایر داده‌های اپلیکیشن را حفظ می‌کند.

### تفاوت بین close و detach چیست؟

-   **Close:** مرورگر/اپلیکیشن را به‌طور کامل خاتمه می‌دهد
-   **Detach:** اتصال خودکارسازی را قطع می‌کند اما مرورگر/اپلیکیشن را در حال اجرا نگه می‌دارد

Detach زمانی مفید است که می‌خواهید پس از خودکارسازی، وضعیت را به‌صورت دستی بررسی کنید.

### جلسه من هنگام دیباگ مدام دچار timeout می‌شود

مقدار timeout دستورات را افزایش دهید:

"اپلیکیشن من را با newCommandTimeout برابر 300 ثانیه اجرا کن"

پیش‌فرض ۳۰۰ ثانیه است. برای جلسات دیباگ بسیار طولانی، ۶۰۰ ثانیه را امتحان کنید.

## عیب‌یابی

### خطای "Session not found"

این یعنی هیچ جلسه فعالی وجود ندارد. ابتدا یک جلسه مرورگر یا اپلیکیشن را شروع کنید:

"Chrome را اجرا کن و به google.com برو"

### خطای "Element not found"

ممکن است المنت قابل مشاهده نباشد یا سلکتور متفاوتی داشته باشد. این موارد را امتحان کنید:

1. ابتدا از Claude بخواهید همه المنت‌های قابل مشاهده را دریافت کند
2. سلکتور دقیق‌تری ارائه دهید
3. منتظر بمانید تا صفحه/اپلیکیشن به‌طور کامل بارگذاری شود
4. از `inViewportOnly: false` برای یافتن المنت‌های خارج از صفحه استفاده کنید

### مرورگر اجرا نمی‌شود

1. مطمئن شوید مرورگر هدف نصب شده است
2. بررسی کنید آیا فرایند دیگری از پورت دیباگ (9222) استفاده می‌کند
3. حالت headless را امتحان کنید

### اتصال به Appium ناموفق بود

این رایج‌ترین مشکل هنگام شروع خودکارسازی موبایل است.

1. **بررسی کنید Appium در حال اجرا است**: `curl http://localhost:4723/status`
2. در صورت نیاز Appium را اجرا کنید: `appium`
3. بررسی کنید اتصال Appium شما با سرور مطابقت دارد (از `appiumConfig` در `start_session` استفاده کنید)
4. مطمئن شوید درایورها نصب شده‌اند: `appium driver list --installed`

:::tip
سرور MCP نیاز دارد که Appium پیش از شروع جلسات موبایل در حال اجرا باشد. حتماً ابتدا Appium را اجرا کنید:
```sh
appium
```
نسخه‌های آینده ممکن است شامل مدیریت خودکار سرویس Appium باشند.
:::

### شبیه‌ساز iOS اجرا نمی‌شود

1. مطمئن شوید Xcode نصب شده است: `xcode-select --install`
2. شبیه‌سازهای موجود را فهرست کنید: `xcrun simctl list devices`
3. خطاهای مربوط به شبیه‌ساز را در Console.app بررسی کنید

### امولاتور Android اجرا نمی‌شود

1. `ANDROID_HOME` را تنظیم کنید: `export ANDROID_HOME=$HOME/Library/Android/sdk`
2. امولاتورها را بررسی کنید: `emulator -list-avds`
3. امولاتور را به‌صورت دستی اجرا کنید: `emulator -avd <avd-name>`
4. بررسی کنید دستگاه متصل است: `adb devices`

### اسکرین‌شات‌ها کار نمی‌کنند

1. برای موبایل، مطمئن شوید جلسه فعال است
2. برای مرورگر، صفحه دیگری را امتحان کنید (برخی صفحات اسکرین‌شات را مسدود می‌کنند)
3. لاگ‌های Claude Desktop را برای یافتن خطاها بررسی کنید

اسکرین‌شات‌ها به‌طور خودکار به حداکثر 1MB فشرده می‌شوند، بنابراین اسکرین‌شات‌های بزرگ کار می‌کنند اما ممکن است کیفیت پایین‌تری داشته باشند.

## عملکرد

### چرا خودکارسازی موبایل کند است؟

خودکارسازی موبایل شامل موارد زیر است:
1. ارتباط شبکه‌ای با سرور Appium
2. ارتباط Appium با دستگاه/شبیه‌ساز
3. رندر و پاسخ دستگاه

نکاتی برای خودکارسازی سریع‌تر:
-   برای توسعه، به جای دستگاه‌های واقعی از امولاتورها/شبیه‌سازها استفاده کنید
-   به جای XPath از accessibility IDها استفاده کنید
-   برای تشخیص المنت، `inViewportOnly: true` را فعال کنید
-   برای کاهش مصرف توکن از صفحه‌بندی (`limit`) استفاده کنید

### چگونه می‌توانم تشخیص المنت را سریع‌تر کنم؟

سرور MCP از قبل تشخیص المنت را با استفاده از تجزیه XML page source بهینه کرده است (۲ فراخوانی HTTP در مقابل بیش از ۶۰۰ فراخوانی برای کوئری‌های سنتی المنت). نکات اضافی:

-   `inViewportOnly: true` را تنظیم کنید تا المنت‌های خارج از صفحه فیلتر شوند
-   `includeContainers: false` را تنظیم کنید (پیش‌فرض)
-   از `limit` و `offset` برای صفحه‌بندی در صفحه‌های بزرگ استفاده کنید
-   به جای یافتن همه المنت‌ها از سلکتورهای مشخص استفاده کنید

### اسکرین‌شات‌ها کند هستند یا ناموفق می‌شوند

اسکرین‌شات‌ها به‌طور خودکار بهینه می‌شوند:
- در صورت بزرگ‌تر بودن از 2000px تغییر اندازه داده می‌شوند
- فشرده می‌شوند تا زیر 1MB بمانند
- در صورت بزرگ بودن بیش از حد PNG، به JPEG تبدیل می‌شوند

این بهینه‌سازی زمان پردازش را کاهش می‌دهد و تضمین می‌کند Claude بتواند تصویر را پردازش کند.

## محدودیت‌ها

### محدودیت‌های فعلی چیست؟

-   **تک‌جلسه‌ای:** فقط یک مرورگر/اپلیکیشن در هر زمان
-   **پشتیبانی از iframe:** iframeهای هم‌origin از طریق `switch_frame` پشتیبانی می‌شوند؛ iframeهای cross-origin به دلیل محدودیت‌های امنیتی مرورگر قابل دسترسی نیستند
-   **آپلود فایل:** به‌طور مستقیم از طریق ابزارها پشتیبانی نمی‌شود
-   **صوت/ویدیو:** امکان تعامل با پخش رسانه وجود ندارد
-   **افزونه‌های مرورگر:** پشتیبانی نمی‌شوند

### آیا می‌توانم از این برای تست production استفاده کنم؟

WebdriverIO MCP برای خودکارسازی تعاملی با کمک هوش مصنوعی طراحی شده است. برای تست CI/CD در production، استفاده از test runner سنتی WebdriverIO با کنترل کامل برنامه‌نویسی را در نظر بگیرید.

## امنیت

### آیا داده‌های من امن است؟

سرور MCP به‌صورت محلی روی دستگاه شما اجرا می‌شود. تمام خودکارسازی از طریق اتصالات محلی مرورگر/Appium انجام می‌شود. هیچ داده‌ای فراتر از آنچه شما صراحتاً به آن پیمایش می‌کنید، به سرورهای خارجی ارسال نمی‌شود.

هنگام استفاده از حالت انتقال HTTP (`--http`)، سرور به‌طور پیش‌فرض فقط اتصالات از `localhost` را می‌پذیرد؛ برای کنترل دسترسی از `--allowedHosts` و `--allowedOrigins` استفاده کنید. برای جزئیات بیشتر به [Transport](./transport) مراجعه کنید.

### آیا Claude می‌تواند به رمزهای عبور من دسترسی داشته باشد؟

Claude می‌تواند محتوای صفحه را ببیند و با المنت‌ها تعامل کند، اما:
-   رمزهای عبور در فیلدهای `<input type="password">` پوشانده شده‌اند
-   باید از خودکارسازی اطلاعات ورود حساس خودداری کنید
-   برای خودکارسازی از حساب‌های آزمایشی استفاده کنید
