यह ट्यूटोरियल उन लोगों के लिए है जो Protractor का उपयोग कर रहे हैं और अपने फ्रेमवर्क को WebdriverIO में माइग्रेट करना चाहते हैं। इसकी शुरुआत तब हुई जब Angular टीम ने [घोषणा की](https://github.com/angular/protractor/issues/5502) कि Protractor को अब और सपोर्ट नहीं किया जाएगा। WebdriverIO, Protractor के कई डिज़ाइन निर्णयों से प्रभावित रहा है, यही कारण है कि माइग्रेट करने के लिए यह संभवतः सबसे निकटतम फ्रेमवर्क है। WebdriverIO टीम Protractor के हर एक योगदानकर्ता के काम की सराहना करती है और आशा करती है कि यह ट्यूटोरियल WebdriverIO में संक्रमण को आसान और सीधा बना देगा।

हालाँकि हम इसके लिए एक पूरी तरह से स्वचालित प्रक्रिया चाहते, लेकिन वास्तविकता कुछ और है। हर किसी का सेटअप अलग होता है और हर कोई Protractor का अलग-अलग तरीकों से उपयोग करता है। प्रत्येक चरण को मार्गदर्शन के रूप में देखा जाना चाहिए, न कि चरण-दर-चरण निर्देश के रूप में। यदि आपको माइग्रेशन में समस्याएँ आती हैं, तो [हमसे संपर्क करने](https://github.com/webdriverio/codemod/discussions/new) में संकोच न करें।

## सेटअप

Protractor और WebdriverIO का API वास्तव में बहुत समान है, इस हद तक कि अधिकांश कमांड्स को एक [codemod](https://github.com/webdriverio/codemod) के माध्यम से स्वचालित तरीके से फिर से लिखा जा सकता है।

codemod इंस्टॉल करने के लिए, चलाएँ:

```sh
npm install jscodeshift @wdio/codemod
```

## रणनीति

माइग्रेशन की कई रणनीतियाँ हैं। आपकी टीम के आकार, टेस्ट फ़ाइलों की संख्या और माइग्रेट करने की तात्कालिकता के आधार पर, आप सभी टेस्ट को एक साथ या फ़ाइल दर फ़ाइल बदलने का प्रयास कर सकते हैं। चूँकि Protractor का रखरखाव Angular संस्करण 15 (2022 के अंत) तक जारी रहेगा, इसलिए आपके पास अभी भी पर्याप्त समय है। आप Protractor और WebdriverIO टेस्ट को एक ही समय पर चला सकते हैं और नए टेस्ट WebdriverIO में लिखना शुरू कर सकते हैं। अपने समय बजट के अनुसार, आप पहले महत्वपूर्ण टेस्ट केस माइग्रेट करना शुरू कर सकते हैं और धीरे-धीरे उन टेस्ट तक पहुँच सकते हैं जिन्हें शायद आप हटा भी सकते हैं।

## पहले कॉन्फ़िग फ़ाइल

codemod इंस्टॉल करने के बाद हम पहली फ़ाइल को बदलना शुरू कर सकते हैं। पहले [WebdriverIO के कॉन्फ़िगरेशन विकल्पों](configuration) पर एक नज़र डालें। कॉन्फ़िग फ़ाइलें बहुत जटिल हो सकती हैं और यह समझदारी हो सकती है कि केवल आवश्यक भागों को पोर्ट किया जाए और देखा जाए कि बाकी को कैसे जोड़ा जा सकता है, जब संबंधित टेस्ट, जिन्हें कुछ विशेष विकल्पों की आवश्यकता होती है, माइग्रेट किए जा रहे हों।

पहले माइग्रेशन के लिए हम केवल कॉन्फ़िग फ़ाइल को बदलते हैं और चलाते हैं:

```sh
npx jscodeshift -t ./node_modules/@wdio/codemod/protractor ./conf.ts
```

:::info

 आपकी कॉन्फ़िग का नाम अलग हो सकता है, फिर भी सिद्धांत वही होना चाहिए: माइग्रेशन की शुरुआत पहले कॉन्फ़िग से करें।

:::

## WebdriverIO Dependencies इंस्टॉल करें

अगला चरण एक न्यूनतम WebdriverIO सेटअप को कॉन्फ़िगर करना है, जिसे हम एक फ्रेमवर्क से दूसरे में माइग्रेट करते हुए धीरे-धीरे विकसित करेंगे। सबसे पहले हम WebdriverIO CLI को इसके माध्यम से इंस्टॉल करते हैं:

```sh
npm install --save-dev @wdio/cli
```

इसके बाद हम कॉन्फ़िगरेशन विज़ार्ड चलाते हैं:

```sh
npx wdio config
```

यह आपको कुछ प्रश्नों के माध्यम से आगे ले जाएगा। इस माइग्रेशन परिदृश्य के लिए आप:
- डिफ़ॉल्ट विकल्प चुनें
- हम सुझाव देते हैं कि उदाहरण फ़ाइलें स्वतः जनरेट न करें
- WebdriverIO फ़ाइलों के लिए एक अलग फ़ोल्डर चुनें
- और Jasmine के बजाय Mocha चुनें।

:::info Mocha क्यों?
भले ही आप पहले Protractor का उपयोग Jasmine के साथ कर रहे हों, फिर भी Mocha बेहतर retry मैकेनिज़्म प्रदान करता है। चुनाव आपका है!
:::

इस छोटी प्रश्नावली के बाद विज़ार्ड सभी आवश्यक पैकेज इंस्टॉल करेगा और उन्हें आपकी `package.json` में सहेज देगा।

## कॉन्फ़िगरेशन फ़ाइल माइग्रेट करें

जब हमारे पास एक रूपांतरित `conf.ts` और एक नई `wdio.conf.ts` हो जाती है, तो अब समय है कॉन्फ़िगरेशन को एक कॉन्फ़िग से दूसरी में माइग्रेट करने का। सुनिश्चित करें कि केवल वही कोड पोर्ट करें जो सभी टेस्ट को चलाने के लिए आवश्यक है। हमारे मामले में हम hook फ़ंक्शन और फ्रेमवर्क timeout को पोर्ट करते हैं।

अब हम केवल अपनी `wdio.conf.ts` फ़ाइल के साथ आगे बढ़ेंगे और इसलिए मूल Protractor कॉन्फ़िग में अब किसी बदलाव की आवश्यकता नहीं होगी। हम उन बदलावों को revert कर सकते हैं ताकि दोनों फ्रेमवर्क एक-दूसरे के साथ चल सकें और हम एक बार में एक फ़ाइल पोर्ट कर सकें।

## टेस्ट फ़ाइल माइग्रेट करें

अब हम पहली टेस्ट फ़ाइल को पोर्ट करने के लिए तैयार हैं। सरल शुरुआत के लिए, आइए एक ऐसी फ़ाइल से शुरू करें जिसकी 3rd party पैकेज या PageObjects जैसी अन्य फ़ाइलों पर अधिक निर्भरता न हो। हमारे उदाहरण में माइग्रेट की जाने वाली पहली फ़ाइल `first-test.spec.ts` है। सबसे पहले वह डायरेक्टरी बनाएँ जहाँ नया WebdriverIO कॉन्फ़िगरेशन अपनी फ़ाइलों की अपेक्षा करता है और फिर फ़ाइल को वहाँ ले जाएँ:

```sh
mv mkdir -p ./test/specs/
mv test-suites/first-test.spec.ts ./test/specs
```

अब आइए इस फ़ाइल को रूपांतरित करें:

```sh
npx jscodeshift -t ./node_modules/@wdio/codemod/protractor ./test/specs/first-test.spec.ts
```

बस इतना ही! यह फ़ाइल इतनी सरल है कि हमें अब किसी अतिरिक्त बदलाव की आवश्यकता नहीं है और हम सीधे WebdriverIO को इसके माध्यम से चलाने का प्रयास कर सकते हैं:

```sh
npx wdio run wdio.conf.ts
```

बधाई हो 🥳 आपने अभी-अभी पहली फ़ाइल माइग्रेट कर ली!

## अगले चरण

इस बिंदु से आप टेस्ट दर टेस्ट और page object दर page object रूपांतरण जारी रखते हैं। संभावना है कि कुछ फ़ाइलों के लिए codemod इस तरह की त्रुटि के साथ विफल हो जाए:

```
ERR /path/to/project/test/testdata/failing_submit.js Transformation error (Error transforming /test/testdata/failing_submit.js:2)
Error transforming /test/testdata/failing_submit.js:2

> login_form.submit()
  ^

The command "submit" is not supported in WebdriverIO. We advise to use the click command to click on the submit button instead. For more information on this configuration, see https://webdriver.io/docs/api/element/click.
  at /path/to/project/test/testdata/failing_submit.js:132:0
```

कुछ Protractor कमांड्स के लिए WebdriverIO में कोई विकल्प मौजूद ही नहीं है। ऐसे में codemod आपको सलाह देगा कि इसे कैसे refactor करें। यदि आपको ऐसे त्रुटि संदेश बहुत बार मिलते हैं, तो बेझिझक [एक issue दर्ज करें](https://github.com/webdriverio/codemod/issues/new) और किसी विशेष रूपांतरण को जोड़ने का अनुरोध करें। हालाँकि codemod पहले से ही Protractor API के अधिकांश हिस्से को रूपांतरित करता है, फिर भी सुधार की काफ़ी गुंजाइश है।

## निष्कर्ष

हमें आशा है कि यह ट्यूटोरियल WebdriverIO में माइग्रेशन प्रक्रिया के दौरान आपका थोड़ा मार्गदर्शन करेगा। समुदाय विभिन्न संगठनों की विभिन्न टीमों के साथ codemod का परीक्षण करते हुए इसमें लगातार सुधार कर रहा है। यदि आपके पास फ़ीडबैक है तो [एक issue दर्ज करने](https://github.com/webdriverio/codemod/issues/new) में या माइग्रेशन प्रक्रिया के दौरान कठिनाई होने पर [एक चर्चा शुरू करने](https://github.com/webdriverio/codemod/discussions/new) में संकोच न करें।
