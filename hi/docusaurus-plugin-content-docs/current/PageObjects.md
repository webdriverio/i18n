WebdriverIO का वर्ज़न 5 पेज ऑब्जेक्ट पैटर्न सपोर्ट को ध्यान में रखकर डिज़ाइन किया गया था। "एलिमेंट्स ऐज़ फर्स्ट क्लास सिटिज़न्स" सिद्धांत को पेश करके, अब इस पैटर्न का उपयोग करके बड़े टेस्ट सूट बनाना संभव है।

पेज ऑब्जेक्ट बनाने के लिए किसी अतिरिक्त पैकेज की आवश्यकता नहीं है। पता चलता है कि साफ़-सुथरी, आधुनिक क्लासेस वे सभी आवश्यक सुविधाएँ प्रदान करती हैं जिनकी हमें ज़रूरत है:

- पेज ऑब्जेक्ट्स के बीच इनहेरिटेंस
- एलिमेंट्स की लेज़ी लोडिंग
- मेथड्स और एक्शन्स का एनकैप्सुलेशन

पेज ऑब्जेक्ट्स का उपयोग करने का लक्ष्य किसी भी पेज जानकारी को वास्तविक टेस्ट से अलग (एब्स्ट्रैक्ट) करना है। आदर्श रूप से, आपको किसी विशेष पेज के लिए अद्वितीय सभी सेलेक्टर्स या विशिष्ट निर्देशों को एक पेज ऑब्जेक्ट में संग्रहीत करना चाहिए, ताकि अपने पेज को पूरी तरह से रीडिज़ाइन करने के बाद भी आप अपना टेस्ट चला सकें।

## एक पेज ऑब्जेक्ट बनाना

सबसे पहले, हमें एक मुख्य पेज ऑब्जेक्ट की आवश्यकता है जिसे हम `Page.js` कहते हैं। इसमें सामान्य सेलेक्टर्स या मेथड्स होंगे जिनसे सभी पेज ऑब्जेक्ट्स इनहेरिट करेंगे।

```js
// Page.js
export default class Page {
    constructor() {
        this.title = 'My Page'
    }

    async open (path) {
        await browser.url(path)
    }
}
```

हम हमेशा एक पेज ऑब्जेक्ट के इंस्टेंस को `export` करेंगे, और कभी भी उस इंस्टेंस को टेस्ट में नहीं बनाएंगे। चूंकि हम एंड-टू-एंड टेस्ट लिख रहे हैं, हम हमेशा पेज को एक स्टेटलेस संरचना मानते हैं&mdash;ठीक वैसे ही जैसे प्रत्येक HTTP रिक्वेस्ट एक स्टेटलेस संरचना है।

बेशक, ब्राउज़र सेशन जानकारी रख सकता है और इसलिए अलग-अलग सेशन के आधार पर अलग-अलग पेज दिखा सकता है, लेकिन यह एक पेज ऑब्जेक्ट के भीतर प्रतिबिंबित नहीं होना चाहिए। इस प्रकार के स्टेट परिवर्तन आपके वास्तविक टेस्ट में होने चाहिए।

आइए पहले पेज का परीक्षण शुरू करें। डेमो उद्देश्यों के लिए, हम [Elemental Selenium](http://elementalselenium.com) द्वारा [The Internet](http://the-internet.herokuapp.com) वेबसाइट को प्रयोग के लिए उपयोग करते हैं। आइए [लॉगिन पेज](http://the-internet.herokuapp.com/login) के लिए एक पेज ऑब्जेक्ट उदाहरण बनाने का प्रयास करें।

## अपने सेलेक्टर्स को `Get` करना

पहला कदम उन सभी महत्वपूर्ण सेलेक्टर्स को गेटर फ़ंक्शंस के रूप में लिखना है जो हमारे `login.page` ऑब्जेक्ट में आवश्यक हैं:

```js
// login.page.js
import Page from './page'

class LoginPage extends Page {

    get username () { return $('#username') }
    get password () { return $('#password') }
    get submitBtn () { return $('form button[type="submit"]') }
    get flash () { return $('#flash') }
    get headerLinks () { return $$('#header a') }

    async open () {
        await super.open('login')
    }

    async submit () {
        await this.submitBtn.click()
    }

}

export default new LoginPage()
```

गेटर फ़ंक्शंस में सेलेक्टर्स को परिभाषित करना थोड़ा अजीब लग सकता है, लेकिन यह वास्तव में उपयोगी है। ये फ़ंक्शंस _जब आप प्रॉपर्टी को एक्सेस करते हैं_ तब मूल्यांकित होते हैं, न कि जब आप ऑब्जेक्ट बनाते हैं। इससे आप हमेशा किसी एलिमेंट पर कोई एक्शन करने से पहले उसे रिक्वेस्ट करते हैं।

## कमांड्स को चेन करना

WebdriverIO आंतरिक रूप से किसी कमांड के अंतिम परिणाम को याद रखता है। यदि आप किसी एलिमेंट कमांड को किसी एक्शन कमांड के साथ चेन करते हैं, तो यह पिछली कमांड से एलिमेंट ढूंढता है और एक्शन को निष्पादित करने के लिए परिणाम का उपयोग करता है। इससे आप सेलेक्टर (पहला पैरामीटर) हटा सकते हैं और कमांड इतनी सरल दिखती है:

```js
await LoginPage.username.setValue('Max Mustermann')
```

जो मूल रूप से इसके समान है:

```js
let elem = await $('#username')
await elem.setValue('Max Mustermann')
```

या

```js
await $('#username').setValue('Max Mustermann')
```

## अपने टेस्ट में पेज ऑब्जेक्ट्स का उपयोग करना

पेज के लिए आवश्यक एलिमेंट्स और मेथड्स को परिभाषित करने के बाद, आप इसके लिए टेस्ट लिखना शुरू कर सकते हैं। पेज ऑब्जेक्ट का उपयोग करने के लिए आपको बस इसे `import` (या `require`) करना है। बस इतना ही!

चूंकि आपने पेज ऑब्जेक्ट का पहले से बनाया गया इंस्टेंस एक्सपोर्ट किया है, इसे इम्पोर्ट करने से आप तुरंत इसका उपयोग शुरू कर सकते हैं।

यदि आप किसी असर्शन फ्रेमवर्क का उपयोग करते हैं, तो आपके टेस्ट और भी अधिक अभिव्यंजक हो सकते हैं:

```js
// login.spec.js
import LoginPage from '../pageobjects/login.page'

describe('login form', () => {
    it('should deny access with wrong creds', async () => {
        await LoginPage.open()
        await LoginPage.username.setValue('foo')
        await LoginPage.password.setValue('bar')
        await LoginPage.submit()

        await expect(LoginPage.flash).toHaveText('Your username is invalid!')
    })

    it('should allow access with correct creds', async () => {
        await LoginPage.open()
        await LoginPage.username.setValue('tomsmith')
        await LoginPage.password.setValue('SuperSecretPassword!')
        await LoginPage.submit()

        await expect(LoginPage.flash).toHaveText('You logged into a secure area!')
    })
})
```

संरचनात्मक दृष्टि से, स्पेक फ़ाइलों और पेज ऑब्जेक्ट्स को अलग-अलग डायरेक्टरी में रखना समझदारी है। इसके अतिरिक्त, आप प्रत्येक पेज ऑब्जेक्ट को `.page.js` एंडिंग दे सकते हैं। इससे यह अधिक स्पष्ट हो जाता है कि आप एक पेज ऑब्जेक्ट इम्पोर्ट कर रहे हैं।

## और आगे बढ़ना

WebdriverIO के साथ पेज ऑब्जेक्ट्स लिखने का यह मूल सिद्धांत है। लेकिन आप इससे कहीं अधिक जटिल पेज ऑब्जेक्ट संरचनाएँ बना सकते हैं! उदाहरण के लिए, आपके पास मोडल्स के लिए विशिष्ट पेज ऑब्जेक्ट्स हो सकते हैं, या आप एक विशाल पेज ऑब्जेक्ट को अलग-अलग क्लासेस में विभाजित कर सकते हैं (प्रत्येक समग्र वेब पेज के एक अलग हिस्से का प्रतिनिधित्व करती है) जो मुख्य पेज ऑब्जेक्ट से इनहेरिट करती हैं। यह पैटर्न वास्तव में पेज जानकारी को आपके टेस्ट से अलग करने के कई अवसर प्रदान करता है, जो ऐसे समय में आपके टेस्ट सूट को संरचित और स्पष्ट रखने के लिए महत्वपूर्ण है जब प्रोजेक्ट और टेस्ट की संख्या बढ़ती है।

आप यह उदाहरण (और इससे भी अधिक पेज ऑब्जेक्ट उदाहरण) GitHub पर [`example` फ़ोल्डर](https://github.com/webdriverio/webdriverio/tree/main/examples/pageobject) में पा सकते हैं।
