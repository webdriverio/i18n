## यह क्या कर सकता है?

WebdriverIO MCP एक **Model Context Protocol (MCP) सर्वर** है जो AI असिस्टेंट्स को वेब ब्राउज़र और मोबाइल एप्लिकेशन को ऑटोमेट करने और उनके साथ इंटरैक्ट करने में सक्षम बनाता है।

### WebdriverIO MCP क्यों?

-   **मोबाइल-फर्स्ट**: केवल-ब्राउज़र MCP सर्वरों के विपरीत, WebdriverIO MCP Appium के माध्यम से iOS और Android नेटिव ऐप ऑटोमेशन को सपोर्ट करता है
-   **क्रॉस-प्लेटफ़ॉर्म सेलेक्टर्स**: स्मार्ट एलिमेंट डिटेक्शन स्वचालित रूप से कई लोकेटर स्ट्रैटेजी (accessibility ID, XPath, UiAutomator, iOS predicates) जनरेट करता है
-   **WebdriverIO इकोसिस्टम**: सर्विसेज़ और रिपोर्टर्स के समृद्ध इकोसिस्टम के साथ परखे हुए WebdriverIO फ्रेमवर्क पर निर्मित

यह निम्नलिखित के लिए एक एकीकृत इंटरफ़ेस प्रदान करता है:

-   🖥️ **डेस्कटॉप ब्राउज़र** (Chrome, Firefox, Edge, Safari, headed या headless)
-   📱 **नेटिव मोबाइल ऐप्स** (Appium के माध्यम से iOS सिम्युलेटर / Android एमुलेटर / रियल डिवाइस)
-   📳 **हाइब्रिड मोबाइल ऐप्स** (Appium के माध्यम से Native + WebView कॉन्टेक्स्ट स्विचिंग)
-   ☁️ **क्लाउड डिवाइस** (BrowserStack, Sauce Labs, TestMu रियल डिवाइस और ब्राउज़र क्लाउड)

[`@wdio/mcp`](https://www.npmjs.com/package/@wdio/mcp) पैकेज के माध्यम से।

यह AI असिस्टेंट्स को निम्नलिखित करने की अनुमति देता है:

-   कॉन्फ़िगर करने योग्य डायमेंशन, headless मोड और वैकल्पिक प्रारंभिक नेविगेशन के साथ **ब्राउज़र लॉन्च और नियंत्रित करना**
-   **वेबसाइटों पर नेविगेट करना** और एलिमेंट्स के साथ इंटरैक्ट करना (क्लिक, टाइप, स्क्रॉल)
-   पेजिनेशन सपोर्ट के साथ accessibility tree और दृश्यमान एलिमेंट्स डिटेक्शन के माध्यम से **पेज कंटेंट का विश्लेषण करना**
-   स्वचालित रूप से ऑप्टिमाइज़ किए गए (रीसाइज़, अधिकतम 1MB तक कंप्रेस) **स्क्रीनशॉट लेना**
-   सेशन हैंडलिंग के लिए **कुकीज़ प्रबंधित करना**
-   जेस्चर (टैप, स्वाइप, ड्रैग एंड ड्रॉप) सहित **मोबाइल डिवाइस नियंत्रित करना**
-   हाइब्रिड ऐप्स में native और webview के बीच **कॉन्टेक्स्ट स्विच करना**
-   **स्क्रिप्ट्स एक्ज़ीक्यूट करना** - ब्राउज़र में JavaScript, डिवाइस पर Appium मोबाइल कमांड
-   रोटेशन, कीबोर्ड, जियोलोकेशन जैसी **डिवाइस सुविधाओं को संभालना**
-   और भी बहुत कुछ, [Tools](./mcp/tools) और [Configuration](./mcp/configuration) विकल्प देखें

:::info

मोबाइल ऐप्स के लिए नोट
मोबाइल ऑटोमेशन के लिए उपयुक्त ड्राइवर्स इंस्टॉल किए हुए एक चालू Appium सर्वर की आवश्यकता होती है। सेटअप निर्देशों के लिए [पूर्वापेक्षाएँ](#prerequisites) देखें।

:::

## इंस्टॉलेशन

`@wdio/mcp` का उपयोग करने का सबसे आसान तरीका बिना किसी लोकल इंस्टॉलेशन के npx के माध्यम से है:

```sh
npx @wdio/mcp
```

या इसे ग्लोबली इंस्टॉल करें:

```sh
npm install -g @wdio/mcp
```

## Claude के साथ उपयोग

Claude के साथ WebdriverIO MCP का उपयोग करने के लिए, कॉन्फ़िगरेशन फ़ाइल को संशोधित करें:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

कॉन्फ़िगरेशन जोड़ने के बाद, अपने हार्नेस को रीस्टार्ट करें। WebdriverIO MCP टूल्स ब्राउज़र और मोबाइल ऑटोमेशन कार्यों के लिए उपलब्ध होंगे।

### Claude Code के साथ उपयोग

Claude Code स्वचालित रूप से MCP सर्वरों का पता लगाता है। आप इसे अपने प्रोजेक्ट की `.claude/settings.json`, या `.mcp.json` में कॉन्फ़िगर कर सकते हैं।

या इसे ग्लोबली .claude.json में निम्न कमांड चलाकर जोड़ें:
```bash
claude mcp add --transport stdio wdio-mcp -- npx -y @wdio/mcp
```
Claude Code के अंदर `/mcp` कमांड चलाकर इसे सत्यापित करें।

## पूर्वापेक्षाएँ

### ब्राउज़र ऑटोमेशन

-   **Chrome, Firefox, Edge, या Safari** इंस्टॉल होना चाहिए
-   WebdriverIO स्वचालित ड्राइवर मैनेजमेंट संभालता है

### मोबाइल ऑटोमेशन

#### iOS

1. Mac App Store से **Xcode इंस्टॉल करें**
2. **Xcode Command Line Tools इंस्टॉल करें**:
   ```sh
   xcode-select --install
   ```
3. **Appium इंस्टॉल करें**:
   ```sh
   npm install -g appium
   ```
4. **XCUITest ड्राइवर इंस्टॉल करें**:
   ```sh
   appium driver install xcuitest
   ```
5. **Appium सर्वर शुरू करें**:
   ```sh
   appium
   ```
6. **सिम्युलेटर के लिए**: सिम्युलेटर बनाने/प्रबंधित करने के लिए Xcode → Window → Devices and Simulators खोलें
7. **रियल डिवाइस के लिए**: आपको डिवाइस UDID (40-कैरेक्टर का यूनिक आइडेंटिफ़ायर) की आवश्यकता होगी

#### Android

1. **Android Studio इंस्टॉल करें** और Android SDK सेट अप करें
2. **एनवायरनमेंट वेरिएबल्स सेट करें**:
   ```sh
   export ANDROID_HOME=$HOME/Library/Android/sdk
   export PATH=$PATH:$ANDROID_HOME/emulator
   export PATH=$PATH:$ANDROID_HOME/platform-tools
   ```
3. **Appium इंस्टॉल करें**:
   ```sh
   npm install -g appium
   ```
4. **UiAutomator2 ड्राइवर इंस्टॉल करें**:
   ```sh
   appium driver install uiautomator2
   ```
5. **Appium सर्वर शुरू करें**:
   ```sh
   appium
   ```
6. Android Studio → Virtual Device Manager के माध्यम से **एक एमुलेटर बनाएँ**
7. टेस्ट चलाने से पहले **एमुलेटर शुरू करें**

## आर्किटेक्चर

### यह कैसे काम करता है

WebdriverIO MCP, AI असिस्टेंट्स और ब्राउज़र/मोबाइल ऑटोमेशन के बीच एक ब्रिज के रूप में कार्य करता है:

```
┌─────────────────┐     MCP Protocol      ┌─────────────────┐
│  Claude Desktop │ ◄──────────────────►  │    @wdio/mcp    │
│  or Claude Code │   (stdio or HTTP)     │     Server      │
└─────────────────┘                       └────────┬────────┘
                                                   │
                                             WebDriverIO API
                                                   │
                    ┌──────────────────────────────┼──────────────────────────────┐
                    │                              │                              │
            ┌───────▼───────┐             ┌───────▼───────┐             ┌───────▼───────┐
            │    Browser    │             │    Appium     │             │   Cloud        │
            │ (local/CDP)   │             │  (iOS/Android)│             │   Providers    │
            └───────────────┘             └───────────────┘             └───────────────┘
```

### सेशन मैनेजमेंट

-   **सिंगल-सेशन मॉडल**: एक समय में केवल एक ब्राउज़र या ऐप सेशन सक्रिय हो सकता है
-   **सेशन स्टेट** टूल कॉल्स के बीच ग्लोबली बनाए रखी जाती है
-   **ऑटो-डिटैच**: संरक्षित स्टेट (`noReset: true`) वाले सेशन बंद करने पर स्वचालित रूप से डिटैच हो जाते हैं

### एलिमेंट डिटेक्शन

#### ब्राउज़र (वेब)

-   सभी दृश्यमान, इंटरैक्ट करने योग्य एलिमेंट्स खोजने के लिए एक ऑप्टिमाइज़्ड ब्राउज़र स्क्रिप्ट का उपयोग करता है
-   CSS सेलेक्टर्स, IDs, क्लासेज़ और ARIA जानकारी के साथ एलिमेंट्स लौटाता है
-   व्यूपोर्ट फ़िल्टरिंग और पेजिनेशन को सपोर्ट करता है

#### मोबाइल (नेटिव ऐप्स)

-   कुशल XML पेज सोर्स पार्सिंग का उपयोग करता है (पारंपरिक क्वेरीज़ के लिए 600+ की तुलना में 2 HTTP कॉल)
-   Android और iOS के लिए प्लेटफ़ॉर्म-विशिष्ट एलिमेंट वर्गीकरण
-   प्रति एलिमेंट कई लोकेटर स्ट्रैटेजी जनरेट करता है:
    -   Accessibility ID (क्रॉस-प्लेटफ़ॉर्म, सबसे स्थिर)
    -   Resource ID / Name एट्रिब्यूट
    -   Text / Label मैचिंग
    -   XPath (पूर्ण और सरलीकृत)
    -   UiAutomator (Android) / Predicates (iOS)

## सेलेक्टर सिंटैक्स

MCP सर्वर कई सेलेक्टर स्ट्रैटेजी को सपोर्ट करता है। विस्तृत डॉक्यूमेंटेशन के लिए [Selectors](./mcp/selectors) देखें।

### वेब (CSS/XPath)

```
# CSS सेलेक्टर्स
button.my-class
#element-id
[data-testid="login"]

# XPath
//button[@class='submit']
//a[contains(text(), 'Click')]

# टेक्स्ट सेलेक्टर्स (WebdriverIO विशिष्ट)
button=Exact Button Text
a*=Partial Link Text
```

### मोबाइल (क्रॉस-प्लेटफ़ॉर्म)

```
# Accessibility ID (अनुशंसित - iOS और Android दोनों पर काम करता है)
~loginButton

# Android UiAutomator
android=new UiSelector().text("Login")

# iOS Predicate String
-ios predicate string:label == "Login"

# iOS Class Chain
-ios class chain:**/XCUIElementTypeButton[`label == "Login"`]

# XPath (दोनों प्लेटफ़ॉर्म पर काम करता है)
//android.widget.Button[@text="Login"]
//XCUIElementTypeButton[@label="Login"]
```

## MCP रिसोर्सेज़

टूल्स के अलावा, सर्वर लाइव सेशन स्टेट को MCP रिसोर्सेज़ के रूप में एक्सपोज़ करता है। संपूर्ण संदर्भ के लिए [Resources](./mcp/resources) देखें।

| रिसोर्स URI | विवरण |
|-------------|-------------|
| `wdio://sessions` | सभी सेशन का इंडेक्स |
| `wdio://session/current/elements` | इंटरैक्ट करने योग्य एलिमेंट्स (स्क्रीनशॉट की तुलना में प्राथमिकता दें) |
| `wdio://session/current/screenshot` | base64 के रूप में स्क्रीनशॉट |
| `wdio://session/current/accessibility` | Accessibility tree |
| `wdio://session/current/cookies` | ब्राउज़र कुकीज़ |
| `wdio://session/current/tabs` | खुले ब्राउज़र टैब |
| `wdio://session/current/contexts` | उपलब्ध मोबाइल कॉन्टेक्स्ट |
| `wdio://session/current/context` | सक्रिय मोबाइल कॉन्टेक्स्ट |
| `wdio://session/current/app-state/{bundleId}` | मोबाइल ऐप लाइफ़साइकल स्टेट |
| `wdio://session/current/geolocation` | वर्तमान GPS ओवरराइड |
| `wdio://session/current/logs` | सेशन लॉग्स (browser console, logcat, crashlog) |
| `wdio://session/current/capabilities` | रॉ WebDriver capabilities |
| `wdio://session/current/code` | जनरेट किया गया WebdriverIO JS |
| `wdio://session/current/steps` | सेशन स्टेप लॉग |
| `wdio://session/{sessionId}/code` | पिछले सेशन के लिए जनरेट किया गया JS |
| `wdio://session/{sessionId}/steps` | पिछले सेशन के स्टेप्स |
| `wdio://browserstack/local-binary` | BrowserStack Local सेटअप निर्देश |
| `wdio://saucelabs/local-binary` | Sauce Connect Proxy सेटअप निर्देश |
| `wdio://testmu/local-binary` | TestMu Tunnel सेटअप निर्देश |
| `wdio://testingbot/local-binary` | TestingBot Tunnel सेटअप निर्देश |

## स्वचालित हैंडलिंग

### परमिशन

डिफ़ॉल्ट रूप से, MCP सर्वर स्वचालित रूप से ऐप परमिशन प्रदान करता है (`autoGrantPermissions: true`), जिससे ऑटोमेशन के दौरान परमिशन डायलॉग को मैन्युअल रूप से संभालने की आवश्यकता समाप्त हो जाती है।

### सिस्टम अलर्ट

सिस्टम अलर्ट (जैसे "Allow notifications?") डिफ़ॉल्ट रूप से स्वचालित रूप से स्वीकार किए जाते हैं (`autoAcceptAlerts: true`)। इसके बजाय इन्हें खारिज करने के लिए `autoDismissAlerts: true` के साथ कॉन्फ़िगर किया जा सकता है।

## ट्रांसपोर्ट

डिफ़ॉल्ट रूप से, सर्वर **stdio** पर चलता है (AI क्लाइंट द्वारा सबप्रोसेस के रूप में लॉन्च किया जाता है)। उन क्लाइंट्स के लिए जो सबप्रोसेस-आधारित MCP को सपोर्ट नहीं करते (llama.cpp, Codex secure mode), **HTTP ट्रांसपोर्ट** का उपयोग करें:

```bash
npx @wdio/mcp --http --port 3000
```

`--allowedHosts` और `--allowedOrigins` सहित सभी विकल्पों के लिए [Transport](./mcp/transport) देखें।

## परफ़ॉर्मेंस ऑप्टिमाइज़ेशन

MCP सर्वर कुशल AI असिस्टेंट संचार के लिए ऑप्टिमाइज़ किया गया है:

-   **TOON फ़ॉर्मेट**: न्यूनतम टोकन उपयोग के लिए Token-Oriented Object Notation का उपयोग करता है
-   **XML पार्सिंग**: मोबाइल एलिमेंट डिटेक्शन 2 HTTP कॉल का उपयोग करता है (पारंपरिक रूप से 600+ की तुलना में)
-   **स्क्रीनशॉट कम्प्रेशन**: इमेजेज़ अधिकतम 1MB तक ऑटो-कंप्रेस की जाती हैं
-   **व्यूपोर्ट फ़िल्टरिंग**: डिफ़ॉल्ट रूप से केवल दृश्यमान एलिमेंट्स लौटाए जाते हैं
-   **पेजिनेशन**: रिस्पॉन्स का आकार कम करने के लिए बड़ी एलिमेंट सूचियों को पेजिनेट किया जा सकता है

## एरर हैंडलिंग

सभी टूल्स मज़बूत एरर हैंडलिंग के साथ डिज़ाइन किए गए हैं:

-   एरर्स टेक्स्ट कंटेंट के रूप में लौटाए जाते हैं (कभी थ्रो नहीं किए जाते), जिससे MCP प्रोटोकॉल की स्थिरता बनी रहती है
-   वर्णनात्मक एरर मैसेज समस्याओं का निदान करने में मदद करते हैं
-   व्यक्तिगत ऑपरेशन विफल होने पर भी सेशन स्टेट संरक्षित रहती है

## उपयोग के मामले

### क्वालिटी एश्योरेंस

-   AI-संचालित टेस्ट केस एक्ज़ीक्यूशन
-   स्क्रीनशॉट के साथ विज़ुअल रिग्रेशन टेस्टिंग
-   accessibility tree विश्लेषण के माध्यम से एक्सेसिबिलिटी ऑडिटिंग

### वेब स्क्रैपिंग और डेटा एक्सट्रैक्शन

-   जटिल मल्टी-पेज फ़्लो में नेविगेट करें
-   डायनामिक कंटेंट से संरचित डेटा निकालें
-   ऑथेंटिकेशन और सेशन मैनेजमेंट संभालें

### मोबाइल ऐप टेस्टिंग

-   क्रॉस-प्लेटफ़ॉर्म टेस्ट ऑटोमेशन (iOS + Android)
-   ऑनबोर्डिंग फ़्लो सत्यापन
-   डीप लिंकिंग और नेविगेशन टेस्टिंग

### इंटीग्रेशन टेस्टिंग

-   एंड-टू-एंड वर्कफ़्लो टेस्टिंग
-   API + UI इंटीग्रेशन सत्यापन
-   मल्टी-प्लेटफ़ॉर्म स्थिरता जाँच

## समस्या निवारण

### ब्राउज़र शुरू नहीं हो रहा

-   सुनिश्चित करें कि लक्षित ब्राउज़र इंस्टॉल है
-   जाँचें कि कोई अन्य प्रोसेस डिफ़ॉल्ट डिबगिंग पोर्ट (9222) का उपयोग नहीं कर रहा है
-   यदि डिस्प्ले संबंधी समस्याएँ आती हैं तो headless मोड आज़माएँ

### Appium कनेक्शन विफल

-   सत्यापित करें कि Appium सर्वर चल रहा है (`appium`)
-   `appiumConfig` में Appium होस्ट और पोर्ट जाँचें
-   सुनिश्चित करें कि उपयुक्त ड्राइवर इंस्टॉल है (`appium driver list`)

### iOS सिम्युलेटर समस्याएँ

-   सुनिश्चित करें कि Xcode इंस्टॉल और अप टू डेट है
-   जाँचें कि सिम्युलेटर उपलब्ध हैं (`xcrun simctl list devices`)
-   रियल डिवाइस के लिए, सत्यापित करें कि UDID सही है

### Android एमुलेटर समस्याएँ

-   सुनिश्चित करें कि Android SDK ठीक से कॉन्फ़िगर है
-   सत्यापित करें कि एमुलेटर चल रहा है (`adb devices`)
-   जाँचें कि `ANDROID_HOME` एनवायरनमेंट वेरिएबल सेट है
