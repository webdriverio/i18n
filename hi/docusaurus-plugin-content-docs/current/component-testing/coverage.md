WebdriverIO का ब्राउज़र रनर [`istanbul`](https://istanbul.js.org/) का उपयोग करके कोड कवरेज रिपोर्टिंग का समर्थन करता है। टेस्टरनर Vite का उपयोग करके आपके कोड को स्वचालित रूप से इंस्ट्रूमेंट करेगा और आपके लिए कोड कवरेज कैप्चर करेगा।

## यह कैसे काम करता है

`@wdio/browser-runner` आपके एप्लिकेशन को सर्व करने के लिए Vite का उपयोग करता है। जब आप कवरेज सक्षम करते हैं, तो यह Vite सर्वर में एक प्लगइन जोड़ता है जो ब्राउज़र द्वारा अनुरोध किए जाने पर आपके सोर्स कोड को तुरंत (on the fly) इंस्ट्रूमेंट करने का प्रयास करता है।

:::warning महत्वपूर्ण
**टेस्ट रनर से दूर नेविगेट न करें!**

कोड कवरेज इस बात पर निर्भर करता है कि फ़ाइलें WebdriverIO द्वारा शुरू किए गए लोकल Vite सर्वर द्वारा सर्व और इंस्ट्रूमेंट की जा रही हों।
यदि आप किसी अन्य पेज पर नेविगेट करने के लिए `browser.url('http://...')` या `browser.url('file://...')` का उपयोग करते हैं, तो आप इंस्ट्रूमेंटेड वातावरण को छोड़ रहे हैं। आपका कोड चलेगा, लेकिन **कोई कवरेज एकत्र नहीं किया जाएगा**।

**सही तरीका (कंपोनेंट टेस्टिंग):**
अपने कंपोनेंट को रेंडर करें या अपने मॉड्यूल को सीधे टेस्ट फ़ाइल में इम्पोर्ट करें।

```js
import { myFunction } from '../src/utils.js'

it('should cover my function', () => {
    myFunction() // यह कवर होता है
})
```

**गलत तरीका (E2E स्टाइल):**
```js
it('will not have coverage', async () => {
    // ❌ दूर नेविगेट करने से इंस्ट्रूमेंटेशन टूट जाता है
    await browser.url('http://localhost:3000')
})
```
:::

## सेटअप

कोड कवरेज रिपोर्टिंग सक्षम करने के लिए, इसे WebdriverIO ब्राउज़र रनर कॉन्फ़िगरेशन के माध्यम से सक्षम करें, उदाहरण के लिए:

```js title=wdio.conf.js
export const config = {
    // ...
    runner: ['browser', {
        preset: process.env.WDIO_PRESET,
        coverage: {
            enabled: true
        }
    }],
    // ...
}
```

इसे ठीक से कॉन्फ़िगर करने का तरीका जानने के लिए सभी [कवरेज विकल्प](/docs/runner#coverage-options) देखें।

:::tip कॉन्फ़िगरेशन टिप्स
यदि आप गैर-मानक फ़ाइलों (जैसे `.html` में इनलाइन स्क्रिप्ट) का परीक्षण कर रहे हैं या यदि आपकी फ़ाइलें पकड़ी नहीं जा रही हैं, तो आपको अपने `include` और `extension` विकल्पों को स्पष्ट रूप से सत्यापित करने की आवश्यकता हो सकती है:

```js
coverage: {
    enabled: true,
    // यदि डिफ़ॉल्ट रिज़ॉल्यूशन विफल हो जाए तो अपनी सोर्स फ़ाइलों को स्पष्ट रूप से लक्षित करें
    include: ['src/**/*.js', 'src/**/*.vue'],
    // यदि आपके पास इनलाइन स्क्रिप्ट हैं तो .html जोड़ें
    extension: ['.js', '.jsx', '.ts', '.tsx', '.vue', '.html']
}
```
:::

## कोड को अनदेखा करना

आपके कोडबेस के कुछ हिस्से ऐसे हो सकते हैं जिन्हें आप जानबूझकर कवरेज ट्रैकिंग से बाहर रखना चाहते हैं, ऐसा करने के लिए आप निम्नलिखित पार्सिंग संकेतों का उपयोग कर सकते हैं:

- `/* istanbul ignore if */`: अगले if स्टेटमेंट को अनदेखा करें।
- `/* istanbul ignore else */`: if स्टेटमेंट के else भाग को अनदेखा करें।
- `/* istanbul ignore next */`: सोर्स-कोड में अगली चीज़ को अनदेखा करें (फ़ंक्शन, if स्टेटमेंट, क्लासेस, आदि)।
- `/* istanbul ignore file */`: पूरी सोर्स-फ़ाइल को अनदेखा करें (इसे फ़ाइल के शीर्ष पर रखा जाना चाहिए)।

:::info

अपनी टेस्ट फ़ाइलों को कवरेज रिपोर्टिंग से बाहर रखने की सलाह दी जाती है क्योंकि इससे त्रुटियाँ हो सकती हैं, उदाहरण के लिए `execute` कमांड को कॉल करते समय। यदि आप उन्हें अपनी रिपोर्ट में रखना चाहते हैं, तो सुनिश्चित करें कि आप उन्हें इंस्ट्रूमेंट होने से इस प्रकार बाहर रखें:

```ts
await browser.execute(/* istanbul ignore next */() => {
    // ...
})
```

:::
