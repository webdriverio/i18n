WebdriverIO समाधान प्रदान करते समय सुरक्षा के पहलू को ध्यान में रखता है। नीचे आपके टेस्ट को बेहतर ढंग से सुरक्षित करने के कुछ तरीके दिए गए हैं।

## सर्वोत्तम प्रथा

- ऐसे संवेदनशील डेटा को कभी भी हार्डकोड न करें जो स्पष्ट टेक्स्ट में उजागर होने पर आपके संगठन को नुकसान पहुँचा सकता है।
- कुंजियों और पासवर्ड को सुरक्षित रूप से संग्रहीत करने और अपने एंड-टू-एंड टेस्ट शुरू करते समय उन्हें प्राप्त करने के लिए किसी तंत्र (जैसे vault) का उपयोग करें।
- सत्यापित करें कि लॉग्स में और क्लाउड प्रदाता द्वारा कोई संवेदनशील डेटा उजागर नहीं हो रहा है, जैसे नेटवर्क लॉग्स में ऑथेंटिकेशन टोकन।

:::info

टेस्ट डेटा के लिए भी, यह पूछना आवश्यक है कि क्या गलत हाथों में पड़ने पर कोई दुर्भावनापूर्ण व्यक्ति जानकारी प्राप्त कर सकता है या उन संसाधनों का दुर्भावनापूर्ण इरादे से उपयोग कर सकता है।

:::

## संवेदनशील डेटा को मास्क करना

यदि आप अपने टेस्ट के दौरान संवेदनशील डेटा का उपयोग कर रहे हैं, तो यह सुनिश्चित करना आवश्यक है कि वह सभी को दिखाई न दे, जैसे कि लॉग्स में। साथ ही, क्लाउड प्रदाता का उपयोग करते समय, अक्सर प्राइवेट कुंजियाँ शामिल होती हैं। इस जानकारी को लॉग्स, रिपोर्टर्स और अन्य टचपॉइंट्स से मास्क किया जाना चाहिए। निम्नलिखित में उन मानों को उजागर किए बिना टेस्ट चलाने के लिए कुछ मास्किंग समाधान दिए गए हैं।

### WebDriverIO

#### कमांड्स के टेक्स्ट मान को मास्क करें

कमांड्स `addValue` और `setValue` लॉग्स और रिपोर्टर्स में मास्क करने के लिए एक boolean mask मान का समर्थन करती हैं। इसके अलावा, अन्य टूल्स, जैसे परफॉर्मेंस टूल्स और थर्ड-पार्टी टूल्स, को भी मास्क किया गया संस्करण प्राप्त होगा, जिससे सुरक्षा बढ़ती है।

उदाहरण के लिए, यदि आप एक वास्तविक प्रोडक्शन यूज़र का उपयोग कर रहे हैं और एक पासवर्ड दर्ज करने की आवश्यकता है जिसे आप मास्क करना चाहते हैं, तो अब यह निम्नलिखित के साथ संभव है:

```ts
  async enterPassword(userPassword) {
    const passwordInputElement = $('Password');

    // फोकस प्राप्त करें
    await passwordInputElement.click();

    await passwordInputElement.setValue(userPassword, { mask: true });
  }
```

ऊपर दिया गया कोड WDIO लॉग्स से टेक्स्ट मान को निम्न प्रकार से छिपा देगा:

लॉग्स उदाहरण:
```text
INFO webdriver: DATA { text: "**MASKED**" }
```

रिपोर्टर्स, जैसे Allure रिपोर्टर्स, और थर्ड-पार्टी टूल्स जैसे BrowserStack का Percy भी मास्क किए गए संस्करण को संभालेंगे।
उचित Appium संस्करण के साथ, Appium लॉग्स भी आपके संवेदनशील डेटा से मुक्त रहेंगे।

:::info

सीमाएँ:
  - Appium में, अतिरिक्त प्लगइन्स जानकारी लीक कर सकते हैं, भले ही हम जानकारी को मास्क करने के लिए कहें।
  - क्लाउड प्रदाता HTTP लॉगिंग के लिए प्रॉक्सी का उपयोग कर सकते हैं, जो लागू किए गए मास्क तंत्र को बायपास कर देता है।
  - `getValue` कमांड समर्थित नहीं है। इसके अलावा, यदि इसे उसी एलिमेंट पर उपयोग किया जाता है, तो यह उस मान को उजागर कर सकती है जिसे `addValue` या `setValue` का उपयोग करते समय मास्क करने का इरादा था।

न्यूनतम आवश्यक संस्करण:
 - WDIO v9.15.0
 - Appium v3.0.0

:::

#### WDIO लॉग्स में मास्क करें

`maskingPatterns` कॉन्फ़िगरेशन का उपयोग करके, हम WDIO लॉग्स से संवेदनशील जानकारी को मास्क कर सकते हैं। हालाँकि, Appium लॉग्स इसमें शामिल नहीं हैं।

उदाहरण के लिए, यदि आप किसी क्लाउड प्रदाता का उपयोग कर रहे हैं और info लेवल का उपयोग करते हैं, तो लगभग निश्चित रूप से आप यूज़र की कुंजी को "लीक" कर देंगे जैसा कि नीचे दिखाया गया है:

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=myCloudSecretExposedKey --spec myTest.test.ts
```

इसका मुकाबला करने के लिए हम रेगुलर एक्सप्रेशन `'--key=([^ ]*)'` पास कर सकते हैं और अब लॉग्स में आप देखेंगे

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=**MASKED** --spec myTest.test.ts
```

आप कॉन्फ़िगरेशन के `maskingPatterns` फ़ील्ड में रेगुलर एक्सप्रेशन प्रदान करके उपरोक्त प्राप्त कर सकते हैं।
  - एकाधिक रेगुलर एक्सप्रेशन के लिए, एक ही स्ट्रिंग का उपयोग करें लेकिन कॉमा से अलग किए गए मानों के साथ।
  - मास्किंग पैटर्न्स के बारे में अधिक जानकारी के लिए, [WDIO Logger README में Masking Patterns अनुभाग](https://github.com/webdriverio/webdriverio/blob/main/packages/wdio-logger/README.md#masking-patterns) देखें।

```ts
export const config: WebdriverIO.Config = {
    specs: [...],
    capabilities: [{...}],
    services: ['lighthouse'],

    /**
     * टेस्ट कॉन्फ़िगरेशन
     */
    logLevel: 'info',
    maskingPatterns: '/--key=([^ ]*)/',
    framework: 'mocha',
    outputDir: __dirname,

    reporters: ['spec'],

    mochaOpts: {
        ui: 'bdd',
        timeout: 60000
    }
}
```

:::info
न्यूनतम आवश्यक संस्करण:
 - WDIO v9.15.0
:::

:::warning
कमांड लाइन के माध्यम से पास किए गए सीक्रेट्स के लिए, मास्किंग विफल हो सकती है क्योंकि wdio.conf.ts फ़ाइल निष्पादन चक्र में बाद में पार्स की जाती है। ऐसे मामलों में एनवायरनमेंट वेरिएबल्स का उपयोग करने की अत्यधिक अनुशंसा की जाती है और यह कहीं अधिक सुरक्षित है।
:::

#### WDIO लॉगर्स को अक्षम करें

संवेदनशील डेटा की लॉगिंग को रोकने का एक अन्य तरीका लॉग लेवल को कम करना या साइलेंट करना या लॉगर को अक्षम करना है।
इसे निम्न प्रकार से प्राप्त किया जा सकता है:

```ts
import logger from '@wdio/logger';

/**
  * किसी promise को *चलाने से पहले WDIO लॉगर के लॉगर लेवल को 'silent' पर सेट करें, जो लॉग्स में संवेदनशील जानकारी को छिपाने में मदद करता है।
 */
export const withSilentLogger = async <T>(promise: () => Promise<T>): Promise<T> => {
  const webdriverLogLevel = driver.options.logLevel ?? 'error';

  try {
    logger.setLevel('webdriver', 'silent');
    return await promise();
  } finally {
    logger.setLevel('webdriver', webdriverLogLevel);
  }
};
```

### थर्ड पार्टी समाधान

#### Appium
Appium अपना स्वयं का मास्किंग समाधान प्रदान करता है; देखें [Log filter](https://appium.io/docs/en/latest/guides/log-filters/)
 - उनके समाधान का उपयोग करना मुश्किल हो सकता है। यदि संभव हो तो एक तरीका यह है कि अपनी स्ट्रिंग में `@mask@` जैसा एक टोकन पास करें और इसे रेगुलर एक्सप्रेशन के रूप में उपयोग करें
 - कुछ Appium संस्करणों में, मान प्रत्येक कैरेक्टर को कॉमा से अलग करके भी लॉग किए जाते हैं, इसलिए हमें सावधान रहने की आवश्यकता है।
 - दुर्भाग्य से, BrowserStack इस समाधान का समर्थन नहीं करता है, लेकिन यह लोकल रूप से फिर भी उपयोगी है

पहले उल्लिखित `@mask@` उदाहरण का उपयोग करते हुए, हम `appiumMaskLogFilters.json` नामक निम्नलिखित JSON फ़ाइल का उपयोग कर सकते हैं
```json
[
  {
    "pattern": "@mask@(.*)",
    "flags": "s",
    "replacer": "**MASKED**"
  },
  {
    "pattern": "\\[(\\\"@\\\",\\\"m\\\",\\\"a\\\",\\\"s\\\",\\\"k\\\",\\\"@\\\",\\S+)\\]",
    "flags": "s",
    "replacer": "[*,*,M,A,S,K,E,D,*,*]"
  }
]
```

फिर JSON फ़ाइल का नाम appium सर्विस कॉन्फ़िग में `logFilters` फ़ील्ड में पास करें:
```ts
import { AppiumServerArguments, AppiumServiceConfig } from '@wdio/appium-service';
import { ServiceEntry } from '@wdio/types/build/Services';

const appium = [
  'appium',
  {
    args: {
      log: './logs/appium.log',
      logFilters: './appiumMaskLogFilters.json',
    } satisfies AppiumServerArguments,
  } satisfies AppiumServiceConfig,
] satisfies ServiceEntry;
```

#### BrowserStack

BrowserStack भी कुछ डेटा छिपाने के लिए कुछ स्तर की मास्किंग प्रदान करता है; देखें [hide sensitive data](https://www.browserstack.com/docs/automate/selenium/hide-sensitive-data)
 - दुर्भाग्य से, यह समाधान सब-कुछ-या-कुछ-नहीं वाला है, इसलिए प्रदान की गई कमांड्स के सभी टेक्स्ट मान मास्क कर दिए जाएँगे।
