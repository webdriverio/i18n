ब्राउज़र सत्रों को `.webm` वीडियो के रूप में रिकॉर्ड करता है। वीडियो DevTools UI में स्नैपशॉट और DOM म्यूटेशन व्यू के साथ प्रदर्शित होते हैं।

तीनों एडेप्टर में उपलब्ध - **WebdriverIO**, **[Selenium WebDriver](/docs/devtools/selenium)**, और **[Nightwatch.js](/docs/devtools/nightwatch#screencast)**। कैप्चर मोड प्रत्येक फ्रेमवर्क के अनुसार भिन्न होता है (जहाँ संभव हो CDP पुश, अन्यथा पोलिंग - नीचे [ब्राउज़र समर्थन](#browser-support) देखें)।

## सेटअप

स्क्रीनकास्ट एन्कोडिंग के लिए `PATH` पर **ffmpeg** और `fluent-ffmpeg` पैकेज आवश्यक है:

```sh
# ffmpeg इंस्टॉल करें - https://ffmpeg.org/download.html
brew install ffmpeg        # macOS
sudo apt install ffmpeg    # Ubuntu/Debian

# fluent-ffmpeg इंस्टॉल करें
npm install fluent-ffmpeg
```

## कॉन्फ़िगरेशन

```ts
services: [
  [
    'devtools',
    {
      screencast: {
        enabled: true,
        captureFormat: 'jpeg',
        quality: 70,
        maxWidth: 1280,
        maxHeight: 720,
      }
    }
  ]
]
```

## विकल्प

| विकल्प | प्रकार | डिफ़ॉल्ट | विवरण |
|---|---|---|---|
| `enabled` | `boolean` | `false` | सत्र रिकॉर्डिंग सक्षम करें |
| `captureFormat` | `'jpeg' \| 'png'` | `'jpeg'` | फ्रेम इमेज फ़ॉर्मेट। **केवल Chrome/Chromium** - यह नियंत्रित करता है कि Chrome CDP पर किस फ़ॉर्मेट में भेजता है। पोलिंग मोड (Firefox, Safari) में अनदेखा किया जाता है, जहाँ स्क्रीनशॉट हमेशा PNG होते हैं। आउटपुट वीडियो कंटेनर को प्रभावित नहीं करता, जो हमेशा `.webm` होता है |
| `quality` | `number` | `70` | JPEG कम्प्रेशन गुणवत्ता 0-100। केवल Chrome/Chromium CDP मोड में `captureFormat: 'jpeg'` के साथ लागू होता है |
| `maxWidth` | `number` | `1280` | पिक्सेल में अधिकतम फ्रेम चौड़ाई। **केवल Chrome/Chromium** - Chrome CDP पर भेजने से पहले फ्रेम को स्केल करता है। पोलिंग मोड में अनदेखा किया जाता है |
| `maxHeight` | `number` | `720` | पिक्सेल में अधिकतम फ्रेम ऊँचाई। **केवल Chrome/Chromium** - ऊपर के समान |
| `pollIntervalMs` | `number` | `200` | गैर-Chrome ब्राउज़रों (पोलिंग मोड) के लिए मिलीसेकंड में स्क्रीनशॉट अंतराल। कम मान = अधिक स्मूथ वीडियो, लेकिन टेस्ट निष्पादन के दौरान अधिक WebDriver राउंड-ट्रिप |

## ब्राउज़र समर्थन

स्वचालित मोड चयन का उपयोग करके रिकॉर्डिंग सभी प्रमुख ब्राउज़रों में काम करती है:

| ब्राउज़र | मोड | टिप्पणियाँ |
|---|---|---|
| Chrome / Chromium / Edge | **CDP पुश** | Chrome DevTools Protocol पर फ्रेम पुश करता है। कुशल - टेस्ट कमांड टाइमिंग पर कोई प्रभाव नहीं |
| Firefox / Safari / अन्य | **BiDi पोलिंग** | `pollIntervalMs` अंतराल पर `browser.takeScreenshot()` कॉल करने पर फ़ॉलबैक करता है। जहाँ भी WebDriver स्क्रीनशॉट समर्थित हैं वहाँ काम करता है; अंतराल के अनुपात में थोड़ा ओवरहेड जोड़ता है |

मोड बदलने के लिए किसी कॉन्फ़िगरेशन परिवर्तन की आवश्यकता नहीं है - सर्विस ब्राउज़र क्षमताओं का स्वचालित रूप से पता लगाती है और लॉग करती है कि कौन-सा मोड सक्रिय है।

## व्यवहार

- रिकॉर्डिंग तब शुरू होती है जब ब्राउज़र सत्र खुलता है और तब रुकती है जब यह बंद होता है।
- शुरुआती खाली फ्रेम (पहले URL नेविगेशन से पहले कैप्चर किए गए) स्वचालित रूप से ट्रिम कर दिए जाते हैं, ताकि वीडियो पहली सार्थक पेज क्रिया से शुरू हों।
- यदि रन के बीच में `browser.reloadSession()` कॉल किया जाता है, तो सर्विस वर्तमान रिकॉर्डिंग को अंतिम रूप देती है और नए सत्र के लिए एक नई रिकॉर्डिंग शुरू करती है। प्रत्येक सत्र अपनी अलग `.webm` फ़ाइल बनाता है।
- जब कई रिकॉर्डिंग मौजूद होती हैं, तो DevTools UI उनके बीच स्विच करने के लिए एक **Recording N** ड्रॉपडाउन दिखाता है।

### आउटपुट फ़ाइलें कहाँ सहेजी जाती हैं

प्रत्येक एडेप्टर द्वारा चुनी गई डायरेक्टरी थोड़ी अलग होती है - वे सभी `@wdio/devtools-core` में एक ही रिज़ॉल्वर साझा करते हैं, लेकिन उसे अलग-अलग इनपुट देते हैं:

| एडेप्टर | आउटपुट स्थान |
|---|---|
| **WebdriverIO** | यदि `wdio.conf.ts` में स्पष्ट रूप से सेट किया गया हो तो `outputDir`, अन्यथा `rootDir` (कॉन्फ़िग वाली डायरेक्टरी)। केवल वीडियो पथ नियंत्रित करने के लिए `outputDir` सेट करने से बचें - WDIO वर्कर लॉग भी वहीं रीडायरेक्ट करता है। |
| **Selenium** | अभी-अभी चली टेस्ट फ़ाइल की डायरेक्टरी, फ़ॉलबैक के रूप में `process.cwd()`। |
| **Nightwatch** | टेस्ट फ़ाइल की डायरेक्टरी, फ़ॉलबैक के रूप में `nightwatch.conf.*` वाली डायरेक्टरी, फिर `process.cwd()`। |

Selenium/Nightwatch पथ पर `node_modules/` के अंतर्गत आने वाली डायरेक्टरी छोड़ दी जाती हैं, ताकि सिमलिंक किए गए वर्कस्पेस वीडियो को किसी डिपेंडेंसी फ़ोल्डर में न डालें।

## आउटपुट फ़ाइलें

लाइव मोड कैप्चर किए गए डेटा को WebSocket पर डैशबोर्ड पर स्ट्रीम करता है और **डिस्क पर कोई ट्रेस फ़ाइल नहीं लिखता** — पोर्टेबल आर्टिफ़ैक्ट के लिए [ट्रेस मोड](/docs/devtools/wdio/trace-mode) (`trace.zip`) का उपयोग करें। लाइव मोड केवल स्क्रीनकास्ट वीडियो फ़ाइल लिखता है, और वह भी केवल तब जब `screencast.enabled: true` हो। फ़ाइल नाम एडेप्टर-विशिष्ट होते हैं (फ्रेमवर्क का नाम प्रीफ़िक्स में दिखाई देता है):

| एडेप्टर | स्क्रीनकास्ट वीडियो |
|---|---|
| WebdriverIO | `wdio-video-{sessionId}.webm` |
| Selenium | `selenium-video-{sessionId}.webm` |
| Nightwatch | `nightwatch-video-{sessionId}.webm` |
