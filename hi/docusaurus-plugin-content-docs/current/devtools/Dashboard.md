लाइव मोड DevTools UI को एक बाहरी ब्राउज़र विंडो में खोलता है और आपके टेस्ट रन को रीयल टाइम में स्ट्रीम करता है। यह [Trace Mode](/docs/devtools/wdio/trace-mode) का इंटरैक्टिव समकक्ष है, जो UI को छोड़ देता है और इसके बजाय एक पोर्टेबल ऑफ़लाइन आर्टिफ़ैक्ट लिखता है। लाइव मोड डिफ़ॉल्ट रूप से सक्षम है (`mode: 'live'`), इसलिए बस अपने WebdriverIO टेस्ट चलाने से ही डैशबोर्ड लॉन्च हो जाता है।

जब आप अपने टेस्ट चलाते हैं, तो DevTools UI अपने आप एक बाहरी ब्राउज़र विंडो में खुल जाता है और टेस्ट रीयल-टाइम विज़ुअलाइज़ेशन के साथ तुरंत निष्पादित होने लगते हैं। प्रारंभिक रन पूरा होने के बाद, अलग-अलग टेस्ट या सुइट्स को फिर से चलाने के लिए प्ले बटन का उपयोग करें, और किसी भी समय चल रहे टेस्ट को समाप्त करने के लिए स्टॉप बटन का उपयोग करें।

## डैशबोर्ड क्या दिखाता है

- **लाइव ब्राउज़र प्रीव्यू** — कमांड निष्पादित होते समय टेस्ट के अधीन ब्राउज़र को देखें।
- **टेस्ट प्रगति** — सुइट्स और टेस्ट चलते समय अपडेट होते हैं।
- **कमांड निष्पादन** — प्रत्येक एक्शन होते ही स्ट्रीम होता है।
- **वर्कबेंच टैब** — चयनित टेस्ट के लिए Actions, Console, Network, Metadata और Source देखें।

## लाइव-मोड सुविधाएँ

- **[इंटरैक्टिव टेस्ट रीरनिंग और विज़ुअलाइज़ेशन](/docs/devtools/wdio/interactive-test-rerunning)** — टेस्ट रीरनिंग के साथ रीयल-टाइम ब्राउज़र प्रीव्यू
- **[प्रिज़र्व और रीरन (तुलना)](/docs/devtools/wdio/preserve-and-rerun)** — विफल टेस्ट का स्नैपशॉट लें, उसे फिर से चलाएँ, और दोनों रन की साथ-साथ तुलना (diff) करें
- **[कंसोल लॉग्स](/docs/devtools/wdio/console-logs)** — ब्राउज़र कंसोल आउटपुट को कैप्चर और निरीक्षण करें
- **[नेटवर्क लॉग्स](/docs/devtools/wdio/network-logs)** — API कॉल और नेटवर्क गतिविधि की निगरानी करें
- **[मेटाडेटा](/docs/devtools/wdio/metadata)** — प्रति ब्राउज़र सेशन, सेशन capabilities, एनवायरनमेंट और टाइमिंग
- **[TestLens](/docs/devtools/wdio/testlens)** — इंटेलिजेंट कोड नेविगेशन के साथ सोर्स कोड पर नेविगेट करें
- **[मल्टी-फ़्रेमवर्क सपोर्ट](/docs/devtools/wdio/multi-framework-support)** — Mocha, Jasmine और Cucumber के साथ काम करता है
- **[सेशन स्क्रीनकास्ट](/docs/devtools/wdio/screencast)** — ब्राउज़र सेशन की स्वचालित वीडियो रिकॉर्डिंग

## डैशबोर्ड विंडो को कॉन्फ़िगर करना

`port`, `hostname` और `devtoolsCapabilities` विकल्प DevTools UI सर्वर और उसके द्वारा खोली जाने वाली विंडो को नियंत्रित करते हैं। विवरण के लिए [कॉन्फ़िगरेशन संदर्भ](/docs/devtools/reference) देखें।

## बैकएंड को स्वतंत्र रूप से चलाना

एडैप्टर डैशबोर्ड सर्वर को इन-प्रोसेस शुरू करते हैं, इसलिए आपको सामान्यतः इसे कभी छूने की ज़रूरत नहीं पड़ती। यह एक स्टैंडअलोन बाइनरी के रूप में भी उपलब्ध है, जिसकी आपको तब ज़रूरत होती है जब डैशबोर्ड को एक रन से अधिक समय तक चलते रहना हो - या जब टेस्ट JavaScript में न हों, जैसे Python एडैप्टर के साथ (देखें [Selenium](/docs/devtools/selenium) पेज)।

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

`--port` एक *प्राथमिकता* है, कोई वादा नहीं: यदि वह पोर्ट पहले से उपयोग में है, तो सर्वर विफल होने के बजाय एक खाली पोर्ट पर बाइंड हो जाता है। यह वास्तव में बाइंड किया गया पोर्ट प्रिंट करता है, और आपको यही लाइन पढ़नी चाहिए, न कि वह पोर्ट जो आपने माँगा था:

```
devtools-backend listening at http://localhost:3000
```

`DEVTOOLS_PORT` के साथ किसी रन को पहले से लिसन कर रहे सर्वर की ओर इंगित करें (हर एडैप्टर इसका पालन करता है), और रन दूसरा सर्वर शुरू करने के बजाय उसी से जुड़ जाएगा।

एक दूसरी बाइनरी, `show-trace`, ट्रेस आर्काइव को ऑफ़लाइन प्लेयर में खोलती है - देखें [Trace Player](/docs/devtools/trace-player)।
