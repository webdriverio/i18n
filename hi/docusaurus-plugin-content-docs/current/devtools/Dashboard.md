लाइव मोड DevTools UI को एक बाहरी ब्राउज़र विंडो में खोलता है और आपके टेस्ट रन को रीयल टाइम में स्ट्रीम करता है। यह [ट्रेस मोड](/docs/devtools/wdio/trace-mode) का इंटरैक्टिव समकक्ष है, जो UI को छोड़ देता है और इसके बजाय एक पोर्टेबल ऑफ़लाइन आर्टिफ़ैक्ट लिखता है। लाइव मोड डिफ़ॉल्ट रूप से सक्षम होता है (`mode: 'live'`), इसलिए केवल अपने WebdriverIO टेस्ट चलाने से ही डैशबोर्ड लॉन्च हो जाता है।

जब आप अपने टेस्ट चलाते हैं, तो DevTools UI अपने आप एक बाहरी ब्राउज़र विंडो में खुल जाता है और टेस्ट रीयल-टाइम विज़ुअलाइज़ेशन के साथ तुरंत चलना शुरू हो जाते हैं। प्रारंभिक रन पूरा होने के बाद, अलग-अलग टेस्ट या सुइट्स को फिर से चलाने के लिए प्ले बटन का उपयोग करें, और चल रहे टेस्ट को किसी भी समय समाप्त करने के लिए स्टॉप बटन का उपयोग करें।

## डैशबोर्ड क्या दिखाता है

- **लाइव ब्राउज़र प्रीव्यू** — कमांड निष्पादित होते समय परीक्षण के अधीन ब्राउज़र को देखें।
- **टेस्ट प्रगति** — सुइट्स और टेस्ट चलते समय अपडेट होते हैं।
- **कमांड निष्पादन** — प्रत्येक एक्शन जैसे ही होता है, स्ट्रीम होता है।
- **वर्कबेंच टैब** — Actions और Metadata, साथ ही Source, Log, Console, Network और Errors (प्रत्येक पर गिनती का बैज होता है), और [Preserve & Rerun](/docs/devtools/wdio/preserve-and-rerun) के बाद Compare।

## लाइव-मोड सुविधाएँ

- **[इंटरैक्टिव टेस्ट रीरनिंग और विज़ुअलाइज़ेशन](/docs/devtools/wdio/interactive-test-rerunning)** — टेस्ट रीरनिंग के साथ रीयल-टाइम ब्राउज़र प्रीव्यू
- **[Preserve & Rerun (Compare)](/docs/devtools/wdio/preserve-and-rerun)** — किसी विफल टेस्ट का स्नैपशॉट लें, उसे फिर से चलाएँ, और दोनों रन की साथ-साथ तुलना करें
- **[कंसोल लॉग्स](/docs/devtools/wdio/console-logs)** — ब्राउज़र कंसोल आउटपुट को कैप्चर और निरीक्षण करें
- **[नेटवर्क लॉग्स](/docs/devtools/wdio/network-logs)** — API कॉल्स और नेटवर्क गतिविधि की निगरानी करें
- **[मेटाडेटा](/docs/devtools/wdio/metadata)** — प्रत्येक ब्राउज़र सेशन के लिए सेशन कैपेबिलिटीज़, एनवायरनमेंट और टाइमिंग
- **[TestLens](/docs/devtools/wdio/testlens)** — इंटेलिजेंट कोड नेविगेशन के साथ सोर्स कोड पर नेविगेट करें
- **[मल्टी-फ़्रेमवर्क सपोर्ट](/docs/devtools/wdio/multi-framework-support)** — Mocha, Jasmine और Cucumber के साथ काम करता है
- **[सेशन स्क्रीनकास्ट](/docs/devtools/wdio/screencast)** — ब्राउज़र सेशन की स्वचालित वीडियो रिकॉर्डिंग

## डैशबोर्ड विंडो को कॉन्फ़िगर करना

`port`, `hostname`, और `devtoolsCapabilities` विकल्प DevTools UI सर्वर और उस विंडो को नियंत्रित करते हैं जिसमें यह खुलता है। विवरण के लिए [कॉन्फ़िगरेशन रेफ़रेंस](/docs/devtools/reference) देखें।

## बैकएंड को स्वतंत्र रूप से चलाना

एडेप्टर डैशबोर्ड सर्वर को इन-प्रोसेस शुरू करते हैं, इसलिए आमतौर पर आपको इसे छूने की ज़रूरत नहीं पड़ती। यह एक स्टैंडअलोन बाइनरी के रूप में भी उपलब्ध है, जिसकी आपको तब ज़रूरत होती है जब डैशबोर्ड को एक रन से अधिक समय तक चलते रहना हो - या जब टेस्ट JavaScript में न हों, जैसे Python एडेप्टर के साथ ([Selenium](/docs/devtools/selenium) पेज देखें)।

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

`--port 8080` और `--port=8080` दोनों रूप स्वीकार किए जाते हैं। `--port` एक *प्राथमिकता* है, कोई गारंटी नहीं: यदि वह पोर्ट पहले से उपयोग में है, तो सर्वर विफल होने के बजाय एक खाली पोर्ट से बाइंड हो जाता है। यह उस पोर्ट को प्रिंट करता है जिससे यह वास्तव में बाइंड हुआ है, और आपको यही लाइन पढ़नी चाहिए, न कि वह पोर्ट जो आपने माँगा था:

```
devtools-backend listening at http://localhost:3000
```

जब `DEVTOOLS_PORT` सेट होता है, तो Python एडेप्टर दूसरा सर्वर शुरू करने के बजाय पहले से सुन रहे सर्वर से जुड़ जाता है। JavaScript एडेप्टर अपना बैकएंड इन-प्रोसेस शुरू करते हैं; पोर्ट चुनने के लिए उनके `port` विकल्प का उपयोग करें।

एक दूसरी बाइनरी, `show-trace`, किसी ट्रेस आर्काइव को ऑफ़लाइन प्लेयर में खोलती है - [ट्रेस प्लेयर](/docs/devtools/trace-player) देखें।
