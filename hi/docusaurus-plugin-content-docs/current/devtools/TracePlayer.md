`show-trace` प्लेयर [Trace Mode](/docs/devtools/wdio/trace-mode) में बनाए गए किसी भी ट्रेस को सीधे WebdriverIO DevTools UI में खोलता है — यह ऑफ़लाइन रीप्ले, समीक्षा और AI-एजेंट डिफ़िंग के लिए एक समर्पित, केवल-पढ़ने योग्य **प्लेयर** मोड है।

## `show-trace` — फ़र्स्ट-पार्टी प्लेयर

DevTools UI में एक ट्रेस खोलें:

```sh
show-trace trace-<sessionId>.zip          # bin on PATH after install
npx show-trace trace-<sessionId>.zip      # or via npx
pnpm show-trace trace-<sessionId>.zip     # from the devtools monorepo
```

`show-trace` bin हर एडैप्टर (`@wdio/devtools-service`, `@wdio/nightwatch-devtools`, `@wdio/selenium-devtools`) के साथ आता है, इसलिए यह उस हर प्रोजेक्ट में उपलब्ध है जिसमें इनमें से कोई एक इंस्टॉल हो — किसी अतिरिक्त डिपेंडेंसी की ज़रूरत नहीं। यह उसी DevTools UI को एक समर्पित **प्लेयर** मोड में शुरू करता है और उसे आपके ब्राउज़र में खोलता है:

- **Action list** (बाएँ) — कैप्चर किए गए कमांड्स, साथ में एक **Metadata** टैब।
- **Browser pane** (बीच में) — चयनित एक्शन के लिए पुनर्निर्मित पेज (नीचे [DOM time-travel](#trace-player-features) देखें)। जब ट्रेस में फ़िल्मस्ट्रिप/वीडियो मौजूद हो, तो एक **Snapshot / Screencast** टॉगल रिकॉर्ड किए गए वीडियो पर स्विच करता है।
- **Timeline strip** (ऊपर) — थंबनेल्स की एक फ़िल्मस्ट्रिप, जो अपनी वॉल-क्लॉक स्थितियों पर होती है, साथ में एक खींचने योग्य प्लेहेड वाली स्क्रब बार। सीक करने के लिए किसी थंबनेल पर क्लिक करें या कहीं भी ड्रैग करें।
- **Controls bar** — प्ले/पॉज़, स्टेप और स्पीड।
- **Dock tabs** (नीचे) — **Source**, **Log**, **Console**, **Network**, **Errors** (हर एक पर उसकी गिनती का बैज), साथ ही केवल-प्लेयर वाले **A11y** और **Transcript** टैब। रिक्वेस्ट का विवरण (headers, timing, status) देखने के लिए किसी **Network** पंक्ति पर क्लिक करें।
- **Keyboard shortcuts** — `Space` प्ले/पॉज़, `←`/`→` एक्शन्स के बीच स्टेप, `Home`/`End` पहले/आख़िरी पर जाएँ, `,`/`.` स्पीड बदलें, `/` फ़िल्टर पर फ़ोकस, `?` सभी शॉर्टकट्स दिखाएँ।

> केवल `.zip` स्वीकार करता है। यही शॉर्टकट्स लाइव डैशबोर्ड में भी काम करते हैं (`←`/`→` कमांड सूची में आगे-पीछे जाते हैं, `?` सहायता दिखाता है)।

### ट्रेस प्लेयर की विशेषताएँ

स्टैटिक फ़्रेम स्टेपिंग से आगे बढ़कर, प्लेयर रन को पुनर्निर्मित करता है और उसके हिस्सों को आपस में जोड़ता है:

- **DOM time-travel** — ब्राउज़र पेन कैप्चर की गई DOM-mutation स्ट्रीम (और फ़ॉर्म फ़ील्ड-स्टेट — input `value`, checkbox `checked`, जिसमें वापस खाली किए गए फ़ील्ड भी शामिल हैं) को रीप्ले करके चयनित एक्शन के समय का *वास्तविक* DOM फिर से बनाता है, सिर्फ़ एक स्क्रीनशॉट नहीं। जिन बिंदुओं पर कोई कैप्चर किया गया फ़्रेम नहीं होता (assertions, static waits), वे भी पेज की सही स्थिति दिखाते हैं।
- **A11y टैब + element overlay ("pick locator")** — **A11y** टैब चयनित कमांड के लिए कैप्चर किया गया accessibility tree (roles + accessible names) दिखाता है। टेस्ट ने जिन-जिन एलिमेंट्स के साथ इंटरैक्ट किया, उन सभी की आउटलाइन दिखाने के लिए ब्राउज़र क्रोम में element overlay टॉगल करें; किसी बॉक्स पर **hover** करने से A11y tree में उसकी पंक्ति हाइलाइट होती है, और **click** करने से एक मज़बूत locator कॉपी हो जाता है। यह लिंक दोनों दिशाओं में काम करता है — tree की किसी पंक्ति पर hover करने से स्नैपशॉट में संबंधित एलिमेंट हाइलाइट होता है।
- **Transcript टैब + Copy-for-LLM** — **Transcript** टैब रन की `transcript.md` (निष्पादन क्रम में एक मानव/LLM-पठनीय सारांश) रेंडर करता है। एक-क्लिक **Copy** ट्रांसक्रिप्ट को किसी भी विफल कमांड की errors के साथ जोड़कर LLM के लिए पेस्ट करने योग्य संदर्भ तैयार कर देता है।
- **Timeline input markers** — हर एक्शन को स्क्रब बार पर उसके प्रकार के अनुसार चिह्नित किया जाता है: कीबोर्ड एक्शन्स हरी पट्टी के रूप में, पॉइंटर एक्शन्स (जिनमें एक hit point होता है) नीले बिंदु के रूप में, और बाकी सामान्य टिक के रूप में — ताकि आप एक नज़र में इंटरैक्शन की लय समझ सकें।
- **Cucumber nesting** — Cucumber रन एक्शन ट्री में Feature → Scenario → Step के रूप में नेस्ट होते हैं, ताकि steps अपने scenario और feature के अंतर्गत दिखें।
- **Dense filmstrip scrubbing** — [`filmstrip`](/docs/devtools/wdio/trace-mode#dense-filmstrip--filmstrip) सक्षम होने पर, टाइमलाइन हर एक्शन पर एक-फ़्रेम वाली छलांगों के बजाय सहज स्क्रबिंग के लिए घने फ़्रेम्स को समाहित करती है।

## अन्य ट्रेस व्यूअर्स

चूँकि आर्टिफ़ैक्ट एक पोर्टेबल, मानक trace-viewer ऑन-डिस्क फ़ॉर्मेट का उपयोग करता है, इसलिए वही `.zip` (या डायरेक्टरी) संगत **standalone trace viewers** में भी खुलती है, और — उसी फ़ॉर्मेट को साझा करने के कारण — **Allure report के embedded trace viewer** (Allure ≥ 2.35) के अंदर भी। ये रेंडर करते हैं:
- समय के साथ एक्शन्स की टाइमलाइन
- हर एक्शन के स्क्रीनशॉट्स
- एलिमेंट स्नैपशॉट्स
- नेटवर्क वॉटरफ़ॉल
- कंसोल इवेंट्स

LLM / एजेंट के उपयोग के लिए, सीधे `transcript.md` पढ़ें — यह selectors और values के साथ एक्शन्स का एक संक्षिप्त Markdown रूपांतरण है।

ट्रेस पाइपलाइन (action-mapping, snapshot serializers, NDJSON writer, zip / directory writer) [`@wdio/devtools-core`](https://github.com/webdriverio/devtools/tree/main/packages/core) के माध्यम से सभी एडैप्टर्स में साझा की जाती है, इसलिए आर्टिफ़ैक्ट का स्वरूप एक जैसा रहता है, चाहे उसे किसी भी एडैप्टर ने बनाया हो — देखें [Cross-Framework Support](/docs/devtools/cross-framework)।
