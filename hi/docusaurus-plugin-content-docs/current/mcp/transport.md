WebdriverIO MCP सर्वर दो ट्रांसपोर्ट मोड सपोर्ट करता है: **stdio** (डिफ़ॉल्ट) और **HTTP**।

## stdio (डिफ़ॉल्ट)

stdio मानक MCP ट्रांसपोर्ट है। AI क्लाइंट सर्वर को एक चाइल्ड प्रोसेस के रूप में लॉन्च करता है और stdin/stdout के माध्यम से संवाद करता है।

```json
{
  "mcpServers": {
    "webdriverio": {
      "command": "npx",
      "args": ["-y", "@wdio/mcp"]
    }
  }
}
```

Claude Desktop, Claude Code, Cursor और इसी तरह के उन क्लाइंट्स के साथ लोकल सेटअप के लिए stdio का उपयोग करें जो सर्वर लाइफसाइकिल को स्वयं मैनेज करते हैं।

## HTTP (Streamable HTTP)

HTTP मोड सर्वर को एक स्टैंडअलोन प्रोसेस के रूप में चलाता है जो किसी पोर्ट पर सुनता है। क्लाइंट इसे सबप्रोसेस के रूप में लॉन्च करने के बजाय HTTP के माध्यम से इससे कनेक्ट होते हैं। इसका उपयोग तब करें जब:

- आपका क्लाइंट सबप्रोसेस-आधारित MCP सपोर्ट नहीं करता (जैसे llama.cpp का वेब UI)
- आप एक ही सर्वर इंस्टेंस को कई क्लाइंट्स के बीच साझा करना चाहते हैं
- आप Codex सिक्योर मोड में चला रहे हैं जहाँ सबप्रोसेस एक्ज़ीक्यूशन प्रतिबंधित है
- आप सर्वर को कई क्लाइंट सेशन के दौरान चालू रखना चाहते हैं

### HTTP मोड में शुरू करना

```bash
npx @wdio/mcp --http --port 3000
```

सर्वर एक ही एंडपॉइंट उपलब्ध कराता है: `http://localhost:<port>/mcp`

### सभी विकल्प

```bash
npx @wdio/mcp --http \
  --port 3000 \
  --allowedHosts "localhost,127.0.0.1,::1" \
  --allowedOrigins "http://localhost:5173,https://myapp.example.com"
```

| फ़्लैग               | डिफ़ॉल्ट                     | विवरण                                                                     |
| ------------------ | --------------------------- | ------------------------------------------------------------------------------- |
| `--http`           | —                           | HTTP ट्रांसपोर्ट मोड सक्षम करें                                                      |
| `--port`           | `3000`                      | सुनने के लिए पोर्ट                                                               |
| `--allowedHosts`   | `localhost,127.0.0.1,::1`   | कॉमा से अलग की गई अनुमत `Host` हेडर वैल्यूज़ (DNS rebinding सुरक्षा)         |
| `--allowedOrigins` | _(कोई नहीं — ब्राउज़र ब्लॉक)_ | CORS के लिए कॉमा से अलग की गई अनुमत `Origin` वैल्यूज़। सभी origins की अनुमति देने के लिए `*` का उपयोग करें। |

### सुरक्षा

**`--allowedHosts`** — DNS rebinding हमलों से सुरक्षा करता है। केवल वे रिक्वेस्ट स्वीकार की जाती हैं जिनका `Host` हेडर इस सूची से मेल खाता है। डिफ़ॉल्ट (`localhost,127.0.0.1,::1`) लोकल उपयोग के लिए सुरक्षित है। यदि आप सर्वर को किसी पब्लिक इंटरफ़ेस पर एक्सपोज़ करते हैं, तो अपना होस्टनेम यहाँ जोड़ें।

**`--allowedOrigins`** — नियंत्रित करता है कि कौन से ब्राउज़र origins क्रॉस-ऑरिजिन रिक्वेस्ट (CORS) कर सकते हैं। डिफ़ॉल्ट रूप से, किसी भी ब्राउज़र origin की अनुमति नहीं है। यह मनमानी वेबसाइटों से एक्सेस को ब्लॉक करता है, जबकि नॉन-ब्राउज़र क्लाइंट्स (CLI टूल्स, API क्लाइंट्स) को अनुमति देता रहता है। सभी origins की अनुमति देने के लिए `*` सेट करें, या विशिष्ट origins की सूची दें।

नॉन-ब्राउज़र क्लाइंट्स (बिना `Origin` हेडर) से आने वाली रिक्वेस्ट पर CORS जाँच लागू नहीं होती; केवल `--allowedHosts` लागू होता है।

## उपयोग के मामले

### llama.cpp वेब UI

llama.cpp का वेब UI ब्राउज़र में चलता है और हर रिक्वेस्ट के साथ एक `Origin` हेडर भेजता है। सर्वर को UI के origin से मेल खाते `--allowedOrigins` के साथ शुरू करें:

```bash
# llama.cpp web UI runs at http://localhost:8080
npx @wdio/mcp --http --port 3000 --allowedOrigins "http://localhost:8080"

# Or allow all local origins
npx @wdio/mcp --http --port 3000 --allowedOrigins "*"
```

llama.cpp की सेटिंग्स में, `http://localhost:3000/mcp` की ओर इंगित करने वाला एक MCP सर्वर जोड़ें।

---

### Codex सिक्योर मोड

OpenAI Codex बिना सबप्रोसेस सपोर्ट वाले सैंडबॉक्स्ड वातावरण में चलता है। HTTP ट्रांसपोर्ट का उपयोग करें ताकि Codex आपकी होस्ट मशीन पर चल रहे MCP सर्वर तक पहुँच सके:

```bash
# Start on your host
npx @wdio/mcp --http --port 3000
```

अपने Codex MCP कॉन्फ़िगरेशन में, सर्वर URL को `http://localhost:3000/mcp` पर सेट करें (या यदि Codex किसी VM में चलता है तो अपने होस्ट का IP)।

### प्रति-रिक्वेस्ट आर्किटेक्चर

प्रत्येक HTTP रिक्वेस्ट एक नया MCP सर्वर इंस्टेंस बनाती है। इसका अर्थ है:

- कनेक्शन टूटने के बाद क्लाइंट बिना किसी त्रुटि के फिर से कनेक्ट हो सकते हैं।
- कई क्लाइंट एक साथ कनेक्ट हो सकते हैं (प्रत्येक को एक स्वतंत्र MCP सेशन मिलता है)।
- सेशन स्टेट (सक्रिय ब्राउज़र/ऐप) ग्लोबल स्टेट के माध्यम से साझा की जाती है, ट्रांसपोर्ट स्टेट के माध्यम से नहीं।

कोई mutex नहीं है; रिक्वेस्ट समवर्ती रूप से हैंडल की जाती हैं। MCP प्रोटोकॉल की स्टेटफ़ुलनेस (initialize → tool calls) को प्रति-रिक्वेस्ट हैंडल किया जाता है।
