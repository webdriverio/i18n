Автоматизированное тестирование нативных мобильных приложений и десктопных сайтов может быть особенно сложным, когда приходится иметь дело с элементами, у которых нет уникальных идентификаторов. Стандартные [селекторы WebdriverIO](https://webdriver.io/docs/selectors) не всегда могут помочь. Познакомьтесь с `@wdio/ocr-service` — мощным сервисом, который использует OCR ([оптическое распознавание символов](https://en.wikipedia.org/wiki/Optical_character_recognition)) для поиска элементов на экране, ожидания их появления и взаимодействия с ними на основе их **видимого текста**.

Следующие пользовательские команды будут добавлены в объект `browser/driver`, чтобы у вас был подходящий набор инструментов для работы.

-   [`await browser.ocrGetText`](./ocr-get-text.md)
-   [`await browser.ocrGetElementPositionByText`](./ocr-get-element-position-by-text.md)
-   [`await browser.ocrWaitForTextDisplayed`](./ocr-wait-for-text-displayed.md)
-   [`await browser.ocrClickOnText`](./ocr-click-on-text.md)
-   [`await browser.ocrSetValue`](./ocr-set-value.md)

### Как это работает

Этот сервис:

1. создаёт скриншот вашего экрана/устройства. (При необходимости вы можете указать haystack — элемент или объект прямоугольника, — чтобы выделить конкретную область. См. документацию к каждой команде.)
1. оптимизирует результат для OCR, преобразуя скриншот в чёрно-белое изображение с высокой контрастностью (высокая контрастность нужна, чтобы избежать большого количества фонового шума на изображении. Это можно настроить для каждой команды.)
1. использует [оптическое распознавание символов](https://en.wikipedia.org/wiki/Optical_character_recognition) из [Tesseract.js](https://github.com/naptha/tesseract.js)/[Tesseract](https://github.com/tesseract-ocr/tesseract), чтобы получить весь текст с экрана и выделить весь найденный текст на изображении. Поддерживается несколько языков, список которых можно найти [здесь.](https://tesseract-ocr.github.io/tessdoc/Data-Files-in-different-versions.html)
1. использует нечёткую логику из [Fuse.js](https://fusejs.io/) для поиска строк, которые _приблизительно соответствуют_ заданному шаблону (а не точно). Это означает, например, что по запросу `Username` также может быть найден текст `Usename`, и наоборот.
1. предоставляет CLI-мастер (`npx ocr-service`) для проверки ваших изображений и извлечения текста через терминал

Пример шагов 1, 2 и 3 можно увидеть на этом изображении

Сервис работает с **НУЛЕВЫМИ** системными зависимостями (помимо тех, что использует WebdriverIO), но при необходимости он также может работать с локальной установкой [Tesseract](https://tesseract-ocr.github.io/tessdoc/), что значительно сократит время выполнения! (См. также раздел [Оптимизация выполнения тестов](#test-execution-optimization), чтобы узнать, как ускорить ваши тесты.)

Заинтересовались? Начните использовать сервис уже сегодня, следуя руководству [Начало работы](./getting-started).

:::caution Важно
Существует множество причин, по которым Tesseract может выдавать результат низкого качества. Одной из главных причин, которая может быть связана с вашим приложением и этим модулем, является отсутствие чёткого цветового различия между искомым текстом и фоном. Например, белый текст на тёмном фоне находится _легко_, а светлый текст на белом фоне или тёмный текст на тёмном фоне найти практически невозможно.

См. также [эту страницу](https://tesseract-ocr.github.io/tessdoc/ImproveQuality) для получения дополнительной информации от Tesseract.

Также не забудьте прочитать [FAQ](./ocr-faq).
:::
