Раннер в WebdriverIO управляет тем, как и где выполняются тесты при использовании тестраннера. В настоящее время WebdriverIO поддерживает два типа раннеров: локальный и браузерный.

## Локальный раннер

[Локальный раннер](https://www.npmjs.com/package/@wdio/local-runner) запускает ваш фреймворк (например, Mocha, Jasmine или Cucumber) внутри рабочего процесса и выполняет все ваши тестовые файлы в среде Node.js. Каждый тестовый файл выполняется в отдельном рабочем процессе для каждой capability, что обеспечивает максимальный параллелизм. Каждый рабочий процесс использует один экземпляр браузера и, следовательно, запускает собственную сессию браузера, что обеспечивает максимальную изоляцию.

Поскольку каждый тест выполняется в собственном изолированном процессе, обмен данными между тестовыми файлами невозможен. Есть два способа обойти это ограничение:

- использовать [`@wdio/shared-store-service`](https://www.npmjs.com/package/@wdio/shared-store-service) для обмена данными между всеми рабочими процессами
- группировать spec-файлы (подробнее в разделе [Организация набора тестов](https://webdriver.io/docs/organizingsuites#grouping-test-specs-to-run-sequentially))

Если в `wdio.conf.js` не указано иное, локальный раннер используется в WebdriverIO по умолчанию.

### Установка

Чтобы использовать локальный раннер, установите его с помощью:

```sh
npm install --save-dev @wdio/local-runner
```

### Настройка

Локальный раннер используется в WebdriverIO по умолчанию, поэтому нет необходимости указывать его в `wdio.conf.js`. Если вы хотите задать его явно, это можно сделать следующим образом:

```js
// wdio.conf.js
export const {
    // ...
    runner: 'local',
    // ...
}
```

## Браузерный раннер

В отличие от [локального раннера](https://www.npmjs.com/package/@wdio/local-runner), [браузерный раннер](https://www.npmjs.com/package/@wdio/browser-runner) инициализирует и выполняет фреймворк внутри браузера. Это позволяет запускать модульные или компонентные тесты в настоящем браузере, а не в JSDOM, как во многих других тестовых фреймворках. Тестовый бандл работает в Chrome 90, Edge 90, Firefox 90 и Safari 14.1 или новее. См. [Поддержка браузеров](/docs/component-testing#browser-support).

Хотя [JSDOM](https://www.npmjs.com/package/jsdom) широко используется для тестирования, в конечном счёте это не настоящий браузер, и с его помощью нельзя эмулировать мобильные среды. С этим раннером WebdriverIO позволяет легко запускать тесты в браузере и использовать команды WebDriver для взаимодействия с элементами, отображаемыми на странице.

Ниже приведено сравнение выполнения тестов в JSDOM и в браузерном раннере WebdriverIO

| | JSDOM | Браузерный раннер WebdriverIO |
|-|-------|----------------------------|
|1.| Выполняет тесты в Node.js, используя повторную реализацию веб-стандартов, в частности стандартов WHATWG DOM и HTML | Выполняет тесты в настоящем браузере и запускает код в той среде, которую используют ваши пользователи |
|2.| Взаимодействие с компонентами можно только имитировать с помощью JavaScript | Вы можете использовать [API WebdriverIO](api) для взаимодействия с элементами через протокол WebDriver |
|3.| Поддержка Canvas требует [дополнительных зависимостей](https://www.npmjs.com/package/canvas) и [имеет ограничения](https://github.com/Automattic/node-canvas/issues) | У вас есть доступ к настоящему [Canvas API](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API) |
|4.| JSDOM имеет некоторые [особенности](https://github.com/jsdom/jsdom#caveats) и неподдерживаемые Web API | Поддерживаются все Web API, так как тесты выполняются в настоящем браузере |
|5.| Невозможно обнаружить кросс-браузерные ошибки | Поддержка всех браузеров, включая мобильные |
|6.| __Нельзя__ тестировать псевдосостояния элементов | Поддержка псевдосостояний, таких как `:hover` или `:active` |

Этот раннер использует [Vite](https://vitejs.dev/) для компиляции тестового кода и его загрузки в браузер. Он поставляется с пресетами для следующих компонентных фреймворков:

- React
- Preact
- Vue.js
- Svelte
- SolidJS
- Stencil

Каждый тестовый файл / группа тестовых файлов выполняется на отдельной странице, что означает, что между тестами страница перезагружается для обеспечения изоляции.

### Установка

Чтобы использовать браузерный раннер, установите его с помощью:

```sh
npm install --save-dev @wdio/browser-runner
```

### Настройка

Чтобы использовать браузерный раннер, необходимо определить свойство `runner` в файле `wdio.conf.js`, например:

```js
// wdio.conf.js
export const {
    // ...
    runner: 'browser',
    // ...
}
```

### Параметры раннера

Браузерный раннер поддерживает следующие параметры конфигурации:

#### `preset`

Если вы тестируете компоненты с использованием одного из упомянутых выше фреймворков, вы можете указать пресет, который обеспечит готовую конфигурацию «из коробки». Этот параметр нельзя использовать вместе с `viteConfig`.

__Тип:__ `vue` | `svelte` | `solid` | `react` | `preact` | `stencil`<br />
__Пример:__

```js title="wdio.conf.js"
export const {
    // ...
    runner: ['browser', {
        preset: 'svelte'
    }],
    // ...
}
```

#### `viteConfig`

Определите собственную [конфигурацию Vite](https://vitejs.dev/config/). Вы можете передать пользовательский объект или импортировать существующий файл `vite.conf.ts`, если используете Vite.js для разработки. Обратите внимание, что WebdriverIO сохраняет пользовательские конфигурации Vite для настройки тестового окружения.

__Тип:__ `string` или [`UserConfig`](https://github.com/vitejs/vite/blob/52e64eb43287d241f3fd547c332e16bd9e301e95/packages/vite/src/node/config.ts#L119-L272) или `(env: ConfigEnv) => UserConfig | Promise<UserConfig>`<br />
__Пример:__

```js title="wdio.conf.ts"
import viteConfig from '../vite.config.ts'

export const {
    // ...
    runner: ['browser', { viteConfig }],
    // или просто:
    runner: ['browser', { viteConfig: '../vites.config.ts' }],
    // или используйте функцию, если ваша конфигурация vite содержит много плагинов,
    // которые нужно разрешать только при чтении значения
    runner: ['browser', {
        viteConfig: () => ({
            // ...
        })
    }],
    // ...
}
```

#### `headless`

Если установлено значение `true`, раннер обновит capabilities для запуска тестов в headless-режиме. По умолчанию это включено в CI-средах, где переменная окружения `CI` установлена в `'1'` или `'true'`.

__Тип:__ `boolean`<br />
__По умолчанию:__ `false`, устанавливается в `true`, если задана переменная окружения `CI`

#### `rootDir`

Корневая директория проекта.

__Тип:__ `string`<br />
__По умолчанию:__ `process.cwd()`

#### `coverage`

WebdriverIO поддерживает отчёты о покрытии тестами с помощью [`istanbul`](https://istanbul.js.org/). Подробнее см. в разделе [Параметры покрытия](#coverage-options).

__Тип:__ `object`<br />
__По умолчанию:__ `undefined`

### Параметры покрытия

Следующие параметры позволяют настроить отчёты о покрытии.

#### `enabled`

Включает сбор данных о покрытии.

__Тип:__ `boolean`<br />
__По умолчанию:__ `false`

#### `include`

Список файлов, включаемых в покрытие, в виде glob-шаблонов.

__Тип:__ `string[]`<br />
__По умолчанию:__ `[**]`

#### `exclude`

Список файлов, исключаемых из покрытия, в виде glob-шаблонов.

__Тип:__ `string[]`<br />
__По умолчанию:__

```
[
  'coverage/**',
  'dist/**',
  'packages/*/test{,s}/**',
  '**/*.d.ts',
  'cypress/**',
  'test{,s}/**',
  'test{,-*}.{js,cjs,mjs,ts,tsx,jsx}',
  '**/*{.,-}test.{js,cjs,mjs,ts,tsx,jsx}',
  '**/*{.,-}spec.{js,cjs,mjs,ts,tsx,jsx}',
  '**/__tests__/**',
  '**/{karma,rollup,webpack,vite,vitest,jest,ava,babel,nyc,cypress,tsup,build}.config.*',
  '**/.{eslint,mocha,prettier}rc.{js,cjs,yml}',
]
```

#### `extension`

Список расширений файлов, которые должен включать отчёт.

__Тип:__ `string | string[]`<br />
__По умолчанию:__ `['.js', '.cjs', '.mjs', '.ts', '.mts', '.cts', '.tsx', '.jsx', '.vue', '.svelte']`

#### `reportsDirectory`

Директория, в которую записывается отчёт о покрытии.

__Тип:__ `string`<br />
__По умолчанию:__ `./coverage`

#### `reporter`

Используемые репортеры покрытия. Полный список всех репортеров см. в [документации istanbul](https://istanbul.js.org/docs/advanced/alternative-reporters/).

__Тип:__ `string[]`<br />
__По умолчанию:__ `['text', 'html', 'clover', 'json-summary']`

#### `perFile`

Проверять пороговые значения для каждого файла. Сами пороговые значения см. в `lines`, `functions`, `branches` и `statements`.

__Тип:__ `boolean`<br />
__По умолчанию:__ `false`

#### `clean`

Очищать результаты покрытия перед запуском тестов.

__Тип:__ `boolean`<br />
__По умолчанию:__ `true`

#### `lines`

Пороговое значение для строк.

__Тип:__ `number`<br />
__По умолчанию:__ `undefined`

#### `functions`

Пороговое значение для функций.

__Тип:__ `number`<br />
__По умолчанию:__ `undefined`

#### `branches`

Пороговое значение для ветвлений.

__Тип:__ `number`<br />
__По умолчанию:__ `undefined`

#### `statements`

Пороговое значение для инструкций.

__Тип:__ `number`<br />
__По умолчанию:__ `undefined`

### Ограничения

При использовании браузерного раннера WebdriverIO важно учитывать, что блокирующие поток диалоги, такие как `alert` или `confirm`, не могут использоваться нативно. Это связано с тем, что они блокируют веб-страницу, из-за чего WebdriverIO не может продолжать взаимодействие со страницей, и выполнение зависает.

В таких ситуациях WebdriverIO предоставляет моки по умолчанию с возвращаемыми значениями по умолчанию для этих API. Это гарантирует, что если пользователь случайно использует синхронные всплывающие веб-API, выполнение не зависнет. Тем не менее пользователю всё же рекомендуется самостоятельно мокировать эти веб-API для более удобной работы. Подробнее в разделе [Мокирование](/docs/component-testing/mocking).
