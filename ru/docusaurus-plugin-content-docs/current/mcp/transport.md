MCP-сервер WebdriverIO поддерживает два режима транспорта: **stdio** (по умолчанию) и **HTTP**.

## stdio (по умолчанию)

stdio — стандартный транспорт MCP. AI-клиент запускает сервер как дочерний процесс и взаимодействует с ним через stdin/stdout.

```json
{
  "mcpServers": {
    "webdriverio": {
      "command": "npx",
      "args": ["-y", "@wdio/mcp"]
    }
  }
}
```

Используйте stdio для локальных конфигураций с Claude Desktop, Claude Code, Cursor и аналогичными клиентами, которые самостоятельно управляют жизненным циклом сервера.

## HTTP (Streamable HTTP)

В режиме HTTP сервер работает как отдельный процесс, прослушивающий порт. Клиенты подключаются к нему по HTTP, а не запускают его как подпроцесс. Используйте этот режим, если:

- Ваш клиент не поддерживает MCP на основе подпроцессов (например, веб-интерфейс llama.cpp)
- Вы хотите использовать один экземпляр сервера для нескольких клиентов
- Вы работаете в безопасном режиме Codex, где запуск подпроцессов ограничен
- Вы хотите, чтобы сервер продолжал работать между несколькими клиентскими сессиями

### Запуск в режиме HTTP

```bash
npx @wdio/mcp --http --port 3000
```

Сервер предоставляет единственную конечную точку: `http://localhost:<port>/mcp`

### Все параметры

```bash
npx @wdio/mcp --http \
  --port 3000 \
  --allowedHosts "localhost,127.0.0.1,::1" \
  --allowedOrigins "http://localhost:5173,https://myapp.example.com"
```

| Флаг               | По умолчанию                | Описание                                                                        |
| ------------------ | --------------------------- | ------------------------------------------------------------------------------- |
| `--http`           | —                           | Включает режим транспорта HTTP                                                  |
| `--port`           | `3000`                      | Порт для прослушивания                                                          |
| `--allowedHosts`   | `localhost,127.0.0.1,::1`   | Разрешённые значения заголовка `Host` через запятую (защита от DNS rebinding)   |
| `--allowedOrigins` | _(нет — браузеры блокируются)_ | Разрешённые значения `Origin` для CORS через запятую. Используйте `*`, чтобы разрешить все источники. |

### Безопасность

**`--allowedHosts`** — защищает от атак DNS rebinding. Принимаются только запросы с заголовком `Host`, соответствующим этому списку. Значение по умолчанию (`localhost,127.0.0.1,::1`) безопасно для локального использования. Если вы открываете сервер на публичном интерфейсе, добавьте сюда своё имя хоста.

**`--allowedOrigins`** — определяет, каким источникам (origins) браузера разрешено выполнять кросс-доменные запросы (CORS). По умолчанию никакие браузерные источники не разрешены. Это блокирует доступ с произвольных веб-сайтов, но по-прежнему позволяет подключаться небраузерным клиентам (CLI-инструментам, API-клиентам). Установите `*`, чтобы разрешить все источники, или перечислите конкретные источники.

На запросы от небраузерных клиентов (без заголовка `Origin`) проверка CORS не распространяется; применяется только `--allowedHosts`.

## Сценарии использования

### Веб-интерфейс llama.cpp

Веб-интерфейс llama.cpp работает в браузере и отправляет заголовок `Origin` с каждым запросом. Запустите сервер с `--allowedOrigins`, соответствующим источнику интерфейса:

```bash
# llama.cpp web UI runs at http://localhost:8080
npx @wdio/mcp --http --port 3000 --allowedOrigins "http://localhost:8080"

# Or allow all local origins
npx @wdio/mcp --http --port 3000 --allowedOrigins "*"
```

В настройках llama.cpp добавьте MCP-сервер, указывающий на `http://localhost:3000/mcp`.

---

### Безопасный режим Codex

OpenAI Codex работает в изолированной среде без поддержки подпроцессов. Используйте транспорт HTTP, чтобы Codex мог обращаться к MCP-серверу, запущенному на вашей хост-машине:

```bash
# Start on your host
npx @wdio/mcp --http --port 3000
```

В конфигурации MCP для Codex укажите URL сервера `http://localhost:3000/mcp` (или IP-адрес вашего хоста, если Codex работает в виртуальной машине).

---

### Архитектура «один запрос — один экземпляр»

Каждый HTTP-запрос создаёт новый экземпляр MCP-сервера. Это означает:

- Клиенты могут переподключаться после разрыва соединения без ошибок.
- Несколько клиентов могут подключаться одновременно (каждый получает независимую MCP-сессию).
- Состояние сессии (активный браузер/приложение) разделяется через глобальное состояние, а не через состояние транспорта.

Мьютекс не используется; запросы обрабатываются параллельно. Сохранение состояния протокола MCP (initialize → вызовы инструментов) обрабатывается в рамках каждого запроса.
