Часто задаваемые вопросы о WebdriverIO MCP.

## Общие вопросы

### Что такое MCP?

MCP (Model Context Protocol) — это открытый протокол, позволяющий ИИ-ассистентам, таким как Claude, взаимодействовать с внешними инструментами и сервисами. WebdriverIO MCP реализует этот протокол, предоставляя возможности автоматизации браузеров и мобильных приложений для Claude Desktop и Claude Code.

### Что можно автоматизировать с помощью WebdriverIO MCP?

Вы можете автоматизировать:
-   **Десктопные браузеры** (Chrome, Firefox, Edge, Safari) — навигация, клики, ввод текста, скриншоты
-   **iOS-приложения** — на симуляторах или реальных устройствах
-   **Android-приложения** — на эмуляторах или реальных устройствах
-   **Гибридные приложения** — переключение между нативным и веб-контекстами
-   **Облачные устройства** — через облачные платформы BrowserStack, Sauce Labs, TestMu и TestingBot

### Нужно ли писать код?

Нет! Это главное преимущество MCP. Вы можете описать, что хотите сделать, на естественном языке, и Claude использует подходящие инструменты для выполнения задачи.

**Примеры запросов:**
-   "Open Chrome and navigate to webdriver.io"
-   "Click the Get Started button"
-   "Take a screenshot of the current page"
-   "Start my iOS app and log in as test user"

## Установка и настройка

### Как установить WebdriverIO MCP?

Устанавливать его отдельно не нужно. MCP-сервер запускается автоматически через npx, когда вы настраиваете его в своей среде. Добавьте следующее в конфигурацию:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

### Где находится файл конфигурации Claude Desktop?

-   **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
-   **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

### Нужен ли Appium для автоматизации браузера?

Нет. Для автоматизации браузера требуется только установленный целевой браузер. WebdriverIO управляет драйверами автоматически.

### Нужен ли Appium для мобильной автоматизации?

Да. Для мобильной автоматизации требуется:
1. Запущенный сервер Appium (`npm install -g appium && appium`)
2. Установленные драйверы платформ (`appium driver install xcuitest` для iOS, `appium driver install uiautomator2` для Android)
3. Соответствующие инструменты разработки (Xcode для iOS, Android SDK для Android)

## Автоматизация браузера

### Какие браузеры поддерживаются?

Поддерживаются Chrome, Firefox, Edge и Safari. Используйте параметр `browser` в `start_session`:

```text
"Start a Firefox session"
"Start Chrome in headless mode"
```

### Можно ли запустить браузер в headless-режиме?

Да. Headless-режим используется по умолчанию (`headless: true`). Попросите Claude запустить браузер в обычном режиме, если хотите его видеть:

"Start Chrome in headed mode (not headless)"

### Можно ли задать размер окна браузера?

Да. Вы можете указать размеры при запуске браузера:

"Start Chrome with a window size of 1920x1080"

Поддерживаемые размеры: от 400 до 3840 пикселей в ширину, от 400 до 2160 пикселей в высоту. По умолчанию — 1920×1080.

### Можно ли запустить браузер и перейти на страницу за один шаг?

Да! Используйте параметр `navigationUrl`:

"Start Chrome and navigate to https://webdriver.io"

Это эффективнее, чем запускать браузер и затем отдельно переходить на страницу.

### Как сделать скриншот?

Просто попросите:

"Take a screenshot of the current page"

Скриншоты автоматически оптимизируются:
- Масштабируются до максимального размера 2000px
- Сжимаются до максимального размера файла 1 МБ
- Формат: PNG или JPEG (выбирается автоматически для оптимального качества)

### Можно ли взаимодействовать с iframe?

Да. Используйте инструмент `switch_frame`, чтобы переключиться в iframe по CSS- или XPath-селектору. Все последующие вызовы `click_element`, `set_value` и `get_elements` выполняются внутри выбранного фрейма. Не указывайте селектор, чтобы вернуться к фрейму верхнего уровня. Iframe должны иметь тот же источник (origin), что и основная страница.

### Можно ли выполнять собственный JavaScript?

Да! Используйте инструмент `execute_script`:

"Execute script to get the page title"
"Execute script: return document.querySelectorAll('button').length"

### Можно ли подключиться к существующей сессии Chrome?

Да. Сначала используйте `launch_chrome` (открывает Chrome с удалённой отладкой), затем `start_session` с `attach: true`.

"Launch Chrome with remote debugging, then attach to it"

### Можно ли работать с несколькими вкладками?

Да. Используйте `get_tabs`, чтобы получить список открытых вкладок, и `switch_tab`, чтобы переключиться на нужную:

"Get all open tabs"
"Switch to the tab at index 1"

## Мобильная автоматизация

### Как запустить сессию iOS или Android?

Используйте `start_session` с соответствующей платформой:

"Start my iOS app located at /path/to/MyApp.app on the iPhone 15 simulator"

"Start my Android app at /path/to/app.apk on the Pixel 7 emulator"

Или для уже установленного приложения:

"Start the app with noReset enabled on the iPhone 15 simulator"

### Можно ли тестировать на реальных устройствах?

Да! Для реальных устройств вам понадобится UDID устройства:

-   **iOS:** Подключите устройство, откройте Finder, выберите устройство и нажмите на серийный номер, чтобы отобразить UDID
-   **Android:** Выполните `adb devices` в терминале

Затем попросите:

"Start my iOS app on the real device with UDID abc123..."

### Как обрабатывать диалоги разрешений?

По умолчанию разрешения предоставляются автоматически (`autoGrantPermissions: true`). Если нужно протестировать сценарии запроса разрешений, эту функцию можно отключить:

"Start my app without automatically granting permissions"

### Какие жесты поддерживаются?

-   **Касание:** Касание элементов или координат (`tap_element`)
-   **Свайп:** Свайп вверх, вниз, влево или вправо (`swipe`)
-   **Перетаскивание:** Перетаскивание от одного элемента к другому или к координатам (`drag_and_drop`)

Примечание: `long_press` доступен через `execute_script` с мобильными командами Appium.

### Как прокручивать в мобильных приложениях?

Используйте жесты свайпа:

"Swipe up to scroll down"
"Swipe down to scroll up"

### Можно ли повернуть устройство?

Да:

"Rotate the device to landscape"
"Rotate the device to portrait"

### Как работать с гибридными приложениями?

Для приложений с webview можно переключать контексты:

"Get available contexts"
"Switch to the webview context"
"Switch back to native context"

### Можно ли выполнять мобильные команды Appium?

Да! Используйте инструмент `execute_script`:

```text
Execute script "mobile: pressKey" with args [{ keycode: 4 }]  // Нажать BACK на Android
Execute script "mobile: activateApp" with args [{ bundleId: "com.example.app" }]
Execute script "mobile: terminateApp" with args [{ bundleId: "com.example.app" }]
```

## Выбор элементов

### Как ИИ-ассистент определяет, с каким элементом взаимодействовать?

Он использует ресурс `wdio://session/current/elements` или инструмент `get_elements` для определения интерактивных элементов на странице/экране. Каждый элемент поставляется с готовыми к использованию селекторами.

### Что делать, если на странице слишком много элементов?

Используйте пагинацию для работы с большими списками элементов:

"Get the first 20 elements"
"Get elements with offset 20 and limit 20"

Ответ содержит `total`, `showing` и `hasMore`, чтобы помочь в навигации по элементам.

### Что делать, если Claude нажимает не на тот элемент?

Можно указать точнее:

-   Укажите точный текст: "Click the button that says 'Submit Order'"
-   Укажите селектор: "Click the element with selector #submit-btn"
-   Укажите accessibility ID: "Click the element with accessibility ID loginButton"

### Какая стратегия выбора селекторов лучше всего подходит для мобильных устройств?

1. **Accessibility ID** (лучший вариант) — `~loginButton`
2. **Resource ID** (Android) — `id=login_button`
3. **Predicate String** (iOS) — `-ios predicate string:label == "Login"`
4. **XPath** (крайний случай) — медленнее, но работает везде

### Что такое дерево доступности и когда его использовать?

Дерево доступности предоставляет семантическую информацию об элементах страницы (роли, имена, состояния). Используйте `get_accessibility_tree`, когда:
- `get_elements` не возвращает ожидаемые элементы
- Нужно найти элементы по роли доступности (button, link, textbox и т. д.)
- Нужна подробная семантическая информация об элементах

"Get accessibility tree filtered to button and link roles"

## Управление сессиями

### Можно ли иметь несколько сессий одновременно?

Нет. MCP-сервер использует модель с одной сессией. Одновременно может быть активна только одна сессия браузера или приложения.

### Что происходит при закрытии сессии?

Это зависит от типа сессии и настроек:

-   **Браузер:** Браузер полностью закрывается
-   **Мобильное приложение с `noReset: false`:** Приложение завершается
-   **Мобильное приложение с `noReset: true` или без `appPath`:** Приложение остаётся открытым (сессия автоматически отсоединяется)

### Можно ли сохранить состояние приложения между сессиями?

Да! Используйте опцию `noReset`:

"Start my app with noReset enabled"

Это сохраняет состояние входа, настройки и другие данные приложения.

### В чём разница между закрытием и отсоединением?

-   **Закрытие:** Полностью завершает браузер/приложение
-   **Отсоединение:** Отключает автоматизацию, но оставляет браузер/приложение запущенным

Отсоединение полезно, когда нужно вручную изучить состояние после автоматизации.

### Моя сессия постоянно завершается по тайм-ауту во время отладки

Увеличьте тайм-аут команд:

"Start my app with newCommandTimeout of 300 seconds"

По умолчанию — 300 секунд. Для очень долгих сессий отладки попробуйте 600 секунд.

## Устранение неполадок

### Ошибка "Session not found"

Это означает, что активной сессии нет. Сначала запустите сессию браузера или приложения:

"Start Chrome and navigate to google.com"

### Ошибка "Element not found"

Элемент может быть невидимым или иметь другой селектор. Попробуйте:

1. Сначала попросить Claude получить все видимые элементы
2. Указать более точный селектор
3. Дождаться полной загрузки страницы/приложения
4. Использовать `inViewportOnly: false`, чтобы найти элементы за пределами экрана

### Браузер не запускается

1. Убедитесь, что целевой браузер установлен
2. Проверьте, не использует ли другой процесс порт отладки (9222)
3. Попробуйте headless-режим

### Не удалось подключиться к Appium

Это самая распространённая проблема при запуске мобильной автоматизации.

1. **Убедитесь, что Appium запущен**: `curl http://localhost:4723/status`
2. При необходимости запустите Appium: `appium`
3. Проверьте, что параметры подключения к Appium соответствуют серверу (используйте `appiumConfig` в `start_session`)
4. Убедитесь, что драйверы установлены: `appium driver list --installed`

:::tip
MCP-сервер требует, чтобы Appium был запущен до начала мобильных сессий. Обязательно сначала запустите Appium:
```sh
appium
```
В будущих версиях может появиться автоматическое управление сервисом Appium.
:::

### Симулятор iOS не запускается

1. Убедитесь, что Xcode установлен: `xcode-select --install`
2. Выведите список доступных симуляторов: `xcrun simctl list devices`
3. Проверьте наличие ошибок конкретного симулятора в Console.app

### Эмулятор Android не запускается

1. Задайте `ANDROID_HOME`: `export ANDROID_HOME=$HOME/Library/Android/sdk`
2. Проверьте эмуляторы: `emulator -list-avds`
3. Запустите эмулятор вручную: `emulator -avd <avd-name>`
4. Убедитесь, что устройство подключено: `adb devices`

### Скриншоты не работают

1. Для мобильных устройств убедитесь, что сессия активна
2. Для браузера попробуйте другую страницу (некоторые страницы блокируют скриншоты)
3. Проверьте логи Claude Desktop на наличие ошибок

Скриншоты автоматически сжимаются до максимума в 1 МБ, поэтому большие скриншоты будут работать, но могут иметь более низкое качество.

## Производительность

### Почему мобильная автоматизация медленная?

Мобильная автоматизация включает:
1. Сетевое взаимодействие с сервером Appium
2. Взаимодействие Appium с устройством/симулятором
3. Отрисовку и отклик устройства

Советы для ускорения автоматизации:
-   Используйте эмуляторы/симуляторы вместо реальных устройств при разработке
-   Используйте accessibility ID вместо XPath
-   Включите `inViewportOnly: true` для обнаружения элементов
-   Используйте пагинацию (`limit`), чтобы сократить расход токенов

### Как ускорить обнаружение элементов?

MCP-сервер уже оптимизирует обнаружение элементов с помощью разбора XML-исходника страницы (2 HTTP-запроса против 600+ при традиционных запросах элементов). Дополнительные советы:

-   Установите `inViewportOnly: true`, чтобы отфильтровать элементы за пределами экрана
-   Установите `includeContainers: false` (по умолчанию)
-   Используйте `limit` и `offset` для пагинации на больших экранах
-   Используйте конкретные селекторы вместо поиска всех элементов

### Скриншоты создаются медленно или не создаются

Скриншоты автоматически оптимизируются:
- Изменяется размер, если он превышает 2000px
- Сжимаются, чтобы не превышать 1 МБ
- Конвертируются в JPEG, если PNG слишком большой

Такая оптимизация сокращает время обработки и гарантирует, что Claude сможет обработать изображение.

## Ограничения

### Каковы текущие ограничения?

-   **Одна сессия:** Только один браузер/приложение одновременно
-   **Поддержка iframe:** Iframe с тем же источником поддерживаются через `switch_frame`; iframe с другим источником недоступны из-за ограничений безопасности браузера
-   **Загрузка файлов:** Напрямую через инструменты не поддерживается
-   **Аудио/видео:** Невозможно взаимодействовать с воспроизведением медиа
-   **Расширения браузера:** Не поддерживаются

### Можно ли использовать это для продакшн-тестирования?

WebdriverIO MCP предназначен для интерактивной автоматизации с помощью ИИ. Для продакшн-тестирования в CI/CD рассмотрите использование традиционного тестового раннера WebdriverIO с полным программным управлением.

## Безопасность

### Защищены ли мои данные?

MCP-сервер работает локально на вашем компьютере. Вся автоматизация выполняется через локальные подключения к браузеру/Appium. Никакие данные не отправляются на внешние серверы, кроме тех, на которые вы явно переходите.

При использовании режима HTTP-транспорта (`--http`) сервер по умолчанию принимает подключения только с `localhost`; используйте `--allowedHosts` и `--allowedOrigins` для управления доступом. Подробнее см. [Транспорт](./transport).

### Может ли Claude получить доступ к моим паролям?

Claude может видеть содержимое страницы и взаимодействовать с элементами, но:
-   Пароли в полях `<input type="password">` скрыты
-   Следует избегать автоматизации с конфиденциальными учётными данными
-   Используйте тестовые аккаунты для автоматизации
