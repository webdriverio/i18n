Параметры сравнения — это параметры, которые влияют на то, как выполняется сравнение.

:::info ПРИМЕЧАНИЕ
Все параметры сравнения можно использовать при инициализации сервиса или для каждого отдельного вызова `checkElement`, `checkScreen` и `checkFullPageScreen`. Если параметр метода имеет тот же ключ, что и параметр, заданный при инициализации сервиса, то параметр сравнения метода переопределит значение параметра сравнения сервиса.
:::

## Визуальная чувствительность

---

:::info История версий для параметров `ignore*`
Поведение пресетов `ignore*` один раз изменилось (критическое изменение), когда движок сравнения был заменён с ResembleJS на Pixelmatch:

| Версия | Движок | Примечания |
| --- | --- | --- |
| v9 и ниже | ResembleJS | Исходная семантика `ignore*` (на основе RGB/яркости, собственный порядок пресетов resemble). |
| v10 и выше | Pixelmatch | Пресеты `ignore*` соответствуют настройкам порога/AA в pixelmatch. Текущие значения по умолчанию и поведение описаны ниже для каждого параметра; новые функции/исправления поверх этого отмечены примечанием «Начиная с» у соответствующего параметра. |

:::

**Порядок «побеждает последний»:** если одновременно включено несколько флагов `ignore*`, фактически применяется только один пресет в следующем порядке (побеждает последний): `ignoreAlpha` → `ignoreAntialiasing` → `ignoreColors` → `ignoreLess` → `ignoreNothing`. В лог выводится предупреждение с указанием, какой пресет победил.

### `ignoreColors`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_
-   **Начиная с:** `v10.1.0`: сравнение только по яркости с использованием весов яркости resemble (`0.3/0.59/0.11`).

Сравнивает только яркость, игнорируя различия в оттенке/цвете. Пресет: строгий порог (~16/255), сглаживание не прощается.

**Используйте, когда** ожидается, что сам цвет может меняться (например, UI с темами, изображения, перекрашиваемые в зависимости от окружения), но при этом нужно отлавливать изменения макета или яркости.

</Option>
### `ignoreAlpha`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_
-   **Начиная с:** `v10.1.0`: применяет собственное правило порога/AA независимо от других флагов `ignore*`.

Сравнивает изображения, отбрасывая различия в альфа-канале. Пресет: строгий порог (~16/255), сглаживание не прощается.

**Используйте, когда** отрисовка прозрачности/непрозрачности нестабильна (например, оверлеи, полупрозрачные элементы), но фактические цвета пикселей под ними имеют значение.

</Option>
### `ignoreAntialiasing`

<Option type="boolean" default="true" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_
-   **Начиная с:** `v10`: значение по умолчанию изменено на `true` (в v9 и ниже было `false`).

Прощает сглаженные пиксели при сравнении (ослабленный порог ~32/255). Это единственный пресет, который прощает сглаживание, и он включён по умолчанию, чтобы шум субпиксельной отрисовки не приводил к провалу сравнений «из коробки». Установите `false` для строгого сравнения, при котором сглаженные пиксели должны считаться несовпадениями.

**Используйте, чтобы** устранить самую распространённую причину нестабильности визуальных тестов: края текста и фигур, которые отрисовываются с немного разным сглаживанием на разных машинах/в разных браузерах, хотя на самом деле ничего не изменилось.

</Option>
### `ignoreLess`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_
-   **Начиная с:** `v10.1.0`: применяет собственное правило порога/AA независимо от других флагов `ignore*`.

Сравнивает изображения с ослабленным допуском RGB (~16/255 на канал в пространстве YIQ). Пресет: строгий порог, сглаживание не прощается.

**Используйте, когда** нужен небольшой запас для незначительного шума отрисовки (артефакты сжатия в стиле JPEG, небольшое округление цветов) без прощения сглаживания.

</Option>
### `ignoreNothing`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_
-   **Начиная с:** `v10.1.0`: применяет собственное правило порога/AA независимо от других флагов `ignore*`.

Использует нулевой допуск: любое различие пикселей считается несовпадением, включая сглаживание.

**Используйте, когда** нужно попиксельное доказательство того, что вообще ничего не изменилось, например, при проверке того, что исправление не внесло никакой регрессии, даже самой малой.

</Option>
### `scaleImagesToSameSize`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_

Масштабирует 2 изображения до одинакового размера перед выполнением сравнения. Настоятельно рекомендуется включить `ignoreAntialiasing` и `ignoreAlpha`

</Option>
## Прямое управление pixelmatch

---

:::info Добавлено в v10.1.0
У `compareOptions.pixelmatch` нет эквивалента в v9 (ResembleJS). Это совершенно новый способ напрямую управлять движком сравнения вместо использования пресета `ignore*`.
:::

### `compareOptions.pixelmatch`

<Option type="object" default="undefined" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина для конкретного используемого метода_
-   **Добавлено в:** `v10.1.0`

Передаёт настройки напрямую в [pixelmatch](https://github.com/mapbox/pixelmatch) вместо использования пресета `ignore*`. **Используйте, когда пять пресетов `ignore*` слишком грубы:** вам нужно конкретное значение порога, которого нет в пресетах, или diff-изображение, которое действительно удобно читать в ваших отчётах/выводе CI вместо стандартной пурпурной подсветки.

:::warning Взаимоисключающие в пределах одного объекта параметров
Указание любого ключа `ignore*` вместе с `pixelmatch` в **одном и том же** объекте параметров выбрасывает `CompareOptionsConflictError`, даже если значение `ignore*` равно `false` (см. недопустимый пример ниже). Выберите один режим для каждого объекта: пресеты `ignore*` или `pixelmatch`, но никогда не оба.

Это относится только к одному объекту. Конфигурация сервиса и параметры вызова метода — это отдельные объекты, поэтому вызову `check*` **разрешено** использовать режим, отличный от конфигурации сервиса: например, сервис использует пресеты `ignore*`, а один из вызовов передаёт `pixelmatch` (или наоборот). В этом случае ошибки нет, только в лог выводится предупреждение о смене режима сравнения.
:::

| Поле | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `threshold` | `number` | `0.1` | Чувствительность от 0 (любое различие пикселей приводит к провалу) до 1 (почти ничего не приводит к провалу). Используйте, чтобы задать одно точное значение чувствительности вместо выбора ближайшего пресета `ignore*`. |
| `includeAA` | `boolean` | `false` | `true` считает сглаженные пиксели на краях несовпадениями; `false` прощает их. Отключите, если различия в отрисовке краёв шрифтов/фигур вызывают нестабильные провалы. |
| `diffColor` | `[number, number, number]` | `[255, 0, 255]` (пурпурный) | RGB-цвет для несовпадающих пикселей в diff-изображении. Измените его, если пурпурный сливается с вашим UI (например, розовая/фиолетовая тема) и несовпадения трудно заметить. |
| `aaColor` | `[number, number, number]` | `[255, 0, 255]` (пурпурный) | RGB-цвет для сглаженных пикселей, визуально отделённых от реальных несовпадений, чтобы с первого взгляда отличать «шум отрисовки» от «настоящего бага». |
| `diffColorAlt` | `[number, number, number]` | `[255, 0, 255]` (пурпурный) | RGB-цвет для пикселей, которые были добавлены или удалены (а не просто перекрашены); полезно для различения смещений макета и изменений цвета. |
| `alpha` | `number` | `0.1` | Непрозрачность diff-наложения поверх фактического скриншота. Увеличьте, чтобы различия были заметнее в отчётах; уменьшите, чтобы по-прежнему чётко видеть исходный UI. Не связано с пресетом `ignoreAlpha`. |
| `diffMask` | `boolean` | `false` | Установите `true`, чтобы выводить только «сырой» diff (прозрачный фон) вместо diff, нарисованного поверх скриншота; полезно для создания собственного средства просмотра/отчёта о различиях. |
| `checkerboard` | `boolean` | `true` | Управляет тем, как полупрозрачные пиксели отображаются в diff. Отключите, если шахматный узор легко спутать с реальным содержимым ваших скриншотов. |

**Конфигурация сервиса:**

```js
// wdio.conf.js
export const config = {
    // ...
    services: [
        ['visual', {
            compareOptions: {
                pixelmatch: {
                    threshold: 0.063,
                    includeAA: true,
                },
            },
        }],
    ],
}
```

**Переопределение в методе, когда сервис использует пресеты `ignore*`:**

```js
await browser.checkScreen('homepage', {
    pixelmatch: { threshold: 0.05 },
})
```

**Переопределение в методе, когда сервис использует `pixelmatch`:**

```js
await browser.checkScreen('homepage', {
    ignoreLess: true,
})
```

**Недопустимо: выбрасывает `CompareOptionsConflictError`**

```js
compareOptions: {
    ignoreLess: false,
    pixelmatch: { threshold: 0.063 },
}
```

Полное описание семантики параметров см. в [документации pixelmatch](https://github.com/mapbox/pixelmatch).

</Option>
## Скрытие элементов на мобильных устройствах

---

### `blockOutStatusBar`

<Option type="boolean" default="true" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина. **Только для мобильных устройств**_

Автоматически скрывает строку состояния и адресную строку во время сравнения. Это предотвращает провалы из-за времени, статуса Wi-Fi или батареи.

</Option>
### `blockOutToolBar`

<Option type="boolean" default="true" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина. **Только для мобильных устройств**_

Автоматически скрывает панель инструментов.

</Option>
### `blockOutSideBar`

<Option type="boolean" default="true" required="no">

-   **Примечание:** _Может использоваться только для `checkScreen()`. Переопределяет настройку плагина. **Только для iPad**_

Автоматически скрывает боковую панель на iPad в альбомной ориентации во время сравнения. Это предотвращает провалы из-за нативного компонента вкладок/приватного режима/закладок.

</Option>
## Результаты и отчётность

---

### `rawMisMatchPercentage`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_

Если `true`, возвращаемый процент будет иметь вид `0.12345678`, по умолчанию — `0.12`

</Option>
### `returnAllCompareData`

<Option type="boolean" default="false" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_

Возвращает все данные сравнения, а не только процент несовпадения

</Option>
### `saveAboveTolerance`

<Option type="number" default="0" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Переопределяет настройку плагина_

Допустимое значение `misMatchPercentage`, которое предотвращает сохранение изображений с различиями

</Option>
### `diffPixelBoundingBoxProximity`

<Option type="number" default="5" required="no">

-   **Примечание:** _Также может использоваться для `checkElement`, `checkScreen()` и `checkFullPageScreen()`. Имеет значение только при включённом [`createJsonReportFiles`](/docs/visual-testing/service-options#createjsonreportfiles)._

Близость пикселей, используемая для группировки различающихся пикселей в JSON-отчётах. Более высокие значения объединяют больше пикселей в меньшее количество ограничивающих рамок; более низкие значения дают более точные, но более многочисленные рамки.

</Option>
