Записывает сеансы браузера в виде видео `.webm`. Видео отображаются в интерфейсе DevTools рядом с представлениями снимков и мутаций DOM.

Доступно во всех трёх адаптерах - **WebdriverIO**, **[Selenium WebDriver](/docs/devtools/selenium)** и **[Nightwatch.js](/docs/devtools/nightwatch#screencast)**. Режим захвата зависит от фреймворка (CDP push, где это возможно, в остальных случаях - опрос; см. раздел [Поддержка браузеров](#browser-support) ниже).

## Установка

Для кодирования записи требуется **ffmpeg** в `PATH` и пакет `fluent-ffmpeg`:

```sh
# Установите ffmpeg - https://ffmpeg.org/download.html
brew install ffmpeg        # macOS
sudo apt install ffmpeg    # Ubuntu/Debian

# Установите fluent-ffmpeg
npm install fluent-ffmpeg
```

## Конфигурация

```ts
services: [
  [
    'devtools',
    {
      screencast: {
        enabled: true,
        captureFormat: 'jpeg',
        quality: 70,
        maxWidth: 1280,
        maxHeight: 720,
      }
    }
  ]
]
```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | `boolean` | `false` | Включить запись сеанса |
| `captureFormat` | `'jpeg' \| 'png'` | `'jpeg'` | Формат изображения кадров. **Только Chrome/Chromium** - определяет формат, в котором Chrome отправляет кадры через CDP. Игнорируется в режиме опроса (Firefox, Safari), где скриншоты всегда в формате PNG. Не влияет на контейнер выходного видео, который всегда `.webm` |
| `quality` | `number` | `70` | Качество сжатия JPEG от 0 до 100. Применяется только в режиме CDP в Chrome/Chromium с `captureFormat: 'jpeg'` |
| `maxWidth` | `number` | `1280` | Максимальная ширина кадра в пикселях. **Только Chrome/Chromium** - Chrome масштабирует кадры перед отправкой через CDP. Игнорируется в режиме опроса |
| `maxHeight` | `number` | `720` | Максимальная высота кадра в пикселях. **Только Chrome/Chromium** - аналогично предыдущему |
| `pollIntervalMs` | `number` | `200` | Интервал создания скриншотов в миллисекундах для браузеров, отличных от Chrome (режим опроса). Меньшее значение = более плавное видео, но больше обращений к WebDriver во время выполнения тестов |

## Поддержка браузеров

Запись работает во всех основных браузерах благодаря автоматическому выбору режима:

| Браузер | Режим | Примечания |
|---|---|---|
| Chrome / Chromium / Edge | **CDP push** | Chrome отправляет кадры через DevTools Protocol. Эффективно - не влияет на время выполнения тестовых команд |
| Firefox / Safari / другие | **BiDi polling** | Используется резервный вариант с вызовом `browser.takeScreenshot()` с интервалом `pollIntervalMs`. Работает везде, где поддерживаются скриншоты WebDriver; добавляет небольшие накладные расходы, пропорциональные интервалу |

Для переключения режимов не требуется изменять конфигурацию - сервис автоматически определяет возможности браузера и записывает в журнал, какой режим активен.

## Поведение

- Запись начинается при открытии сеанса браузера и останавливается при его закрытии.
- Начальные пустые кадры (захваченные до первой навигации по URL) автоматически обрезаются, поэтому видео начинается с первого значимого действия на странице.
- Если во время выполнения вызывается `browser.reloadSession()`, сервис завершает текущую запись и начинает новую для нового сеанса. Каждый сеанс создаёт собственный файл `.webm`.
- Если существует несколько записей, в интерфейсе DevTools отображается выпадающий список **Recording N** для переключения между ними.

### Куда сохраняются выходные файлы

Каждый адаптер выбирает каталог немного по-разному - все они используют один и тот же механизм определения пути из `@wdio/devtools-core`, но передают ему разные входные данные:

| Адаптер | Расположение выходных файлов |
|---|---|
| **WebdriverIO** | `outputDir`, если он явно задан в `wdio.conf.ts`, иначе `rootDir` (каталог, содержащий конфигурацию). Не задавайте `outputDir` только ради управления путями к видео - WDIO также перенаправляет туда журналы воркеров. |
| **Selenium** | Каталог только что выполненного тестового файла, с резервным вариантом `process.cwd()`. |
| **Nightwatch** | Каталог тестового файла, с резервным вариантом в виде каталога, содержащего `nightwatch.conf.*`, а затем `process.cwd()`. |

Каталоги внутри `node_modules/` пропускаются для Selenium/Nightwatch, чтобы в рабочих пространствах с символическими ссылками видео не попадали в папку зависимостей.

## Выходные файлы

Режим live передаёт захваченные данные на панель мониторинга через WebSocket и **не записывает файл трассировки на диск** — для переносимого артефакта используйте [режим трассировки](/docs/devtools/wdio/trace-mode) (`trace.zip`). Единственный файл, который записывает режим live, — это видео записи, и только при `screencast.enabled: true`. Имена файлов зависят от адаптера (название фреймворка указывается в префиксе):

| Адаптер | Видео записи |
|---|---|
| WebdriverIO | `wdio-video-{sessionId}.webm` |
| Selenium | `selenium-video-{sessionId}.webm` |
| Nightwatch | `nightwatch-video-{sessionId}.webm` |
