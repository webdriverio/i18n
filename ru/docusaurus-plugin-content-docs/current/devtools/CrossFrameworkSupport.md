Формат трассировки и плеер `show-trace` идентичны для WebdriverIO / Selenium / Nightwatch; на этой странице показано, где различается полнота захвата. Полный справочник по режиму трассировки см. в разделе [Trace Mode](/docs/devtools/wdio/trace-mode).

Преобразования, которые строят трассировку, находятся в [`@wdio/devtools-trace`](https://github.com/webdriverio/devtools/tree/main/packages/trace), на один уровень ниже адаптеров, поэтому **формат трассировки и плеер `show-trace` идентичны для всех адаптеров** — один и тот же `.zip` (или каталог) открывается в одном и том же плеере независимо от того, какой адаптер его создал. Кроме того, три адаптера ниже используют общие базовые опции (`mode`, `traceGranularity`, `tracePolicy`, `traceFormat`, `filmstrip`, `emitArtifactsManifest`, `captureAssertions`).

Однако **полнота захвата зависит от адаптера** — WebdriverIO наиболее полный; Selenium и Nightwatch покрывают основной сценарий с пробелами, указанными ниже. Синтаксис включения для конкретного фреймворка описан на странице каждого адаптера — см. [Selenium](/docs/devtools/selenium#trace-mode) и [Nightwatch](/docs/devtools/nightwatch#trace-mode).

Адаптер для Python (см. вкладки **Python** на странице [Selenium](/docs/devtools/selenium)) записывает такой же архив, который открывается в том же плеере, но он не включён в эту таблицу: он не выполняет JavaScript в процессе теста, поэтому трассировку строит бэкенд из захваченного потока, а не адаптер внутри процесса. Для гранулярности и политики хранения в Python есть эквиваленты — `--devtools-trace-granularity session|test` и `--devtools-trace-policy`, причём значения последней, учитывающие повторы, сводятся к `retain-on-failure`, поскольку ничто в этом протоколе не передаёт номер попытки. Строки без эквивалента в Python — это строки, касающиеся артефактов отдельных тестов: `screenshot`, `video` и встроенное прикрепление к Allure. То, что он захватывает — DOM time-travel, плотная плёнка кадров, дерево A11y и наложение элементов, команды, консоль, сеть, утверждения, элементы управления запуском и Preserve & Rerun, — описано на отдельной странице.

| Возможность | WebdriverIO | Selenium | Nightwatch |
|---|---|---|---|
| Режим трассировки + плеер `show-trace` | ✅ | ✅ | ✅ |
| DOM time-travel (захват мутаций) | ✅ | ✅ ¹ | ✅ |
| Вкладка A11y + наложение выбора локатора (плеер трассировки) | ✅ | ✅ | ✅ |
| Transcript + Copy-for-LLM | ✅ | ✅ | ✅ |
| `screenshot` / `video` для каждого теста | ✅ встроенно в Allure | ✅ встроенно в Allure | ⚠️ только создание ² |
| Автоопределение `emitArtifactsManifest` | ✅ | ✅ | ⚠️ только при явном включении |
| `tracePolicy` с учётом повторов | ✅ | ✅ | ⚠️ только `retain-on-failure` ³ |
| `traceGranularity: 'test'` | ✅ | ✅ | ⚠️ Cucumber / exports-object; BDD `describe/it` сводится к срезу сессии |
| Вложенность Cucumber Feature→Scenario→Step | Scenario→Step ⁴ | ✅ полная | Feature→Scenario ⁵ |
| Захват BiDi (консоль / сеть / исключения) | ✅ автоматически | ✅ автоматически | ⚠️ при явном включении (`bidi: true` + `webSocketUrl`) |
| Screencast (плёнка кадров / видео) | CDP push | CDP push | только опрос |
| Вкладка A11y + наложение в live-дашборде | ✅ | только плеер трассировки | только плеер трассировки |

¹ Selenium восстанавливает DOM для каждой навигации; привязка по времени приблизительна (снимок навигации может отставать от команды, которая её вызвала).
² У Nightwatch нет API для прикрепления к Allure в реальном времени, поэтому артефакты отдельных тестов записываются в выходной каталог трассировки и перечисляются в манифесте, но не прикрепляются к тесту Allure.
³ `--retries` в Nightwatch перезапускает тест внутренне, не вызывая повторно хуки плагина для каждого теста, поэтому политики с учётом повторов (`on-first-retry`, `retain-on-first-failure`, …) сводятся к `retain-on-failure`.
⁴ WebdriverIO пока не передаёт информацию о родительском уровне feature, поэтому вложенность Cucumber в нём — Scenario→Step.
⁵ Nightwatch пока не проставляет вложенность на уровне шагов (только Feature→Scenario).
