Что [режим трассировки](/docs/devtools/wdio/trace-mode) намеренно пропускает, а также известные пробелы в работе адаптеров.

## Что пропускает режим трассировки

- **Окно интерфейса DevTools** — экземпляр Chrome для панели управления не открывается.
- **Привязка порта бэкенда** — порт на localhost не резервируется (одинаково для всех трёх адаптеров начиная с v1.2+).
- **`screencast.enabled`** — непрерывная запись `.webm` из live-режима в режиме трассировки игнорируется (в лог выводится предупреждение). Вместо этого режим трассировки **по умолчанию** записывает в архив плотную [`filmstrip`](/docs/devtools/wdio/trace-mode#dense-filmstrip--filmstrip) (установите `filmstrip: false`, чтобы получать один кадр на действие), а также, если включено, фрагменты [`video`](/docs/devtools/wdio/trace-mode#per-test-screenshot--video--screenshot--video) для каждого теста. Поля **настройки** screencast (`quality`, `maxWidth`, `pollIntervalMs`, …) по-прежнему применяются к тому рекордеру, который запущен.
- **Дамп `wdio-trace-<sessionId>.json`** — полностью удалён. Устаревший монолитный JSON, который раньше записывал live-режим WDIO, больше не создаётся; теперь live-режим передаёт данные в панель управления в потоковом режиме и ничего не записывает на диск, а `trace.zip` является единственным артефактом трассировки.

## Известные ограничения

- **Nightwatch BDD `describe/it`** — `traceGranularity: 'test'` сводится к **одному фрагменту в рамках сессии**: Nightwatch выполняет отдельные `it` внутренне, без хука уровня теста, который мог бы отследить плагин, поэтому фрагмент привязывается к первому тесту. Сбор метаданных (состояние каждого testcase в манифесте) не затрагивается, однако привязка трассировки/скриншотов/видео к каждому `it` и хранение с учётом повторных попыток для этого интерфейса деградируют до уровня сессии. Интерфейсы Nightwatch **exports-object** и **Cucumber** предоставляют хуки для каждого сценария/теста и обеспечивают полноценное разделение по тестам. (WebdriverIO mocha/cucumber и Selenium mocha это не затрагивает.)
- **Хранение с учётом повторных попыток в Nightwatch** — работает только `retain-on-failure`; другие политики, учитывающие повторные попытки, деградируют, поскольку Nightwatch при `--retries` перезапускает testcase внутренне, не вызывая повторно хуки уровня теста. См. [Хранение](/docs/devtools/wdio/trace-mode#retention--tracepolicy).
- **Прикрепление к Allure в Nightwatch** — `screenshot`/`video` для каждого теста только создаются (файлы + манифест), но не прикрепляются встроенно; см. [интеграцию с Allure](/docs/devtools/allure).
- **Видео/filmstrip не в Chrome** — в браузерах без механизма push-доставки через CDP рекордер опрашивает `takeScreenshot`, что добавляет дополнительные обращения к WebDriver и (при использовании Allure) засоряет лог шагов; используйте вместе с параметрами репортера для подавления шагов.
