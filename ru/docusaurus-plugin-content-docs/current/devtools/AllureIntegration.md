Артефакты режима трассировки — zip-архив трассировки, а также скриншот и видео каждого теста — автоматически прикрепляются к отчёту Allure, поэтому их можно открыть прямо из отчёта. О том, как включить режим трассировки и получить эти артефакты, см. в разделе [Режим трассировки](/docs/devtools/wdio/trace-mode).

Если подключён репортер Allure, артефакты режима трассировки автоматически прикрепляются к отчёту Allure — без дополнительной настройки:

- **`traceGranularity: 'test'`** — `trace.zip` каждого теста (`application/zip`, загружаемый файл, который открывается в `show-trace`), `screenshot` (`image/png`, встроенный) и `video` (`video/webm`, встроенное) прикрепляются к карточке соответствующего теста. Именно эту гранулярность следует использовать для отчёта Allure с разбивкой по тестам.
- **`traceGranularity: 'session'` / `'spec'`** — трассировка, охватывающая сессию/спецификацию, записывается на диск и указывается в [манифесте артефактов](/docs/devtools/wdio/trace-mode#artifacts-manifest--emitartifactsmanifest), но **не** прикрепляется к карточкам отдельных тестов: трассировка сессии/спецификации финализируется только после выполнения всех её тестов, а к этому моменту их карточки Allure уже закрыты и открытого теста, к которому можно было бы прикрепить артефакт, нет. Чтобы всё же отобразить её, обработайте манифест в собственном хуке `onComplete`.

Поддержка в зависимости от адаптера:

| Адаптер | Механизм прикрепления |
|---|---|
| **WebdriverIO** | Полноценная поддержка через `addAttachment` из `@wdio/allure-reporter`. |
| **Selenium** | Через `attachment()` из `allure-js-commons` — не зависит от среды выполнения, прикрепляет артефакты при любом адаптере раннера Allure, при условии наличия активной среды выполнения `allure-js-commons`. |
| **Nightwatch** | **Только создание** — файлы и манифест записываются, но не прикрепляются к отчёту (нет API для прикрепления к Allure в реальном времени). |

**Встроенный просмотрщик трассировки.** Поскольку архив использует переносимый стандартный формат хранения trace-viewer на диске, собственный **встроенный просмотрщик трассировки** отчёта Allure (Allure ≥ 2.35) может открыть прикреплённый `trace.zip` непосредственно внутри отчёта.

**Шум в отчёте.** В режиме трассировки для построения временной шкалы при каждом действии выполняется `takeScreenshot`; Allure записывает каждую команду WebDriver как шаг и сохраняет скриншот для каждого `takeScreenshot`. Отключите этот поток с помощью собственных опций репортера — на вложения трассировки, скриншотов и видео это не повлияет:

```ts
reporters: [
  ['allure', {
    outputDir: 'allure-results',
    disableWebdriverStepsReporting: true,
    disableWebdriverScreenshotsReporting: true
  }]
]
```
