Режим Live открывает интерфейс DevTools во внешнем окне браузера и транслирует выполнение ваших тестов в реальном времени. Это интерактивный аналог [Trace Mode](/docs/devtools/wdio/trace-mode), который обходится без интерфейса и вместо этого создаёт переносимый офлайн-артефакт. Режим Live включён по умолчанию (`mode: 'live'`), поэтому достаточно просто запустить тесты WebdriverIO, чтобы открылась панель управления.

При запуске тестов интерфейс DevTools автоматически открывается во внешнем окне браузера, и тесты сразу начинают выполняться с визуализацией в реальном времени. После завершения первого прогона используйте кнопки воспроизведения, чтобы перезапустить отдельные тесты или наборы тестов, и кнопку остановки, чтобы в любой момент прервать выполняющиеся тесты.

## Что показывает панель управления

- **Предпросмотр браузера в реальном времени** — наблюдайте за тестируемым браузером по мере выполнения команд.
- **Прогресс тестов** — наборы тестов и тесты обновляются по ходу выполнения.
- **Выполнение команд** — каждое действие транслируется в момент его выполнения.
- **Вкладки рабочей области** — изучайте Actions, Console, Network, Metadata и Source для выбранного теста.

## Возможности режима Live

- **[Интерактивный перезапуск и визуализация тестов](/docs/devtools/wdio/interactive-test-rerunning)** — предпросмотр браузера в реальном времени с возможностью перезапуска тестов
- **[Сохранение и перезапуск (сравнение)](/docs/devtools/wdio/preserve-and-rerun)** — сохраните снимок упавшего теста, перезапустите его и сравните два прогона бок о бок
- **[Логи консоли](/docs/devtools/wdio/console-logs)** — захват и просмотр вывода консоли браузера
- **[Сетевые логи](/docs/devtools/wdio/network-logs)** — мониторинг API-вызовов и сетевой активности
- **[Метаданные](/docs/devtools/wdio/metadata)** — capabilities сессии, окружение и тайминги для каждой сессии браузера
- **[TestLens](/docs/devtools/wdio/testlens)** — переход к исходному коду с интеллектуальной навигацией по коду
- **[Поддержка нескольких фреймворков](/docs/devtools/wdio/multi-framework-support)** — работает с Mocha, Jasmine и Cucumber
- **[Запись экрана сессии](/docs/devtools/wdio/screencast)** — автоматическая видеозапись сессий браузера

## Настройка окна панели управления

Параметры `port`, `hostname` и `devtoolsCapabilities` управляют сервером интерфейса DevTools и окном, в котором он открывается. Подробности см. в [справочнике по конфигурации](/docs/devtools/reference).

## Запуск бэкенда отдельно

Адаптеры запускают сервер панели управления внутри процесса, поэтому обычно вам не нужно с ним взаимодействовать. Он также поставляется в виде отдельного бинарного файла — это то, что вам нужно, если панель управления должна продолжать работать дольше одного прогона, или если тесты написаны не на JavaScript, как в случае с адаптером для Python (см. страницу [Selenium](/docs/devtools/selenium)).

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

`--port` — это *пожелание*, а не гарантия: если порт занят, сервер вместо ошибки привяжется к свободному. Он выводит порт, к которому фактически привязался, — ориентируйтесь именно на эту строку, а не на запрошенный порт:

```
devtools-backend listening at http://localhost:3000
```

Чтобы подключить прогон к уже запущенному серверу, укажите `DEVTOOLS_PORT` (его учитывает каждый адаптер) — тогда прогон подключится к существующему серверу, а не запустит второй.

Второй бинарный файл, `show-trace`, открывает архив трассировки в офлайн-плеере — см. [Trace Player](/docs/devtools/trace-player).
