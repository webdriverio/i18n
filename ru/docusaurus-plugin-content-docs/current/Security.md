WebdriverIO учитывает аспекты безопасности при предоставлении решений. Ниже приведены некоторые способы лучше защитить ваши тесты.

## Лучшие практики

- Никогда не прописывайте в коде конфиденциальные данные, которые могут навредить вашей организации, если окажутся раскрыты в открытом виде.
- Используйте специальный механизм (например, хранилище секретов) для безопасного хранения ключей и паролей и получайте их при запуске end-to-end тестов.
- Убедитесь, что никакие конфиденциальные данные не раскрываются в логах и у облачного провайдера, например токены аутентификации в сетевых логах.

:::info

Даже в случае тестовых данных важно задаться вопросом: сможет ли злоумышленник, получив их, извлечь информацию или использовать эти ресурсы со злым умыслом?

:::

## Маскирование конфиденциальных данных

Если вы используете конфиденциальные данные в тестах, важно убедиться, что они не видны всем, например в логах. Кроме того, при использовании облачного провайдера часто задействуются приватные ключи. Эта информация должна быть замаскирована в логах, репортерах и других точках соприкосновения. Ниже приведены некоторые решения для маскирования, позволяющие запускать тесты, не раскрывая эти значения.

### WebDriverIO

#### Маскирование текстовых значений команд

Команды `addValue` и `setValue` поддерживают булево значение mask для маскирования в логах, а также в репортерах. Более того, другие инструменты, такие как инструменты для измерения производительности и сторонние инструменты, также будут получать замаскированную версию, что повышает безопасность.

Например, если вы используете реального пользователя из продакшена и вам нужно ввести пароль, который вы хотите замаскировать, теперь это можно сделать следующим образом:

```ts
  async enterPassword(userPassword) {
    const passwordInputElement = $('Password');

    // Get focus
    await passwordInputElement.click();

    await passwordInputElement.setValue(userPassword, { mask: true });
  }
```

Приведённый выше код скроет текстовое значение в логах WDIO следующим образом:

Пример логов:
```text
INFO webdriver: DATA { text: "**MASKED**" }
```

Репортеры, такие как Allure, и сторонние инструменты, такие как Percy от BrowserStack, также будут обрабатывать замаскированную версию.
В сочетании с подходящей версией Appium логи Appium также не будут содержать ваших конфиденциальных данных.

:::info

Ограничения:
  - В Appium дополнительные плагины могут допускать утечку данных, даже если мы запрашиваем маскирование информации.
  - Облачные провайдеры могут использовать прокси для логирования HTTP, что позволяет обойти установленный механизм маскирования.
  - Команда `getValue` не поддерживается. Более того, при использовании на том же элементе она может раскрыть значение, которое должно было быть замаскировано при использовании `addValue` или `setValue`.

Минимально необходимая версия:
 - WDIO v9.15.0
 - Appium v3.0.0

:::

#### Маскирование в логах WDIO

С помощью конфигурации `maskingPatterns` можно замаскировать конфиденциальную информацию в логах WDIO. Однако логи Appium при этом не охватываются.

Например, если вы используете облачного провайдера и уровень логирования info, то вы почти наверняка допустите «утечку» ключа пользователя, как показано ниже:

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=myCloudSecretExposedKey --spec myTest.test.ts
```

Чтобы этого избежать, можно передать регулярное выражение `'--key=([^ ]*)'`, и теперь в логах вы увидите

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=**MASKED** --spec myTest.test.ts
```

Этого можно добиться, указав регулярное выражение в поле `maskingPatterns` конфигурации.
  - Для нескольких регулярных выражений используйте одну строку со значениями, разделёнными запятыми.
  - Подробнее о шаблонах маскирования см. в [разделе Masking Patterns в README WDIO Logger](https://github.com/webdriverio/webdriverio/blob/main/packages/wdio-logger/README.md#masking-patterns).

```ts
export const config: WebdriverIO.Config = {
    specs: [...],
    capabilities: [{...}],
    services: ['lighthouse'],

    /**
     * test configurations
     */
    logLevel: 'info',
    maskingPatterns: '/--key=([^ ]*)/',
    framework: 'mocha',
    outputDir: __dirname,

    reporters: ['spec'],

    mochaOpts: {
        ui: 'bdd',
        timeout: 60000
    }
}
```

:::info
Минимально необходимая версия:
 - WDIO v9.15.0
:::

:::warning
Для секретов, передаваемых через командную строку, маскирование может не сработать, поскольку файл wdio.conf.ts обрабатывается позже в цикле выполнения. В таких случаях настоятельно рекомендуется использовать переменные окружения — это гораздо безопаснее.
:::

#### Отключение логгеров WDIO

Ещё один способ предотвратить логирование конфиденциальных данных — понизить уровень логирования, перевести его в режим silent или отключить логгер.
Это можно сделать следующим образом:

```ts
import logger from '@wdio/logger';

/**
  * Устанавливает уровень логгера WDIO в 'silent' перед *выполнением промиса, что помогает скрыть конфиденциальную информацию в логах.
 */
export const withSilentLogger = async <T>(promise: () => Promise<T>): Promise<T> => {
  const webdriverLogLevel = driver.options.logLevel ?? 'error';

  try {
    logger.setLevel('webdriver', 'silent');
    return await promise();
  } finally {
    logger.setLevel('webdriver', webdriverLogLevel);
  }
};
```

### Сторонние решения

#### Appium
Appium предлагает собственное решение для маскирования; см. [Log filter](https://appium.io/docs/en/latest/guides/log-filters/)
 - Использовать их решение может быть непросто. Один из способов, если это возможно, — передавать в строке токен, например `@mask@`, и использовать его в качестве регулярного выражения
 - В некоторых версиях Appium значения также логируются посимвольно через запятую, поэтому нужно быть внимательными.
 - К сожалению, BrowserStack не поддерживает это решение, но оно всё равно полезно при локальном запуске

Используя упомянутый ранее пример с `@mask@`, можно применить следующий JSON-файл с именем `appiumMaskLogFilters.json`
```json
[
  {
    "pattern": "@mask@(.*)",
    "flags": "s",
    "replacer": "**MASKED**"
  },
  {
    "pattern": "\\[(\\\"@\\\",\\\"m\\\",\\\"a\\\",\\\"s\\\",\\\"k\\\",\\\"@\\\",\\S+)\\]",
    "flags": "s",
    "replacer": "[*,*,M,A,S,K,E,D,*,*]"
  }
]
```

Затем передайте имя JSON-файла в поле `logFilters` конфигурации сервиса appium:
```ts
import { AppiumServerArguments, AppiumServiceConfig } from '@wdio/appium-service';
import { ServiceEntry } from '@wdio/types/build/Services';

const appium = [
  'appium',
  {
    args: {
      log: './logs/appium.log',
      logFilters: './appiumMaskLogFilters.json',
    } satisfies AppiumServerArguments,
  } satisfies AppiumServiceConfig,
] satisfies ServiceEntry;
```

#### BrowserStack

BrowserStack также предоставляет определённые возможности маскирования для скрытия данных; см. [hide sensitive data](https://www.browserstack.com/docs/automate/selenium/hide-sensitive-data)
 - К сожалению, это решение работает по принципу «всё или ничего», поэтому будут замаскированы все текстовые значения указанных команд.
