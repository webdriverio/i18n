WebdriverIO предлагает тесную интеграцию с CI-системами, такими как [Jenkins](https://jenkins-ci.org). С помощью репортера `junit` вы можете легко отлаживать свои тесты, а также отслеживать результаты тестирования. Интеграция довольно проста.

1. Установите тестовый репортер `junit`: `$ npm install @wdio/junit-reporter --save-dev`)
1. Обновите конфигурацию, чтобы сохранять результаты XUnit там, где Jenkins сможет их найти,
    (и укажите репортер `junit`):

```js
// wdio.conf.js
module.exports = {
    // ...
    reporters: [
        'dot',
        ['junit', {
            outputDir: './'
        }]
    ],
    // ...
}
```

Какой фреймворк выбрать — решать вам. Отчёты будут похожими.
В этом руководстве мы будем использовать Jasmine.

После того как вы напишете пару тестов, вы можете настроить новую задачу (job) в Jenkins. Задайте ей имя и описание:

![Name And Description](/img/jenkins/jobname.png "Name And Description")

Затем убедитесь, что она всегда получает самую свежую версию вашего репозитория:

![Jenkins Git Setup](/img/jenkins/gitsetup.png "Jenkins Git Setup")

**Теперь важная часть:** создайте шаг `build` для выполнения shell-команд. Шаг `build` должен собирать ваш проект. Поскольку этот демонстрационный проект тестирует только внешнее приложение, собирать ничего не нужно. Просто установите node-зависимости и выполните команду `npm test` (которая является псевдонимом для `node_modules/.bin/wdio test/wdio.conf.js`).

Если вы установили плагин, например AnsiColor, но логи всё ещё не окрашены, запускайте тесты с переменной окружения `FORCE_COLOR=1` (например, `FORCE_COLOR=1 npm test`).

![Build Step](/img/jenkins/runjob.png "Build Step")

После выполнения тестов вы захотите, чтобы Jenkins отслеживал ваш отчёт XUnit. Для этого необходимо добавить послесборочное действие (post-build action) под названием _"Publish JUnit test result report"_.

Вы также можете установить внешний плагин XUnit для отслеживания отчётов. Плагин JUnit входит в базовую установку Jenkins, и на данный момент его вполне достаточно.

Согласно файлу конфигурации, отчёты XUnit будут сохраняться в корневой директории проекта. Эти отчёты представляют собой XML-файлы. Поэтому всё, что нужно сделать для отслеживания отчётов, — это указать Jenkins на все XML-файлы в корневой директории:

![Post-build Action](/img/jenkins/postjob.png "Post-build Action")

Вот и всё! Теперь вы настроили Jenkins для запуска задач WebdriverIO. Ваша задача будет предоставлять подробные результаты тестов с графиками истории, информацией о трассировке стека для неудачных задач и списком команд с полезной нагрузкой (payload), которые использовались в каждом тесте.
