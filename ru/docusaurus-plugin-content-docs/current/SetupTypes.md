WebdriverIO можно использовать для различных целей. Он реализует API протокола WebDriver и может запускать браузер в автоматизированном режиме. Фреймворк спроектирован для работы в любой произвольной среде и для любого типа задач. Он не зависит от каких-либо сторонних фреймворков и для работы требует только Node.js.

## Привязки к протоколу

Для базового взаимодействия с протоколом WebDriver WebdriverIO использует собственные привязки к протоколу, основанные на NPM-пакете [`webdriver`](https://www.npmjs.com/package/webdriver):

```js reference useHTTPS
https://github.com/webdriverio/example-recipes/blob/e8b147e88e7a38351b0918b4f7efbd9ae292201d/setup/webdriver.js#L5-L20
```

Все [команды протокола](api/webdriver) возвращают необработанный ответ от драйвера автоматизации. Пакет очень легковесный, и в нём __нет__ никакой умной логики, такой как автоматические ожидания, для упрощения работы с протоколом.

Команды протокола, применяемые к экземпляру, зависят от первоначального ответа драйвера при создании сессии. Например, если ответ указывает, что была запущена мобильная сессия, пакет применяет команды Appium к прототипу экземпляра.

Дополнительную информацию об интерфейсе пакета `webdriver` см. в разделе [Modules API](/docs/api/modules).

[WebdriverIO DevTools](/docs/devtools) не является протоколом автоматизации. Это пользовательский интерфейс для отладки, позволяющий наблюдать за выполнением в реальном времени и затем воспроизводить трассировки.

## Автономный режим

Чтобы упростить взаимодействие с протоколом WebDriver, пакет `webdriverio` реализует множество команд поверх протокола (например, команду [`dragAndDrop`](api/element/dragAndDrop)) и ключевые концепции, такие как [умные селекторы](selectors) или [автоматические ожидания](autowait). Пример выше можно упростить следующим образом:

```js reference useHTTPS
https://github.com/webdriverio/example-recipes/blob/e8b147e88e7a38351b0918b4f7efbd9ae292201d/setup/standalone.js#L2-L19
```

Использование WebdriverIO в автономном режиме по-прежнему даёт доступ ко всем командам протокола, но при этом предоставляет расширенный набор дополнительных команд для более высокоуровневого взаимодействия с браузером. Это позволяет интегрировать данный инструмент автоматизации в ваш собственный (тестовый) проект для создания новой библиотеки автоматизации. Популярными примерами являются [Oxygen](https://github.com/oxygenhq/oxygen) или [CodeceptJS](http://codecept.io). Вы также можете писать простые Node-скрипты для сбора контента из интернета (или для чего-либо ещё, что требует запущенного браузера).

Если не заданы конкретные параметры, WebdriverIO всегда будет пытаться загрузить и настроить драйвер браузера, соответствующий свойству `browserName` в ваших capabilities. В случае Chrome и Firefox он также может установить сами браузеры, в зависимости от того, сможет ли он найти соответствующий браузер на машине.

Дополнительную информацию об интерфейсах пакета `webdriverio` см. в разделе [Modules API](/docs/api/modules).

## WDIO Testrunner

Тем не менее основное назначение WebdriverIO — сквозное (end-to-end) тестирование в больших масштабах. Поэтому мы реализовали тестовый раннер, который помогает создавать надёжный набор тестов, легко читаемый и поддерживаемый.

Тестовый раннер решает многие проблемы, характерные для работы с обычными библиотеками автоматизации. Во-первых, он организует запуски тестов и распределяет тестовые спецификации так, чтобы тесты выполнялись с максимальным параллелизмом. Он также управляет сессиями и предоставляет множество функций, помогающих отлаживать проблемы и находить ошибки в тестах.

Вот тот же пример, что и выше, написанный в виде тестовой спецификации и выполняемый WDIO:

```js reference useHTTPS
https://github.com/webdriverio/example-recipes/blob/e8b147e88e7a38351b0918b4f7efbd9ae292201d/setup/testrunner.js
```

Тестовый раннер является абстракцией над популярными тестовыми фреймворками, такими как Mocha, Jasmine или Cucumber. Чтобы запустить тесты с помощью тестового раннера WDIO, обратитесь к разделу [Начало работы](gettingstarted) для получения дополнительной информации.

Дополнительную информацию об интерфейсе пакета тестового раннера `@wdio/cli` см. в разделе [Modules API](/docs/api/modules).
