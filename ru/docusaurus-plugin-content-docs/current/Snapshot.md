Тесты со снапшотами могут быть очень полезны для одновременной проверки множества аспектов вашего компонента или логики. В WebdriverIO вы можете делать снапшоты любого произвольного объекта, а также DOM-структуры WebElement или результатов команд WebdriverIO.

Как и другие тестовые фреймворки, WebdriverIO делает снапшот переданного значения, а затем сравнивает его с эталонным файлом снапшота, который хранится рядом с тестом. Тест завершится неудачей, если два снапшота не совпадают: либо изменение является неожиданным, либо эталонный снапшот необходимо обновить до новой версии результата.

:::info Кроссплатформенная поддержка

Эти возможности работы со снапшотами доступны как при запуске end-to-end тестов в среде Node.js, так и при запуске [модульных и компонентных](/docs/component-testing) тестов в браузере или на мобильных устройствах.

:::

## Использование снапшотов
Чтобы сделать снапшот значения, вы можете использовать `toMatchSnapshot()` из API [`expect()`](/docs/api/expect-webdriverio):

```ts
import { browser, expect } from '@wdio/globals'

it('can take a DOM snapshot', () => {
    await browser.url('https://guinea-pig.webdriver.io/')
    await expect($('.findme')).toMatchSnapshot()
})
```

При первом запуске этого теста WebdriverIO создаст файл снапшота, который выглядит так:

```js
// Snapshot v1

exports[`main suite 1 > can take a DOM snapshot 1`] = `"<h1 class="findme">Test CSS Attributes</h1>"`;
```

Артефакт снапшота следует коммитить вместе с изменениями кода и проверять в рамках процесса код-ревью. При последующих запусках тестов WebdriverIO будет сравнивать отрисованный результат с предыдущим снапшотом. Если они совпадают, тест пройдёт. Если нет, то либо тестовый раннер обнаружил в вашем коде ошибку, которую нужно исправить, либо реализация изменилась и снапшот необходимо обновить.

Чтобы обновить снапшот, передайте флаг `-s` (или `--updateSnapshot`) команде `wdio`, например:

```sh
npx wdio run wdio.conf.js -s
```

__Примечание:__ если вы запускаете тесты в нескольких браузерах параллельно, создаётся и используется для сравнения только один снапшот. Если вы хотите иметь отдельный снапшот для каждой capability, пожалуйста, [создайте issue](https://github.com/webdriverio/webdriverio/issues/new?assignees=&labels=Idea+%F0%9F%92%A1%2CNeeds+Triaging+%E2%8F%B3&projects=&template=feature-request.yml&title=%5B%F0%9F%92%A1+Feature%5D%3A+%3Ctitle%3E) и расскажите нам о вашем сценарии использования.

## Встроенные снапшоты

Аналогичным образом вы можете использовать `toMatchInlineSnapshot()`, чтобы хранить снапшот прямо в файле теста.

```ts
import { expect, $ } from '@wdio/globals'

it('can take inline DOM snapshots', () => {
  const elem = $('.container')
  await expect(elem.getCSSProperty()).toMatchInlineSnapshot()
})
```

Вместо создания файла снапшота Vitest напрямую изменит файл теста, чтобы обновить снапшот в виде строки:

```ts
import { expect, $ } from '@wdio/globals'

it('can take inline DOM snapshots', () => {
    const elem = $('.container')
    await expect(elem.getCSSProperty()).toMatchInlineSnapshot(`
        {
            "parsed": {
                "alpha": 0,
                "hex": "#000000",
                "rgba": "rgba(0,0,0,0)",
                "type": "color",
            },
            "property": "background-color",
            "value": "rgba(0,0,0,0)",
        }
    `)
})
```

Это позволяет видеть ожидаемый результат сразу, без переключения между разными файлами.

## Визуальные снапшоты

Создание DOM-снапшота элемента может быть не лучшей идеей, особенно если DOM-структура слишком большая и содержит динамические свойства элементов. В таких случаях рекомендуется полагаться на визуальные снапшоты элементов.

Чтобы включить визуальные снапшоты, добавьте `@wdio/visual-service` в вашу конфигурацию. Вы можете следовать инструкциям по настройке в [документации](/docs/visual-testing#installation) по визуальному тестированию.

После этого вы можете сделать визуальный снапшот с помощью `toMatchElementSnapshot()`, например:

```ts
import { expect, $ } from '@wdio/globals'

it('can take inline DOM snapshots', () => {
  const elem = $('.container')
  await expect(elem.getCSSProperty()).toMatchInlineSnapshot()
})
```

Затем изображение сохраняется в каталоге эталонов (baseline). Подробнее см. в разделе [Визуальное тестирование](/docs/visual-testing).
