При использовании команды, которая напрямую взаимодействует с элементом, WebdriverIO автоматически ожидает, пока элемент станет видимым и доступным для взаимодействия, поэтому при использовании таких команд (например, click, setValue и т. д.) ручные ожидания не нужны.
Элемент считается доступным для взаимодействия, когда выполнены условия для [isClickable](https://webdriver.io/docs/api/element/isClickable).

Хотя WebdriverIO автоматически ожидает, пока элементы станут доступными для взаимодействия, существуют редкие случаи, в которых может потребоваться ручное ожидание. Для таких редких случаев мы предлагаем команды, например [`waitForDisplayed`](/docs/api/element/waitForDisplayed).


## Неявные тайм-ауты (не рекомендуется)

Хотя мы не рекомендуем их использовать, протокол WebDriver предоставляет [неявные тайм-ауты](https://w3c.github.io/webdriver/#timeouts), которые позволяют указать, как долго драйвер должен ожидать появления элемента. По умолчанию этот тайм-аут равен `0`, поэтому драйвер сразу возвращает ошибку `no such element`, если элемент не удалось найти на странице. Увеличение этого тайм-аута с помощью [`setTimeout`](/docs/api/browser/setTimeout) заставит драйвер ожидать и повысит вероятность того, что элемент в конечном итоге появится.

:::note

Подробнее о тайм-аутах WebDriver и тайм-аутах, связанных с фреймворком, читайте в [руководстве по тайм-аутам](/docs/timeouts)

:::
