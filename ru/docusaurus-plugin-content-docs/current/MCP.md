## Что он умеет?

WebdriverIO MCP — это **сервер Model Context Protocol (MCP)**, который позволяет ИИ-ассистентам автоматизировать веб-браузеры и мобильные приложения и взаимодействовать с ними.

### Почему WebdriverIO MCP?

-   **Mobile-First**: В отличие от MCP-серверов, работающих только с браузерами, WebdriverIO MCP поддерживает автоматизацию нативных приложений iOS и Android через Appium
-   **Кроссплатформенные селекторы**: Интеллектуальное обнаружение элементов автоматически генерирует несколько стратегий локаторов (accessibility ID, XPath, UiAutomator, iOS predicates)
-   **Экосистема WebdriverIO**: Построен на проверенном временем фреймворке WebdriverIO с его богатой экосистемой сервисов и репортеров

Он предоставляет единый интерфейс для:

-   🖥️ **Десктопных браузеров** (Chrome, Firefox, Edge, Safari, в обычном или headless-режиме)
-   📱 **Нативных мобильных приложений** (симуляторы iOS / эмуляторы Android / реальные устройства через Appium)
-   📳 **Гибридных мобильных приложений** (переключение контекстов Native + WebView через Appium)
-   ☁️ **Облачных устройств** (облака реальных устройств и браузеров BrowserStack, Sauce Labs, TestMu)

посредством пакета [`@wdio/mcp`](https://www.npmjs.com/package/@wdio/mcp).

Это позволяет ИИ-ассистентам:

-   **Запускать браузеры и управлять ими** с настраиваемыми размерами, headless-режимом и опциональной начальной навигацией
-   **Переходить по веб-сайтам** и взаимодействовать с элементами (клик, ввод текста, прокрутка)
-   **Анализировать содержимое страницы** с помощью дерева доступности и обнаружения видимых элементов с поддержкой пагинации
-   **Делать скриншоты** с автоматической оптимизацией (изменение размера, сжатие до максимум 1 МБ)
-   **Управлять cookies** для работы с сессиями
-   **Управлять мобильными устройствами**, включая жесты (тап, свайп, перетаскивание)
-   **Переключать контексты** в гибридных приложениях между native и webview
-   **Выполнять скрипты** — JavaScript в браузерах, мобильные команды Appium на устройствах
-   **Работать с функциями устройства**, такими как поворот, клавиатура, геолокация
-   и многое другое, см. [Инструменты](./mcp/tools) и параметры [Конфигурации](./mcp/configuration)

:::info

ПРИМЕЧАНИЕ для мобильных приложений
Для мобильной автоматизации требуется запущенный сервер Appium с установленными соответствующими драйверами. Инструкции по настройке см. в разделе [Предварительные требования](#prerequisites).

:::

## Установка

Самый простой способ использовать `@wdio/mcp` — через npx без локальной установки:

```sh
npx @wdio/mcp
```

Или установите его глобально:

```sh
npm install -g @wdio/mcp
```

## Использование с Claude

Чтобы использовать WebdriverIO MCP с Claude, измените файл конфигурации:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

После добавления конфигурации перезапустите вашу среду. Инструменты WebdriverIO MCP станут доступны для задач автоматизации браузеров и мобильных устройств.

### Использование с Claude Code

Claude Code автоматически обнаруживает MCP-серверы. Вы можете настроить его в файле `.claude/settings.json` или `.mcp.json` вашего проекта.

Или добавьте его глобально в .claude.json, выполнив:
```bash
claude mcp add --transport stdio wdio-mcp -- npx -y @wdio/mcp
```
Проверьте это, выполнив команду `/mcp` внутри Claude Code.

## Предварительные требования

### Автоматизация браузера

-   Должен быть установлен **Chrome, Firefox, Edge или Safari**
-   WebdriverIO автоматически управляет драйверами

### Мобильная автоматизация

#### iOS

1. **Установите Xcode** из Mac App Store
2. **Установите Xcode Command Line Tools**:
   ```sh
   xcode-select --install
   ```
3. **Установите Appium**:
   ```sh
   npm install -g appium
   ```
4. **Установите драйвер XCUITest**:
   ```sh
   appium driver install xcuitest
   ```
5. **Запустите сервер Appium**:
   ```sh
   appium
   ```
6. **Для симуляторов**: откройте Xcode → Window → Devices and Simulators, чтобы создавать симуляторы и управлять ими
7. **Для реальных устройств**: вам понадобится UDID устройства (40-символьный уникальный идентификатор)

#### Android

1. **Установите Android Studio** и настройте Android SDK
2. **Задайте переменные окружения**:
   ```sh
   export ANDROID_HOME=$HOME/Library/Android/sdk
   export PATH=$PATH:$ANDROID_HOME/emulator
   export PATH=$PATH:$ANDROID_HOME/platform-tools
   ```
3. **Установите Appium**:
   ```sh
   npm install -g appium
   ```
4. **Установите драйвер UiAutomator2**:
   ```sh
   appium driver install uiautomator2
   ```
5. **Запустите сервер Appium**:
   ```sh
   appium
   ```
6. **Создайте эмулятор** через Android Studio → Virtual Device Manager
7. **Запустите эмулятор** перед выполнением тестов

## Архитектура

### Как это работает

WebdriverIO MCP выступает мостом между ИИ-ассистентами и автоматизацией браузеров/мобильных устройств:

```
┌─────────────────┐     MCP Protocol      ┌─────────────────┐
│  Claude Desktop │ ◄──────────────────►  │    @wdio/mcp    │
│  or Claude Code │   (stdio or HTTP)     │     Server      │
└─────────────────┘                       └────────┬────────┘
                                                   │
                                             WebDriverIO API
                                                   │
                    ┌──────────────────────────────┼──────────────────────────────┐
                    │                              │                              │
            ┌───────▼───────┐             ┌───────▼───────┐             ┌───────▼───────┐
            │    Browser    │             │    Appium     │             │   Cloud        │
            │ (local/CDP)   │             │  (iOS/Android)│             │   Providers    │
            └───────────────┘             └───────────────┘             └───────────────┘
```

### Управление сессиями

-   **Модель одной сессии**: одновременно может быть активна только одна сессия браузера ИЛИ приложения
-   **Состояние сессии** сохраняется глобально между вызовами инструментов
-   **Автоотключение**: сессии с сохраняемым состоянием (`noReset: true`) автоматически отключаются при закрытии

### Обнаружение элементов

#### Браузер (Web)

-   Использует оптимизированный браузерный скрипт для поиска всех видимых интерактивных элементов
-   Возвращает элементы с CSS-селекторами, ID, классами и ARIA-информацией
-   Поддерживает фильтрацию по вьюпорту и пагинацию

#### Мобильные устройства (нативные приложения)

-   Использует эффективный парсинг XML-исходника страницы (2 HTTP-запроса против 600+ при традиционных запросах)
-   Платформозависимая классификация элементов для Android и iOS
-   Генерирует несколько стратегий локаторов для каждого элемента:
    -   Accessibility ID (кроссплатформенный, наиболее стабильный)
    -   Атрибут Resource ID / Name
    -   Сопоставление по тексту / метке
    -   XPath (полный и упрощённый)
    -   UiAutomator (Android) / Predicates (iOS)

## Синтаксис селекторов

MCP-сервер поддерживает несколько стратегий селекторов. Подробную документацию см. в разделе [Селекторы](./mcp/selectors).

### Web (CSS/XPath)

```
# CSS-селекторы
button.my-class
#element-id
[data-testid="login"]

# XPath
//button[@class='submit']
//a[contains(text(), 'Click')]

# Текстовые селекторы (специфичные для WebdriverIO)
button=Exact Button Text
a*=Partial Link Text
```

### Мобильные (кроссплатформенные)

```
# Accessibility ID (рекомендуется — работает на iOS и Android)
~loginButton

# Android UiAutomator
android=new UiSelector().text("Login")

# iOS Predicate String
-ios predicate string:label == "Login"

# iOS Class Chain
-ios class chain:**/XCUIElementTypeButton[`label == "Login"`]

# XPath (работает на обеих платформах)
//android.widget.Button[@text="Login"]
//XCUIElementTypeButton[@label="Login"]
```

## Автоматическая обработка

### Разрешения

По умолчанию MCP-сервер автоматически предоставляет разрешения приложению (`autoGrantPermissions: true`), избавляя от необходимости вручную обрабатывать диалоги разрешений во время автоматизации.

### Системные уведомления

Системные уведомления (например, «Разрешить уведомления?») по умолчанию принимаются автоматически (`autoAcceptAlerts: true`). Вместо этого можно настроить их отклонение с помощью `autoDismissAlerts: true`.

## Транспорт

По умолчанию сервер работает через **stdio** (запускается ИИ-клиентом как подпроцесс). Для клиентов, которые не поддерживают MCP на основе подпроцессов (llama.cpp, безопасный режим Codex), используйте **HTTP-транспорт**:

```bash
npx @wdio/mcp --http --port 3000
```

Полный список параметров, включая `--allowedHosts` и `--allowedOrigins`, см. в разделе [Транспорт](./mcp/transport).

## Оптимизация производительности

MCP-сервер оптимизирован для эффективного взаимодействия с ИИ-ассистентами:

-   **Формат TOON**: использует Token-Oriented Object Notation для минимального расхода токенов
-   **Парсинг XML**: обнаружение мобильных элементов использует 2 HTTP-запроса (против 600+ при традиционном подходе)
-   **Сжатие скриншотов**: изображения автоматически сжимаются до максимум 1 МБ
-   **Фильтрация по вьюпорту**: по умолчанию возвращаются только видимые элементы
-   **Пагинация**: большие списки элементов можно разбивать на страницы для уменьшения размера ответа

## Обработка ошибок

Все инструменты спроектированы с надёжной обработкой ошибок:

-   Ошибки возвращаются в виде текстового содержимого (никогда не выбрасываются), что обеспечивает стабильность протокола MCP
-   Информативные сообщения об ошибках помогают диагностировать проблемы
-   Состояние сессии сохраняется даже при сбое отдельных операций

-   Проверка согласованности на разных платформах

## Устранение неполадок

### Браузер не запускается

-   Убедитесь, что целевой браузер установлен
-   Проверьте, что порт отладки по умолчанию (9222) не занят другим процессом
-   Попробуйте headless-режим, если возникают проблемы с отображением

### Не удалось подключиться к Appium

-   Убедитесь, что сервер Appium запущен (`appium`)
-   Проверьте хост и порт Appium в `appiumConfig`
-   Убедитесь, что установлен соответствующий драйвер (`appium driver list`)

### Проблемы с симулятором iOS

-   Убедитесь, что Xcode установлен и обновлён
-   Проверьте, что симуляторы доступны (`xcrun simctl list devices`)
-   Для реальных устройств проверьте правильность UDID

### Проблемы с эмулятором Android

-   Убедитесь, что Android SDK правильно настроен
-   Проверьте, что эмулятор запущен (`adb devices`)
-   Проверьте, что задана переменная окружения `ANDROID_HOME`
