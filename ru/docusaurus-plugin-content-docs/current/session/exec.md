`exec` выполняет код WebdriverIO в открытой сессии. Используйте его, когда шаг сложнее одиночного `click` или `fill`, а также для всех проверок.

```sh
npx wdio session exec -e "await browser.getTitle()"
npx wdio session <<'JS'
await $('aria/Cart (1)').waitForDisplayed()
JS
```

Всегда используйте `await` для команд. `$` возвращает один элемент и выбрасывает ошибку, если он не найден. `$$` возвращает список. Синхронного режима и `browser.element` нет.

Объявленные вами имена остаются доступными в следующем `exec`. `import` верхнего уровня загружается из каталога проекта.

## Проверки

Размещайте проверки в `exec` с помощью `expect-webdriverio`. Установите его в свой проект. Без него `expect(...)` завершится ошибкой с подсказкой по установке.

```sh
npx wdio session exec -e "await expect($('h1')).toHaveText('Cart')"
```

Используйте `visual check <tag>`, когда нужно проверить, как выглядит экран. Для этой команды требуется `@wdio/visual-service`:

```sh
npx wdio session visual check cart
```

`visual accept cart` копирует последнее фактическое изображение для этого тега поверх эталонного. Более старые изображения с тем же префиксом тега не копируются.

## Когда лучше использовать сокращённую команду

`click`, `fill`, `type`, `press` и `tap` короче, чем `exec`, для одного взаимодействия, и они выводят выполненную строку WebdriverIO. Предпочитайте их, используя ссылку из последнего [снимка](/docs/session/snapshots). Используйте `exec` для ожиданий, проверок и всего, что требует более одной команды.
