Сделайте снапшот, прежде чем кликать. Снапшот — это список элементов, с которыми можно взаимодействовать. Каждая интерактивная строка заканчивается ссылкой (ref), например `[ref=e3]`.

```sh
npx wdio session open chrome http://localhost:3000
npx wdio session snapshot --interactive
```

Строка выглядит так: `button "Add to cart" [ref=e3]`. Следующая команда использует эту ссылку:

```sh
npx wdio session click e3
```

Ссылки берутся из последнего снапшота. После навигации сделайте снапшот снова. Устаревшая ссылка завершается ошибкой `REF_STALE`. Неизвестная ссылка завершается ошибкой `REF_NOT_FOUND`.

:::caution Экспериментальная функция

Текстовый формат снапшота и структура, которую для него выводит `--json`, являются экспериментальными: минорный релиз может их изменить, например, чтобы использовать общий движок снапшотов с [трассировкой DevTools](/docs/devtools/wdio/trace-mode). Синтаксис ссылок (`e3`, `@e3`), действия, принимающие ссылку, и код, который они записывают, остаются стабильными. Берите ссылки из снапшота и не разбирайте остальное содержимое его строк.

:::

## Что запускать

| Команда | Для чего использовать |
| --- | --- |
| `snapshot --interactive` | Элементы, с которыми можно взаимодействовать, каждый со ссылкой |
| `find "Add to cart"` | Каждое совпадение вместе с окружающим его узлом, например целым элементом списка, чтобы значение рядом с совпадением тоже попало в вывод. `-A`, `-B` и `-C` выводят простой построчный контекст, как grep |
| `diff` | Что изменилось с предыдущего снапшота |
| `screenshot` | Макет страницы. Пропустите, если снапшот отвечает на вопрос |
| `source` | HTML страницы или нативный XML |

`snapshot` без `--interactive` включает больше узлов дерева. Предпочитайте `--interactive`, когда собираетесь кликнуть или ввести текст.

## Что изменило действие

В веб-сессии `open` выводит интерактивный снапшот открытой страницы, а каждое действие, которое может изменить страницу (`click`, `fill`, `type`, `press`, `select`, `check`, `navigate`, `frame`, …), сообщает, что изменилось:

```text
Clicked e6 (button "Start subscription")
Changes:
+ - status "Subscription started. Confirmation code: 4F2A9C"
```

Если действие открыло вкладку, отчёт сообщает об этом (`Opened a new tab [1]: https://…`); сессия остаётся на текущей вкладке, пока вы не выполните `tabs switch`. Если вместо сайта открылась проверка на бота (Cloudflare, DataDome, Akamai, …), отчёт также сообщает об этом — один раз на страницу. Сессия не пытается её обойти; в headless-браузере она предлагает переоткрыть страницу с `--headed`.

На той же странице вы получаете новые или изменённые строки с их ссылками, включая неинтерактивный текст, как статус выше. После навигации вы получаете интерактивные элементы новой страницы, а для большой страницы — однострочную сводку, указывающую на `find`. Поэтому отдельный `snapshot` после действия нужен редко. Установите `WDIO_SESSION_CHANGES=0`, чтобы отключить отчёт, и передайте `open --no-snapshot`, чтобы пропустить снапшот после `open`.

## Фреймы

В сессии WebDriver BiDi снапшот показывает содержимое iframe страницы, включая кросс-доменные, под тем iframe, в котором оно находится:

```text
- iframe "Payment" [ref=e4]
  - textbox "Card number" [ref=e5]
  - button "Pay" [ref=e6]
```

Действия по этим ссылкам входят во фрейм, выполняются и возвращаются на страницу, и выводимый код делает то же самое. Показывается до пяти iframe, каждый обрезается до 300 элементов; `frame e4` и `snapshot` показывают фрейм целиком, если он был обрезан. Iframe площадью менее 100 квадратных пикселей, например пиксели отслеживания, не включаются.

## Shadow DOM и кликабельные элементы без роли

С WebDriver BiDi снапшот также охватывает закрытые shadow root, а элементы, у которых есть только обработчик клика (иконка, подключённая через `addEventListener`), получают ссылку. У такого элемента нет доступного имени, поэтому снапшот описывает его иначе:

```text
- generic [ref=e8] (icon 3 of 3 in "Invoice #1002 · Contoso Ltd · $860.00")
```

На Android, iOS, macOS и Windows снапшот строится из page source Appium. Два элемента управления с общим accessibility id остаются отдельными ссылками, если остальные части их селекторов различаются. `snapshot --scope e3` ограничивает дерево этой ссылкой.

## Повторяющиеся элементы управления

Когда несколько элементов управления имеют одинаковые роль и имя, например кнопка «Add to cart» в каждой строке таблицы товаров, строка ссылки заканчивается на `∈ "<text>"` — текст строки, карточки или элемента списка, который содержит этот элемент управления и никакой другой с тем же именем:

```text
- button "Add to cart" [ref=e9] ∈ "Desk lamp · Brass · In stock · $49.00"
```

Текст обрезается до 80 символов. Элемент управления, контейнером которого является ориентир страницы (landmark) — например, ссылка «Sign in» и в шапке, и в подвале, — такой пометки не получает. Метка видимого элемента формы не выводится: имя несёт сам элемент управления.

## Нативные касания

Веб-сессии используют `click`. Мобильные и нативные десктопные сессии используют `tap` с той же ссылкой:

```sh
npx wdio session open android --app ./shop.apk
npx wdio session snapshot --interactive
npx wdio session tap e3
```

## Устранение неполадок

| Сообщение | Что делать |
| --- | --- |
| `REF_STALE` | Элемент из последнего снапшота исчез. Выполните `snapshot` и используйте новую ссылку. |
| `REF_NOT_FOUND` | Этого id никогда не было в данной сессии. Ссылка в вашей команде не соответствует последнему снапшоту. |
| `NO_MATCH` | `find` не нашёл этот текст. Сделайте снапшот и прочитайте имена, которые действительно присутствуют. |
| `NOT_EDITABLE` | Цель `fill` не является редактируемым полем и не содержит внутри ровно одного редактируемого поля (или за `aria-controls`/`aria-owns`/меткой). Выполните `snapshot --scope <target>` и заполните поле по его ссылке. |
