Файл `wdio.conf.ts` — это основной конфигурационный файл любого проекта WebdriverIO. Именно здесь вы определяете, где запускаются тесты, какие тестовые фреймворки используются, а также задаёте необходимые `capabilities`, чтобы Appium мог корректно инициализировать Flutter-приложение.

:::warning
`appium-flutter-driver` работает иначе, чем традиционные нативные драйверы (такие как `UiAutomator2` или `XCUITest`). Он взаимодействует с тестовым расширением Flutter (`flutter_driver`) через специализированный протокол. Из-за этого стандартные нативные команды автоматизации могут работать иначе или строго требовать использования `appium-flutter-finder`.

Чтобы в полной мере понять ограничения, поддерживаемые команды и расширения протокола, обратитесь к официальному репозиторию инструмента: [Appium Flutter Driver на GitHub](https://github.com/appium/appium-flutter-driver).
:::

### Настройка capabilities (Android и iOS)

```typescript
export const config: WebdriverIO.Config = {
    // ... другие настройки wdio.conf.ts (runner, specs и т. д.)
    

    services: [
        ['appium', {
            // WebdriverIO управляет жизненным циклом сервера Appium
            args: {},
            command: 'appium'
        }]
    ],

    capabilities: [
        // ==========================================
        // КОНФИГУРАЦИЯ ANDROID
        // ==========================================
        {
            'platformName': 'Android',
            'appium:automationName': 'Flutter', // Задаёт обязательное использование драйвера Flutter
            'appium:deviceName': 'Android_Emulator', // Имя вашего настроенного эмулятора или реального устройства
            // ЗАМЕЧАНИЕ О ПУТИ (см. примечание об операционных системах ниже)
            'appium:app': './build/app/outputs/flutter-apk/app-debug.apk', 
            'appium:autoGrantPermissions': true
        },
        
        // ==========================================
        // КОНФИГУРАЦИЯ IOS (требуется macOS)
        // ==========================================
        {
            'platformName': 'iOS',
            'appium:automationName': 'Flutter', // Задаёт обязательное использование драйвера Flutter
            'appium:deviceName': 'iPhone Simulator', // Имя симулятора iOS или реального устройства
            'appium:platformVersion': '17.2', // Измените на целевую версию ОС
            // ЗАМЕЧАНИЕ О ПУТИ (см. примечание об операционных системах ниже)
            // Используйте .app для iOS Simulator или .ipa для реальных устройств iOS
            'appium:app': './ios/build/Build/Products/Debug-iphonesimulator/Runner.app',
            'appium:noReset': false
        }
    ],

    // ... остальная конфигурация
};
```

### Важные замечания о путях к файлам (appium:app)

Указание пути к бинарному файлу приложения (`.apk` для Android, `.app` или `.ipa` для iOS) в свойстве `appium:app` требует особого внимания в зависимости от операционной системы и целевого окружения:

- **В Windows**: операционная система использует обратные слэши (`\`) в путях к каталогам. При указании пути к файлу `.apk` в Windows обязательно экранируйте обратные слэши в конфигурационном файле (например, `.\\build\\app\\outputs\\flutter-apk\\app-debug.apk`) или последовательно используйте прямые слэши (`/`), которые корректно обрабатываются Node.js.
- **В macOS / Linux**: используются стандартные пути с прямыми слэшами (`/`). Помните, что сборки для iOS (`.app` для Simulator или `.ipa` для реальных устройств) можно скомпилировать только в окружении macOS.
- **iOS Simulator и реальные устройства**: используйте бандлы `.app` при запуске на iOS Simulator и подписанные пакеты `.ipa` при запуске на физических устройствах iOS.
- **Абсолютные и относительные пути**: настоятельно рекомендуется использовать относительные пути от корня проекта (с помощью `./`), чтобы гарантировать переносимость между разными машинами разработчиков и окружениями непрерывной интеграции (CI).
