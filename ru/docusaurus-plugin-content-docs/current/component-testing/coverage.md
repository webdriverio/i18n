Браузерный раннер WebdriverIO поддерживает формирование отчётов о покрытии кода с помощью [`istanbul`](https://istanbul.js.org/). Тестраннер автоматически инструментирует ваш код с помощью Vite и собирает данные о покрытии кода за вас.

## Как это работает

`@wdio/browser-runner` использует Vite для обслуживания вашего приложения. Когда вы включаете покрытие, он добавляет в сервер Vite плагин, который пытается инструментировать ваш исходный код на лету по мере его запроса браузером.

:::warning Важно
**Не уходите со страницы тестраннера!**

Покрытие кода зависит от того, что файлы обслуживаются и инструментируются локальным сервером Vite, запущенным WebdriverIO.
Если вы используете `browser.url('http://...')` или `browser.url('file://...')` для перехода на другую страницу, вы покидаете инструментированную среду. Ваш код будет выполняться, но **данные о покрытии собираться не будут**.

**Правильный подход (компонентное тестирование):**
Рендерите ваш компонент или импортируйте ваш модуль непосредственно в файле теста.

```js
import { myFunction } from '../src/utils.js'

it('should cover my function', () => {
    myFunction() // Это покрыто
})
```

**Неправильный подход (в стиле E2E):**
```js
it('will not have coverage', async () => {
    // ❌ переход на другую страницу нарушает инструментирование
    await browser.url('http://localhost:3000')
})
```
:::

## Настройка

Чтобы включить формирование отчётов о покрытии кода, активируйте его через конфигурацию браузерного раннера WebdriverIO, например:

```js title=wdio.conf.js
export const config = {
    // ...
    runner: ['browser', {
        preset: process.env.WDIO_PRESET,
        coverage: {
            enabled: true
        }
    }],
    // ...
}
```

Ознакомьтесь со всеми [параметрами покрытия](/docs/runner#coverage-options), чтобы узнать, как правильно его настроить.

:::tip Советы по настройке
Если вы тестируете нестандартные файлы (например, встроенные скрипты в `.html`) или если ваши файлы не подхватываются, возможно, вам потребуется явно проверить параметры `include` и `extension`:

```js
coverage: {
    enabled: true,
    // Явно укажите ваши исходные файлы, если разрешение по умолчанию не срабатывает
    include: ['src/**/*.js', 'src/**/*.vue'],
    // Добавьте .html, если у вас есть встроенные скрипты
    extension: ['.js', '.jsx', '.ts', '.tsx', '.vue', '.html']
}
```
:::

## Игнорирование кода

В вашей кодовой базе могут быть разделы, которые вы намеренно хотите исключить из отслеживания покрытия. Для этого можно использовать следующие подсказки для парсера:

- `/* istanbul ignore if */`: игнорировать следующий оператор if.
- `/* istanbul ignore else */`: игнорировать ветку else оператора if.
- `/* istanbul ignore next */`: игнорировать следующий элемент исходного кода (функции, операторы if, классы и т. д.).
- `/* istanbul ignore file */`: игнорировать весь исходный файл (эта подсказка должна располагаться в начале файла).

:::info

Рекомендуется исключать файлы тестов из отчёта о покрытии, так как это может вызывать ошибки, например при вызове команды `execute`. Если вы хотите оставить их в отчёте, убедитесь, что исключили их из инструментирования с помощью:

```ts
await browser.execute(/* istanbul ignore next */() => {
    // ...
})
```

:::
