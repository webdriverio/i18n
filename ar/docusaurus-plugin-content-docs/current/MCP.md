## ماذا يمكنه أن يفعل؟

WebdriverIO MCP هو **خادم بروتوكول سياق النموذج (MCP)** يُمكّن مساعدي الذكاء الاصطناعي من أتمتة متصفحات الويب وتطبيقات الهاتف المحمول والتفاعل معها.

### لماذا WebdriverIO MCP؟

-   **الأولوية للهاتف المحمول**: على عكس خوادم MCP المخصصة للمتصفحات فقط، يدعم WebdriverIO MCP أتمتة التطبيقات الأصلية على iOS وAndroid عبر Appium
-   **محددات متعددة المنصات**: يُنشئ الكشف الذكي عن العناصر استراتيجيات تحديد مواقع متعددة (accessibility ID وXPath وUiAutomator وiOS predicates) تلقائيًا
-   **منظومة WebdriverIO**: مبني على إطار عمل WebdriverIO المُجرَّب والموثوق مع منظومته الغنية من الخدمات وأدوات التقارير

يوفر واجهة موحدة لـ:

-   🖥️ **متصفحات سطح المكتب** (Chrome وFirefox وEdge وSafari، بواجهة رسومية أو بدونها)
-   📱 **تطبيقات الهاتف المحمول الأصلية** (محاكيات iOS / محاكيات Android / الأجهزة الحقيقية عبر Appium)
-   📳 **تطبيقات الهاتف المحمول الهجينة** (التبديل بين سياق Native وWebView عبر Appium)
-   ☁️ **الأجهزة السحابية** (سحابات الأجهزة والمتصفحات الحقيقية من BrowserStack وSauce Labs وTestMu)

من خلال حزمة [`@wdio/mcp`](https://www.npmjs.com/package/@wdio/mcp).

يتيح هذا لمساعدي الذكاء الاصطناعي:

-   **تشغيل المتصفحات والتحكم بها** مع أبعاد قابلة للتهيئة، ووضع headless، وتنقل أولي اختياري
-   **التنقل في مواقع الويب** والتفاعل مع العناصر (النقر، الكتابة، التمرير)
-   **تحليل محتوى الصفحة** عبر شجرة إمكانية الوصول والكشف عن العناصر المرئية مع دعم التقسيم إلى صفحات
-   **التقاط لقطات الشاشة** المُحسَّنة تلقائيًا (تغيير الحجم، والضغط إلى 1 ميجابايت كحد أقصى)
-   **إدارة ملفات تعريف الارتباط** للتعامل مع الجلسات
-   **التحكم في الأجهزة المحمولة** بما في ذلك الإيماءات (النقر، السحب، السحب والإفلات)
-   **التبديل بين السياقات** في التطبيقات الهجينة بين native وwebview
-   **تنفيذ السكربتات** - JavaScript في المتصفحات، وأوامر Appium للهاتف المحمول على الأجهزة
-   **التعامل مع ميزات الجهاز** مثل التدوير ولوحة المفاتيح والموقع الجغرافي
-   والكثير غير ذلك، راجع خيارات [الأدوات](./mcp/tools) و[التهيئة](./mcp/configuration)

:::info

ملاحظة لتطبيقات الهاتف المحمول
تتطلب أتمتة الهاتف المحمول خادم Appium قيد التشغيل مع تثبيت برامج التشغيل المناسبة. راجع [المتطلبات المسبقة](#prerequisites) للاطلاع على تعليمات الإعداد.

:::

## التثبيت

أسهل طريقة لاستخدام `@wdio/mcp` هي عبر npx دون أي تثبيت محلي:

```sh
npx @wdio/mcp
```

أو قم بتثبيته بشكل عام:

```sh
npm install -g @wdio/mcp
```

## الاستخدام مع Claude

لاستخدام WebdriverIO MCP مع Claude، عدّل ملف التهيئة:

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

بعد إضافة التهيئة، أعد تشغيل بيئة التشغيل الخاصة بك. ستكون أدوات WebdriverIO MCP متاحة لمهام أتمتة المتصفح والهاتف المحمول.

### الاستخدام مع Claude Code

يكتشف Claude Code خوادم MCP تلقائيًا. يمكنك تهيئته في ملف `.claude/settings.json` أو `.mcp.json` الخاص بمشروعك.

أو أضفه إلى .claude.json بشكل عام عن طريق تنفيذ:
```bash
claude mcp add --transport stdio wdio-mcp -- npx -y @wdio/mcp
```
تحقق منه بتشغيل الأمر `/mcp` داخل Claude Code.

## المتطلبات المسبقة

### أتمتة المتصفح

-   يجب تثبيت **Chrome أو Firefox أو Edge أو Safari**
-   يتولى WebdriverIO إدارة برامج التشغيل تلقائيًا

### أتمتة الهاتف المحمول

#### iOS

1. **ثبّت Xcode** من Mac App Store
2. **ثبّت أدوات سطر أوامر Xcode**:
   ```sh
   xcode-select --install
   ```
3. **ثبّت Appium**:
   ```sh
   npm install -g appium
   ```
4. **ثبّت برنامج تشغيل XCUITest**:
   ```sh
   appium driver install xcuitest
   ```
5. **شغّل خادم Appium**:
   ```sh
   appium
   ```
6. **للمحاكيات**: افتح Xcode ← Window ← Devices and Simulators لإنشاء/إدارة المحاكيات
7. **للأجهزة الحقيقية**: ستحتاج إلى UDID الخاص بالجهاز (معرّف فريد مكوّن من 40 حرفًا)

#### Android

1. **ثبّت Android Studio** وقم بإعداد Android SDK
2. **عيّن متغيرات البيئة**:
   ```sh
   export ANDROID_HOME=$HOME/Library/Android/sdk
   export PATH=$PATH:$ANDROID_HOME/emulator
   export PATH=$PATH:$ANDROID_HOME/platform-tools
   ```
3. **ثبّت Appium**:
   ```sh
   npm install -g appium
   ```
4. **ثبّت برنامج تشغيل UiAutomator2**:
   ```sh
   appium driver install uiautomator2
   ```
5. **شغّل خادم Appium**:
   ```sh
   appium
   ```
6. **أنشئ محاكيًا** عبر Android Studio ← Virtual Device Manager
7. **شغّل المحاكي** قبل تشغيل الاختبارات

## البنية

### كيف يعمل

يعمل WebdriverIO MCP كجسر بين مساعدي الذكاء الاصطناعي وأتمتة المتصفح/الهاتف المحمول:

```
┌─────────────────┐     MCP Protocol      ┌─────────────────┐
│  Claude Desktop │ ◄──────────────────►  │    @wdio/mcp    │
│  or Claude Code │   (stdio or HTTP)     │     Server      │
└─────────────────┘                       └────────┬────────┘
                                                   │
                                             WebDriverIO API
                                                   │
                    ┌──────────────────────────────┼──────────────────────────────┐
                    │                              │                              │
            ┌───────▼───────┐             ┌───────▼───────┐             ┌───────▼───────┐
            │    Browser    │             │    Appium     │             │   Cloud        │
            │ (local/CDP)   │             │  (iOS/Android)│             │   Providers    │
            └───────────────┘             └───────────────┘             └───────────────┘
```

### إدارة الجلسات

-   **نموذج الجلسة الواحدة**: يمكن أن تكون جلسة متصفح واحدة فقط أو جلسة تطبيق واحدة فقط نشطة في كل مرة
-   **حالة الجلسة** يتم الحفاظ عليها بشكل عام عبر استدعاءات الأدوات
-   **الفصل التلقائي**: الجلسات ذات الحالة المحفوظة (`noReset: true`) تنفصل تلقائيًا عند الإغلاق

### الكشف عن العناصر

#### المتصفح (الويب)

-   يستخدم سكربت متصفح مُحسَّنًا للعثور على جميع العناصر المرئية القابلة للتفاعل
-   يُرجع العناصر مع محددات CSS والمعرّفات والفئات ومعلومات ARIA
-   يدعم التصفية حسب منفذ العرض والتقسيم إلى صفحات

#### الهاتف المحمول (التطبيقات الأصلية)

-   يستخدم تحليلًا فعالًا لمصدر الصفحة بصيغة XML (استدعاءان HTTP مقابل أكثر من 600 للاستعلامات التقليدية)
-   تصنيف العناصر الخاص بكل منصة لـ Android وiOS
-   يُنشئ استراتيجيات تحديد مواقع متعددة لكل عنصر:
    -   Accessibility ID (متعدد المنصات، الأكثر استقرارًا)
    -   Resource ID / سمة Name
    -   مطابقة Text / Label
    -   XPath (كامل ومبسّط)
    -   UiAutomator (Android) / Predicates (iOS)

## صيغة المحددات

يدعم خادم MCP استراتيجيات محددات متعددة. راجع [المحددات](./mcp/selectors) للاطلاع على التوثيق المفصّل.

### الويب (CSS/XPath)

```
# محددات CSS
button.my-class
#element-id
[data-testid="login"]

# XPath
//button[@class='submit']
//a[contains(text(), 'Click')]

# محددات النص (خاصة بـ WebdriverIO)
button=Exact Button Text
a*=Partial Link Text
```

### الهاتف المحمول (متعدد المنصات)

```
# Accessibility ID (موصى به - يعمل على iOS وAndroid)
~loginButton

# Android UiAutomator
android=new UiSelector().text("Login")

# iOS Predicate String
-ios predicate string:label == "Login"

# iOS Class Chain
-ios class chain:**/XCUIElementTypeButton[`label == "Login"`]

# XPath (يعمل على كلتا المنصتين)
//android.widget.Button[@text="Login"]
//XCUIElementTypeButton[@label="Login"]
```

## المعالجة التلقائية

### الأذونات

بشكل افتراضي، يمنح خادم MCP أذونات التطبيق تلقائيًا (`autoGrantPermissions: true`)، مما يلغي الحاجة إلى التعامل يدويًا مع مربعات حوار الأذونات أثناء الأتمتة.

### تنبيهات النظام

يتم قبول تنبيهات النظام (مثل "Allow notifications?") تلقائيًا بشكل افتراضي (`autoAcceptAlerts: true`). يمكن تهيئة ذلك لرفضها بدلًا من ذلك باستخدام `autoDismissAlerts: true`.

## النقل

بشكل افتراضي، يعمل الخادم عبر **stdio** (يتم تشغيله كعملية فرعية بواسطة عميل الذكاء الاصطناعي). بالنسبة للعملاء الذين لا يدعمون MCP القائم على العمليات الفرعية (llama.cpp، ووضع Codex الآمن)، استخدم **نقل HTTP**:

```bash
npx @wdio/mcp --http --port 3000
```

راجع [النقل](./mcp/transport) للاطلاع على الخيارات الكاملة بما في ذلك `--allowedHosts` و`--allowedOrigins`.

## تحسين الأداء

خادم MCP مُحسَّن للتواصل الفعّال مع مساعدي الذكاء الاصطناعي:

-   **تنسيق TOON**: يستخدم Token-Oriented Object Notation لتقليل استهلاك الرموز إلى الحد الأدنى
-   **تحليل XML**: يستخدم الكشف عن عناصر الهاتف المحمول استدعاءين HTTP (مقابل أكثر من 600 بالطريقة التقليدية)
-   **ضغط لقطات الشاشة**: يتم ضغط الصور تلقائيًا إلى 1 ميجابايت كحد أقصى
-   **التصفية حسب منفذ العرض**: يتم إرجاع العناصر المرئية فقط بشكل افتراضي
-   **التقسيم إلى صفحات**: يمكن تقسيم قوائم العناصر الكبيرة إلى صفحات لتقليل حجم الاستجابة

## معالجة الأخطاء

صُممت جميع الأدوات بمعالجة قوية للأخطاء:

-   يتم إرجاع الأخطاء كمحتوى نصي (ولا يتم رميها أبدًا)، مما يحافظ على استقرار بروتوكول MCP
-   تساعد رسائل الخطأ الوصفية في تشخيص المشكلات
-   يتم الحفاظ على حالة الجلسة حتى عند فشل العمليات الفردية

## حالات الاستخدام

### ضمان الجودة

-   تنفيذ حالات الاختبار بمساعدة الذكاء الاصطناعي
-   اختبار الانحدار المرئي باستخدام لقطات الشاشة
-   تدقيق إمكانية الوصول عبر تحليل شجرة إمكانية الوصول

### استخراج بيانات الويب واستخلاصها

-   التنقل في تدفقات معقدة متعددة الصفحات
-   استخراج بيانات منظمة من المحتوى الديناميكي
-   التعامل مع المصادقة وإدارة الجلسات

### اختبار تطبيقات الهاتف المحمول

-   أتمتة الاختبارات متعددة المنصات (iOS + Android)
-   التحقق من تدفق التهيئة الأولية للمستخدم
-   اختبار الروابط العميقة والتنقل

### اختبار التكامل

-   اختبار سير العمل من البداية إلى النهاية
-   التحقق من تكامل API + واجهة المستخدم
-   فحوصات الاتساق عبر منصات متعددة

## استكشاف الأخطاء وإصلاحها

### المتصفح لا يبدأ

-   تأكد من تثبيت المتصفح المستهدف
-   تحقق من عدم استخدام أي عملية أخرى لمنفذ التصحيح الافتراضي (9222)
-   جرّب وضع headless في حال حدوث مشكلات في العرض

### فشل الاتصال بـ Appium

-   تحقق من أن خادم Appium قيد التشغيل (`appium`)
-   تحقق من مضيف Appium والمنفذ في `appiumConfig`
-   تأكد من تثبيت برنامج التشغيل المناسب (`appium driver list`)

### مشكلات محاكي iOS

-   تأكد من تثبيت Xcode وتحديثه
-   تحقق من توفر المحاكيات (`xcrun simctl list devices`)
-   بالنسبة للأجهزة الحقيقية، تحقق من صحة UDID

### مشكلات محاكي Android

-   تأكد من تهيئة Android SDK بشكل صحيح
-   تحقق من أن المحاكي قيد التشغيل (`adb devices`)
-   تحقق من تعيين متغير البيئة `ANDROID_HOME`
