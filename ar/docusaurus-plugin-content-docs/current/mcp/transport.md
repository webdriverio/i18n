يدعم خادم WebdriverIO MCP وضعين للنقل: **stdio** (الافتراضي) و**HTTP**.

## stdio (الافتراضي)

stdio هو وسيلة النقل القياسية في MCP. يقوم عميل الذكاء الاصطناعي بتشغيل الخادم كعملية فرعية ويتواصل معه عبر stdin/stdout.

```json
{
  "mcpServers": {
    "webdriverio": {
      "command": "npx",
      "args": ["-y", "@wdio/mcp"]
    }
  }
}
```

استخدم stdio للإعدادات المحلية مع Claude Desktop وClaude Code وCursor والعملاء المماثلة التي تدير دورة حياة الخادم بنفسها.

## HTTP (Streamable HTTP)

يشغّل وضع HTTP الخادم كعملية مستقلة تستمع على منفذ معين. يتصل العملاء به عبر HTTP بدلاً من تشغيله كعملية فرعية. استخدم هذا الوضع عندما:

- لا يدعم عميلك MCP القائم على العمليات الفرعية (مثل واجهة الويب الخاصة بـ llama.cpp)
- تريد مشاركة نسخة واحدة من الخادم بين عدة عملاء
- تعمل في وضع Codex الآمن حيث يكون تنفيذ العمليات الفرعية مقيداً
- تريد إبقاء الخادم قيد التشغيل عبر جلسات عملاء متعددة

### التشغيل في وضع HTTP

```bash
npx @wdio/mcp --http --port 3000
```

يوفّر الخادم نقطة نهاية واحدة: `http://localhost:<port>/mcp`

### الخيارات الكاملة

```bash
npx @wdio/mcp --http \
  --port 3000 \
  --allowedHosts "localhost,127.0.0.1,::1" \
  --allowedOrigins "http://localhost:5173,https://myapp.example.com"
```

| العلامة            | القيمة الافتراضية                     | الوصف                                                                     |
| ------------------ | --------------------------- | ------------------------------------------------------------------------------- |
| `--http`           | —                           | تفعيل وضع النقل عبر HTTP                                                      |
| `--port`           | `3000`                      | المنفذ الذي يتم الاستماع عليه                                                               |
| `--allowedHosts`   | `localhost,127.0.0.1,::1`   | قيم ترويسة `Host` المسموح بها مفصولة بفواصل (حماية من DNS rebinding)         |
| `--allowedOrigins` | _(لا شيء — المتصفحات محظورة)_ | قيم `Origin` المسموح بها لـ CORS مفصولة بفواصل. استخدم `*` للسماح بجميع المصادر. |

### الأمان

**`--allowedHosts`** — يحمي من هجمات DNS rebinding. لا تُقبل إلا الطلبات التي تحتوي على ترويسة `Host` مطابقة لهذه القائمة. القيمة الافتراضية (`localhost,127.0.0.1,::1`) آمنة للاستخدام المحلي. إذا كنت تعرض الخادم على واجهة عامة، فأضف اسم المضيف الخاص بك هنا.

**`--allowedOrigins`** — يتحكم في مصادر المتصفح التي يمكنها إجراء طلبات عبر المصادر (CORS). افتراضياً، لا يُسمح بأي مصادر للمتصفح. يمنع هذا الوصول من مواقع ويب عشوائية مع الاستمرار في السماح للعملاء غير المتصفحات (أدوات CLI، عملاء API). اضبطه على `*` للسماح بجميع المصادر، أو اذكر مصادر محددة.

لا تخضع الطلبات الواردة من العملاء غير المتصفحات (بدون ترويسة `Origin`) لفحص CORS؛ ولا يُطبّق عليها سوى `--allowedHosts`.

## حالات الاستخدام

### واجهة الويب الخاصة بـ llama.cpp

تعمل واجهة الويب الخاصة بـ llama.cpp في المتصفح وترسل ترويسة `Origin` مع كل طلب. شغّل الخادم مع `--allowedOrigins` مطابقاً لمصدر الواجهة:

```bash
# llama.cpp web UI runs at http://localhost:8080
npx @wdio/mcp --http --port 3000 --allowedOrigins "http://localhost:8080"

# Or allow all local origins
npx @wdio/mcp --http --port 3000 --allowedOrigins "*"
```

في إعدادات llama.cpp، أضف خادم MCP يشير إلى `http://localhost:3000/mcp`.

---

### وضع Codex الآمن

يعمل OpenAI Codex في بيئة معزولة (sandbox) دون دعم للعمليات الفرعية. استخدم النقل عبر HTTP حتى يتمكن Codex من الوصول إلى خادم MCP الذي يعمل على جهازك المضيف:

```bash
# Start on your host
npx @wdio/mcp --http --port 3000
```

في إعدادات MCP الخاصة بـ Codex، اضبط عنوان URL للخادم على `http://localhost:3000/mcp` (أو عنوان IP لجهازك المضيف إذا كان Codex يعمل في جهاز افتراضي).

---

### البنية القائمة على كل طلب

ينشئ كل طلب HTTP نسخة جديدة من خادم MCP. وهذا يعني:

- يمكن للعملاء إعادة الاتصال بعد انقطاع الاتصال دون حدوث أخطاء.
- يمكن لعدة عملاء الاتصال في الوقت نفسه (يحصل كل منهم على جلسة MCP مستقلة).
- تتم مشاركة حالة الجلسة (المتصفح/التطبيق النشط) عبر الحالة العامة، وليس عبر حالة النقل.

لا يوجد قفل (mutex)؛ إذ تتم معالجة الطلبات بشكل متزامن. وتتم معالجة الحالة في بروتوكول MCP (initialize → استدعاءات الأدوات) لكل طلب على حدة.
