يمكنك باستخدام مشغل اختبارات WebdriverIO إعادة تشغيل اختبارات معينة يتبين أنها غير مستقرة بسبب أمور مثل شبكة غير مستقرة أو حالات التسابق (race conditions). (ومع ذلك، لا يُنصح ببساطة بزيادة معدل إعادة التشغيل إذا أصبحت الاختبارات غير مستقرة!)

## إعادة تشغيل المجموعات في Mocha

منذ الإصدار 3 من Mocha، يمكنك إعادة تشغيل مجموعات اختبار كاملة (كل ما بداخل كتلة `describe`). إذا كنت تستخدم Mocha، فيجب أن تفضّل آلية إعادة المحاولة هذه بدلًا من تطبيق WebdriverIO الذي يسمح لك فقط بإعادة تشغيل كتل اختبار معينة (كل ما بداخل كتلة `it`). لاستخدام الدالة `this.retries()`، يجب أن تستخدم كتلة المجموعة `describe` دالة غير مرتبطة `function(){}` بدلًا من الدالة السهمية `() => {}`، كما هو موضح في [توثيق Mocha](https://mochajs.org/#arrow-functions). باستخدام Mocha، يمكنك أيضًا تعيين عدد مرات إعادة المحاولة لجميع المواصفات باستخدام `mochaOpts.retries` في ملف `wdio.conf.js` الخاص بك.

إليك مثالًا:

```js
describe('retries', function () {
    // أعد محاولة جميع الاختبارات في هذه المجموعة حتى 4 مرات
    this.retries(4)

    beforeEach(async () => {
        await browser.url('http://www.yahoo.com')
    })

    it('should succeed on the 3rd try', async function () {
        // حدد أن هذا الاختبار يُعاد حتى مرتين فقط
        this.retries(2)
        console.log('run')
        await expect($('.foo')).toBeDisplayed()
    })
})
```

لإعادة تشغيل كتلة اختبار معينة، يمكنك ببساطة تمرير عدد مرات إعادة التشغيل كمعامل أخير بعد دالة كتلة الاختبار:

     */

        console.log(this.wdioRetries) // يعيد عدد مرات إعادة المحاولة

    }, 1)

})

تسمح آلية إعادة المحاولة هذه فقط بإعادة محاولة خطافات فردية أو كتل اختبار فردية. إذا كان اختبارك مصحوبًا بخطاف لإعداد تطبيقك، فلن يتم تشغيل هذا الخطاف. [يوفر Mocha](https://mochajs.org/#retry-tests) إعادة محاولة أصلية للاختبارات توفر هذا السلوك، بينما لا يوفرها Jasmine. يمكنك الوصول إلى عدد مرات إعادة المحاولة المنفذة في الخطاف `afterTest`.

مع Mocha، تتشارك جميع محاولات الاختبار أو الخطاف مهلته الزمنية: يبدأ Mocha المؤقت مرة واحدة، ويُفشل الاختبار عندما تستغرق جميع المحاولات مجتمعةً وقتًا أطول من المهلة الزمنية. لذا فإن هذه الآلية تعيد محاولة الاختبار أو الخطاف الذي يفشل (على سبيل المثال، تأكيد أو أمر فاشل)، ولكنها لا تعيد محاولة ما يصل إلى مهلته الزمنية، لأن المحاولة اللاحقة لن تتمكن من الانتهاء في الوقت المحدد. يذكر خطأ المهلة الزمنية لاختبار أو خطاف مع إعادات محاولة WebdriverIO المحاولةَ التي انتهت مهلتها، على سبيل المثال `(WDIO attempt 2/3)`. بالنسبة للاختبارات التي قد تنتهي مهلتها، استخدم [إعادات المحاولة في Mocha](https://mochajs.org/#retry-tests) (`this.retries()`): إذ يشغّل Mocha كل محاولة من جديد بمهلة زمنية كاملة.

## إعادة التشغيل في Cucumber

### إعادة تشغيل المجموعات الكاملة في Cucumber

بالنسبة لـ cucumber >=6، يمكنك توفير خيار الإعداد [`retry`](https://github.com/cucumber/cucumber-js/blob/master/docs/cli.md#retry-failing-tests) مع المعامل الاختياري `retryTagFilter` لجعل جميع السيناريوهات الفاشلة أو بعضها تحصل على إعادات محاولة إضافية حتى تنجح.

### إعادة تشغيل تعريفات الخطوات في Cucumber

لتحديد معدل إعادة تشغيل لتعريفات خطوات معينة، ما عليك سوى تطبيق خيار إعادة المحاولة عليها، مثل:

```js
export default function () {
    /**
     * تعريف خطوة يعمل 3 مرات كحد أقصى (تشغيل فعلي واحد + إعادتا تشغيل)
     */
    this.Given(/^some step definition$/, { wrapperOptions: { retry: 2 } }, async () => {
        // ...
    })
    // ...
})
```

لا يمكن تعريف إعادات التشغيل إلا في ملف تعريفات الخطوات الخاص بك، وليس في ملف الميزات (feature file) أبدًا.

## إضافة إعادات المحاولة على مستوى كل ملف مواصفات

في السابق، كانت إعادات المحاولة متاحة فقط على مستوى الاختبار والمجموعة، وهي مناسبة في معظم الحالات.

لكن في أي اختبارات تتضمن حالة (state) (كما هو الحال على خادم أو في قاعدة بيانات)، قد تُترك الحالة غير صالحة بعد فشل الاختبار الأول. وقد لا تكون لأي إعادات محاولة لاحقة فرصة للنجاح، بسبب الحالة غير الصالحة التي ستبدأ بها.

يتم إنشاء نسخة `browser` جديدة لكل ملف مواصفات، مما يجعل هذا مكانًا مثاليًا لربط وإعداد أي حالات أخرى (الخادم، قواعد البيانات). وتعني إعادات المحاولة على هذا المستوى أن عملية الإعداد بأكملها ستتكرر ببساطة، تمامًا كما لو كانت لملف مواصفات جديد.

```js title="wdio.conf.js"
export const config = {
    // ...
    /**
     * عدد مرات إعادة محاولة ملف المواصفات بالكامل عندما يفشل ككل
     */
    specFileRetries: 1,
    /**
     * التأخير بالثواني بين محاولات إعادة تشغيل ملف المواصفات
     */
    specFileRetriesDelay: 0,
    /**
     * تُدرج ملفات المواصفات المُعاد محاولتها في بداية قائمة الانتظار وتُعاد محاولتها فورًا
     */
    specFileRetriesDeferred: false
}
```

## تشغيل اختبار محدد عدة مرات

يهدف هذا إلى المساعدة في منع إدخال اختبارات غير مستقرة إلى قاعدة الشيفرة. بإضافة خيار سطر الأوامر `--repeat`، سيتم تشغيل المواصفات أو المجموعات المحددة N مرة. عند استخدام علامة سطر الأوامر هذه، يجب أيضًا تحديد العلامة `--spec` أو `--suite`.

عند إضافة اختبارات جديدة إلى قاعدة الشيفرة، خاصةً من خلال عملية CI/CD، قد تنجح الاختبارات ويتم دمجها ولكنها تصبح غير مستقرة لاحقًا. قد ينتج عدم الاستقرار هذا عن عدد من الأمور مثل مشكلات الشبكة، أو حمل الخادم، أو حجم قاعدة البيانات، وما إلى ذلك. يمكن أن يساعد استخدام العلامة `--repeat` في عملية CD/CD الخاصة بك على اكتشاف هذه الاختبارات غير المستقرة قبل دمجها في قاعدة الشيفرة الرئيسية.

إحدى الاستراتيجيات التي يمكن استخدامها هي تشغيل اختباراتك كالمعتاد في عملية CI/CD، ولكن إذا كنت تضيف اختبارًا جديدًا، يمكنك حينها تشغيل مجموعة أخرى من الاختبارات مع تحديد المواصفة الجديدة في `--spec` إلى جانب `--repeat` بحيث يتم تشغيل الاختبار الجديد عددًا x من المرات. إذا فشل الاختبار في أي من تلك المرات، فلن يتم دمج الاختبار وسيتعين البحث في سبب فشله.

```sh
# سيؤدي هذا إلى تشغيل المواصفة example.e2e.js خمس مرات
npx wdio run ./wdio.conf.js --spec example.e2e.js --repeat 5
```
