مسار التقاط بدون واجهة — لا تُفتح أي نافذة لواجهة DevTools. في نهاية الجلسة يكتب المحوّل عناصر التتبع في مجلد `test-results/` بجوار مجلد ملفات المواصفات / الإعدادات الخاص بك. بالنسبة لمستوى التفصيل `session` / `spec` يكون الناتج ملف `trace-<sessionId>.zip` (أو مجلد `trace-<sessionId>/`)؛ أما بالنسبة لمستوى التفصيل `test` فيحصل كل اختبار على مجلد فرعي خاص به (راجع [مستوى تفصيل التتبع](#trace-granularity--tracegranularity)). العنصر الناتج قابل للنقل ويتضمن كل ما يلزم لإعادة التشغيل دون اتصال، أو للمقارنة بواسطة وكلاء الذكاء الاصطناعي، أو لأي مستهلك يفضّل ملفًا على واجهة مباشرة.

وضع التتبع **لا يمكن استخدامه مع الوضع المباشر في آنٍ واحد**. اختر واحدًا لكل جلسة: البشر الذين يصحّحون الأخطاء بشكل تفاعلي يفضّلون الوضع المباشر؛ أما الوكلاء الذين يقارنون عمليات التشغيل أو روبوتات CI التي تجمع العناصر فيفضّلون وضع التتبع.

## التفعيل

```ts
// wdio.conf.ts
services: [
  [
    'devtools',
    {
      mode: 'trace',
      traceFormat: 'zip' // optional; 'zip' (default) | 'ndjson-directory'
    }
  ]
]
```

يتوفر ملف إعدادات مرجعي كامل وجاهز للنسخ واللصق في [`examples/wdio/wdio.trace.conf.ts`](https://github.com/webdriverio/devtools/blob/main/examples/wdio/wdio.trace.conf.ts).

يوفّر Selenium وNightwatch مسار التتبع نفسه — راجع صفحات المحوّلات الخاصة بهما لمعرفة صيغة التفعيل الخاصة بكل إطار عمل: [Selenium](/docs/devtools/selenium#trace-mode) · [Nightwatch](/docs/devtools/nightwatch#trace-mode).

## محتويات العنصر الناتج

| الملف | المحتويات |
|---|---|
| `trace.trace` | أحداث NDJSON من نوع `context-options` + أحداث الإجراءات `before` / `after`؛ سطر واحد لكل سجل |
| `trace.network` | إدخالات الشبكة بنمط HAR، إدخال واحد في كل سطر |
| `transcript.md` | ملخص Markdown قابل للقراءة من البشر/نماذج LLM يتضمن التوقيتات والمحددات وتعليقات القيم |
| `resources/page@<id>-<ts>.jpeg` | لقطة شاشة تُلتقط عند كل إجراء يواجه المستخدم |
| `resources/page@<id>-<ts>-elements.json` | قائمة مسطّحة بالعناصر القابلة للتفاعل عند ذلك الإجراء |
| `resources/page@<id>-<ts>-snapshot.txt` | لقطة لشجرة إمكانية الوصول بمسافات بادئة حسب العمق (مناسبة للذكاء الاصطناعي) |

### ما الذي يُعدّ "إجراءً"

تُرشَّح الأوامر عبر قائمة سماح قبل أن تُنتج إدخالات في التتبع. أمثلة على ما يظهر في التتبع:

- `url` / `get` ← `Page.navigate`
- `click` ← `Element.click`
- `setValue` / `sendKeys` ← `Element.fill`
- `submit`، `clear`، `selectByVisibleText`، …

الأوامر الداخلية مثل `findElement` و`waitUntil` و`executeScript` مستبعدة عمدًا — فهي لا تمثّل نية موجّهة للمستخدم وستُحدث ضوضاء في المخطط الزمني. توجد قائمة السماح الكاملة في [`@wdio/devtools-core/action-mapping.ts`](https://github.com/webdriverio/devtools/blob/main/packages/core/src/action-mapping.ts).

## تنسيق المخرجات — `traceFormat`

```ts
{
  mode: 'trace',
  traceFormat: 'zip' | 'ndjson-directory'  // default: 'zip'
}
```

- **`zip`** (الافتراضي) — أرشيف واحد في `test-results/trace-<sessionId>.zip`.
- **`ndjson-directory`** — الملفات نفسها غير مضغوطة في `test-results/trace-<sessionId>/`. خطوة فك ضغط أقل للمستهلكين البرمجيين أو الوكلاء الذين يريدون البحث في NDJSON أو بثّه مباشرة.

يُفتح كلا التنسيقين في [مشغّل `show-trace`](/docs/devtools/trace-player) الرسمي وفي عارضات التتبع المتوافقة الأخرى.

## مستوى تفصيل التتبع — `traceGranularity`

عدد عناصر التتبع التي ينتجها التشغيل:

```ts
{
  mode: 'trace',
  traceGranularity: 'session' | 'spec' | 'test' // default: 'session'
}
```

| القيمة | المخرجات |
|---|---|
| `session` (الافتراضي) | تتبع واحد لكل عامل/جلسة — `test-results/trace-<sessionId>.zip`. |
| `spec` | تتبع واحد لكل ملف مواصفات. أصغر حجمًا وأسهل في التصفح. |
| `test` | تتبع واحد **لكل اختبار**، كلٌّ في مجلده الخاص: `test-results/<spec>-<title>-<browser>[-retry<N>]/trace.zip`. |

بالنسبة لمستوى التفصيل `test` يُبنى اسم المجلد من الاسم الأساسي لملف المواصفات، ونسخة مختصرة (slug) من عنوان الاختبار، والمتصفح، ولاحقة `-retry<N>` للمحاولات المُعادة — مثلًا `test-results/login_e2e-logs-in-chrome/trace.zip`، وتكون أول إعادة محاولة في `test-results/login_e2e-logs-in-chrome-retry1/trace.zip`. التتبعات لكل اختبار هي الأسهل في التصفح، وتعمل بشكل أفضل مع سياسة احتفاظ بحيث لا تُكتب إلا التتبعات التي تهمّك.

## الاحتفاظ — `tracePolicy`

افتراضيًا يُحتفظ بكل تتبع (`'on'`). للاحتفاظ بالتتبعات المهمة فقط — وهو مثالي مع `traceGranularity: 'test'`:

```ts
{
  mode: 'trace',
  traceGranularity: 'test',
  tracePolicy: 'retain-on-failure' // default: 'on'
}
```

| السياسة | يُحتفظ بالتتبع عندما… |
|---|---|
| `'on'` (الافتراضي) | دائمًا — يُكتب كل تتبع. |
| `'retain-on-failure'` | فشلت المحاولة **الأخيرة** للاختبار. تسلسل إعادة المحاولة الذي يفشل ثم ينجح ينتهي بحالة `passed`، لذا *لا* يُحتفظ به — فلن تحتفظ بشكل مفرط باختبار متقلّب نجح في النهاية. |
| `'retain-on-first-failure'` | فشلت **المحاولة 0**، بغض النظر عمّا إذا نجحت إعادة محاولة لاحقة. |
| `'on-first-retry'` | أُعيدت محاولة الاختبار مرة واحدة على الأقل (توجد المحاولة 1). |
| `'on-all-retries'` | توجد أي محاولة مُعادة (المحاولة ≥ 1). |
| `'retain-on-failure-and-retries'` | فشلت المحاولة الأخيرة **أو** أُعيدت محاولة الاختبار. |

يُتخذ القرار بشأن الشريحة غير المحتفظ بها مسبقًا ولا تُكتب على القرص أبدًا. تعتمد السياسات المدركة لإعادة المحاولة على **سجل نتائج** لكل محاولة يحتفظ به المحوّل لكل معرّف اختبار ثابت عبر إعادة المحاولات، بحيث تقيّم `retain-on-failure` و`retain-on-first-failure` المحاولة الصحيحة. وحيث لا يكشف المشغّل معلومات إعادة المحاولة لكل محاولة، تتراجع كل سياسة باستثناء `retain-on-failure` إلى `retain-on-failure`؛ أما التشغيل الذي لا تُرصد فيه أي نتائج (مثل سكربت مستقل بسيط) فيعمل بمبدأ **الفشل المفتوح** ويحتفظ بالتتبع بدلًا من المخاطرة بحذف تتبع قد تحتاجه.

> تم التحقق من الاحتفاظ المدرك لإعادة المحاولة من البداية إلى النهاية في **WebdriverIO** (mocha / cucumber) و**Selenium** (mocha). بالنسبة لـ **Nightwatch**، تعمل `retain-on-failure`، لكن السياسات الأخرى المدركة لإعادة المحاولة تتراجع إليها لأن خيار `--retries` في Nightwatch يعيد تشغيل حالة الاختبار داخليًا دون إعادة إطلاق الخطافات الخاصة بكل اختبار. كما أن خيار `specFileRetries` في WDIO الذي يعمل عبر العمليات يقع خارج السجل (الخاص بكل عامل). راجع [صفحة محوّل Nightwatch](/docs/devtools/nightwatch#trace-mode) للتفاصيل.

## شريط الإطارات الكثيف — `filmstrip`

**افتراضيًا** يسجّل التتبع بثًّا للشاشة **كثيفًا ومتواصلًا** بحيث يوفّر المشغّل تشغيلًا سلسًا عند التمرير بدلًا من القفز من إطار إلى آخر. توجد الإطارات الكثيفة إلى جانب الإطارات الخاصة بكل إجراء (التي تحمل لقطات DOM). اضبط `filmstrip: false` لتسجيل إطار واحد فقط لكل إجراء — تتبع أصغر حجمًا دون مسجّل متواصل:

```ts
{
  mode: 'trace',
  filmstrip: false // opt out — one frame per action (default is true)
}
```

- تُضاف الإطارات الكثيفة **إلى جانب** الإطارات الخاصة بكل إجراء (التي تحمل لقطات DOM)، لذا لا تُفقد أي بيانات DOM — وعند وجود الإطارات الكثيفة فإنها تحلّ محل شريط الإطارات المتفرّق الخاص بالإجراءات عند التمرير.
- تُخفَّف الإطارات عند التصدير (بفاصل ≥100 مللي ثانية) وتُعنوَن حسب المحتوى، لذا تُدمج الإطارات المتطابقة (انتظار ثابت) في مورد واحد. يُحدّ مخزن الجلسة المباشرة المؤقت بواسطة `screencast.maxBufferFrames` (الافتراضي 2000).
- يستخدم التسجيل مسجّل بث الشاشة — دفع CDP على Chrome/Chromium، واستطلاع لقطات الشاشة في غيرهما. على المتصفحات غير Chrome يُصدر الاستطلاع العديد من أوامر `takeScreenshot`؛ استخدمه مع خيار إسكات الخطوات في أداة التقارير لديك (راجع [تكامل Allure](/docs/devtools/allure)).

يتوفر `filmstrip` في المحوّلات الثلاثة (WebdriverIO / Selenium / Nightwatch).

## لقطة الشاشة والفيديو لكل اختبار — `screenshot` / `video`

عند `traceGranularity: 'test'` يمكن لكل اختبار أيضًا أن ينتج لقطة شاشة مستقلة و/أو شريحة فيديو خاصة به، بما يحاكي الأسلوب المألوف للقطات الشاشة/الفيديو عند الفشل:

```ts
{
  mode: 'trace',
  traceGranularity: 'test',
  screenshot: 'only-on-failure', // 'off' (default) | 'on' | 'only-on-failure'
  video: 'retain-on-failure'     // 'off' (default) | any tracePolicy value
}
```

| الخيار | القيم | السلوك |
|---|---|---|
| `screenshot` | `'off'` (الافتراضي) · `'on'` · `'only-on-failure'` | `'on'` تلتقط بعد كل اختبار؛ `'only-on-failure'` فقط بعد اختبار فاشل. بتنسيق PNG. |
| `video` | `'off'` (الافتراضي) · أي قيمة من قيم `tracePolicy` | يسجّل بث الشاشة بشكل متواصل ويحتفظ بشريحة كل اختبار وفق دلالات الاحتفاظ نفسها الخاصة بـ `tracePolicy`. بتنسيق WebM. ضبط قيمة غير `off` يشغّل المسجّل تلقائيًا — لا تحتاج أيضًا إلى `filmstrip` أو `screencast.enabled`. |

كلاهما مقيّد بوضع التتبع + `traceGranularity: 'test'` (النطاق الخاص بكل اختبار الذي يرتبطان به). في مستويات التفصيل الأشمل لا يكون لهما أي تأثير.

- **WebdriverIO** — `screenshot` / `video` هما خيارا خدمة؛ ويُرفقان مباشرة في Allure عند وجود `@wdio/allure-reporter`.
- **Selenium** — الخيارات نفسها في `DevToolsOptions` الخاص به؛ وتُرفق مباشرة في Allure عبر `allure-js-commons` عند تفعيل محوّل مشغّل Allure.
- **Nightwatch** — **إنتاج فقط**: تُكتب الملفات في مجلد مخرجات التتبع (وتُدرج في البيان)، لكنها لا تُرفق مباشرة في Allure — إذ لا يملك Nightwatch واجهة برمجية لإرفاق Allure المباشر. راجع [قيود وضع التتبع](/docs/devtools/limitations).

> `screencast.enabled` هو تسجيل `.webm` المتواصل المنفصل الخاص **بالوضع المباشر** ويُتجاهل في وضع التتبع. في وضع التتبع استخدم `filmstrip` (إطارات كثيفة داخل التتبع) أو `video` لكل اختبار؛ ولا تزال حقول ضبط بث الشاشة (`quality`، `maxWidth`، `pollIntervalMs`، …) تنطبق على أي مسجّل يعمل.

## بيان العناصر — `emitArtifactsManifest`

يكتب ملف `devtools-artifacts-<sessionId>.json` بجوار التتبع — وهو فهرس عام تستخدمه أدوات التقارير وأنظمة CI لاكتشاف العناصر المُنتَجة (كل تتبع / لقطة شاشة / فيديو، بالإضافة إلى حالة كل اختبار):

```ts
{
  mode: 'trace',
  emitArtifactsManifest: true // default: off; auto-on when Allure is detected
}
```

- **معطّل افتراضيًا.** **يُفعَّل تلقائيًا** عند اكتشاف أداة تقارير Allure — `@wdio/allure-reporter` الخاصة بـ WebdriverIO في الإعدادات، أو بيئة تشغيل `allure-js-commons` نشطة في Selenium.
- **Nightwatch بالاشتراك الاختياري**: لا يملك إشارة Allure مباشرة يمكن الاكتشاف التلقائي بناءً عليها (`nightwatch-allure` يعمل بعد التنفيذ)، لذا لا يُفعَّل تلقائيًا أبدًا — اضبطه صراحةً إذا كنت تريد البيان.

## التأكيدات — `captureAssertions`

تظهر التأكيدات كصفوف إجراءات أساسية في التتبع (مفعّلة افتراضيًا؛ اضبط `captureAssertions: false` لإلغائها):

- **`node:assert`** — تُلتقط في المحوّلات الثلاثة كصفوف `assert.<method>`.
- **`expect` في WebdriverIO** — تظهر مطابقات `expect(...)` الناجحة *والفاشلة* (`expect($el).toHaveText(...)`، `toBeExisting()`، …) كصفوف `expect.<matcher>` تحمل القيمة المتوقعة وموقع العنصر في الشيفرة المصدرية ولقطة؛ وتُخفى أوامر الاستطلاع الداخلية للمطابق بحيث يظهر التأكيد فقط.
- **`browser.assert.*` / `browser.verify.*` في Nightwatch** — تظهر التأكيدات الأصلية كصفوف `assert.<m>` / `verify.<m>`.

تُعرض التأكيدات الناجحة باللون الأخضر؛ والفاشلة باللون الأحمر مع رسالة الخطأ.

## اختبار الأجهزة المحمولة

يكتشف وضع التتبع جلسات الأجهزة المحمولة عبر `platformName: 'android' | 'ios'` (دون تمييز حالة الأحرف) ويتكيّف معها:

- **الويب على الأجهزة المحمولة** (Chrome على Android، وSafari على iOS): مسار اللقطات نفسه المعتمد على DOM كما في سطح المكتب.
- **التطبيقات الأصلية على الأجهزة المحمولة**: تُعطَّل سكربتات DOM المحقونة في الصفحة؛ ويُستخدم `getPageSource()` للحصول على شجرة XML الخاصة بـ Appium، والتي تُغذّي مُسلسِل اللقطات بدلًا منها.

يسجّل `context-options` في التتبع `title: 'android — <deviceName>'` / `'ios — <deviceName>'` بحيث يعنون العارض الإطارات بشكل صحيح. يتوفر ملف إعدادات WDIO مرجعي لـ Android Chrome عبر Appium في [`examples/wdio/wdio.mobile.conf.ts`](https://github.com/webdriverio/devtools/blob/main/examples/wdio/wdio.mobile.conf.ts).

## عرض العنصر الناتج

افتح التتبع في **[مشغّل التتبع](/docs/devtools/trace-player)** الرسمي — وهو واجهة WebdriverIO DevTools في وضع مشغّل مخصص للقراءة فقط:

```sh
show-trace trace-<sessionId>.zip          # bin on PATH after install
npx show-trace trace-<sessionId>.zip      # or via npx
```

يوفّر لك المشغّل التنقل عبر الزمن في DOM، وتبويب A11y وطبقة اختيار المحدِّد، وتبويب Transcript مع خيار Copy-for-LLM، وتبويبات Errors / Console / Network / Source في الشريط السفلي، ومخططًا زمنيًا قابلًا للتمرير. يُفتح ملف `.zip` القابل للنقل نفسه أيضًا في عارضات التتبع المستقلة الأخرى وداخل العارض المضمّن في تقرير Allure. راجع صفحة **[مشغّل التتبع](/docs/devtools/trace-player)** للحصول على الشرح الكامل والميزات واختصارات لوحة المفاتيح.

## اعرف المزيد
يفتح الملف التنفيذي `show-trace` المرفق مع كل محوّل الأرشيفَ نفسه في مشغّل DevTools، والذي يوفّر إضافةً إلى ذلك **تبويب A11y**: شجرة إمكانية الوصول الملتقطة لكل إجراء، حيث يؤدي النقر على أي صف إلى نسخ محدِّد ذلك العنصر.

تُكتب هذه المحدِّدات بلهجة المشغّل الذي سجّل التتبع، لذا يمكن لصقها مباشرة في إطار العمل الذي أنتج التتبع. فالعنصر المعرَّف بنصه فقط يكون `a*=Logout` في WebdriverIO و`//a[contains(., "Logout")]` في Selenium — مع تعليق يوضّح الاستدعاء الذي يحلّه، `By.xpath()`. يفضّل Nightwatch محدِّد CSS أصليًا مثل `button[type="submit"]`، لأنه المشغّل الوحيد الذي يقرأ سلسلة محدِّد مجردة وفق استراتيجية CSS افتراضية، ولا يلجأ إلى XPath (مع التعليق `useXpath()` / `locateStrategy: 'xpath'`) إلا عند عدم وجود محدِّد CSS فريد. أما كل المحدِّدات الأخرى فهي CSS قابلة للنقل.

للاستخدام من قِبل نماذج LLM / الوكلاء، اقرأ `transcript.md` مباشرة — فهو عرض Markdown موجز للإجراءات مع المحدِّدات والقيم.

- **[مشغّل التتبع](/docs/devtools/trace-player)** — الشرح الكامل لمشغّل `show-trace` وميزاته واختصارات لوحة المفاتيح.
- **[تكامل Allure](/docs/devtools/allure)** — كيفية إرفاق عناصر التتبع / لقطات الشاشة / الفيديو في تقرير Allure.
