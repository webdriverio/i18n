مسار التقاط بدون واجهة — لا تُفتح أي نافذة لواجهة DevTools. في نهاية الجلسة، يكتب المحوّل عناصر التتبع في مجلد `test-results/` بجوار دليل ملف الاختبار / الإعدادات. بالنسبة لمستوى التفصيل `session` / `spec` يكون الناتج ملف `trace-<sessionId>.zip` (أو دليل `trace-<sessionId>/`)؛ أما بالنسبة لمستوى التفصيل `test` فيحصل كل اختبار على مجلد فرعي خاص به (انظر [مستوى تفصيل التتبع](#trace-granularity--tracegranularity)). العنصر الناتج قابل للنقل ويحتوي على كل ما يلزم لإعادة التشغيل دون اتصال، أو للمقارنة بواسطة وكلاء الذكاء الاصطناعي، أو لأي مستهلك يفضّل ملفًا على واجهة حية.

وضع التتبع **لا يمكن استخدامه مع الوضع الحي في الوقت نفسه**. اختر واحدًا لكل جلسة: البشر الذين يصحّحون الأخطاء تفاعليًا يحتاجون إلى الوضع الحي؛ والوكلاء الذين يقارنون عمليات التشغيل أو روبوتات CI التي تجمع العناصر تحتاج إلى وضع التتبع.

## التفعيل

```ts
// wdio.conf.ts
services: [
  [
    'devtools',
    {
      mode: 'trace',
      traceFormat: 'zip' // optional; 'zip' (default) | 'ndjson-directory'
    }
  ]
]
```

يتوفر ملف إعدادات مرجعي كامل وجاهز للنسخ في [`examples/wdio/wdio.trace.conf.ts`](https://github.com/webdriverio/devtools/blob/main/examples/wdio/wdio.trace.conf.ts).

يوفّر كل من Selenium وNightwatch مسار التتبع نفسه — راجع صفحات المحوّلات الخاصة بهما لمعرفة صيغة التفعيل الخاصة بكل إطار عمل: [Selenium](/docs/devtools/selenium#trace-mode) · [Nightwatch](/docs/devtools/nightwatch#trace-mode).

## محتويات العنصر الناتج

| الملف | المحتويات |
|---|---|
| `trace.trace` | أحداث NDJSON من نوع `context-options` + أحداث الإجراءات `before` / `after`؛ سطر واحد لكل سجل |
| `trace.network` | إدخالات شبكة بأسلوب HAR، إدخال واحد في كل سطر |
| `transcript.md` | ملخص Markdown قابل للقراءة من قِبل البشر/النماذج اللغوية، يتضمن التوقيت والمحددات وتعليقات القيم |
| `resources/page@<id>-<ts>.jpeg` | لقطة شاشة تُلتقط عند كل إجراء موجّه للمستخدم |
| `resources/page@<id>-<ts>-elements.json` | قائمة مسطّحة بالعناصر القابلة للتفاعل عند ذلك الإجراء |
| `resources/page@<id>-<ts>-snapshot.txt` | لقطة لشجرة إمكانية الوصول بمسافات بادئة حسب العمق (مناسبة للذكاء الاصطناعي) |

### ما الذي يُعدّ "إجراءً"

تُرشَّح الأوامر عبر قائمة سماح قبل أن تُنتج إدخالات في التتبع. أمثلة على ما يظهر في التتبع:

- `url` / `get` ← `Page.navigate`
- `click` ← `Element.click`
- `setValue` / `sendKeys` ← `Element.fill`
- `submit`، `clear`، `selectByVisibleText`، …

الأوامر الداخلية مثل `findElement` و`waitUntil` و`executeScript` مستبعدة عمدًا — فهي لا تمثّل نية موجّهة للمستخدم وستُحدث ضجيجًا في الخط الزمني. توجد قائمة السماح الكاملة في [`@wdio/devtools-core/action-mapping.ts`](https://github.com/webdriverio/devtools/blob/main/packages/core/src/action-mapping.ts).

## تنسيق المخرجات — `traceFormat`

```ts
{
  mode: 'trace',
  traceFormat: 'zip' | 'ndjson-directory'  // default: 'zip'
}
```

- **`zip`** (الافتراضي) — أرشيف واحد في `test-results/trace-<sessionId>.zip`.
- **`ndjson-directory`** — الملفات نفسها غير مضغوطة في `test-results/trace-<sessionId>/`. يوفّر خطوة فك ضغط للمستهلكين البرمجيين أو الوكلاء الذين يريدون البحث باستخدام grep / بث ملفات NDJSON مباشرة.

يُفتح كلا التنسيقين في [مشغّل `show-trace`](/docs/devtools/trace-player) الرسمي وفي عارضات التتبع المتوافقة الأخرى.

## مستوى تفصيل التتبع — `traceGranularity`

عدد عناصر التتبع التي يُنتجها التشغيل:

```ts
{
  mode: 'trace',
  traceGranularity: 'session' | 'spec' | 'test' // default: 'session'
}
```

| القيمة | المخرجات |
|---|---|
| `session` (الافتراضي) | تتبع واحد لكل عامل/جلسة — `test-results/trace-<sessionId>.zip`. |
| `spec` | تتبع واحد لكل ملف اختبار. أصغر حجمًا وأسهل في التصفح. |
| `test` | تتبع واحد **لكل اختبار**، كلٌّ في مجلده الخاص: `test-results/<spec>-<title>-<browser>[-retry<N>]/trace.zip`. |

بالنسبة لمستوى التفصيل `test`، يُبنى اسم المجلد من الاسم الأساسي لملف الاختبار، ونسخة مختصرة (slug) من عنوان الاختبار، والمتصفح، ولاحقة `-retry<N>` في محاولات إعادة التشغيل — مثل `test-results/login_e2e-logs-in-chrome/trace.zip`، مع أول إعادة محاولة في `test-results/login_e2e-logs-in-chrome-retry1/trace.zip`. التتبعات لكل اختبار هي الأسهل تصفحًا، وتعمل بشكل أفضل مع سياسة احتفاظ بحيث لا تُكتب إلا التتبعات التي تهمّك.

## الاحتفاظ — `tracePolicy`

افتراضيًا يُحتفظ بكل تتبع (`'on'`). للاحتفاظ بالتتبعات المهمة فقط — وهو مثالي مع `traceGranularity: 'test'`:

```ts
{
  mode: 'trace',
  traceGranularity: 'test',
  tracePolicy: 'retain-on-failure' // default: 'on'
}
```

| السياسة | يُحتفظ بالتتبع عندما… |
|---|---|
| `'on'` (الافتراضي) | دائمًا — يُكتب كل تتبع. |
| `'retain-on-failure'` | فشلت المحاولة **الأخيرة** للاختبار. تسلسل إعادة المحاولة الذي يفشل ثم ينجح ينتهي بحالة `passed`، لذا *لا* يُحتفظ به — فلا تحتفظ بأكثر من اللازم باختبار متقلّب نجح في النهاية. |
| `'retain-on-first-failure'` | فشلت **المحاولة 0**، بغض النظر عمّا إذا نجحت إعادة محاولة لاحقة. |
| `'on-first-retry'` | أُعيدت محاولة الاختبار مرة واحدة على الأقل (توجد المحاولة 1). |
| `'on-all-retries'` | توجد أي محاولة معادة (المحاولة ≥ 1). |
| `'retain-on-failure-and-retries'` | فشلت المحاولة الأخيرة **أو** أُعيدت محاولة الاختبار. |

الشريحة غير المحتفظ بها يُتّخذ القرار بشأنها ولا تُكتب على القرص أبدًا. تعتمد السياسات المدركة لإعادة المحاولة على **سجل نتائج** لكل محاولة يحتفظ به المحوّل لكل معرّف اختبار ثابت عبر إعادة المحاولات، بحيث تُقيّم `retain-on-failure` و`retain-on-first-failure` المحاولة الصحيحة. عندما لا يكشف المشغّل عن معلومات إعادة المحاولة لكل محاولة، تتراجع كل سياسة باستثناء `retain-on-failure` إلى `retain-on-failure`؛ أما التشغيل الذي لا تُرصد فيه أي نتائج (مثل سكربت مستقل بسيط) فيفشل بشكل **مفتوح** ويحتفظ بالتتبع بدلًا من المخاطرة بحذف تتبع قد تحتاجه.

> تم التحقق من الاحتفاظ المدرك لإعادة المحاولة من البداية إلى النهاية لكل من **WebdriverIO** (mocha / cucumber) و**Selenium** (mocha). بالنسبة لـ **Nightwatch**، تعمل `retain-on-failure`، لكن السياسات الأخرى المدركة لإعادة المحاولة تتراجع إليها لأن خيار `--retries` في Nightwatch يعيد تشغيل حالة الاختبار داخليًا دون إعادة تشغيل الخطافات الخاصة بكل اختبار. كما أن `specFileRetries` العابر للعمليات في WDIO يقع خارج نطاق السجل (الخاص بكل عامل). راجع [صفحة محوّل Nightwatch](/docs/devtools/nightwatch#trace-mode) للتفاصيل.

## شريط الإطارات الكثيف — `filmstrip`

**افتراضيًا** يسجّل التتبع تسجيل شاشة **كثيفًا ومستمرًا** بحيث يتيح المشغّل تشغيلًا سلسًا عند التمرير بدلًا من القفز من إطار لآخر. توجد الإطارات الكثيفة جنبًا إلى جنب مع الإطارات الخاصة بكل إجراء (التي تحمل لقطات DOM). اضبط `filmstrip: false` لتسجيل إطار واحد فقط لكل إجراء — تتبع أصغر بدون مسجّل مستمر:

```ts
{
  mode: 'trace',
  filmstrip: false // opt out — one frame per action (default is true)
}
```

- تُضاف الإطارات الكثيفة **جنبًا إلى جنب** مع الإطارات الخاصة بكل إجراء (التي تحمل لقطات DOM)، لذا لا تُفقد أي بيانات DOM — وعند وجود الإطارات الكثيفة فإنها تحل محل شريط الإطارات المتفرق الخاص بكل إجراء عند التمرير.
- تُقلَّل الإطارات عند التصدير (بفاصل ≥100 مللي ثانية) وتُعنون حسب المحتوى، لذا تُدمج الإطارات المتطابقة (انتظار ثابت) في مورد واحد. يُحدّ مخزن الجلسة الحية بواسطة `screencast.maxBufferFrames` (الافتراضي 2000).
- يستخدم التسجيل مسجّل الشاشة — دفع CDP على Chrome/Chromium، واستطلاع لقطات الشاشة في غيرها. على المتصفحات غير Chrome يُصدر الاستطلاع العديد من أوامر `takeScreenshot`؛ استخدمه مع خيار إسكات الخطوات في أداة التقارير لديك (انظر [التكامل مع Allure](/docs/devtools/allure)).

يتوفر `filmstrip` على المحوّلات الثلاثة جميعها (WebdriverIO / Selenium / Nightwatch).

## لقطة الشاشة والفيديو لكل اختبار — `screenshot` / `video`

عند `traceGranularity: 'test'` يمكن لكل اختبار أيضًا أن يُنتج لقطة شاشة مستقلة و/أو شريحة فيديو خاصة به، على غرار الأسلوب المألوف للقطات الشاشة/الفيديو عند الفشل:

```ts
{
  mode: 'trace',
  traceGranularity: 'test',
  screenshot: 'only-on-failure', // 'off' (default) | 'on' | 'only-on-failure'
  video: 'retain-on-failure'     // 'off' (default) | any tracePolicy value
}
```

| الخيار | القيم | السلوك |
|---|---|---|
| `screenshot` | `'off'` (الافتراضي) · `'on'` · `'only-on-failure'` | `'on'` تلتقط بعد كل اختبار؛ `'only-on-failure'` فقط بعد اختبار فاشل. بتنسيق PNG. |
| `video` | `'off'` (الافتراضي) · أي قيمة من قيم `tracePolicy` | يسجّل الشاشة باستمرار ويحتفظ بشريحة كل اختبار وفق دلالات الاحتفاظ نفسها الخاصة بـ `tracePolicy`. بتنسيق WebM. ضبط قيمة غير `off` يشغّل المسجّل تلقائيًا — لا تحتاج أيضًا إلى `filmstrip` أو `screencast.enabled`. |

كلاهما مقيّد بوضع التتبع + `traceGranularity: 'test'` (النطاق الخاص بكل اختبار الذي يرتبطان به). في مستويات التفصيل الأشمل لا يكون لهما أي تأثير.

- **WebdriverIO** — `screenshot` / `video` هما خياران للخدمة؛ يُرفقان مباشرة في Allure عند وجود `@wdio/allure-reporter`.
- **Selenium** — الخيارات نفسها في `DevToolsOptions` الخاص به؛ تُرفق مباشرة في Allure عبر `allure-js-commons` عند تفعيل محوّل مشغّل Allure.
- **Nightwatch** — **إنتاج فقط**: تُكتب الملفات في دليل مخرجات التتبع (وتُدرج في البيان)، لكنها لا تُرفق مباشرة في Allure — إذ لا يمتلك Nightwatch واجهة برمجية للإرفاق الحي في Allure. راجع [قيود وضع التتبع](/docs/devtools/limitations).

> `screencast.enabled` هو تسجيل `.webm` المستمر المنفصل الخاص **بالوضع الحي** ويتم تجاهله في وضع التتبع. في وضع التتبع استخدم `filmstrip` (إطارات كثيفة داخل التتبع) أو `video` لكل اختبار؛ ولا تزال حقول ضبط تسجيل الشاشة (`quality`، `maxWidth`، `pollIntervalMs`، …) تنطبق على أي مسجّل يعمل.

## بيان العناصر — `emitArtifactsManifest`

يكتب ملف `devtools-artifacts-<sessionId>.json` بجوار التتبع — وهو فهرس عام تستهلكه أدوات التقارير وCI لاكتشاف العناصر المُنتجة (كل تتبع / لقطة شاشة / فيديو، بالإضافة إلى حالة كل اختبار):

```ts
{
  mode: 'trace',
  emitArtifactsManifest: true // default: off; auto-on when Allure is detected
}
```

- **معطّل افتراضيًا.** **يُفعّل تلقائيًا** عند اكتشاف أداة تقارير Allure — `@wdio/allure-reporter` الخاص بـ WebdriverIO في الإعدادات، أو بيئة تشغيل `allure-js-commons` نشطة في Selenium.
- **Nightwatch يتطلب التفعيل اليدوي**: لا توجد لديه إشارة Allure حية يمكن الاكتشاف التلقائي بناءً عليها (`nightwatch-allure` يعمل بعد التنفيذ)، لذا لا يُفعّل تلقائيًا أبدًا — اضبطه صراحةً إذا كنت تريد البيان.

## التأكيدات — `captureAssertions`

تظهر التأكيدات كصفوف إجراءات أساسية في التتبع (مفعّلة افتراضيًا؛ اضبط `captureAssertions: false` لإلغاء التفعيل):

- **`node:assert`** — تُلتقط عبر المحوّلات الثلاثة كصفوف `assert.<method>`.
- **`expect` في WebdriverIO** — تظهر مطابقات `expect(...)` الناجحة *والفاشلة* (`expect($el).toHaveText(...)`، `toBeExisting()`، …) كصفوف `expect.<matcher>` تحمل القيمة المتوقعة، وموقع العنصر في الشيفرة المصدرية، ولقطة؛ وتُخفى أوامر الاستطلاع الداخلية للمطابِق بحيث لا يظهر إلا التأكيد.
- **`browser.assert.*` / `browser.verify.*` في Nightwatch** — تظهر التأكيدات الأصلية كصفوف `assert.<m>` / `verify.<m>`.

تُعرض التأكيدات الناجحة باللون الأخضر؛ وتُعرض الفاشلة باللون الأحمر مع رسالة الخطأ.

## اختبار الأجهزة المحمولة

يكتشف وضع التتبع جلسات الأجهزة المحمولة عبر `platformName: 'android' | 'ios'` (بغض النظر عن حالة الأحرف) ويتكيّف وفقًا لذلك:

- **الويب على الأجهزة المحمولة** (Chrome على Android، وSafari على iOS): مسار اللقطات نفسه المعتمد على DOM كما في سطح المكتب.
- **التطبيقات الأصلية للأجهزة المحمولة**: تُعطَّل سكربتات DOM المحقونة في الصفحة؛ ويُستخدم `getPageSource()` للحصول على شجرة XML من Appium، والتي تُغذّي أداة تسلسل اللقطات بدلًا من ذلك.

يسجّل `context-options` في التتبع `title: 'android — <deviceName>'` / `'ios — <deviceName>'` بحيث يعنون العارض الإطارات بشكل صحيح. يتوفر ملف إعدادات WDIO مرجعي لـ Chrome على Android عبر Appium في [`examples/wdio/wdio.mobile.conf.ts`](https://github.com/webdriverio/devtools/blob/main/examples/wdio/wdio.mobile.conf.ts).

## عرض العنصر الناتج

افتح التتبع في **[مشغّل التتبع](/docs/devtools/trace-player)** الرسمي — واجهة WebdriverIO DevTools في وضع مشغّل مخصص للقراءة فقط:

```sh
show-trace trace-<sessionId>.zip          # bin on PATH after install
npx show-trace trace-<sessionId>.zip      # or via npx
```

يوفّر لك المشغّل التنقل الزمني في DOM، وتبويب A11y وطبقة اختيار المحدِّد، وتبويب Transcript مع خاصية Copy-for-LLM، وتبويبات Errors / Console / Network / Source في اللوحة، وخطًا زمنيًا قابلًا للتمرير. كما يُفتح ملف `.zip` المحمول نفسه في عارضات التتبع المستقلة الأخرى وداخل العارض المضمّن في تقرير Allure. راجع صفحة **[مشغّل التتبع](/docs/devtools/trace-player)** للحصول على الشرح الكامل والميزات واختصارات لوحة المفاتيح.

## اعرف المزيد
يفتح الأمر `show-trace` المرفق مع كل محوّل الأرشيف نفسه في مشغّل DevTools، والذي يوفّر إضافةً إلى ذلك **تبويب A11y**: شجرة إمكانية الوصول الملتقطة لكل إجراء، حيث يؤدي النقر على صف إلى نسخ محدِّد ذلك العنصر.

تُكتب هذه المحدِّدات بلهجة المشغّل الذي أجرى التسجيل، لذا يمكن لصقها مباشرة في إطار العمل الذي أنتج التتبع. العنصر الذي لا يُعرَّف إلا بنصه يكون `a*=Logout` في WebdriverIO و`//a[contains(., "Logout")]` في Selenium — مع تعليق يوضح الاستدعاء الذي يحلّه، `By.xpath()`. يفضّل Nightwatch محدِّد CSS أصليًا مثل `button[type="submit"]`، لأنه المشغّل الوحيد الذي يقرأ سلسلة محدِّد مجردة باستراتيجية CSS افتراضية، ولا يلجأ إلى XPath (مع التعليق `useXpath()` / `locateStrategy: 'xpath'`) إلا عند عدم وجود محدِّد CSS فريد. أما جميع المحدِّدات الأخرى فهي CSS قابلة للنقل.

للاستهلاك من قِبل النماذج اللغوية / الوكلاء، اقرأ `transcript.md` مباشرة — فهو عرض Markdown موجز للإجراءات مع المحدِّدات والقيم.

- **[مشغّل التتبع](/docs/devtools/trace-player)** — الشرح الكامل لمشغّل `show-trace` وميزاته واختصارات لوحة المفاتيح.
- **[التكامل مع Allure](/docs/devtools/allure)** — كيفية إرفاق عناصر التتبع / لقطات الشاشة / الفيديو بتقرير Allure.
