يفتح الوضع المباشر (Live mode) واجهة DevTools في نافذة متصفح خارجية ويبث عملية تشغيل اختباراتك في الوقت الفعلي. وهو النظير التفاعلي لـ[وضع التتبع](/docs/devtools/wdio/trace-mode)، الذي يتخطى الواجهة ويكتب بدلاً من ذلك ملفاً محمولاً للاستخدام دون اتصال. الوضع المباشر مُفعّل افتراضياً (`mode: 'live'`)، لذا فإن مجرد تشغيل اختبارات WebdriverIO الخاصة بك يُطلق لوحة التحكم.

عند تشغيل اختباراتك، تُفتح واجهة DevTools تلقائياً في نافذة متصفح خارجية وتبدأ الاختبارات بالتنفيذ فوراً مع عرض مرئي في الوقت الفعلي. بعد اكتمال التشغيل الأولي، استخدم أزرار التشغيل لإعادة تشغيل اختبارات فردية أو مجموعات اختبارات، وزر الإيقاف لإنهاء الاختبارات الجارية في أي وقت.

## ما تعرضه لوحة التحكم

- **معاينة مباشرة للمتصفح** — شاهد المتصفح قيد الاختبار أثناء تنفيذ الأوامر.
- **تقدم الاختبارات** — تتحدث مجموعات الاختبارات والاختبارات أثناء تشغيلها.
- **تنفيذ الأوامر** — يُبث كل إجراء فور حدوثه.
- **علامات تبويب منطقة العمل** — Actions وMetadata، بالإضافة إلى Source وLog وConsole وNetwork وErrors (يحمل كل منها شارة بالعدد)، وCompare بعد استخدام [الحفظ وإعادة التشغيل](/docs/devtools/wdio/preserve-and-rerun).

## ميزات الوضع المباشر

- **[إعادة تشغيل الاختبارات التفاعلية والعرض المرئي](/docs/devtools/wdio/interactive-test-rerunning)** — معاينات للمتصفح في الوقت الفعلي مع إمكانية إعادة تشغيل الاختبارات
- **[الحفظ وإعادة التشغيل (المقارنة)](/docs/devtools/wdio/preserve-and-rerun)** — التقط لقطة لاختبار فاشل، وأعد تشغيله، وقارن بين التشغيلين جنباً إلى جنب
- **[سجلات وحدة التحكم](/docs/devtools/wdio/console-logs)** — التقط مخرجات وحدة تحكم المتصفح وافحصها
- **[سجلات الشبكة](/docs/devtools/wdio/network-logs)** — راقب استدعاءات API ونشاط الشبكة
- **[البيانات الوصفية](/docs/devtools/wdio/metadata)** — إمكانات الجلسة والبيئة والتوقيت لكل جلسة متصفح
- **[TestLens](/docs/devtools/wdio/testlens)** — انتقل إلى الشيفرة المصدرية عبر تنقل ذكي في الشيفرة
- **[دعم أطر عمل متعددة](/docs/devtools/wdio/multi-framework-support)** — يعمل مع Mocha وJasmine وCucumber
- **[تسجيل شاشة الجلسة](/docs/devtools/wdio/screencast)** — تسجيل فيديو تلقائي لجلسات المتصفح

## ضبط نافذة لوحة التحكم

تتحكم الخيارات `port` و`hostname` و`devtoolsCapabilities` في خادم واجهة DevTools والنافذة التي تُفتح فيها. راجع [مرجع الإعدادات](/docs/devtools/reference) للاطلاع على التفاصيل.

## تشغيل الخادم الخلفي بشكل مستقل

تُشغّل المحوّلات (adapters) خادم لوحة التحكم ضمن العملية نفسها، لذا لن تحتاج عادةً إلى التعامل معه. ويأتي أيضاً كملف تنفيذي مستقل، وهو ما تحتاجه عندما يجب أن تستمر لوحة التحكم لما بعد تشغيل واحد - أو عندما لا تكون الاختبارات مكتوبة بـ JavaScript، كما هو الحال مع محوّل Python (راجع صفحة [Selenium](/docs/devtools/selenium)).

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

يُقبل كلا الشكلين `--port 8080` و`--port=8080`. الخيار `--port` هو *تفضيل* وليس ضماناً: إذا كان المنفذ مشغولاً، يرتبط الخادم بمنفذ متاح بدلاً من الفشل. ويطبع المنفذ الذي ارتبط به فعلياً، وهو السطر الذي يجب قراءته بدلاً من المنفذ الذي طلبته:

```
devtools-backend listening at http://localhost:3000
```

يتصل محوّل Python بخادم قيد الاستماع بالفعل عند تعيين `DEVTOOLS_PORT`، بدلاً من تشغيل خادم ثانٍ. أما محوّلات JavaScript فتُشغّل خادمها الخلفي ضمن العملية نفسها؛ استخدم الخيار `port` الخاص بها لاختيار المنفذ.

يفتح ملف تنفيذي ثانٍ، `show-trace`، أرشيف تتبع في المشغّل غير المتصل - راجع [مشغّل التتبع](/docs/devtools/trace-player).
