يفتح الوضع المباشر (Live mode) واجهة DevTools في نافذة متصفح خارجية ويبث عملية تشغيل اختباراتك في الوقت الفعلي. وهو النظير التفاعلي لـ [وضع التتبع](/docs/devtools/wdio/trace-mode)، الذي يتخطى الواجهة ويكتب بدلاً من ذلك ملفاً محمولاً يمكن استخدامه دون اتصال. الوضع المباشر مفعّل افتراضياً (`mode: 'live'`)، لذا فإن مجرد تشغيل اختبارات WebdriverIO الخاصة بك يُطلق لوحة التحكم.

عند تشغيل اختباراتك، تُفتح واجهة DevTools تلقائياً في نافذة متصفح خارجية وتبدأ الاختبارات بالتنفيذ فوراً مع عرض مرئي في الوقت الفعلي. بعد اكتمال التشغيل الأولي، استخدم أزرار التشغيل لإعادة تشغيل اختبارات فردية أو مجموعات اختبارات، وزر الإيقاف لإنهاء الاختبارات الجارية في أي وقت.

## ما تعرضه لوحة التحكم

- **معاينة مباشرة للمتصفح** — شاهد المتصفح قيد الاختبار أثناء تنفيذ الأوامر.
- **تقدّم الاختبارات** — تتحدّث مجموعات الاختبارات والاختبارات أثناء تشغيلها.
- **تنفيذ الأوامر** — يُبث كل إجراء فور حدوثه.
- **علامات تبويب منضدة العمل** — استكشف Actions وConsole وNetwork وMetadata وSource للاختبار المحدد.

## ميزات الوضع المباشر

- **[إعادة تشغيل الاختبارات التفاعلية والعرض المرئي](/docs/devtools/wdio/interactive-test-rerunning)** — معاينات للمتصفح في الوقت الفعلي مع إمكانية إعادة تشغيل الاختبارات
- **[الحفظ وإعادة التشغيل (المقارنة)](/docs/devtools/wdio/preserve-and-rerun)** — التقط لقطة لاختبار فاشل، وأعد تشغيله، وقارن بين عمليتي التشغيل جنباً إلى جنب
- **[سجلات وحدة التحكم](/docs/devtools/wdio/console-logs)** — التقط مخرجات وحدة تحكم المتصفح وافحصها
- **[سجلات الشبكة](/docs/devtools/wdio/network-logs)** — راقب استدعاءات API ونشاط الشبكة
- **[البيانات الوصفية](/docs/devtools/wdio/metadata)** — قدرات الجلسة والبيئة والتوقيت لكل جلسة متصفح
- **[TestLens](/docs/devtools/wdio/testlens)** — انتقل إلى الشيفرة المصدرية عبر التنقل الذكي في الشيفرة
- **[دعم أطر عمل متعددة](/docs/devtools/wdio/multi-framework-support)** — يعمل مع Mocha وJasmine وCucumber
- **[تسجيل شاشة الجلسة](/docs/devtools/wdio/screencast)** — تسجيل فيديو تلقائي لجلسات المتصفح

## ضبط نافذة لوحة التحكم

تتحكم الخيارات `port` و`hostname` و`devtoolsCapabilities` في خادم واجهة DevTools والنافذة التي تُفتح فيها. راجع [مرجع الإعدادات](/docs/devtools/reference) لمزيد من التفاصيل.

## تشغيل الخادم الخلفي بشكل مستقل

تبدأ المحوّلات (adapters) خادم لوحة التحكم داخل العملية نفسها، لذا لن تحتاج عادةً إلى التعامل معه. كما يُوفَّر أيضاً كملف تنفيذي مستقل، وهو ما تحتاجه عندما يجب أن تستمر لوحة التحكم لما بعد عملية تشغيل واحدة - أو عندما لا تكون الاختبارات مكتوبة بـ JavaScript، كما هو الحال مع محوّل Python (راجع صفحة [Selenium](/docs/devtools/selenium)).

```bash
npx @wdio/devtools-backend
```

```
Usage: devtools-backend [options]

Options:
  --port <number>     Preferred port; a free one is chosen if it is taken
  --hostname <host>   Host to bind (default: localhost)
  -h, --help          Show this message
```

الخيار `--port` هو *تفضيل* وليس ضماناً: إذا كان ذلك المنفذ مشغولاً، يرتبط الخادم بمنفذ متاح بدلاً من أن يفشل. ويطبع المنفذ الذي ارتبط به فعلياً، وهذا هو السطر الذي يجب قراءته بدلاً من المنفذ الذي طلبته:

```
devtools-backend listening at http://localhost:3000
```

وجّه عملية التشغيل إلى خادم يعمل بالفعل باستخدام `DEVTOOLS_PORT` (تحترمه جميع المحوّلات)، وستتصل عملية التشغيل به بدلاً من بدء خادم ثانٍ.

يوجد ملف تنفيذي ثانٍ، `show-trace`، يفتح أرشيف تتبع في المشغّل غير المتصل - راجع [مشغّل التتبع](/docs/devtools/trace-player).
