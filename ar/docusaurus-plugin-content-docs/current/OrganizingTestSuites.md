مع نمو المشاريع، تُضاف حتمًا المزيد والمزيد من اختبارات التكامل. وهذا يزيد من وقت البناء ويُبطئ الإنتاجية.

لمنع ذلك، يجب عليك تشغيل اختباراتك بالتوازي. يختبر WebdriverIO بالفعل كل ملف مواصفات (أو _ملف ميزة_ في Cucumber) بالتوازي ضمن جلسة واحدة. بشكل عام، حاول اختبار ميزة واحدة فقط لكل ملف مواصفات. حاول ألا يكون لديك عدد كبير جدًا أو قليل جدًا من الاختبارات في ملف واحد. (ومع ذلك، لا توجد قاعدة ذهبية هنا.)

بمجرد أن تحتوي اختباراتك على عدة ملفات مواصفات، يجب أن تبدأ في تشغيل اختباراتك بشكل متزامن. للقيام بذلك، اضبط خاصية `maxInstances` في ملف الإعداد الخاص بك. يتيح لك WebdriverIO تشغيل اختباراتك بأقصى قدر من التزامن—مما يعني أنه بغض النظر عن عدد الملفات والاختبارات لديك، يمكن تشغيلها جميعًا بالتوازي.  (لا يزال هذا خاضعًا لحدود معينة، مثل وحدة المعالجة المركزية لجهاز الكمبيوتر الخاص بك، وقيود التزامن، وما إلى ذلك.)

> لنفترض أن لديك 3 إمكانيات (capabilities) مختلفة (Chrome وFirefox وSafari) وقمت بتعيين `maxInstances` إلى `1`. سيُنشئ مشغّل اختبارات WDIO ثلاث عمليات. لذلك، إذا كان لديك 10 ملفات مواصفات وقمت بتعيين `maxInstances` إلى `10`، فسيتم اختبار _جميع_ ملفات المواصفات في وقت واحد، وسيتم إنشاء 30 عملية.

يمكنك تعريف خاصية `maxInstances` بشكل عام لتعيين السمة لجميع المتصفحات.

إذا كنت تُشغّل شبكة WebDriver الخاصة بك، فقد يكون لديك (على سبيل المثال) سعة أكبر لمتصفح ما مقارنة بآخر. في هذه الحالة، يمكنك _تقييد_ `maxInstances` في كائن الإمكانيات الخاص بك:

```js
// wdio.conf.js
export const config = {
    // ...
    // set maxInstance for all browser
    maxInstances: 10,
    // ...
    capabilities: [{
        browserName: 'firefox'
    }, {
        // maxInstances can get overwritten per capability. So if you have an in-house WebDriver
        // grid with only 5 firefox instance available you can make sure that not more than
        // 5 instance gets started at a time.
        browserName: 'chrome'
    }],
    // ...
}
```

## الوراثة من ملف الإعداد الرئيسي

إذا كنت تُشغّل مجموعة اختباراتك في بيئات متعددة (مثل بيئة التطوير وبيئة التكامل)، فقد يكون من المفيد استخدام ملفات إعداد متعددة للحفاظ على سهولة إدارة الأمور.

على غرار [مفهوم كائن الصفحة](pageobjects)، أول ما ستحتاجه هو ملف إعداد رئيسي. يحتوي هذا الملف على جميع الإعدادات التي تشاركها عبر البيئات.

ثم أنشئ ملف إعداد آخر لكل بيئة، وأكمل الإعداد الرئيسي بالإعدادات الخاصة بكل بيئة:

```js
// wdio.dev.config.js
import { deepmerge } from 'deepmerge-ts'
import wdioConf from './wdio.conf.js'

// have main config file as default but overwrite environment specific information
export const config = deepmerge(wdioConf.config, {
    capabilities: [
        // more caps defined here
        // ...
    ],

    // run tests on sauce instead locally
    user: process.env.SAUCE_USERNAME,
    key: process.env.SAUCE_ACCESS_KEY,
    services: ['sauce']
}, { clone: false })

// add an additional reporter
config.reporters.push('allure')
```

## تجميع ملفات المواصفات في مجموعات

يمكنك تجميع ملفات مواصفات الاختبار في مجموعات (suites) وتشغيل مجموعات محددة بدلاً من تشغيلها جميعًا.

أولاً، عرّف مجموعاتك في إعداد WDIO:

```js
// wdio.conf.js
export const config = {
    // define all tests
    specs: ['./test/specs/**/*.spec.js'],
    // ...
    // define specific suites
    suites: {
        login: [
            './test/specs/login.success.spec.js',
            './test/specs/login.failure.spec.js'
        ],
        otherFeature: [
            // ...
        ]
    },
    // ...
}
```

الآن، إذا كنت تريد تشغيل مجموعة واحدة فقط، يمكنك تمرير اسم المجموعة كوسيط في سطر الأوامر:

```sh
wdio wdio.conf.js --suite login
```

أو تشغيل عدة مجموعات في وقت واحد:

```sh
wdio wdio.conf.js --suite login --suite otherFeature
```

## تجميع ملفات المواصفات لتشغيلها بشكل تسلسلي

كما هو موضح أعلاه، هناك فوائد لتشغيل الاختبارات بشكل متزامن. ومع ذلك، هناك حالات يكون من المفيد فيها تجميع الاختبارات معًا لتشغيلها بشكل تسلسلي في نسخة واحدة. ومن أمثلة ذلك بشكل رئيسي الحالات التي تكون فيها تكلفة الإعداد كبيرة، مثل تحويل الشيفرة البرمجية (transpiling) أو تجهيز نسخ سحابية، ولكن هناك أيضًا نماذج استخدام متقدمة تستفيد من هذه الإمكانية.

لتجميع الاختبارات لتشغيلها في نسخة واحدة، عرّفها كمصفوفة ضمن تعريف specs.

```json
    "specs": [
        [
            "./test/specs/test_login.js",
            "./test/specs/test_product_order.js",
            "./test/specs/test_checkout.js"
        ],
        "./test/specs/test_b*.js",
    ],
```
في المثال أعلاه، سيتم تشغيل الاختبارات 'test_login.js' و'test_product_order.js' و'test_checkout.js' بشكل تسلسلي في نسخة واحدة، وسيتم تشغيل كل اختبار من اختبارات "test_b*" بشكل متزامن في نسخ منفصلة.

من الممكن أيضًا تجميع ملفات المواصفات المعرّفة في المجموعات، لذا يمكنك الآن أيضًا تعريف المجموعات على النحو التالي:
```json
    "suites": {
        end2end: [
            [
                "./test/specs/test_login.js",
                "./test/specs/test_product_order.js",
                "./test/specs/test_checkout.js"
            ]
        ],
        allb: ["./test/specs/test_b*.js"]
},
```
وفي هذه الحالة سيتم تشغيل جميع اختبارات مجموعة "end2end" في نسخة واحدة.

عند تشغيل الاختبارات بشكل تسلسلي باستخدام نمط، سيتم تشغيل ملفات المواصفات بترتيب أبجدي

```json
  "suites": {
    end2end: ["./test/specs/test_*.js"]
  },
```

سيؤدي هذا إلى تشغيل الملفات المطابقة للنمط أعلاه بالترتيب التالي:

```
  [
      "./test/specs/test_checkout.js",
      "./test/specs/test_login.js",
      "./test/specs/test_product_order.js"
  ]
```

## تشغيل اختبارات محددة

في بعض الحالات، قد ترغب في تنفيذ اختبار واحد فقط (أو مجموعة فرعية من الاختبارات) من مجموعاتك.

باستخدام المعامل `--spec`، يمكنك تحديد أي _مجموعة_ (Mocha، Jasmine) أو _ميزة_ (Cucumber) يجب تشغيلها. يتم حل المسار نسبةً إلى دليل العمل الحالي.

على سبيل المثال، لتشغيل اختبار تسجيل الدخول فقط:

```sh
wdio wdio.conf.js --spec ./test/specs/e2e/login.js
```

أو تشغيل عدة ملفات مواصفات في وقت واحد:

```sh
wdio wdio.conf.js --spec ./test/specs/signup.js --spec ./test/specs/forgot-password.js
```

إذا لم تُشِر قيمة `--spec` إلى ملف مواصفات معين، فسيتم استخدامها بدلاً من ذلك لتصفية أسماء ملفات المواصفات المعرّفة في إعدادك.

لتشغيل جميع ملفات المواصفات التي تحتوي أسماؤها على كلمة "dialog"، يمكنك استخدام:

```sh
wdio wdio.conf.js --spec dialog
```

لاحظ أن كل ملف اختبار يعمل في عملية مشغّل اختبارات واحدة. وبما أننا لا نفحص الملفات مسبقًا (راجع القسم التالي للحصول على معلومات حول تمرير أسماء الملفات عبر الأنابيب إلى `wdio`)، فإنك _لا يمكنك_ استخدام (على سبيل المثال) `describe.only` في أعلى ملف المواصفات الخاص بك لتوجيه Mocha لتشغيل تلك المجموعة فقط.

ستساعدك هذه الميزة على تحقيق الهدف نفسه.

عند توفير الخيار `--spec`، فإنه سيتجاوز أي أنماط معرّفة بواسطة `specs` في الإعداد أو `wdio:specs` في الإمكانيات.

## استبعاد اختبارات محددة

عند الحاجة، إذا كنت تحتاج إلى استبعاد ملف (ملفات) مواصفات معينة من التشغيل، يمكنك استخدام المعامل `--exclude` (Mocha، Jasmine) أو الميزة (Cucumber).

على سبيل المثال، لاستبعاد اختبار تسجيل الدخول من تشغيل الاختبارات:

```sh
wdio wdio.conf.js --exclude ./test/specs/e2e/login.js
```

أو استبعاد عدة ملفات مواصفات:

 ```sh
wdio wdio.conf.js --exclude ./test/specs/signup.js --exclude ./test/specs/forgot-password.js
```

أو استبعاد ملف مواصفات عند التصفية باستخدام مجموعة:

```sh
wdio wdio.conf.js --suite login --exclude ./test/specs/e2e/login.js
```

إذا لم تُشِر قيمة `--exclude` إلى ملف مواصفات معين، فسيتم استخدامها بدلاً من ذلك لتصفية أسماء ملفات المواصفات المعرّفة في إعدادك.

لاستبعاد جميع ملفات المواصفات التي تحتوي أسماؤها على كلمة "dialog"، يمكنك استخدام:

```sh
wdio wdio.conf.js --exclude dialog
```

### استبعاد مجموعة كاملة

يمكنك أيضًا استبعاد مجموعة كاملة بالاسم. إذا تطابقت قيمة الاستبعاد مع اسم مجموعة معرّفة في إعدادك ولم تبدُ كمسار ملف، فسيتم تخطي المجموعة بأكملها:

```sh
wdio wdio.conf.js --suite login --suite checkout --exclude login
```

سيؤدي هذا إلى تشغيل مجموعة `checkout` فقط، مع تخطي مجموعة `login` بالكامل.

تعمل الاستبعادات المختلطة (المجموعات وأنماط ملفات المواصفات) كما هو متوقع:

```sh
wdio wdio.conf.js --suite login --exclude dialog --exclude signup
```

في هذا المثال، إذا كان `signup` اسم مجموعة معرّفة، فسيتم استبعاد تلك المجموعة. وسيقوم النمط `dialog` بتصفية أي ملفات مواصفات تحتوي أسماؤها على "dialog".

:::note
إذا حددت كلاً من `--suite X` و`--exclude X`، فإن الاستبعاد له الأولوية ولن يتم تشغيل المجموعة `X`.
:::

عند توفير الخيار `--exclude`، فإنه سيتجاوز أي أنماط معرّفة بواسطة `exclude` في الإعداد أو `wdio:exclude` في الإمكانيات.

## تشغيل المجموعات وملفات المواصفات

شغّل مجموعة كاملة إلى جانب ملفات مواصفات فردية.

```sh
wdio wdio.conf.js --suite login --spec ./test/specs/signup.js
```

## تشغيل عدة ملفات مواصفات محددة

من الضروري أحيانًا&mdash;في سياق التكامل المستمر وغيره&mdash;تحديد مجموعات متعددة من ملفات المواصفات لتشغيلها. تقبل أداة سطر الأوامر `wdio` الخاصة بـ WebdriverIO أسماء الملفات الممررة عبر الأنابيب (من `find` أو `grep` أو غيرها).

تتجاوز أسماء الملفات الممررة عبر الأنابيب قائمة أنماط glob أو أسماء الملفات المحددة في قائمة `spec` في الإعداد.

```sh
grep -r -l --include "*.js" "myText" | wdio wdio.conf.js
```

_**ملاحظة:** هذا_ لا _يتجاوز العلامة `--spec` لتشغيل ملف مواصفات واحد._

## تشغيل اختبارات محددة باستخدام MochaOpts

يمكنك أيضًا تصفية `suite|describe` و/أو `it|test` المحددة التي تريد تشغيلها عن طريق تمرير وسيط خاص بـ mocha: `--mochaOpts.grep` إلى واجهة سطر أوامر wdio.

```sh
wdio wdio.conf.js --mochaOpts.grep myText
wdio wdio.conf.js --mochaOpts.grep "Text with spaces"
```

_**ملاحظة:** سيقوم Mocha بتصفية الاختبارات بعد أن يُنشئ مشغّل اختبارات WDIO النسخ، لذلك قد ترى عدة نسخ يتم إنشاؤها دون أن يتم تنفيذها فعليًا._

## استبعاد اختبارات محددة باستخدام MochaOpts

يمكنك أيضًا تصفية `suite|describe` و/أو `it|test` المحددة التي تريد استبعادها عن طريق تمرير وسيط خاص بـ mocha: `--mochaOpts.invert` إلى واجهة سطر أوامر wdio. يؤدي `--mochaOpts.invert` عكس ما يؤديه `--mochaOpts.grep`

```sh
wdio wdio.conf.js --mochaOpts.grep "string|regex" --mochaOpts.invert
wdio wdio.conf.js --spec ./test/specs/e2e/login.js --mochaOpts.grep "string|regex" --mochaOpts.invert
```

_**ملاحظة:** سيقوم Mocha بتصفية الاختبارات بعد أن يُنشئ مشغّل اختبارات WDIO النسخ، لذلك قد ترى عدة نسخ يتم إنشاؤها دون أن يتم تنفيذها فعليًا._

## إيقاف الاختبار بعد الفشل

باستخدام الخيار `bail`، يمكنك إخبار WebdriverIO بإيقاف الاختبار بعد فشل أي اختبار.

يكون هذا مفيدًا مع مجموعات الاختبارات الكبيرة عندما تعلم مسبقًا أن عملية البناء ستفشل، لكنك تريد تجنب الانتظار الطويل لتشغيل الاختبارات بالكامل.

يتوقع الخيار `bail` رقمًا يحدد عدد حالات فشل الاختبار التي يمكن أن تحدث قبل أن يوقف WebDriver تشغيل الاختبارات بالكامل. القيمة الافتراضية هي `0`، مما يعني أنه يُشغّل دائمًا جميع ملفات مواصفات الاختبار التي يمكنه العثور عليها.

يُرجى مراجعة [صفحة الخيارات](configuration) للحصول على معلومات إضافية حول إعداد bail.
## تسلسل أولوية خيارات التشغيل

عند تحديد ملفات المواصفات التي سيتم تشغيلها، هناك تسلسل هرمي معين يحدد النمط الذي ستكون له الأولوية. حاليًا، هذه هي طريقة عمله، من الأولوية الأعلى إلى الأدنى:

> CLI `--spec` argument > capability `wdio:specs` > config `specs`
> CLI `--exclude` argument > config `exclude` > capability `wdio:exclude`

إذا تم توفير معامل الإعداد فقط، فسيتم استخدامه لجميع الإمكانيات. ومع ذلك، إذا تم تعريف النمط على مستوى الإمكانية، فسيتم استخدامه بدلاً من نمط الإعداد. وأخيرًا، فإن أي نمط مواصفات معرّف في سطر الأوامر سيتجاوز جميع الأنماط الأخرى المعطاة.

### استخدام أنماط المواصفات المعرّفة على مستوى الإمكانيات

عندما تُعرّف نمط مواصفات على مستوى الإمكانية، فإنه سيتجاوز أي أنماط معرّفة على مستوى الإعداد. يكون هذا مفيدًا عند الحاجة إلى فصل الاختبارات بناءً على اختلاف إمكانيات الأجهزة. في حالات كهذه، يكون من الأفضل استخدام نمط مواصفات عام على مستوى الإعداد، وأنماط أكثر تحديدًا على مستوى الإمكانيات.

على سبيل المثال، لنفترض أن لديك دليلين، أحدهما لاختبارات Android والآخر لاختبارات iOS.

قد يُعرّف ملف الإعداد الخاص بك النمط على هذا النحو، للاختبارات غير الخاصة بجهاز معين:

```js
{
    specs: ['tests/general/**/*.js']
}
```

ولكن بعد ذلك، سيكون لديك إمكانيات مختلفة لأجهزة Android وiOS، حيث يمكن أن تبدو الأنماط على النحو التالي:

```json
{
  "platformName": "Android",
  "wdio:specs": [
    "tests/android/**/*.js"
  ]
}
```

```json
{
  "platformName": "iOS",
  "wdio:specs": [
    "tests/ios/**/*.js"
  ]
}
```

إذا كنت تحتاج إلى كلتا هاتين الإمكانيتين في ملف الإعداد الخاص بك، فإن جهاز Android سيُشغّل فقط الاختبارات الموجودة ضمن نطاق "android"، وستُشغّل اختبارات iOS فقط الاختبارات الموجودة ضمن نطاق "ios"!

```js
//wdio.conf.js
export const config = {
    "specs": [
        "tests/general/**/*.js"
    ],
    "capabilities": [
        {
            platformName: "Android",
            "wdio:specs": ["tests/android/**/*.js"],
            //...
        },
        {
            platformName: "iOS",
            "wdio:specs": ["tests/ios/**/*.js"],
            //...
        },
        {
            platformName: "Chrome",
            //config level specs will be used
        }
    ]
}
```
