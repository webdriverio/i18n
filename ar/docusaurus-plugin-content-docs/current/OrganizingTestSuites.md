مع نمو المشاريع، تُضاف حتمًا المزيد والمزيد من اختبارات التكامل. وهذا يزيد من وقت البناء ويبطئ الإنتاجية.

لمنع ذلك، يجب عليك تشغيل اختباراتك بالتوازي. يختبر WebdriverIO بالفعل كل ملف مواصفات (أو _ملف ميزة_ في Cucumber) بالتوازي ضمن جلسة واحدة. بشكل عام، حاول اختبار ميزة واحدة فقط لكل ملف مواصفات. وحاول ألا يكون لديك عدد كبير جدًا أو قليل جدًا من الاختبارات في ملف واحد. (ومع ذلك، لا توجد قاعدة ذهبية هنا.)

بمجرد أن تحتوي اختباراتك على عدة ملفات مواصفات، يجب أن تبدأ في تشغيل اختباراتك بشكل متزامن. للقيام بذلك، اضبط خاصية `maxInstances` في ملف الإعدادات الخاص بك. يتيح لك WebdriverIO تشغيل اختباراتك بأقصى قدر من التزامن—مما يعني أنه بغض النظر عن عدد الملفات والاختبارات لديك، يمكن تشغيلها جميعًا بالتوازي. (لا يزال هذا خاضعًا لحدود معينة، مثل وحدة المعالجة المركزية لجهاز الكمبيوتر الخاص بك، وقيود التزامن، وما إلى ذلك.)

> لنفترض أن لديك 3 قدرات مختلفة (Chrome وFirefox وSafari) وقمت بتعيين `maxInstances` إلى `1`. سيقوم مشغل اختبارات WDIO بإنشاء 3 عمليات. لذلك، إذا كان لديك 10 ملفات مواصفات وقمت بتعيين `maxInstances` إلى `10`، فسيتم اختبار _جميع_ ملفات المواصفات في وقت واحد، وسيتم إنشاء 30 عملية.

يمكنك تعريف خاصية `maxInstances` بشكل عام لتعيين السمة لجميع المتصفحات.

إذا كنت تشغّل شبكة WebDriver الخاصة بك، فقد تكون لديك (على سبيل المثال) سعة أكبر لمتصفح ما مقارنة بآخر. في هذه الحالة، يمكنك _تقييد_ `maxInstances` في كائن القدرات الخاص بك:

```js
// wdio.conf.js
export const config = {
    // ...
    // تعيين maxInstance لجميع المتصفحات
    maxInstances: 10,
    // ...
    capabilities: [{
        browserName: 'firefox'
    }, {
        // يمكن تجاوز maxInstances لكل قدرة. لذا إذا كانت لديك شبكة WebDriver داخلية
        // تتوفر فيها 5 نسخ فقط من firefox، يمكنك التأكد من عدم تشغيل أكثر من
        // 5 نسخ في وقت واحد.
        browserName: 'chrome'
    }],
    // ...
}
```

لتشغيل الاختبارات الموجودة *داخل* ملف مواصفات واحد في الوقت نفسه أيضًا، كل منها في نافذة متصفح خاصة به، راجع [الاختبارات المتوازية في ملف مواصفات](./ParallelTests.md).

## الوراثة من ملف الإعدادات الرئيسي

إذا كنت تشغّل مجموعة اختباراتك في بيئات متعددة (مثل بيئة التطوير وبيئة التكامل)، فقد يكون من المفيد استخدام ملفات إعدادات متعددة للحفاظ على سهولة الإدارة.

على غرار [مفهوم كائن الصفحة](pageobjects)، أول ما ستحتاجه هو ملف إعدادات رئيسي. يحتوي على جميع الإعدادات التي تشاركها عبر البيئات.

ثم أنشئ ملف إعدادات آخر لكل بيئة، وأكمل الإعدادات الرئيسية بالإعدادات الخاصة بكل بيئة:

```js
// wdio.dev.config.js
import { deepmerge } from 'deepmerge-ts'
import wdioConf from './wdio.conf.js'

// استخدام ملف الإعدادات الرئيسي كافتراضي مع تجاوز المعلومات الخاصة بالبيئة
export const config = deepmerge(wdioConf.config, {
    capabilities: [
        // المزيد من القدرات معرّفة هنا
        // ...
    ],

    // تشغيل الاختبارات على sauce بدلاً من التشغيل المحلي
    user: process.env.SAUCE_USERNAME,
    key: process.env.SAUCE_ACCESS_KEY,
    services: ['sauce']
}, { clone: false })

// إضافة مُبلِّغ إضافي
config.reporters.push('allure')
```

## تجميع ملفات مواصفات الاختبار في مجموعات

يمكنك تجميع ملفات مواصفات الاختبار في مجموعات وتشغيل مجموعات محددة بعينها بدلاً من تشغيلها جميعًا.

أولاً، عرّف مجموعاتك في إعدادات WDIO:

```js
// wdio.conf.js
export const config = {
    // تعريف جميع الاختبارات
    specs: ['./test/specs/**/*.spec.js'],
    // ...
    // تعريف مجموعات محددة
    suites: {
        login: [
            './test/specs/login.success.spec.js',
            './test/specs/login.failure.spec.js'
        ],
        otherFeature: [
            // ...
        ]
    },
    // ...
}
```

الآن، إذا كنت تريد تشغيل مجموعة واحدة فقط، يمكنك تمرير اسم المجموعة كوسيط في سطر الأوامر:

```sh
wdio wdio.conf.js --suite login
```

أو تشغيل مجموعات متعددة في آن واحد:

```sh
wdio wdio.conf.js --suite login --suite otherFeature
```

## تجميع ملفات مواصفات الاختبار لتشغيلها بشكل تسلسلي

كما هو موضح أعلاه، هناك فوائد لتشغيل الاختبارات بشكل متزامن. ومع ذلك، هناك حالات يكون فيها من المفيد تجميع الاختبارات معًا لتشغيلها بشكل تسلسلي في نسخة واحدة. ومن أمثلة ذلك بشكل رئيسي الحالات التي تكون فيها تكلفة الإعداد كبيرة، مثل تحويل الشيفرة البرمجية أو تجهيز نسخ سحابية، ولكن هناك أيضًا نماذج استخدام متقدمة تستفيد من هذه الإمكانية.

لتجميع الاختبارات لتشغيلها في نسخة واحدة، عرّفها كمصفوفة ضمن تعريف specs.

```json
    "specs": [
        [
            "./test/specs/test_login.js",
            "./test/specs/test_product_order.js",
            "./test/specs/test_checkout.js"
        ],
        "./test/specs/test_b*.js",
    ],
```
في المثال أعلاه، سيتم تشغيل الاختبارات 'test_login.js' و'test_product_order.js' و'test_checkout.js' بشكل تسلسلي في نسخة واحدة، وسيتم تشغيل كل اختبار من اختبارات "test_b*" بشكل متزامن في نسخ منفصلة.

من الممكن أيضًا تجميع ملفات المواصفات المعرّفة في المجموعات، لذا يمكنك الآن أيضًا تعريف مجموعات كهذه:
```json
    "suites": {
        end2end: [
            [
                "./test/specs/test_login.js",
                "./test/specs/test_product_order.js",
                "./test/specs/test_checkout.js"
            ]
        ],
        allb: ["./test/specs/test_b*.js"]
},
```
وفي هذه الحالة، سيتم تشغيل جميع اختبارات مجموعة "end2end" في نسخة واحدة.

عند تشغيل الاختبارات بشكل تسلسلي باستخدام نمط، سيتم تشغيل ملفات المواصفات بترتيب أبجدي

```json
  "suites": {
    end2end: ["./test/specs/test_*.js"]
  },
```

سيؤدي هذا إلى تشغيل الملفات المطابقة للنمط أعلاه بالترتيب التالي:

```
  [
      "./test/specs/test_checkout.js",
      "./test/specs/test_login.js",
      "./test/specs/test_product_order.js"
  ]
```

## تشغيل اختبارات محددة

في بعض الحالات، قد ترغب في تنفيذ اختبار واحد فقط (أو مجموعة فرعية من الاختبارات) من مجموعاتك.

باستخدام المعامل `--spec`، يمكنك تحديد أي _مجموعة_ (Mocha، Jasmine) أو _ميزة_ (Cucumber) يجب تشغيلها. يتم تحليل المسار نسبةً إلى دليل العمل الحالي.

على سبيل المثال، لتشغيل اختبار تسجيل الدخول فقط:

```sh
wdio wdio.conf.js --spec ./test/specs/e2e/login.js
```

أو تشغيل ملفات مواصفات متعددة في آن واحد:

```sh
wdio wdio.conf.js --spec ./test/specs/signup.js --spec ./test/specs/forgot-password.js
```

إذا كانت قيمة `--spec` لا تشير إلى ملف مواصفات معين، فسيتم استخدامها بدلاً من ذلك لتصفية أسماء ملفات المواصفات المعرّفة في إعداداتك.

لتشغيل جميع ملفات المواصفات التي تحتوي أسماؤها على كلمة "dialog"، يمكنك استخدام:

```sh
wdio wdio.conf.js --spec dialog
```

لاحظ أن كل ملف اختبار يعمل في عملية مشغل اختبار واحدة. وبما أننا لا نفحص الملفات مسبقًا (راجع القسم التالي للحصول على معلومات حول تمرير أسماء الملفات عبر الأنابيب إلى `wdio`)، فإنك _لا يمكنك_ استخدام `describe.only` (على سبيل المثال) في أعلى ملف المواصفات الخاص بك لتوجيه Mocha لتشغيل تلك المجموعة فقط.

ستساعدك هذه الميزة على تحقيق الهدف نفسه.

عند توفير الخيار `--spec`، فإنه سيتجاوز أي أنماط معرّفة بواسطة `specs` في الإعدادات أو `wdio:specs` الخاصة بالقدرة.

## استبعاد اختبارات محددة

عند الحاجة، إذا كنت بحاجة إلى استبعاد ملف (أو ملفات) مواصفات معينة من التشغيل، يمكنك استخدام المعامل `--exclude` (Mocha، Jasmine) أو الميزة (Cucumber).

على سبيل المثال، لاستبعاد اختبار تسجيل الدخول من تشغيل الاختبارات:

```sh
wdio wdio.conf.js --exclude ./test/specs/e2e/login.js
```

أو استبعاد ملفات مواصفات متعددة:

 ```sh
wdio wdio.conf.js --exclude ./test/specs/signup.js --exclude ./test/specs/forgot-password.js
```

أو استبعاد ملف مواصفات عند التصفية باستخدام مجموعة:

```sh
wdio wdio.conf.js --suite login --exclude ./test/specs/e2e/login.js
```

إذا كانت قيمة `--exclude` لا تشير إلى ملف مواصفات معين، فسيتم استخدامها بدلاً من ذلك لتصفية أسماء ملفات المواصفات المعرّفة في إعداداتك.

لاستبعاد جميع ملفات المواصفات التي تحتوي أسماؤها على كلمة "dialog"، يمكنك استخدام:

```sh
wdio wdio.conf.js --exclude dialog
```

### استبعاد مجموعة كاملة

يمكنك أيضًا استبعاد مجموعة كاملة بالاسم. إذا تطابقت قيمة الاستبعاد مع اسم مجموعة معرّفة في إعداداتك ولم تكن تبدو كمسار ملف، فسيتم تخطي المجموعة بأكملها:

```sh
wdio wdio.conf.js --suite login --suite checkout --exclude login
```

سيؤدي هذا إلى تشغيل مجموعة `checkout` فقط، مع تخطي مجموعة `login` بالكامل.

تعمل الاستبعادات المختلطة (المجموعات وأنماط ملفات المواصفات) كما هو متوقع:

```sh
wdio wdio.conf.js --suite login --exclude dialog --exclude signup
```

في هذا المثال، إذا كان `signup` اسم مجموعة معرّفة، فسيتم استبعاد تلك المجموعة. وسيقوم النمط `dialog` بتصفية أي ملفات مواصفات تحتوي أسماؤها على "dialog".

:::note
إذا حددت كلاً من `--suite X` و`--exclude X`، فإن الاستبعاد تكون له الأولوية ولن يتم تشغيل المجموعة `X`.
:::

عند توفير الخيار `--exclude`، فإنه سيتجاوز أي أنماط معرّفة بواسطة `exclude` في الإعدادات أو `wdio:exclude` الخاصة بالقدرة.

## تشغيل المجموعات وملفات مواصفات الاختبار

شغّل مجموعة كاملة إلى جانب ملفات مواصفات فردية.

```sh
wdio wdio.conf.js --suite login --spec ./test/specs/signup.js
```

## تشغيل ملفات مواصفات اختبار متعددة ومحددة

من الضروري أحيانًا&mdash;في سياق التكامل المستمر وغيره&mdash;تحديد مجموعات متعددة من ملفات المواصفات لتشغيلها. تقبل أداة سطر الأوامر `wdio` الخاصة بـ WebdriverIO أسماء الملفات الممرّرة عبر الأنابيب (من `find` أو `grep` أو غيرها).

تتجاوز أسماء الملفات الممرّرة عبر الأنابيب قائمة أنماط glob أو أسماء الملفات المحددة في قائمة `spec` في الإعدادات.

```sh
grep -r -l --include "*.js" "myText" | wdio wdio.conf.js
```

_**ملاحظة:** هذا_ لن _يتجاوز العلامة `--spec` لتشغيل ملف مواصفات واحد._

## تشغيل اختبارات محددة باستخدام MochaOpts

يمكنك أيضًا تصفية `suite|describe` و/أو `it|test` المحددة التي تريد تشغيلها عن طريق تمرير وسيط خاص بـ mocha: `--mochaOpts.grep` إلى واجهة سطر أوامر wdio.

```sh
wdio wdio.conf.js --mochaOpts.grep myText
wdio wdio.conf.js --mochaOpts.grep "Text with spaces"
```

_**ملاحظة:** سيقوم Mocha بتصفية الاختبارات بعد أن ينشئ مشغل اختبارات WDIO النسخ، لذا قد ترى عدة نسخ يتم إنشاؤها دون أن يتم تنفيذها فعليًا._

## استبعاد اختبارات محددة باستخدام MochaOpts

يمكنك أيضًا تصفية `suite|describe` و/أو `it|test` المحددة التي تريد استبعادها عن طريق تمرير وسيط خاص بـ mocha: `--mochaOpts.invert` إلى واجهة سطر أوامر wdio. يؤدي `--mochaOpts.invert` عكس ما يؤديه `--mochaOpts.grep`

```sh
wdio wdio.conf.js --mochaOpts.grep "string|regex" --mochaOpts.invert
wdio wdio.conf.js --spec ./test/specs/e2e/login.js --mochaOpts.grep "string|regex" --mochaOpts.invert
```

_**ملاحظة:** سيقوم Mocha بتصفية الاختبارات بعد أن ينشئ مشغل اختبارات WDIO النسخ، لذا قد ترى عدة نسخ يتم إنشاؤها دون أن يتم تنفيذها فعليًا._

## إيقاف الاختبار بعد الفشل

باستخدام الخيار `bail`، يمكنك إخبار WebdriverIO بإيقاف الاختبار بعد فشل أي اختبار.

يكون هذا مفيدًا مع مجموعات الاختبارات الكبيرة عندما تعلم مسبقًا أن عملية البناء ستفشل، ولكنك تريد تجنب الانتظار الطويل لتشغيل الاختبارات بالكامل.

يتوقع الخيار `bail` رقمًا يحدد عدد حالات فشل الاختبارات التي يمكن أن تحدث قبل أن يوقف WebDriver تشغيل الاختبارات بالكامل. القيمة الافتراضية هي `0`، مما يعني أنه يشغّل دائمًا جميع ملفات مواصفات الاختبار التي يمكنه العثور عليها.

يرجى مراجعة [صفحة الخيارات](configuration) للحصول على معلومات إضافية حول إعداد bail.
## التسلسل الهرمي لخيارات التشغيل

عند تحديد ملفات المواصفات المراد تشغيلها، هناك تسلسل هرمي معين يحدد أي نمط ستكون له الأولوية. حاليًا، هذه هي طريقة عمله، من الأولوية الأعلى إلى الأدنى:

> CLI `--spec` argument > capability `wdio:specs` > config `specs`
> CLI `--exclude` argument > config `exclude` > capability `wdio:exclude`

إذا تم توفير معامل الإعدادات فقط، فسيتم استخدامه لجميع القدرات. ومع ذلك، إذا تم تعريف النمط على مستوى القدرة، فسيتم استخدامه بدلاً من نمط الإعدادات. وأخيرًا، أي نمط مواصفات معرّف في سطر الأوامر سيتجاوز جميع الأنماط الأخرى المقدمة.

### استخدام أنماط المواصفات المعرّفة على مستوى القدرة

عندما تعرّف نمط مواصفات على مستوى القدرة، فإنه سيتجاوز أي أنماط معرّفة على مستوى الإعدادات. يكون هذا مفيدًا عند الحاجة إلى فصل الاختبارات بناءً على قدرات الأجهزة المختلفة. في مثل هذه الحالات، يكون من الأفيد استخدام نمط مواصفات عام على مستوى الإعدادات، وأنماط أكثر تحديدًا على مستوى القدرة.

على سبيل المثال، لنفترض أن لديك دليلين، أحدهما لاختبارات Android والآخر لاختبارات iOS.

قد يعرّف ملف الإعدادات الخاص بك النمط على هذا النحو، لاختبارات الأجهزة غير المحددة:

```js
{
    specs: ['tests/general/**/*.js']
}
```

ولكن بعد ذلك، ستكون لديك قدرات مختلفة لأجهزة Android وiOS، حيث يمكن أن تبدو الأنماط كالتالي:

```json
{
  "platformName": "Android",
  "wdio:specs": [
    "tests/android/**/*.js"
  ]
}
```

```json
{
  "platformName": "iOS",
  "wdio:specs": [
    "tests/ios/**/*.js"
  ]
}
```

إذا كنت تحتاج إلى كلتا القدرتين في ملف الإعدادات الخاص بك، فإن جهاز Android سيشغّل فقط الاختبارات الموجودة ضمن نطاق "android"، وسيشغّل جهاز iOS فقط الاختبارات الموجودة ضمن نطاق "ios"!

```js
//wdio.conf.js
export const config = {
    "specs": [
        "tests/general/**/*.js"
    ],
    "capabilities": [
        {
            platformName: "Android",
            "wdio:specs": ["tests/android/**/*.js"],
            //...
        },
        {
            platformName: "iOS",
            "wdio:specs": ["tests/ios/**/*.js"],
            //...
        },
        {
            platformName: "Chrome",
            //سيتم استخدام ملفات المواصفات المعرّفة على مستوى الإعدادات
        }
    ]
}
```
