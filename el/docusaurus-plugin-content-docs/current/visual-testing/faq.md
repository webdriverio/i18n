### Χρειάζεται να χρησιμοποιήσω τις μεθόδους `save(Screen/Element/FullPageScreen)` όταν θέλω να εκτελέσω το `check(Screen/Element/FullPageScreen)`;

Όχι, δεν χρειάζεται να το κάνετε αυτό. Το `check(Screen/Element/FullPageScreen)` θα το κάνει αυτόματα για εσάς.

### Οι οπτικοί έλεγχοί μου αποτυγχάνουν με κάποια διαφορά, πώς μπορώ να ενημερώσω το baseline μου;

Μπορείτε να ενημερώσετε τις εικόνες baseline μέσω της γραμμής εντολών προσθέτοντας το όρισμα `--update-visual-baseline`. Αυτό θα

-   αντιγράψει αυτόματα το πραγματικό στιγμιότυπο οθόνης που λήφθηκε και θα το τοποθετήσει στον φάκελο baseline
-   αν υπάρχουν διαφορές, θα αφήσει τον έλεγχο να περάσει επειδή το baseline έχει ενημερωθεί

**Χρήση:**

```sh
npm run test.local.desktop  --update-visual-baseline
```

Όταν εκτελείτε σε λειτουργία καταγραφής info/debug, θα δείτε να προστίθενται τα ακόλουθα logs

```logs
[0-0] ..............
[0-0] #####################################################################################
[0-0]  INFO:
[0-0]  Updated the actual image to
[0-0]  /Users/wswebcreation/Git/wdio/visual-testing/localBaseline/chromel/demo-chrome-1366x768.png
[0-0] #####################################################################################
[0-0] ..........
```

### Το πλάτος και το ύψος δεν μπορούν να είναι αρνητικά

Ενδέχεται να εμφανιστεί το σφάλμα `Width and height cannot be negative`. Στις 9 από τις 10 περιπτώσεις αυτό σχετίζεται με τη δημιουργία εικόνας ενός στοιχείου που δεν βρίσκεται εντός της ορατής περιοχής. Βεβαιωθείτε πάντα ότι το στοιχείο βρίσκεται εντός της ορατής περιοχής πριν προσπαθήσετε να δημιουργήσετε εικόνα του στοιχείου.

### Η εγκατάσταση του Canvas στα Windows απέτυχε με logs του Node-Gyp

Αν αντιμετωπίσετε προβλήματα με την εγκατάσταση του Canvas στα Windows λόγω σφαλμάτων του Node-Gyp, σημειώστε ότι αυτό ισχύει μόνο για την Έκδοση 4 και παλαιότερες. Για να αποφύγετε αυτά τα προβλήματα, εξετάστε το ενδεχόμενο αναβάθμισης στην Έκδοση 5 ή νεότερη, η οποία δεν έχει αυτές τις εξαρτήσεις. Οι Εκδόσεις 5 έως 9 χρησιμοποιούσαν το [Jimp](https://github.com/jimp-dev/jimp) για την επεξεργασία εικόνων· η Έκδοση 10 και νεότερες χρησιμοποιούν το [fast-png](https://github.com/image-js/fast-png) και το [Pixelmatch](https://github.com/mapbox/pixelmatch) χωρίς native εξαρτήσεις.

Αν εξακολουθείτε να χρειάζεται να επιλύσετε τα προβλήματα με την Έκδοση 4, ελέγξτε:

-   την ενότητα Node Canvas στον οδηγό [Ξεκινώντας](/docs/visual-testing#system-requirements)
-   [αυτή την ανάρτηση](https://spin.atomicobject.com/2019/03/27/node-gyp-windows/) για τη Διόρθωση Προβλημάτων του Node-Gyp στα Windows. (Ευχαριστούμε τον [IgorSasovets](https://github.com/IgorSasovets))

### Αναβάθμισα στην v10, γιατί αποτυγχάνουν οι οπτικοί έλεγχοί μου;

Η μηχανή σύγκρισης άλλαξε από το ResembleJS στο [Pixelmatch](https://github.com/mapbox/pixelmatch) στην v10. Το Pixelmatch χρησιμοποιεί ένα αντιληπτικό (YIQ) χρωματικό μοντέλο αντί για ακατέργαστο RGB, επομένως τα ποσοστά απόκλισης διαφέρουν από την v9. Οι έλεγχοί σας δεν έχουν χαλάσει· απλώς τα baselines χρειάζεται να αναδημιουργηθούν μία φορά. Εκτελέστε τους ελέγχους σας με `--update-visual-baseline` για να αποδεχτείτε τις νέες τιμές, ή διαγράψτε τον φάκελο baseline και αφήστε το `autoSaveBaseline` να τον αναδημιουργήσει.
