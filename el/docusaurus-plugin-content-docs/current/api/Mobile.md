# Εισαγωγή στις προσαρμοσμένες και βελτιωμένες εντολές για κινητές συσκευές στο WebdriverIO

Ο έλεγχος εφαρμογών για κινητές συσκευές και εφαρμογών ιστού για κινητά συνοδεύεται από τις δικές του προκλήσεις, ειδικά όταν πρόκειται για διαφορές μεταξύ των πλατφορμών Android και iOS. Ενώ το Appium παρέχει την ευελιξία να χειριστείτε αυτές τις διαφορές, συχνά απαιτεί να εμβαθύνετε σε πολύπλοκη τεκμηρίωση που εξαρτάται από την πλατφόρμα ([Android](https://github.com/appium/appium-uiautomator2-driver/blob/master/docs/android-mobile-gestures.md), [iOS](https://appium.github.io/appium-xcuitest-driver/latest/reference/execute-methods/)) και σε αντίστοιχες εντολές. Αυτό μπορεί να κάνει τη συγγραφή σεναρίων ελέγχου πιο χρονοβόρα, επιρρεπή σε σφάλματα και δύσκολη στη συντήρηση.

Για να απλοποιήσει τη διαδικασία, το WebdriverIO εισάγει **προσαρμοσμένες και βελτιωμένες εντολές για κινητές συσκευές**, σχεδιασμένες ειδικά για τον έλεγχο εφαρμογών ιστού για κινητά και εγγενών (native) εφαρμογών. Αυτές οι εντολές αποκρύπτουν τις περιπλοκές των υποκείμενων Appium APIs, επιτρέποντάς σας να γράφετε συνοπτικά, εύληπτα και ανεξάρτητα από την πλατφόρμα σενάρια ελέγχου. Εστιάζοντας στην ευκολία χρήσης, στοχεύουμε να μειώσουμε τον επιπλέον φόρτο κατά την ανάπτυξη σεναρίων Appium και να σας δώσουμε τη δυνατότητα να αυτοματοποιείτε εφαρμογές για κινητά χωρίς κόπο.

## Γιατί προσαρμοσμένες εντολές για κινητές συσκευές;

### 1. **Απλοποίηση πολύπλοκων APIs**
Ορισμένες εντολές του Appium, όπως οι χειρονομίες (gestures) ή οι αλληλεπιδράσεις με στοιχεία, περιλαμβάνουν φλύαρη και περίπλοκη σύνταξη. Για παράδειγμα, η εκτέλεση μιας ενέργειας παρατεταμένου πατήματος (long press) με το εγγενές Appium API απαιτεί τη χειροκίνητη κατασκευή μιας αλυσίδας `action`:

```ts
const element = $('~Contacts')

await browser
    .action( 'pointer', { parameters: { pointerType: 'touch' } })
    .move({ origin: element })
    .down()
    .pause(1500)
    .up()
    .perform()
```

Με τις προσαρμοσμένες εντολές του WebdriverIO, η ίδια ενέργεια μπορεί να εκτελεστεί με μία μόνο, εκφραστική γραμμή κώδικα:

```ts
await $('~Contacts').longPress();
```

Αυτό μειώνει δραστικά τον επαναλαμβανόμενο κώδικα (boilerplate), κάνοντας τα σενάριά σας πιο καθαρά και πιο εύκολα κατανοητά.

### 2. **Αφαίρεση μεταξύ πλατφορμών**
Οι εφαρμογές για κινητά συχνά απαιτούν χειρισμό ειδικό για κάθε πλατφόρμα. Για παράδειγμα, η κύλιση σε εγγενείς εφαρμογές διαφέρει σημαντικά μεταξύ [Android](https://github.com/appium/appium-uiautomator2-driver/blob/master/docs/android-mobile-gestures.md#mobile-scrollgesture) και [iOS](https://appium.github.io/appium-xcuitest-driver/latest/reference/execute-methods/#mobile-scroll). Το WebdriverIO γεφυρώνει αυτό το χάσμα παρέχοντας ενοποιημένες εντολές όπως η `scrollIntoView()`, που λειτουργούν απρόσκοπτα σε όλες τις πλατφόρμες, ανεξάρτητα από την υποκείμενη υλοποίηση.

```ts
await $('~element').scrollIntoView();
```

Αυτή η αφαίρεση διασφαλίζει ότι οι έλεγχοί σας είναι φορητοί και δεν απαιτούν συνεχείς διακλαδώσεις ή λογική συνθηκών για να ληφθούν υπόψη οι διαφορές των λειτουργικών συστημάτων.

### 3. **Αυξημένη παραγωγικότητα**
Μειώνοντας την ανάγκη κατανόησης και υλοποίησης εντολών χαμηλού επιπέδου του Appium, οι εντολές για κινητές συσκευές του WebdriverIO σας επιτρέπουν να εστιάσετε στον έλεγχο της λειτουργικότητας της εφαρμογής σας αντί να παλεύετε με ιδιαιτερότητες κάθε πλατφόρμας. Αυτό είναι ιδιαίτερα ωφέλιμο για ομάδες με περιορισμένη εμπειρία στον αυτοματισμό κινητών συσκευών ή για όσες επιδιώκουν να επιταχύνουν τον κύκλο ανάπτυξής τους.

### 4. **Συνέπεια και ευκολία συντήρησης**
Οι προσαρμοσμένες εντολές φέρνουν ομοιομορφία στα σενάρια ελέγχου σας. Αντί να υπάρχουν διαφορετικές υλοποιήσεις για παρόμοιες ενέργειες, η ομάδα σας μπορεί να βασίζεται σε τυποποιημένες, επαναχρησιμοποιήσιμες εντολές. Αυτό όχι μόνο κάνει τη βάση κώδικα πιο εύκολα συντηρήσιμη, αλλά επίσης διευκολύνει την ένταξη νέων μελών στην ομάδα.

## Γιατί βελτιώνουμε ορισμένες εντολές για κινητές συσκευές;

### 1. Προσθήκη ευελιξίας
Ορισμένες εντολές για κινητές συσκευές έχουν βελτιωθεί ώστε να παρέχουν επιπλέον επιλογές και παραμέτρους που δεν είναι διαθέσιμες στα προεπιλεγμένα Appium APIs. Για παράδειγμα, το WebdriverIO προσθέτει λογική επαναπροσπάθειας, χρονικά όρια (timeouts) και τη δυνατότητα φιλτραρίσματος των webviews με βάση συγκεκριμένα κριτήρια, προσφέροντας μεγαλύτερο έλεγχο σε πολύπλοκα σενάρια.

```ts
// Example: Customizing retry intervals and timeouts for webview detection
await driver.getContexts({
  returnDetailedContexts: true,
  androidWebviewConnectionRetryTime: 1000, // Retry every 1 second
  androidWebviewConnectTimeout: 10000,    // Timeout after 10 seconds
});
```

Αυτές οι επιλογές βοηθούν στην προσαρμογή των σεναρίων αυτοματισμού στη δυναμική συμπεριφορά της εφαρμογής χωρίς επιπλέον επαναλαμβανόμενο κώδικα.

### 2. Βελτίωση της ευχρηστίας
Οι βελτιωμένες εντολές αποκρύπτουν τις πολυπλοκότητες και τα επαναλαμβανόμενα μοτίβα που υπάρχουν στα εγγενή APIs. Σας επιτρέπουν να εκτελείτε περισσότερες ενέργειες με λιγότερες γραμμές κώδικα, μειώνοντας την καμπύλη εκμάθησης για νέους χρήστες και κάνοντας τα σενάρια πιο ευανάγνωστα και πιο εύκολα στη συντήρηση.

```ts
// Example: Enhanced command for switching context by title
await driver.switchContext({
  title: 'My Webview Title',
});
```

Σε σύγκριση με τις προεπιλεγμένες μεθόδους του Appium, οι βελτιωμένες εντολές εξαλείφουν την ανάγκη για επιπλέον βήματα, όπως η χειροκίνητη ανάκτηση των διαθέσιμων contexts και το φιλτράρισμά τους.

### 3. Τυποποίηση της συμπεριφοράς
Το WebdriverIO διασφαλίζει ότι οι βελτιωμένες εντολές συμπεριφέρονται με συνέπεια σε πλατφόρμες όπως το Android και το iOS. Αυτή η αφαίρεση μεταξύ πλατφορμών ελαχιστοποιεί την ανάγκη για λογική διακλάδωσης με βάση το λειτουργικό σύστημα, οδηγώντας σε πιο εύκολα συντηρήσιμα σενάρια ελέγχου.

```ts
// Example: Unified scroll command for both platforms
await $('~element').scrollIntoView();
```

Αυτή η τυποποίηση απλοποιεί τις βάσεις κώδικα, ειδικά για ομάδες που αυτοματοποιούν ελέγχους σε πολλαπλές πλατφόρμες.

### 4. Αύξηση της αξιοπιστίας
Ενσωματώνοντας μηχανισμούς επαναπροσπάθειας, έξυπνες προεπιλογές και λεπτομερή μηνύματα σφάλματος, οι βελτιωμένες εντολές μειώνουν την πιθανότητα ασταθών (flaky) ελέγχων. Αυτές οι βελτιώσεις διασφαλίζουν ότι οι έλεγχοί σας είναι ανθεκτικοί σε ζητήματα όπως καθυστερήσεις στην αρχικοποίηση των webviews ή παροδικές καταστάσεις της εφαρμογής.

```ts
// Example: Enhanced webview switching with robust matching logic
await driver.switchContext({
  url: /.*my-app\/dashboard/,
  androidWebviewConnectionRetryTime: 500,
  androidWebviewConnectTimeout: 7000,
});
```

Αυτό κάνει την εκτέλεση των ελέγχων πιο προβλέψιμη και λιγότερο επιρρεπή σε αποτυχίες που προκαλούνται από περιβαλλοντικούς παράγοντες.

### 5. Ενίσχυση των δυνατοτήτων αποσφαλμάτωσης
Οι βελτιωμένες εντολές συχνά επιστρέφουν πλουσιότερα μεταδεδομένα, διευκολύνοντας την αποσφαλμάτωση πολύπλοκων σεναρίων, ιδιαίτερα σε υβριδικές εφαρμογές. Για παράδειγμα, εντολές όπως οι getContext και getContexts μπορούν να επιστρέψουν λεπτομερείς πληροφορίες για τα webviews, συμπεριλαμβανομένων του τίτλου, του url και της κατάστασης ορατότητας.

```ts
// Example: Retrieving detailed metadata for debugging
const contexts = await driver.getContexts({ returnDetailedContexts: true });
console.log(contexts);
```

Αυτά τα μεταδεδομένα βοηθούν στον ταχύτερο εντοπισμό και την επίλυση προβλημάτων, βελτιώνοντας τη συνολική εμπειρία αποσφαλμάτωσης.


Βελτιώνοντας τις εντολές για κινητές συσκευές, το WebdriverIO όχι μόνο κάνει τον αυτοματισμό ευκολότερο, αλλά ευθυγραμμίζεται επίσης με την αποστολή του να παρέχει στους προγραμματιστές εργαλεία ισχυρά, αξιόπιστα και εύχρηστα.

## Υβριδικές εφαρμογές

Οι υβριδικές εφαρμογές συνδυάζουν περιεχόμενο ιστού με εγγενή λειτουργικότητα και απαιτούν εξειδικευμένο χειρισμό κατά τον αυτοματισμό. Αυτές οι εφαρμογές χρησιμοποιούν webviews για την απόδοση περιεχομένου ιστού μέσα σε μια εγγενή εφαρμογή. Το WebdriverIO παρέχει βελτιωμένες μεθόδους για την αποτελεσματική εργασία με υβριδικές εφαρμογές.

### Κατανόηση των Webviews
Ένα webview είναι ένα στοιχείο παρόμοιο με πρόγραμμα περιήγησης, ενσωματωμένο σε μια εγγενή εφαρμογή:

- **Android:** Τα webviews βασίζονται στο Chrome/System Webview και μπορεί να περιέχουν πολλαπλές σελίδες (παρόμοια με τις καρτέλες ενός προγράμματος περιήγησης). Αυτά τα webviews απαιτούν το ChromeDriver για την αυτοματοποίηση των αλληλεπιδράσεων. Το Appium μπορεί να προσδιορίσει αυτόματα την απαιτούμενη έκδοση του ChromeDriver με βάση την έκδοση του System WebView ή του Chrome που είναι εγκατεστημένη στη συσκευή και να τη λάβει αυτόματα, εάν δεν είναι ήδη διαθέσιμη. Αυτή η προσέγγιση διασφαλίζει απρόσκοπτη συμβατότητα και ελαχιστοποιεί τη χειροκίνητη ρύθμιση. Ανατρέξτε στην [τεκμηρίωση του Appium UIAutomator2](https://github.com/appium/appium-uiautomator2-driver?tab=readme-ov-file#automatic-discovery-of-compatible-chromedriver) για να μάθετε πώς το Appium λαμβάνει αυτόματα τη σωστή έκδοση του ChromeDriver.
- **iOS:** Τα webviews τροφοδοτούνται από το Safari (WebKit) και αναγνωρίζονται από γενικά αναγνωριστικά όπως `WEBVIEW_{id}`.

### Προκλήσεις με τις υβριδικές εφαρμογές
1. Αναγνώριση του σωστού webview ανάμεσα σε πολλαπλές επιλογές.
2. Ανάκτηση επιπλέον μεταδεδομένων, όπως ο τίτλος, το URL ή το όνομα πακέτου, για καλύτερο πλαίσιο.
3. Χειρισμός των διαφορών μεταξύ των πλατφορμών Android και iOS.
4. Αξιόπιστη εναλλαγή στο σωστό context σε μια υβριδική εφαρμογή.

### Βασικές εντολές για υβριδικές εφαρμογές

#### 1. `getContext`
Ανακτά το τρέχον context της συνεδρίας. Από προεπιλογή, συμπεριφέρεται όπως η μέθοδος getContext του Appium, αλλά μπορεί να παρέχει λεπτομερείς πληροφορίες context όταν είναι ενεργοποιημένο το `returnDetailedContext`. Για περισσότερες πληροφορίες δείτε το [`getContext`](/docs/api/mobile/getContext)

#### 2. `getContexts`
Επιστρέφει μια λεπτομερή λίστα των διαθέσιμων contexts, βελτιώνοντας τη μέθοδο contexts του Appium. Αυτό διευκολύνει την αναγνώριση του σωστού webview για αλληλεπίδραση χωρίς την κλήση επιπλέον εντολών για τον προσδιορισμό του τίτλου, του url ή του ενεργού `bundleId|packageName`. Για περισσότερες πληροφορίες δείτε το [`getContexts`](/docs/api/mobile/getContexts)

#### 3. `switchContext`
Μεταβαίνει σε ένα συγκεκριμένο webview με βάση το όνομα, τον τίτλο ή το url. Παρέχει επιπλέον ευελιξία, όπως τη χρήση κανονικών εκφράσεων (regular expressions) για την αντιστοίχιση. Για περισσότερες πληροφορίες δείτε το [`switchContext`](/docs/api/mobile/switchContext)

### Βασικά χαρακτηριστικά για υβριδικές εφαρμογές
1. Λεπτομερή μεταδεδομένα: Ανάκτηση αναλυτικών λεπτομερειών για αποσφαλμάτωση και αξιόπιστη εναλλαγή context.
2. Συνέπεια μεταξύ πλατφορμών: Ενοποιημένη συμπεριφορά για Android και iOS, με απρόσκοπτο χειρισμό των ιδιαιτεροτήτων κάθε πλατφόρμας.
3. Προσαρμοσμένη λογική επαναπροσπάθειας (Android): Ρύθμιση των διαστημάτων επαναπροσπάθειας και των χρονικών ορίων για τον εντοπισμό webviews.


:::info Σημειώσεις και περιορισμοί
- Το Android παρέχει επιπλέον μεταδεδομένα, όπως `packageName` και `webviewPageId`, ενώ το iOS εστιάζει στο `bundleId`.
- Η λογική επαναπροσπάθειας είναι προσαρμόσιμη για το Android, αλλά δεν εφαρμόζεται στο iOS.
- Υπάρχουν αρκετές περιπτώσεις όπου το iOS δεν μπορεί να βρει το Webview. Το Appium παρέχει διάφορα επιπλέον capabilities για το `appium-xcuitest-driver` ώστε να βρεθεί το Webview. Εάν πιστεύετε ότι το Webview δεν εντοπίζεται, μπορείτε να δοκιμάσετε να ορίσετε ένα από τα ακόλουθα capabilities:
    - `appium:includeSafariInWebviews`: Προσθέτει τα web contexts του Safari στη λίστα των διαθέσιμων contexts κατά τη διάρκεια ενός ελέγχου εγγενούς εφαρμογής/webview. Αυτό είναι χρήσιμο εάν ο έλεγχος ανοίγει το Safari και χρειάζεται να μπορεί να αλληλεπιδράσει με αυτό. Η προεπιλογή είναι `false`.
    - `appium:webviewConnectRetries`: Ο μέγιστος αριθμός επαναπροσπαθειών πριν από την εγκατάλειψη του εντοπισμού σελίδων webview. Η καθυστέρηση μεταξύ κάθε επαναπροσπάθειας είναι 500ms, η προεπιλογή είναι `10` επαναπροσπάθειες.
    - `appium:webviewConnectTimeout`: Ο μέγιστος χρόνος σε χιλιοστά του δευτερολέπτου αναμονής για τον εντοπισμό μιας σελίδας webview. Η προεπιλογή είναι `5000` ms.

Για προχωρημένα παραδείγματα και λεπτομέρειες, ανατρέξτε στην τεκμηρίωση του WebdriverIO Mobile API.
:::
