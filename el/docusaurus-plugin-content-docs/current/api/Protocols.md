Το WebdriverIO είναι ένα framework αυτοματοποίησης που βασίζεται σε διάφορα πρωτόκολλα αυτοματοποίησης για τον έλεγχο ενός απομακρυσμένου agent, π.χ. για ένα πρόγραμμα περιήγησης, μια κινητή συσκευή ή μια τηλεόραση. Ανάλογα με την απομακρυσμένη συσκευή, τίθενται σε λειτουργία διαφορετικά πρωτόκολλα. Αυτές οι εντολές αντιστοιχίζονται στο αντικείμενο [Browser](/docs/api/browser) ή [Element](/docs/api/element), ανάλογα με τις πληροφορίες συνεδρίας από τον απομακρυσμένο διακομιστή (π.χ. τον driver του προγράμματος περιήγησης).

Εσωτερικά, το WebdriverIO χρησιμοποιεί εντολές πρωτοκόλλου για σχεδόν όλες τις αλληλεπιδράσεις με τον απομακρυσμένο agent. Ωστόσο, πρόσθετες εντολές που αντιστοιχίζονται στο αντικείμενο [Browser](/docs/api/browser) ή [Element](/docs/api/element) απλοποιούν τη χρήση του WebdriverIO. Για παράδειγμα, η λήψη του κειμένου ενός στοιχείου με χρήση εντολών πρωτοκόλλου θα έμοιαζε κάπως έτσι:

```js
const searchInput = await browser.findElement('css selector', '#lst-ib')
await client.getElementText(searchInput['element-6066-11e4-a52e-4f735466cecf'])
```

Χρησιμοποιώντας τις βολικές εντολές του αντικειμένου [Browser](/docs/api/browser) ή [Element](/docs/api/element), αυτό μπορεί να συντομευτεί σε:

```js
$('#lst-ib').getText()
```

Η παρακάτω ενότητα εξηγεί κάθε πρωτόκολλο ξεχωριστά.

## Πρωτόκολλο WebDriver

Το πρωτόκολλο [WebDriver](https://w3c.github.io/webdriver/#elements) είναι ένα πρότυπο του web για την αυτοματοποίηση προγραμμάτων περιήγησης. Σε αντίθεση με κάποια άλλα εργαλεία E2E, εγγυάται ότι η αυτοματοποίηση μπορεί να γίνει σε πραγματικά προγράμματα περιήγησης που χρησιμοποιούνται από τους χρήστες σας, π.χ. Firefox, Safari και Chrome, καθώς και προγράμματα περιήγησης βασισμένα στο Chromium όπως το Edge, και όχι μόνο σε μηχανές προγραμμάτων περιήγησης, π.χ. WebKit, οι οποίες είναι πολύ διαφορετικές.

Το πλεονέκτημα της χρήσης του πρωτοκόλλου WebDriver σε σύγκριση με πρωτόκολλα αποσφαλμάτωσης όπως το [Chrome DevTools](https://w3c.github.io/webdriver/#elements) είναι ότι διαθέτετε ένα συγκεκριμένο σύνολο εντολών που επιτρέπουν την αλληλεπίδραση με το πρόγραμμα περιήγησης με τον ίδιο τρόπο σε όλα τα προγράμματα περιήγησης, κάτι που μειώνει την πιθανότητα ασταθών (flaky) τεστ. Επιπλέον, αυτό το πρωτόκολλο προσφέρει δυνατότητες για μαζική κλιμάκωση μέσω παρόχων cloud όπως το [Sauce Labs](https://saucelabs.com/), το [BrowserStack](https://www.browserstack.com/) και [άλλων](https://github.com/christian-bromann/awesome-selenium#cloud-services).

## Πρωτόκολλο WebDriver Bidi

Το πρωτόκολλο [WebDriver Bidi](https://w3c.github.io/webdriver-bidi/) είναι η δεύτερη γενιά του πρωτοκόλλου και βρίσκεται αυτή τη στιγμή υπό ανάπτυξη από τους περισσότερους κατασκευαστές προγραμμάτων περιήγησης. Σε σύγκριση με τον προκάτοχό του, το πρωτόκολλο υποστηρίζει αμφίδρομη επικοινωνία (εξ ου και "Bidi") μεταξύ του framework και της απομακρυσμένης συσκευής. Επιπλέον, εισάγει πρόσθετα βασικά στοιχεία (primitives) για καλύτερη ενδοσκόπηση του προγράμματος περιήγησης, ώστε να αυτοματοποιούνται καλύτερα οι σύγχρονες web εφαρμογές στο πρόγραμμα περιήγησης.

Δεδομένου ότι αυτό το πρωτόκολλο βρίσκεται ακόμη υπό ανάπτυξη, περισσότερες λειτουργίες θα προστίθενται με την πάροδο του χρόνου και θα υποστηρίζονται από τα προγράμματα περιήγησης. Αν χρησιμοποιείτε τις βολικές εντολές του WebdriverIO, τίποτα δεν θα αλλάξει για εσάς. Το WebdriverIO θα αξιοποιήσει αυτές τις νέες δυνατότητες του πρωτοκόλλου μόλις γίνουν διαθέσιμες και υποστηριχθούν από το πρόγραμμα περιήγησης.

## Appium

Το έργο [Appium](https://appium.io/) παρέχει δυνατότητες αυτοματοποίησης για κινητές συσκευές, υπολογιστές και κάθε άλλου είδους συσκευές IoT. Ενώ το WebDriver εστιάζει στα προγράμματα περιήγησης και στο web, το όραμα του Appium είναι να χρησιμοποιήσει την ίδια προσέγγιση αλλά για οποιαδήποτε συσκευή. Εκτός από τις εντολές που ορίζει το WebDriver, διαθέτει ειδικές εντολές που συχνά αφορούν συγκεκριμένα την απομακρυσμένη συσκευή που αυτοματοποιείται. Για σενάρια δοκιμών σε κινητές συσκευές, αυτό είναι ιδανικό όταν θέλετε να γράψετε και να εκτελέσετε τα ίδια τεστ τόσο για εφαρμογές Android όσο και για iOS.

Σύμφωνα με την [τεκμηρίωση](https://appium.github.io/appium.io/docs/en/about-appium/intro/?lang=en) του Appium, σχεδιάστηκε για να καλύψει τις ανάγκες αυτοματοποίησης κινητών συσκευών σύμφωνα με μια φιλοσοφία που περιγράφεται από τις ακόλουθες τέσσερις αρχές:

- Δεν θα πρέπει να χρειάζεται να κάνετε εκ νέου μεταγλώττιση της εφαρμογής σας ή να την τροποποιήσετε με οποιονδήποτε τρόπο για να την αυτοματοποιήσετε.
- Δεν θα πρέπει να είστε δεσμευμένοι σε μια συγκεκριμένη γλώσσα ή framework για να γράφετε και να εκτελείτε τα τεστ σας.
- Ένα framework αυτοματοποίησης κινητών συσκευών δεν θα πρέπει να ανακαλύπτει ξανά τον τροχό όσον αφορά τα APIs αυτοματοποίησης.
- Ένα framework αυτοματοποίησης κινητών συσκευών θα πρέπει να είναι ανοιχτού κώδικα, στο πνεύμα και στην πράξη, όχι μόνο κατ' όνομα!
