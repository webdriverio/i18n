Καταγράφει συνεδρίες προγράμματος περιήγησης ως βίντεο `.webm`. Τα βίντεο εμφανίζονται στο UI του DevTools δίπλα στις προβολές στιγμιοτύπων και μεταλλάξεων DOM.

Διαθέσιμο και στους τρεις adapters - **WebdriverIO**, **[Selenium WebDriver](/docs/devtools/selenium)** και **[Nightwatch.js](/docs/devtools/nightwatch#screencast)**. Η λειτουργία καταγραφής διαφέρει ανά framework (CDP push όπου είναι δυνατό, αλλιώς polling - δείτε την ενότητα [Υποστήριξη Προγραμμάτων Περιήγησης](#browser-support) παρακάτω).

## Εγκατάσταση

Η κωδικοποίηση του screencast απαιτεί το **ffmpeg** στο `PATH` και το πακέτο `fluent-ffmpeg`:

```sh
# Εγκατάσταση ffmpeg - https://ffmpeg.org/download.html
brew install ffmpeg        # macOS
sudo apt install ffmpeg    # Ubuntu/Debian

# Εγκατάσταση fluent-ffmpeg
npm install fluent-ffmpeg
```

## Διαμόρφωση

```ts
services: [
  [
    'devtools',
    {
      screencast: {
        enabled: true,
        captureFormat: 'jpeg',
        quality: 70,
        maxWidth: 1280,
        maxHeight: 720,
      }
    }
  ]
]
```

## Επιλογές

| Επιλογή | Τύπος | Προεπιλογή | Περιγραφή |
|---|---|---|---|
| `enabled` | `boolean` | `false` | Ενεργοποίηση καταγραφής συνεδρίας |
| `captureFormat` | `'jpeg' \| 'png'` | `'jpeg'` | Μορφή εικόνας καρέ. **Μόνο Chrome/Chromium** - ελέγχει τη μορφή που στέλνει το Chrome μέσω CDP. Αγνοείται σε λειτουργία polling (Firefox, Safari), όπου τα στιγμιότυπα οθόνης είναι πάντα PNG. Δεν επηρεάζει το container του βίντεο εξόδου, το οποίο είναι πάντα `.webm` |
| `quality` | `number` | `70` | Ποιότητα συμπίεσης JPEG 0-100. Ισχύει μόνο σε λειτουργία CDP του Chrome/Chromium με `captureFormat: 'jpeg'` |
| `maxWidth` | `number` | `1280` | Μέγιστο πλάτος καρέ σε pixels. **Μόνο Chrome/Chromium** - το Chrome κλιμακώνει τα καρέ πριν τα στείλει μέσω CDP. Αγνοείται σε λειτουργία polling |
| `maxHeight` | `number` | `720` | Μέγιστο ύψος καρέ σε pixels. **Μόνο Chrome/Chromium** - όπως παραπάνω |
| `pollIntervalMs` | `number` | `200` | Διάστημα λήψης στιγμιοτύπων οθόνης σε χιλιοστά του δευτερολέπτου για προγράμματα περιήγησης εκτός Chrome (λειτουργία polling). Μικρότερη τιμή = πιο ομαλό βίντεο αλλά περισσότερα round-trips του WebDriver κατά την εκτέλεση των τεστ |

## Υποστήριξη Προγραμμάτων Περιήγησης

Η καταγραφή λειτουργεί σε όλα τα κύρια προγράμματα περιήγησης με αυτόματη επιλογή λειτουργίας:

| Πρόγραμμα περιήγησης | Λειτουργία | Σημειώσεις |
|---|---|---|
| Chrome / Chromium / Edge | **CDP push** | Το Chrome στέλνει καρέ μέσω του DevTools Protocol. Αποδοτικό - καμία επίπτωση στον χρονισμό των εντολών των τεστ |
| Firefox / Safari / άλλα | **BiDi polling** | Καταφεύγει στην κλήση του `browser.takeScreenshot()` ανά διαστήματα `pollIntervalMs`. Λειτουργεί όπου υποστηρίζονται στιγμιότυπα οθόνης WebDriver· προσθέτει μια μικρή επιβάρυνση ανάλογη του διαστήματος |

Δεν απαιτείται καμία αλλαγή διαμόρφωσης για την εναλλαγή λειτουργιών - το service εντοπίζει αυτόματα τις δυνατότητες του προγράμματος περιήγησης και καταγράφει στα logs ποια λειτουργία είναι ενεργή.

## Συμπεριφορά

- Η καταγραφή ξεκινά όταν ανοίγει η συνεδρία του προγράμματος περιήγησης και σταματά όταν κλείνει.
- Τα αρχικά κενά καρέ (που καταγράφονται πριν από την πρώτη πλοήγηση σε URL) περικόπτονται αυτόματα, ώστε τα βίντεο να ξεκινούν από την πρώτη ουσιαστική ενέργεια στη σελίδα.
- Αν κληθεί το `browser.reloadSession()` κατά τη διάρκεια της εκτέλεσης, το service ολοκληρώνει την τρέχουσα καταγραφή και ξεκινά μια νέα για τη νέα συνεδρία. Κάθε συνεδρία παράγει το δικό της αρχείο `.webm`.
- Όταν υπάρχουν πολλαπλές καταγραφές, το UI του DevTools εμφανίζει ένα αναπτυσσόμενο μενού **Recording N** για εναλλαγή μεταξύ τους.

### Πού αποθηκεύονται τα αρχεία εξόδου

Ο κατάλογος που επιλέγει κάθε adapter διαφέρει ελαφρώς - όλοι μοιράζονται τον ίδιο resolver στο `@wdio/devtools-core` αλλά του παρέχουν διαφορετικές εισόδους:

| Adapter | Τοποθεσία εξόδου |
|---|---|
| **WebdriverIO** | `outputDir` αν έχει οριστεί ρητά στο `wdio.conf.ts`, αλλιώς `rootDir` (ο κατάλογος που περιέχει το config). Αποφύγετε να ορίζετε το `outputDir` μόνο για τον έλεγχο των διαδρομών των βίντεο - το WDIO ανακατευθύνει εκεί και τα logs των workers. |
| **Selenium** | Ο κατάλογος του αρχείου τεστ που μόλις εκτελέστηκε, με εναλλακτική το `process.cwd()`. |
| **Nightwatch** | Ο κατάλογος του αρχείου τεστ, με εναλλακτική τον κατάλογο που περιέχει το `nightwatch.conf.*` και στη συνέχεια το `process.cwd()`. |

Οι κατάλογοι κάτω από το `node_modules/` παραλείπονται στη διαδρομή Selenium/Nightwatch, ώστε τα symlinked workspaces να μην αποθέτουν βίντεο σε φάκελο εξάρτησης.

## Αρχεία Εξόδου

Η λειτουργία live μεταδίδει τα δεδομένα που καταγράφονται στο dashboard μέσω WebSocket και **δεν γράφει κανένα αρχείο trace στον δίσκο** — για ένα φορητό artifact, χρησιμοποιήστε τη [λειτουργία trace](/docs/devtools/wdio/trace-mode) (`trace.zip`). Το μόνο αρχείο που γράφει η λειτουργία live είναι το βίντεο του screencast, και μόνο όταν `screencast.enabled: true`. Τα ονόματα αρχείων εξαρτώνται από τον adapter (το όνομα του framework εμφανίζεται στο πρόθεμα):

| Adapter | Βίντεο screencast |
|---|---|
| WebdriverIO | `wdio-video-{sessionId}.webm` |
| Selenium | `selenium-video-{sessionId}.webm` |
| Nightwatch | `nightwatch-video-{sessionId}.webm` |
