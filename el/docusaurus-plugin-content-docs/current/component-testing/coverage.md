Ο browser runner του WebdriverIO υποστηρίζει αναφορές κάλυψης κώδικα χρησιμοποιώντας το [`istanbul`](https://istanbul.js.org/). Ο testrunner θα κάνει αυτόματα instrumentation του κώδικά σας χρησιμοποιώντας το Vite και θα καταγράψει την κάλυψη κώδικα για εσάς.

## Πώς Λειτουργεί

Ο `@wdio/browser-runner` χρησιμοποιεί το Vite για να εξυπηρετήσει την εφαρμογή σας. Όταν ενεργοποιείτε την κάλυψη, προσθέτει ένα plugin στον Vite server που προσπαθεί να κάνει instrumentation του πηγαίου κώδικά σας σε πραγματικό χρόνο, καθώς ζητείται από τον browser.

:::warning Σημαντικό
**Μην πλοηγηθείτε μακριά από τον test runner!**

Η κάλυψη κώδικα βασίζεται στο ότι τα αρχεία εξυπηρετούνται και γίνεται instrumentation σε αυτά από τον τοπικό Vite server που εκκινεί το WebdriverIO.
Αν χρησιμοποιήσετε `browser.url('http://...')` ή `browser.url('file://...')` για να πλοηγηθείτε σε διαφορετική σελίδα, αφήνετε το περιβάλλον instrumentation. Ο κώδικάς σας θα εκτελεστεί, αλλά **δεν θα συλλεχθεί καμία κάλυψη**.

**Σωστή Προσέγγιση (Component Testing):**
Κάντε render το component σας ή εισάγετε το module σας απευθείας στο αρχείο δοκιμής.

```js
import { myFunction } from '../src/utils.js'

it('should cover my function', () => {
    myFunction() // Αυτό καλύπτεται
})
```

**Λανθασμένη Προσέγγιση (Στυλ E2E):**
```js
it('will not have coverage', async () => {
    // ❌ η πλοήγηση σε άλλη σελίδα χαλάει το instrumentation
    await browser.url('http://localhost:3000')
})
```
:::

## Ρύθμιση

Για να ενεργοποιήσετε τις αναφορές κάλυψης κώδικα, ενεργοποιήστε τις μέσω της διαμόρφωσης του browser runner του WebdriverIO, π.χ.:

```js title=wdio.conf.js
export const config = {
    // ...
    runner: ['browser', {
        preset: process.env.WDIO_PRESET,
        coverage: {
            enabled: true
        }
    }],
    // ...
}
```

Δείτε όλες τις [επιλογές κάλυψης](/docs/runner#coverage-options), για να μάθετε πώς να τη διαμορφώσετε σωστά.

:::tip Συμβουλές Διαμόρφωσης
Αν δοκιμάζετε μη τυπικά αρχεία (όπως inline scripts σε `.html`) ή αν τα αρχεία σας δεν εντοπίζονται, ίσως χρειαστεί να επαληθεύσετε ρητά τις επιλογές `include` και `extension`:

```js
coverage: {
    enabled: true,
    // Στοχεύστε ρητά τα πηγαία αρχεία σας αν η προεπιλεγμένη ανάλυση αποτύχει
    include: ['src/**/*.js', 'src/**/*.vue'],
    // Προσθέστε .html αν έχετε inline scripts
    extension: ['.js', '.jsx', '.ts', '.tsx', '.vue', '.html']
}
```
:::

## Παράβλεψη Κώδικα

Μπορεί να υπάρχουν ορισμένα τμήματα του κώδικά σας που θέλετε σκόπιμα να εξαιρέσετε από την παρακολούθηση κάλυψης. Για να το κάνετε αυτό, μπορείτε να χρησιμοποιήσετε τις ακόλουθες υποδείξεις ανάλυσης:

- `/* istanbul ignore if */`: παράβλεψη της επόμενης εντολής if.
- `/* istanbul ignore else */`: παράβλεψη του τμήματος else μιας εντολής if.
- `/* istanbul ignore next */`: παράβλεψη του επόμενου στοιχείου στον πηγαίο κώδικα (συναρτήσεις, εντολές if, κλάσεις, οτιδήποτε).
- `/* istanbul ignore file */`: παράβλεψη ενός ολόκληρου πηγαίου αρχείου (αυτό πρέπει να τοποθετείται στην κορυφή του αρχείου).

:::info

Συνιστάται να εξαιρείτε τα αρχεία δοκιμών σας από την αναφορά κάλυψης, καθώς θα μπορούσε να προκαλέσει σφάλματα, π.χ. κατά την κλήση της εντολής `execute`. Αν θέλετε να τα διατηρήσετε στην αναφορά σας, βεβαιωθείτε ότι εξαιρείτε το instrumentation τους μέσω:

```ts
await browser.execute(/* istanbul ignore next */() => {
    // ...
})
```

:::
