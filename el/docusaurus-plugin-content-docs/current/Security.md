Το WebdriverIO λαμβάνει υπόψη την πτυχή της ασφάλειας όταν παρέχει λύσεις. Παρακάτω παρουσιάζονται μερικοί τρόποι για να ασφαλίσετε καλύτερα τις δοκιμές σας.

## Βέλτιστες Πρακτικές

- Μην ενσωματώνετε ποτέ απευθείας στον κώδικα ευαίσθητα δεδομένα που μπορούν να βλάψουν τον οργανισμό σας εάν εκτεθούν σε απλό κείμενο.
- Χρησιμοποιήστε έναν μηχανισμό (όπως ένα vault) για την ασφαλή αποθήκευση κλειδιών και κωδικών πρόσβασης και την ανάκτησή τους κατά την έναρξη των end-to-end δοκιμών σας.
- Επαληθεύστε ότι δεν εκτίθενται ευαίσθητα δεδομένα στα αρχεία καταγραφής (Logs) και από τον πάροχο cloud, όπως tokens πιστοποίησης στα Network Logs.

:::info

Ακόμη και για δεδομένα δοκιμών, είναι απαραίτητο να αναρωτηθείτε εάν, σε λάθος χέρια, ένα κακόβουλο άτομο θα μπορούσε να ανακτήσει πληροφορίες ή να χρησιμοποιήσει αυτούς τους πόρους με κακόβουλη πρόθεση.

:::

## Απόκρυψη Ευαίσθητων Δεδομένων

Εάν χρησιμοποιείτε ευαίσθητα δεδομένα κατά τη διάρκεια της δοκιμής σας, είναι απαραίτητο να διασφαλίσετε ότι δεν είναι ορατά σε όλους, όπως για παράδειγμα στα αρχεία καταγραφής. Επίσης, όταν χρησιμοποιείτε έναν πάροχο cloud, συχνά εμπλέκονται ιδιωτικά κλειδιά. Αυτές οι πληροφορίες πρέπει να αποκρύπτονται από τα αρχεία καταγραφής, τους reporters και άλλα σημεία επαφής. Παρακάτω παρέχονται ορισμένες λύσεις απόκρυψης για την εκτέλεση δοκιμών χωρίς την έκθεση αυτών των τιμών.

### WebDriverIO

#### Απόκρυψη της Τιμής Κειμένου των Εντολών

Οι εντολές `addValue` και `setValue` υποστηρίζουν μια boolean τιμή mask για απόκρυψη στα αρχεία καταγραφής, καθώς και στους reporters. Επιπλέον, άλλα εργαλεία, όπως εργαλεία απόδοσης και εργαλεία τρίτων, θα λαμβάνουν επίσης την αποκρυμμένη έκδοση, ενισχύοντας την ασφάλεια.

Για παράδειγμα, εάν χρησιμοποιείτε έναν πραγματικό χρήστη παραγωγής και πρέπει να εισαγάγετε έναν κωδικό πρόσβασης που θέλετε να αποκρύψετε, αυτό είναι πλέον δυνατό με τον ακόλουθο τρόπο:

```ts
  async enterPassword(userPassword) {
    const passwordInputElement = $('Password');

    // Λήψη εστίασης
    await passwordInputElement.click();

    await passwordInputElement.setValue(userPassword, { mask: true });
  }
```

Το παραπάνω θα αποκρύψει την τιμή κειμένου από τα αρχεία καταγραφής του WDIO ως εξής:

Παράδειγμα αρχείων καταγραφής:
```text
INFO webdriver: DATA { text: "**MASKED**" }
```

Οι reporters, όπως οι Allure reporters, και εργαλεία τρίτων όπως το Percy από το BrowserStack θα χειρίζονται επίσης την αποκρυμμένη έκδοση.
Σε συνδυασμό με την κατάλληλη έκδοση του Appium, τα Appium Logs θα είναι επίσης απαλλαγμένα από τα ευαίσθητα δεδομένα σας.

:::info

Περιορισμοί:
  - Στο Appium, πρόσθετα plugins θα μπορούσαν να διαρρεύσουν τις πληροφορίες, παρόλο που ζητάμε την απόκρυψή τους.
  - Οι πάροχοι cloud θα μπορούσαν να χρησιμοποιούν έναν proxy για την καταγραφή HTTP, ο οποίος παρακάμπτει τον μηχανισμό απόκρυψης που έχει τεθεί σε εφαρμογή.
  - Η εντολή `getValue` δεν υποστηρίζεται. Επιπλέον, εάν χρησιμοποιηθεί στο ίδιο στοιχείο, μπορεί να εκθέσει την τιμή που προορίζεται για απόκρυψη κατά τη χρήση των `addValue` ή `setValue`.

Ελάχιστη απαιτούμενη έκδοση:
 - WDIO v9.15.0
 - Appium v3.0.0

:::

#### Απόκρυψη στα Αρχεία Καταγραφής του WDIO

Χρησιμοποιώντας τη ρύθμιση `maskingPatterns`, μπορούμε να αποκρύψουμε ευαίσθητες πληροφορίες από τα αρχεία καταγραφής του WDIO. Ωστόσο, τα αρχεία καταγραφής του Appium δεν καλύπτονται.

Για παράδειγμα, εάν χρησιμοποιείτε έναν πάροχο cloud και το επίπεδο info, τότε σχεδόν σίγουρα θα «διαρρεύσετε» το κλειδί του χρήστη, όπως φαίνεται παρακάτω:

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=myCloudSecretExposedKey --spec myTest.test.ts
```

Για να το αντιμετωπίσουμε αυτό, μπορούμε να περάσουμε την κανονική έκφραση `'--key=([^ ]*)'` και τώρα στα αρχεία καταγραφής θα δείτε

```text
INFO @wdio/local-runner: Start worker 0-0 with arg: ./wdio.conf.ts --user=cloud_user --key=**MASKED** --spec myTest.test.ts
```

Μπορείτε να επιτύχετε το παραπάνω παρέχοντας την κανονική έκφραση στο πεδίο `maskingPatterns` της διαμόρφωσης.
  - Για πολλαπλές κανονικές εκφράσεις, χρησιμοποιήστε μία μόνο συμβολοσειρά αλλά με τιμές διαχωρισμένες με κόμμα.
  - Για περισσότερες λεπτομέρειες σχετικά με τα μοτίβα απόκρυψης, δείτε την [ενότητα Masking Patterns στο README του WDIO Logger](https://github.com/webdriverio/webdriverio/blob/main/packages/wdio-logger/README.md#masking-patterns).

```ts
export const config: WebdriverIO.Config = {
    specs: [...],
    capabilities: [{...}],
    services: ['lighthouse'],

    /**
     * διαμορφώσεις δοκιμών
     */
    logLevel: 'info',
    maskingPatterns: '/--key=([^ ]*)/',
    framework: 'mocha',
    outputDir: __dirname,

    reporters: ['spec'],

    mochaOpts: {
        ui: 'bdd',
        timeout: 60000
    }
}
```

:::info
Ελάχιστη απαιτούμενη έκδοση:
 - WDIO v9.15.0
:::

:::warning
Για μυστικά που περνούν μέσω της γραμμής εντολών, η απόκρυψη ενδέχεται να αποτύχει, επειδή το αρχείο wdio.conf.ts αναλύεται αργότερα στον κύκλο εκτέλεσης. Η χρήση μεταβλητών περιβάλλοντος για αυτές τις περιπτώσεις συνιστάται ιδιαίτερα και είναι πολύ ασφαλέστερη.
:::

#### Απενεργοποίηση των Loggers του WDIO

Ένας άλλος τρόπος για να αποτρέψετε την καταγραφή ευαίσθητων δεδομένων είναι να μειώσετε ή να σιγάσετε το επίπεδο καταγραφής ή να απενεργοποιήσετε τον logger.
Αυτό μπορεί να επιτευχθεί ως εξής:

```ts
import logger from '@wdio/logger';

/**
  * Ορίζει το επίπεδο του WDIO logger σε 'silent' πριν από την *εκτέλεση ενός promise, γεγονός που βοηθά στην απόκρυψη ευαίσθητων πληροφοριών στα αρχεία καταγραφής.
 */
export const withSilentLogger = async <T>(promise: () => Promise<T>): Promise<T> => {
  const webdriverLogLevel = driver.options.logLevel ?? 'error';

  try {
    logger.setLevel('webdriver', 'silent');
    return await promise();
  } finally {
    logger.setLevel('webdriver', webdriverLogLevel);
  }
};
```

### Λύσεις Τρίτων

#### Appium
Το Appium προσφέρει τη δική του λύση απόκρυψης· δείτε [Log filter](https://appium.io/docs/en/latest/guides/log-filters/)
 - Η χρήση της λύσης τους μπορεί να είναι δύσκολη. Ένας τρόπος, εάν είναι δυνατόν, είναι να περάσετε ένα token στη συμβολοσειρά σας, όπως `@mask@`, και να το χρησιμοποιήσετε ως κανονική έκφραση
 - Σε ορισμένες εκδόσεις του Appium, οι τιμές καταγράφονται επίσης με κάθε χαρακτήρα διαχωρισμένο με κόμμα, οπότε πρέπει να είμαστε προσεκτικοί.
 - Δυστυχώς, το BrowserStack δεν υποστηρίζει αυτή τη λύση, αλλά εξακολουθεί να είναι χρήσιμη τοπικά

Χρησιμοποιώντας το παράδειγμα `@mask@` που αναφέρθηκε προηγουμένως, μπορούμε να χρησιμοποιήσουμε το ακόλουθο αρχείο JSON με όνομα `appiumMaskLogFilters.json`
```json
[
  {
    "pattern": "@mask@(.*)",
    "flags": "s",
    "replacer": "**MASKED**"
  },
  {
    "pattern": "\\[(\\\"@\\\",\\\"m\\\",\\\"a\\\",\\\"s\\\",\\\"k\\\",\\\"@\\\",\\S+)\\]",
    "flags": "s",
    "replacer": "[*,*,M,A,S,K,E,D,*,*]"
  }
]
```

Στη συνέχεια, περάστε το όνομα του αρχείου JSON στο πεδίο `logFilters` της διαμόρφωσης του appium service:
```ts
import { AppiumServerArguments, AppiumServiceConfig } from '@wdio/appium-service';
import { ServiceEntry } from '@wdio/types/build/Services';

const appium = [
  'appium',
  {
    args: {
      log: './logs/appium.log',
      logFilters: './appiumMaskLogFilters.json',
    } satisfies AppiumServerArguments,
  } satisfies AppiumServiceConfig,
] satisfies ServiceEntry;
```

#### BrowserStack

Το BrowserStack προσφέρει επίσης κάποιο επίπεδο απόκρυψης για την απόκρυψη ορισμένων δεδομένων· δείτε [hide sensitive data](https://www.browserstack.com/docs/automate/selenium/hide-sensitive-data)
 - Δυστυχώς, η λύση είναι «όλα ή τίποτα», επομένως όλες οι τιμές κειμένου των παρεχόμενων εντολών θα αποκρύπτονται.
