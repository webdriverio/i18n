WebdriverIO MCPに関するよくある質問です。

## 一般

### MCPとは何ですか？

MCP（Model Context Protocol）は、ClaudeのようなAIアシスタントが外部のツールやサービスと連携できるようにするオープンプロトコルです。WebdriverIO MCPはこのプロトコルを実装し、Claude DesktopおよびClaude Codeにブラウザおよびモバイルの自動化機能を提供します。

### WebdriverIO MCPで何を自動化できますか？

以下を自動化できます：
-   **デスクトップブラウザ**（Chrome、Firefox、Edge、Safari） - ナビゲーション、クリック、入力、スクリーンショット
-   **iOSアプリ** - シミュレーターまたは実機上で
-   **Androidアプリ** - エミュレーターまたは実機上で
-   **ハイブリッドアプリ** - ネイティブコンテキストとWebコンテキストの切り替え
-   **クラウドデバイス** - BrowserStack、Sauce Labs、TestMu、TestingBotのデバイスクラウド経由で

### コードを書く必要はありますか？

いいえ！それがMCPの主な利点です。やりたいことを自然言語で説明するだけで、Claudeが適切なツールを使用してタスクを実行します。

**プロンプトの例：**
-   「Chromeを開いてwebdriver.ioに移動して」
-   「Get Startedボタンをクリックして」
-   「現在のページのスクリーンショットを撮って」
-   「iOSアプリを起動してテストユーザーとしてログインして」

## インストールとセットアップ

### WebdriverIO MCPはどのようにインストールしますか？

個別にインストールする必要はありません。ハーネスで設定すると、MCPサーバーはnpx経由で自動的に実行されます。設定に以下を追加してください：

```json
{
    "mcpServers": {
        "wdio-mcp": {
            "command": "npx",
            "args": ["-y", "@wdio/mcp"]
        }
    }
}
```

### Claude Desktopの設定ファイルはどこにありますか？

-   **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
-   **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

### ブラウザ自動化にAppiumは必要ですか？

いいえ。ブラウザ自動化には、対象のブラウザがインストールされていることだけが必要です。WebdriverIOがドライバー管理を自動的に処理します。

### モバイル自動化にAppiumは必要ですか？

はい。モバイル自動化には以下が必要です：
1. Appiumサーバーの起動（`npm install -g appium && appium`）
2. プラットフォームドライバーのインストール（iOSの場合は`appium driver install xcuitest`、Androidの場合は`appium driver install uiautomator2`）
3. 適切な開発ツール（iOSの場合はXcode、Androidの場合はAndroid SDK）

## ブラウザ自動化

### どのブラウザがサポートされていますか？

Chrome、Firefox、Edge、Safariがすべてサポートされています。`start_session`の`browser`パラメータを使用してください：

```text
"Start a Firefox session"
"Start Chrome in headless mode"
```

### ブラウザをヘッドレスモードで実行できますか？

はい。ヘッドレスがデフォルトです（`headless: true`）。ブラウザを表示したい場合は、ヘッドありモードで実行するようClaudeに依頼してください：

「Chromeをヘッドありモード（ヘッドレスではない）で起動して」

### ブラウザのウィンドウサイズを設定できますか？

はい。ブラウザの起動時にサイズを指定できます：

「ウィンドウサイズ1920x1080でChromeを起動して」

サポートされているサイズ：幅400～3840ピクセル、高さ400～2160ピクセル。デフォルトは1920×1080です。

### ブラウザの起動とナビゲーションを1ステップで行えますか？

はい！`navigationUrl`パラメータを使用してください：

「Chromeを起動してhttps://webdriver.ioに移動して」

これは、ブラウザを起動してから別途ナビゲートするよりも効率的です。

### スクリーンショットはどのように撮りますか？

単に次のように依頼してください：

「現在のページのスクリーンショットを撮って」

スクリーンショットは自動的に最適化されます：
- 最大2000pxのサイズにスケーリング
- 最大1MBのファイルサイズに圧縮
- 形式：PNGまたはJPEG（最適な品質になるよう自動選択）

### iframeを操作できますか？

はい。`switch_frame`ツールを使用して、CSSまたはXPathセレクターでiframeに切り替えます。以降の`click_element`、`set_value`、`get_elements`の呼び出しはすべて、切り替えたフレーム内で動作します。セレクターを省略すると、トップレベルのフレームに戻ります。iframeはメインページと同じオリジンである必要があります。

### カスタムJavaScriptを実行できますか？

はい！`execute_script`ツールを使用してください：

「スクリプトを実行してページタイトルを取得して」
「スクリプトを実行：return document.querySelectorAll('button').length」

### 既存のChromeセッションにアタッチできますか？

はい。まず`launch_chrome`を使用し（リモートデバッグを有効にしてChromeを開きます）、次に`attach: true`を指定して`start_session`を使用します。

「リモートデバッグでChromeを起動して、それにアタッチして」

### 複数のタブを扱えますか？

はい。`get_tabs`で開いているタブを一覧表示し、`switch_tab`で特定のタブにフォーカスします：

「開いているすべてのタブを取得して」
「インデックス1のタブに切り替えて」

## モバイル自動化

### iOSまたはAndroidのセッションはどのように開始しますか？

適切なプラットフォームを指定して`start_session`を使用します：

「/path/to/MyApp.appにあるiOSアプリをiPhone 15シミュレーターで起動して」

「/path/to/app.apkにあるAndroidアプリをPixel 7エミュレーターで起動して」

または、すでにインストールされているアプリの場合：

「iPhone 15シミュレーターでnoResetを有効にしてアプリを起動して」

### 実機でテストできますか？

はい！実機の場合は、デバイスのUDIDが必要です：

-   **iOS:** デバイスを接続し、Finderを開いてデバイスをクリックし、シリアル番号をクリックするとUDIDが表示されます
-   **Android:** ターミナルで`adb devices`を実行します

その後、次のように依頼します：

「UDID abc123...の実機でiOSアプリを起動して」

### 権限ダイアログはどのように処理しますか？

デフォルトでは、権限は自動的に許可されます（`autoGrantPermissions: true`）。権限フローをテストする必要がある場合は、これを無効にできます：

「権限を自動的に許可せずにアプリを起動して」

### どのジェスチャーがサポートされていますか？

-   **タップ:** 要素または座標をタップ（`tap_element`）
-   **スワイプ:** 上下左右にスワイプ（`swipe`）
-   **ドラッグ＆ドロップ:** ある要素から別の要素または座標へドラッグ（`drag_and_drop`）

注：`long_press`は、Appiumのモバイルコマンドを使用して`execute_script`経由で利用できます。

### モバイルアプリでスクロールするにはどうすればよいですか？

スワイプジェスチャーを使用します：

「上にスワイプして下にスクロールして」
「下にスワイプして上にスクロールして」

### デバイスを回転できますか？

はい：

「デバイスを横向きに回転して」
「デバイスを縦向きに回転して」

### ハイブリッドアプリはどのように扱いますか？

WebViewを含むアプリの場合、コンテキストを切り替えることができます：

「利用可能なコンテキストを取得して」
「WebViewコンテキストに切り替えて」
「ネイティブコンテキストに戻して」

### Appiumのモバイルコマンドを実行できますか？

はい！`execute_script`ツールを使用してください：

```text
Execute script "mobile: pressKey" with args [{ keycode: 4 }]  // AndroidでBACKを押す
Execute script "mobile: activateApp" with args [{ bundleId: "com.example.app" }]
Execute script "mobile: terminateApp" with args [{ bundleId: "com.example.app" }]
```

## 要素の選択

### AIアシスタントはどの要素を操作すべきかをどのように判断しますか？

`wdio://session/current/elements`リソースまたは`get_elements`ツールを使用して、ページ/画面上のインタラクティブな要素を識別します。各要素には、すぐに使えるセレクターが付属しています。

### ページ上の要素が多すぎる場合はどうすればよいですか？

ページネーションを使用して、大量の要素リストを管理します：

「最初の20個の要素を取得して」
「オフセット20、リミット20で要素を取得して」

レスポンスには`total`、`showing`、`hasMore`が含まれており、要素間のナビゲーションに役立ちます。

### Claudeが間違った要素をクリックした場合はどうすればよいですか？

より具体的に指定できます：

-   正確なテキストを指定：「'Submit Order'と書かれたボタンをクリックして」
-   セレクターを指定：「セレクター#submit-btnの要素をクリックして」
-   アクセシビリティIDを指定：「アクセシビリティID loginButtonの要素をクリックして」

### モバイルに最適なセレクター戦略は何ですか？

1. **アクセシビリティID**（最適） - `~loginButton`
2. **リソースID**（Android） - `id=login_button`
3. **Predicate String**（iOS） - `-ios predicate string:label == "Login"`
4. **XPath**（最終手段） - 遅いがどこでも動作する

### アクセシビリティツリーとは何ですか？いつ使用すべきですか？

アクセシビリティツリーは、ページ要素に関するセマンティックな情報（ロール、名前、状態）を提供します。以下の場合に`get_accessibility_tree`を使用してください：
- `get_elements`が期待する要素を返さない場合
- アクセシビリティロール（button、link、textboxなど）で要素を見つける必要がある場合
- 要素に関する詳細なセマンティック情報が必要な場合

「buttonとlinkロールでフィルタリングしたアクセシビリティツリーを取得して」

## セッション管理

### 複数のセッションを同時に持つことはできますか？

いいえ。MCPサーバーはシングルセッションモデルを使用しています。一度にアクティブにできるブラウザまたはアプリのセッションは1つだけです。

### セッションを閉じるとどうなりますか？

セッションの種類と設定によって異なります：

-   **ブラウザ:** ブラウザが完全に閉じます
-   **`noReset: false`のモバイル:** アプリが終了します
-   **`noReset: true`または`appPath`なしのモバイル:** アプリは開いたままになります（セッションは自動的にデタッチされます）

### セッション間でアプリの状態を保持できますか？

はい！`noReset`オプションを使用してください：

「noResetを有効にしてアプリを起動して」

これにより、ログイン状態、設定、その他のアプリデータが保持されます。

### クローズとデタッチの違いは何ですか？

-   **クローズ:** ブラウザ/アプリを完全に終了します
-   **デタッチ:** 自動化の接続を切断しますが、ブラウザ/アプリは実行したままにします

デタッチは、自動化後に状態を手動で確認したい場合に便利です。

### デバッグ中にセッションがタイムアウトし続けます

コマンドタイムアウトを増やしてください：

「newCommandTimeoutを300秒にしてアプリを起動して」

デフォルトは300秒です。非常に長いデバッグセッションの場合は、600秒を試してください。

## トラブルシューティング

### 「Session not found」エラー

これは、アクティブなセッションが存在しないことを意味します。まずブラウザまたはアプリのセッションを開始してください：

「Chromeを起動してgoogle.comに移動して」

### 「Element not found」エラー

要素が表示されていないか、別のセレクターを持っている可能性があります。以下を試してください：

1. まず表示されているすべての要素を取得するようClaudeに依頼する
2. より具体的なセレクターを指定する
3. ページ/アプリが完全に読み込まれるまで待つ
4. `inViewportOnly: false`を使用して画面外の要素を見つける

### ブラウザが起動しない

1. 対象のブラウザがインストールされていることを確認する
2. 別のプロセスがデバッグポート（9222）を使用していないか確認する
3. ヘッドレスモードを試す

### Appiumへの接続に失敗した

これは、モバイル自動化を開始する際に最もよくある問題です。

1. **Appiumが実行中であることを確認する**: `curl http://localhost:4723/status`
2. 必要に応じてAppiumを起動する: `appium`
3. Appiumの接続設定がサーバーと一致していることを確認する（`start_session`で`appiumConfig`を使用）
4. ドライバーがインストールされていることを確認する: `appium driver list --installed`

:::tip
MCPサーバーでは、モバイルセッションを開始する前にAppiumが実行されている必要があります。必ず最初にAppiumを起動してください：
```sh
appium
```
将来のバージョンでは、Appiumサービスの自動管理が含まれる可能性があります。
:::

### iOSシミュレーターが起動しない

1. Xcodeがインストールされていることを確認する: `xcode-select --install`
2. 利用可能なシミュレーターを一覧表示する: `xcrun simctl list devices`
3. Console.appで特定のシミュレーターのエラーを確認する

### Androidエミュレーターが起動しない

1. `ANDROID_HOME`を設定する: `export ANDROID_HOME=$HOME/Library/Android/sdk`
2. エミュレーターを確認する: `emulator -list-avds`
3. エミュレーターを手動で起動する: `emulator -avd <avd-name>`
4. デバイスが接続されていることを確認する: `adb devices`

### スクリーンショットが機能しない

1. モバイルの場合、セッションがアクティブであることを確認する
2. ブラウザの場合、別のページを試す（一部のページはスクリーンショットをブロックします）
3. Claude Desktopのログでエラーを確認する

スクリーンショットは自動的に最大1MBに圧縮されるため、大きなスクリーンショットも機能しますが、品質が低下する場合があります。

## パフォーマンス

### モバイル自動化が遅いのはなぜですか？

モバイル自動化には以下が含まれます：
1. Appiumサーバーとのネットワーク通信
2. Appiumとデバイス/シミュレーター間の通信
3. デバイスのレンダリングと応答

自動化を高速化するためのヒント：
-   開発には実機ではなくエミュレーター/シミュレーターを使用する
-   XPathの代わりにアクセシビリティIDを使用する
-   要素検出に`inViewportOnly: true`を有効にする
-   ページネーション（`limit`）を使用してトークン使用量を削減する

### 要素検出を高速化するにはどうすればよいですか？

MCPサーバーは、XMLページソースの解析を使用して要素検出をすでに最適化しています（従来の要素クエリでは600回以上のHTTP呼び出しが必要なところを2回に削減）。追加のヒント：

-   `inViewportOnly: true`を設定して画面外の要素を除外する
-   `includeContainers: false`を設定する（デフォルト）
-   大きな画面では`limit`と`offset`を使用してページネーションを行う
-   すべての要素を検索する代わりに、特定のセレクターを使用する

### スクリーンショットが遅い、または失敗する

スクリーンショットは自動的に最適化されます：
- 2000pxより大きい場合はリサイズ
- 1MB未満に収まるよう圧縮
- PNGが大きすぎる場合はJPEGに変換

この最適化により処理時間が短縮され、Claudeが画像を確実に処理できるようになります。

## 制限事項

### 現在の制限事項は何ですか？

-   **シングルセッション:** 一度に1つのブラウザ/アプリのみ
-   **iframeのサポート:** 同一オリジンのiframeは`switch_frame`でサポートされていますが、クロスオリジンのiframeはブラウザのセキュリティ制限によりアクセスできません
-   **ファイルアップロード:** ツールでは直接サポートされていません
-   **音声/動画:** メディア再生を操作できません
-   **ブラウザ拡張機能:** サポートされていません

### 本番環境のテストに使用できますか？

WebdriverIO MCPは、インタラクティブなAI支援型の自動化向けに設計されています。本番環境のCI/CDテストには、完全なプログラム制御が可能なWebdriverIOの従来のテストランナーの使用を検討してください。

## セキュリティ

### データは安全ですか？

MCPサーバーはお使いのマシン上でローカルに実行されます。すべての自動化は、ローカルのブラウザ/Appium接続を通じて行われます。明示的にナビゲートした先以外の外部サーバーにデータが送信されることはありません。

HTTPトランスポートモード（`--http`）を使用する場合、サーバーはデフォルトで`localhost`からの接続のみを受け付けます。アクセスを制御するには`--allowedHosts`と`--allowedOrigins`を使用してください。詳細は[トランスポート](./transport)を参照してください。

### Claudeはパスワードにアクセスできますか？

Claudeはページのコンテンツを見たり要素を操作したりできますが、以下の点に注意してください：
-   `<input type="password">`フィールド内のパスワードはマスクされます
-   機密性の高い認証情報の自動化は避けるべきです
-   自動化にはテストアカウントを使用してください
